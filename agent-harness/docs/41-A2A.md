# 41｜A2A 与 Agent-to-Agent Protocol Boundary

## 1. A2A 解决什么

A2A 面向**独立 Agent 系统之间的互操作**。官方规范强调 capability discovery、interaction modality、collaborative task、secure information exchange，而且不要求暴露彼此内部 memory / tools。

```text
Agent A
  ↕ A2A
Agent B
```

这和同一 Runtime 内部 `spawn_subagent()` 不是一回事。

## 2. MCP vs A2A

```text
MCP：Agent/Host ↔ tools/resources/prompts server
A2A：Agent system ↔ Agent system
```

一个 A2A Agent 内部仍可能用 MCP。

## 3. Protocol 需要什么

- Agent identity / endpoint；
- capability card / discovery；
- task identity；
- messages / artifacts；
- status / progress；
- authentication / authorization；
- cancellation / failure。

## 4. 为什么不直接 RPC

RPC 可以传请求，但 A2A 关注的是长任务、Agent capability 与异步协作语义。是否真的需要 A2A 要看跨团队/跨框架互操作需求，内部简单服务不要为协议而协议。

## 5. Recursive Delegation

Agent A → B → C 时要有：

```text
depth limit
budget propagation
identity / auth
trace correlation
```

否则容易形成调用环或预算失控。

## 🎯 面试

MCP 主要连接 Agent 与 Tool/Context Server；A2A 面向独立 Agent 系统协作。内部 subagent 可直接用 Runtime contract，跨系统才更需要 A2A 的 discovery、task/status/artifact 和安全协议，并要控制递归、预算和 trace。

<details><summary>自测：用了 A2A 后还需要 MCP 吗？</summary>

可能需要。A2A 解决 Agent-to-Agent，Agent 自己访问外部 Tool/Resource 仍可通过 MCP。
</details>
