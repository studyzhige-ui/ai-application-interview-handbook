# Agent Harness / Runtime 高频面试题

> 这些题按知识链组织，不按死记频率排序。真实频率以 `research/questions/agent-harness.md` 为准。

## A｜Agent / Harness / Loop

### 1. Agent 和普通 LLM Application / Workflow 有什么区别？

30 秒：Workflow 路径主要由程序预定义；Agent 根据中间 Observation 动态决定下一步。是否需要 Agent 取决于路径不确定性与自主决策价值，不取决于步骤数量。

### 2. 什么是 Agent Harness / Runtime？为什么 Model 外面还要这一层？

回答：负责 Loop、Context、Tool execution、State/Memory、Permission/Sandbox、Checkpoint/Resume、Cancellation、Trace/Eval。Model 决策，Harness 执行和约束。

### 3. 一个 Minimal Agent Loop 怎么写？

答出 `build context → model decision → validate/execute tool → observation → state update → repeat/stop`。

### 4. Run / Turn / Step 怎么区分？

答出作用域、ID、retry/checkpoint/cancel/trace scope。

### 5. Runtime Message 和 Event 有什么区别？

Message 是 model-visible conversation 的一部分；Event 是真实 Runtime 事实，未必都喂模型。

### 6. Agent 为什么会 Dead Loop？怎么防？

重复 Tool/error、无状态进展；用 signature、max turns、budget、progress detection、replan/human/terminate。

## B｜Tool Runtime

### 7. Tool Calling 完整链路是什么？

Model call → parse/schema → semantic validation → permission/approval → route/executor → result → persist/trace → observation。

### 8. Tool schema 为什么不等于安全？

Schema 只保证结构；还需业务语义、权限、sandbox、side-effect policy。

### 9. Tool Result 应返回字符串还是结构化对象？

优先有稳定 status/error/data 结构；给模型可读摘要，raw result 可外置。

### 10. Tool Failure 怎么分类？

Invalid input、permission、not found、timeout、rate limit、transient network、permanent business、partial success。

### 11. 哪些 Tool 可以自动 Retry？

错误 transient + 动作安全重放/幂等 + budget/deadline 允许。

### 12. Tool 已成功但响应超时怎么办？

进入 UNKNOWN，按 idempotency key/resource id reconcile，而非盲 retry。

### 13. 为什么 Tool 需要 read-only / destructive / concurrency-safe metadata？

决定 approval、parallelism、retry 和 sandbox policy。

### 14. 用户在 Tool 执行中发新消息怎么办？

Runtime 要定义 interrupt behavior：cancel、block，或特定 Tool 的 cooperative handling。

### 15. Tool 很多时怎么处理？

Capability catalog → discovery/rank → progressive load 少量完整 schemas → exact selection。

## C｜Planning / Context

### 16. ReAct 是什么？和 Plan-and-Execute 区别？

ReAct 强调 Reason/Act/Observe 交替；Plan-and-execute 先形成较稳定计划，再执行和修订。按环境不确定性选择。

### 17. Planning 越详细越好吗？

不是。高不确定环境过度前置规划容易基于错误假设，应该增量 replanning。

### 18. Agent Context 由什么组成？

Instructions、Goal、State、History、Memory、Tools、Retrieved Evidence、Tool Results、Environment hints。

### 19. Prompt Engineering、Context Engineering、Harness Engineering 区别？

Prompt 管单次 instruction；Context 管本轮模型看到的整体 token；Harness 管跨轮执行、状态、工具、安全与恢复。

### 20. Context Window 大了还需要 Compaction 吗？

通常仍需要。长 Context 有成本、延迟、噪声和 attention quality 问题，长任务还可能跨多个窗口。

### 21. Context Compaction 完整链路？

Trigger → select history → compact → build replacement → preserve invariants → persist → recompute tokens → continue。

### 22. Compaction 后怎么保证关键约束没丢？

Goal/hard constraints/side-effect/artifact/version/current task 等结构化 invariant，summary 不是 source of truth；做 long-task regression。

### 23. Tool Result 太长怎么办？

Truncate / summarize / offload raw artifact + stable reference，必要时按需读取。

### 24. Stale Context / Stale Memory 怎么处理？

version/hash/provenance，read-on-use validation，invalidate superseded projection。

## D｜Memory / State / Long-running

### 25. Context、Memory、State、History 有什么区别？

Context 是当前 token；Memory 是未来可检索信息；State 是当前执行事实；History 是过去轨迹。

### 26. Memory 应该怎么分层？

Working/Episodic/Semantic/Procedural；写入和读取都有 relevance/confidence/freshness/provenance。

### 27. 错误 Memory 写进去怎么办？

Write gate、provenance/confidence、version、user correction、supersede/delete、revalidation。

### 28. Checkpoint 保存什么？

Run identity、state version、current step、context reference、pending tool/approval、side-effect ledger、artifact、budget。

### 29. Resume 为什么不能只重放 messages？

外部副作用、结构化 state、approval、artifact version 可能不在 messages；还需 reconciliation。

### 30. Tool 成功但 Checkpoint 失败，恢复后怎么办？

稳定 logical action id/idempotency key + side-effect ledger，先 reconcile external status，再决定 retry/compensate/human。

### 31. Pause、Cancel、Fail 有什么区别？

Pause 可 resume；Cancel 是明确终止意图；Fail 是未达到目标的错误终态/可重试态，语义要分开。

### 32. Fork / Branch 需要决定哪些继承语义？

Instructions snapshot、state、history、memory、workspace、permission、credentials、budget，不能无脑 deepcopy。

## E｜Security

### 33. Permission、Approval、Sandbox 区别？

Policy、单次人机决策、强制环境边界三层。

### 34. HITL 为什么不是一个 confirm 弹窗？

长任务中要持久化 WAITING_APPROVAL / RunState，绑定 call_id+args，批准后恢复原 Run。

### 35. Prompt Injection 怎么防？

Trust boundary + least privilege + permission + approval + sandbox + secret/egress containment；检测只是附加层。

### 36. RAG / Tool Result 为什么也是 untrusted context？

外部数据可能携带恶意或过期 instruction，不应提升为 system policy。

### 37. Secret 为什么不要直接放 Context？

用 credential broker/tool 代持；Context 暴露会被模型输出、日志或 injection 外传。

### 38. 怎样限制 Agent blast radius？

workspace/network/credential scope、destructive approval、tenant isolation、resource quota、containment。

## F｜MCP / Skills / Extension

### 39. MCP 是什么？解决什么？

Host/Client/Server 标准协议，连接 Tool/Resource/Prompt；不等于 Agent Loop。

### 40. MCP Tool、Resource、Prompt 怎么区分？

Tool 模型请求执行；Resource 应用管理 context；Prompt 用户控制模板/指令入口。

### 41. MCP 和 A2A 区别？

MCP 偏 Agent ↔ capability/context server；A2A 偏独立 Agent system ↔ Agent system。

### 42. Tool、Skill、MCP、Command 有什么区别？

Tool 动作；Skill 程序性能力包；MCP 连接协议；Command 用户显式入口。

### 43. Hook / Plugin 在 Runtime 里怎么定位？

Hook 是 lifecycle extension point；Plugin 可打包 tools/hooks/skills 等。核心安全语义不要只依赖可选 hook。

## G｜Routing / Multi-Agent

### 44. Intent Routing 怎么实现？

Rule/metadata/small classifier/embedding/LLM/agentic discovery，从简单可靠开始；低置信澄清，做 route eval。

### 45. Model Routing 看哪些因素？

Task、quality、context size、risk、latency SLO、cost、provider health、capability compatibility。

### 46. Multi-Agent 什么时候值得？

子任务独立可并行、Context 可隔离、role/tool 区分明显、结果易聚合。否则单 Agent 更简单。

### 47. Manager、Agent-as-Tool、Handoff 区别？

Manager 持有控制权；agent-as-tool child 返回结果；handoff 转移控制权。

### 48. 多 Agent 同时修改 Repo 怎么办？

Task ownership、独立 worktree/branch、version check/lock、merge + verification。

### 49. A2A 需要哪些关键语义？

Discovery、task id/status、message/artifact、auth、cancel/failure、trace/budget propagation。

## H｜Trace / Eval / Coding / Production

### 50. Agent Trace 应记录什么？

Run/Turn/Generation/Tool/State/Approval/Handoff，model-visible context、tool evidence、latency/cost/error。

### 51. Replay 时为什么不能直接重执行所有 Tool？

会重复副作用且环境已变化；应区分 event replay 和 eval replay，外部 Tool 通常 mock/freeze。

### 52. Agent Eval 和普通 LLM Eval 有什么不同？

除了输出文本，还要评 trajectory、Tool、artifact、environment outcome。

### 53. LLM Judge 可以作为唯一 Agent Grader 吗？

不建议。能 deterministic 验证的环境结果优先；Judge 补主观维度并做人工校准。

### 54. Coding Agent 怎样证明 Patch 可交付？

Repo understanding → patch → focused/broad tests → lint/typecheck/build → diff review → requirement verification。

### 55. Production Agent Runtime 怎么拆？

API / Run Service / Harness Worker / Model Router / Tool Gateway / Sandbox / State-Event / Artifact / Queue / Trace-Eval / Tenant isolation。

### 56. LangGraph / Agents SDK / 自研 Loop 怎么选？

先列 state/recovery/tool-policy/streaming/multi-agent/trace/deployment 需求，再匹配框架抽象；不是看流行度。
