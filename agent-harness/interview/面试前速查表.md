# Agent Harness / Runtime 面试前速查表

## 一句话

> Agent Harness 是模型外层的执行 Runtime：把 Goal、Context、State、Tools、Policy 和 Environment 组织成可循环、可恢复、可审计的任务执行系统。

## Agent vs Workflow

```text
Workflow = 程序预定义路径
Agent    = 模型根据 Observation 动态决定路径
```

## Minimal Loop

```text
Build Context
→ Model Decision
→ Validate / Authorize
→ Execute Tool
→ Observation
→ Update State
→ Stop / Repeat
```

## Runtime Scope

```text
Run / Session
└─ Turn
   └─ Step
```

常用 ID：`run_id / turn_id / step_id / tool_call_id`。

## Tool Pipeline

```text
Tool Call
→ Parse
→ Schema
→ Semantic Validate
→ Permission / Approval
→ Router / Executor
→ Result
→ Persist / Trace
→ Context Observation
```

## Tool Failure

```text
invalid args
permission denied
not found
timeout
rate limit
transient
permanent
partial / unknown
```

Retry 前问：**transient? idempotent? budget?**

## Context

```text
Instructions
Goal
State
Selected History
Selected Memory
Tools
Evidence
Tool Results
```

Context 是 projection，不是 source of truth。

## Compaction

```text
Trigger
→ Select
→ Summarize/Extract
→ Replacement History
→ Preserve Invariants
→ Persist
→ Token Recompute
→ Continue
```

必须保：Goal / hard constraints / side-effect / artifacts / current status。

## Memory / State / History

```text
Context = 当前 inference token
Memory  = 未来可检索信息
State   = 当前执行事实
History = 过去事件轨迹
```

## Checkpoint / Resume

```text
Load
→ Validate Version
→ Reconcile Side Effects
→ Restore State
→ Rebuild Context
→ Continue
```

经典 failure window：**Tool success → crash → checkpoint not written**。

解决：idempotency key + side-effect ledger + reconciliation。

## Cancellation

```text
RUNNING → CANCELLING → CANCELLED
```

要向 child Tool/Subagent 传播，并处理 late result。

## Security 三层

```text
Permission Policy
↓
Human Approval
↓
Sandbox Enforcement
```

外加：Prompt Injection、Secret、Egress、Tenant Isolation。

## Prompt Injection

不能只检测。核心：

```text
trust boundary
least privilege
approval
sandbox
secret isolation
egress control
```

## MCP

```text
Host
└─ Client ↔ Server
           ├─ Tools
```

## Skill / Tool / MCP / Hook

```text
Tool  = executable action

MCP   = connection protocol

```

## Multi-Agent

值得拆：独立、可并行、Context 可隔离、结果易聚合。

```text
Manager
→ Subagents
→ Artifacts
→ Aggregate / Verify
```

## A2A

独立 Agent system 之间 discovery / task / artifact / status / auth 协议。与 MCP 不同。

## Workspace

```text
ownership
isolated worktree / branch
version check / lock
merge
verify
```

## Trace

至少能重建：

```text
模型看到了什么？
为什么调用这个 Tool？
Tool 实际返回什么？
State 怎样变化？
在哪里 Retry / Approval / Handoff？
最终 Environment Outcome 是什么？
```

## Eval

```text
Decision
Trajectory
Artifact
Environment Outcome
```

能 deterministic verify 就不要只问 LLM Judge。
