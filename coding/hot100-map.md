## 1. 怎么读这张表

“首次学习”不是说这题只出现一次：

```text
02–03 = Python Coding Basics / Basic Exercises
05    = Data Structures
06    = Problem Solving & Algorithms
07    = Hot100 收口阶段
```

例如 `283 移动零` 在 02–03 先练 list / for / if，再到 06 推导 O(1) 额外空间双指针，07 才做混合 Recall。

### ACM 标记

| 标记 | 含义 |
|---|---|
| ✅ | 很适合额外改成 stdin → solve → stdout |
| ◐ | 可以做，但不是优先项 |
| — | 通常不必强行改；输入结构可能盖过当前算法目标 |

链表 / 二叉树的 `—` 不代表 OA 不考，而是本课程不要求为了“ACM 化”专门花大量时间设计节点序列化。

## 3. 不要按这张表制造“100 份笔记”

每道题最多保留一张短解题卡：

```text
题号 / 名称：
一句话问题：
Brute Force：
复杂度：
瓶颈：
优化关键：
核心状态 / invariant：
最终复杂度：
最容易错的边界：
状态：L / S / A / R
```

`L = Learned`，`S = Solved`，`A = ACM`，`R = Recall`。其中 A 只对值得 ACM 化的题追求。

## 4. 推荐的第一次推进方式

```text
Coding 01–03
→ 先拿 1 / 49 / 283 / 136（基础版）建立真实题感

Coding 04
→ 把已经会的数组 / 字符串题改成 ACM

Coding 05
→ 解锁链表 / 树 / 栈 / Queue / Heap 的结构型入门题

Coding 06
→ 大规模完成 Medium 主干与算法模式

Coding 07
→ 补 Hard / 综合题 + 专题收口 + 混合 Recall
```

核心不是“越早做越难”，而是：**只在前置知识够用时让 Hot100 进入当前章节。**

## 6. V1 的 Hot100 原则

```text
能用 Hot100 自然解释当前知识 → 用
当前知识不足 → 先用最小例子
以后前置补齐 → 回到 Hot100
已经 AC → 还要问为什么
已经理解 → 还要随机重写
算法熟悉 → 适合时再改 ACM
```

目标不是让 Hot100 成为另一个孤立模块，而是让它成为整条 Coding Curriculum 的贯穿式实践线。
