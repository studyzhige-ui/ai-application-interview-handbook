# 07｜Hot100：把“做过题”收口成稳定算法能力

[← 上一章：Problem Solving & Algorithms](06-problem-solving-and-algorithms.md) · [Coding 首页](../README.md) · [Hot100 Map](../hot100-map.md) · [下一章：Online Assessment →](08-online-assessment.md)

> 到这一章时，Hot100 不应该还是 100 道完全陌生的题。前六章已经不断解锁其中一部分。本章的任务是：**补齐剩余题目、按专题建立联系、混合抽题验证能否真正调用。**

---

## 1. Hot100 在这套课程里的定位

它不是：

```text
100 道答案
→ 背下来
→ 算法学完
```

而是：

```text
Python 基本功
+ 数据结构
+ Problem Solving
+ 常见算法模式
        ↓
Hot100 综合训练
        ↓
真实 OA / 机试
```

所以我们不会重新为每道题写一篇题解。官方题面、运行环境与提交留在 LeetCode；仓库维护的是**第一次出现位置、知识依赖、复习方法和状态**。

---

## 2. 不按照官方展示顺序机械刷

LeetCode Hot100 当前按多个专题组织。本课程进一步按前置知识把第一次学习位置拆散。

完整映射见：[Hot100 Curriculum Map](../hot100-map.md)。

你会看到类似：

```text
1 两数之和
→ 01 暴力预览
→ 02 dict 推导
→ 03 独立重写
→ 04 ACM 改写
→ 07 混合 Recall

283 移动零
→ 01 基础循环
→ 02 list 修改
→ 03 基础独立写
→ 06 双指针优化
→ 07 Recall
```

同一道题重复出现，是因为训练目标不同。

---

## 3. 一道题有四种状态

推荐只记录：

```text
L = Learned
理解题意、核心思路和参考实现

S = Solved
关掉答案能独立写出并通过

A = ACM
适合的题能写成完整 stdin → solve → stdout

R = Recall
隔一段时间随机抽到仍能解释并重写关键实现
```

例如：

```text
1 两数之和
L ✅ S ✅ A ✅ R ⬜
```

不要只记录：

```text
✅ 做过
```

因为“做过”可能只是看完题解。

---

## 4. Pass A：按知识依赖完成第一次系统解锁

第一遍目标不是随机挑战，而是减少无意义卡顿。

建议按照 [Hot100 Map](../hot100-map.md) 中的阶段顺序：

```text
基础容器
→ Hash
→ Array / String
→ Linked List
→ Stack / Queue
→ Tree
→ Two Pointers / Sliding Window / Prefix Sum
→ Binary Search
→ Graph
→ Backtracking
→ Heap
→ Greedy
→ DP
→ Hard / 综合技巧
```

第一次做某个新模式时允许：

```text
看最小讲解
→ 手工 trace
→ 关掉讲解重新写
```

但第二道同类题开始，要逐渐减少依赖。

---

## 5. Pass B：按专题把题目连成“为什么”

专题复习不是背模板，而是回答专题内部的共同问题。

### Hash

问：

> 我把什么历史信息存起来，避免了什么重复查找？

### 双指针

问：

> 两个位置分别代表什么边界 / 进度？移动哪一个为什么不会漏答案？

### 滑动窗口

问：

> 当前窗口满足什么 invariant？何时扩，何时缩？

### 二分

问：

> 搜索空间的单调性是什么？每一步为什么能排除一半？

### DFS / BFS

问：

> 当前状态是什么？邻居是谁？visited 什么时候记录？

### DP

问：

> `dp[...]` 到底表示什么？状态从哪些更小状态转移而来？

如果一个专题只能背代码，说明专题还没形成模型。

---

## 6. Pass C：混合抽题，打破“看到目录就知道答案”

真实笔试不会先告诉你：

> “下面是一道滑动窗口题。”

因此完成专题后必须混合训练。

推荐每次随机抽 3～5 道已经学过的题：

```text
先不看专题标签
↓
3 分钟内复述问题
↓
写暴力或朴素思路
↓
说明瓶颈
↓
说出最终算法
↓
再开始编码
```

如果一离开专题目录就认不出来，说明之前记住的是“分类位置”，不是问题结构。

---

## 7. 每道题只保留一张短解题卡

格式：

```text
题号 / 名称：

一句话问题：

Brute Force：
复杂度：

瓶颈：

优化关键：

核心状态 / invariant：

最终复杂度：

最容易错的边界：

状态：L / S / A / R
```

不要逐题抄长篇题解。

例如 `3. 无重复字符的最长子串`：

```text
一句话：最长连续无重复区间

暴力：枚举子串并检查重复

瓶颈：重复检查大量重叠区间

优化：滑动窗口 + set

状态：窗口始终无重复字符

复杂度：O(n)

易错：遇重复时要 while 缩，不一定只缩一次
```

## 8. 看题解之后必须做什么

如果卡住后看了题解：

```text
看懂
≠
会做
```

固定动作：

1. 关掉题解；
2. 用自己的话写出“暴力 → 瓶颈 → 优化”；
3. 从空白编辑器重新实现；
4. 至少造 3 个测试；
5. 第二天或几天后再抽一次。

只有第 3 步真正独立完成，才从 L 向 S 走。

---

## 9. Hard 题怎么处理

第一次系统学习不要求你对所有 Hard 都“白手起家秒出”。

Hard 题可以分成三个目标：

```text
阶段 1
能理解问题 + 暴力边界

阶段 2
理解最优思路为什么成立

阶段 3
关掉答案能重写关键实现
```

例如：

- `42 接雨水`；
- `76 最小覆盖子串`；
- `25 K 个一组翻转链表`；
- `124 二叉树最大路径和`；
- `84 柱状图最大矩形`；
- `4 两个正序数组中位数`；
- `72 编辑距离`。

这些题不应该卡住整个学习主线数天。

---

## 10. 哪些题值得额外做 ACM 版

优先：

```text
数组
字符串
矩阵
网格 / 图
二分
贪心
DP
```

例如：

- `53 最大子数组和`；
- `56 合并区间`；
- `54 螺旋矩阵`；
- `3 无重复字符最长子串`；
- `200 岛屿数量`；
- `207 课程表`；
- `70 爬楼梯`；
- `322 零钱兑换`。

通常不强制：

```text
大量 TreeNode 构造型题
复杂链表结构题
LRU / Trie 这类本身已经在考结构实现的题
```

ACM 的目标是练完整程序，不是让输入构造盖过算法本身。

---

## 11. Hot100 最终完成不等于每题都背下来

更合理的完成标准：

```text
100 题全部至少达到 L
        ↓
绝大多数 Easy / Medium 达到 S
        ↓
代表性题达到 R
        ↓
适合的题有一批达到 A
        ↓
随机抽题时能先分析，而不是先猜模板
```

如果一道 Hard 题已经理解并能在复习后重建，但第一次独立想不出来，不意味着整个 Hot100 没学完。

真正目标是形成**可迁移的问题求解框架**。

---

## 12. 推荐 Recall 节奏

完成一道代表性题后：

```text
D+1
关掉答案复述思路

D+3 / D+7
空白重写核心代码

D+14+
混合随机抽题
```

如果错了，不是重新从头刷完整专题，而是把错误放入 Error Log：

```text
忘的是状态定义？
边界？
Python API？
还是根本没理解优化原因？
```

针对缺口修。

---

## 13. 完成 Hot100 后的变化

你应该从：

```text
“这题我见过吗？”
```

逐渐变成：

```text
问题要求什么？
最直接怎么做？
瓶颈在哪？
哪些信息可以复用？
需要什么数据结构？
状态 / invariant 是什么？
复杂度是否符合约束？
```

这时才真正准备好进入真实 OA。

---

## 14. Exit Gate

进入下一章前，至少能做到：

- 使用 Hot100 Map 解释每个专题大致解决什么问题；
- 不看题解写出一批核心代表题；
- 随机抽题时先给朴素方案，而不是沉默等模板；
- 对自己最熟悉的题能解释 invariant / 状态定义；
- Hard 题知道自己处于“理解 / 重写 / 独立解决”的哪一级；
- 已把一部分数组、字符串、矩阵、图 / DP 题改写为 ACM；
- Error Log 记录的是错误原因，不是复制完整答案。
