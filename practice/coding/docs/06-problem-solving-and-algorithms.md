# 06｜算法推导：从正确做法到减少重复工作

[← 上一章：数据结构](05-data-structures.md) · [Coding 首页](../README.md) · [下一章：Hot100 综合训练 →](07-hot100.md) · [题目映射](../hot100-map.md)


拿到一道新题时，你可能已经认识每种语法，却仍在想：“我怎么知道这里该用字典，那里该用两个下标？”问题往往不在语法，而在于还没把**题目要求、重复工作和要保存的状态**连起来。

这一章不从背模板开始，而从一个更容易回答的问题开始：最直接的办法怎样做？它反复做了什么？如果把某些信息记住，下次能不能少做一点？下面的算法都围绕这条推导线展开。较长的章节可以按小节逐次练习，不需要一次记住所有模式。

## 1. 每次优化都要回答：省掉了什么工作

遇到陌生题，可以按下面的顺序推进：

1. **说清任务。** 输入是什么，要返回什么，哪些条件由题目保证？
2. **手算一个样例。** 先确定自己没有理解错题意。
3. **写出朴素解。** 暂时不追求最快，但每一步要能解释。
4. **找重复工作。** 哪些查找、求和或尝试，在不同轮次被重新做了？
5. **设计要保存的状态。** 把哪些信息留下，下一轮就不用重做？
6. **实现并验证。** 检查结果、边界和成本，再解释优化为什么不会漏解。

这是一条解题路线，不要求每道熟悉的小题都写六段笔记。

以两数之和为例，每拿到一个数，重新扫描其他位置也能求解。重复之处是：刚才见过的数字，下一轮又得重新寻找。如果把“数字在哪里”留下来，遇到新数字时就可以直接查询它的补数。

所以优化不是把一个“笨算法”换成一个神奇名字，而是先认出浪费在哪里，再决定保存什么信息。

复杂度用来比较数据增多时的工作量。以 `n = 100000` 为例：

| 工作量的增长方式 | 对应的数量级 |
|---|---:|
| 随 n 线性增长 | 约 10⁵ |
| 随 n 的平方增长 | 约 10¹⁰ |

> ⚠️ 这不是运行秒数，也不是对每行代码次数的精确预测。运行环境、常数和元素操作成本仍会影响结果。数据范围可以帮助排除明显过慢的做法，但不能单独告诉你该用哪个算法。

每个状态还应该有一句持续成立的解释。比如“两数之和的字典，在查询时只保存此前的位置”，就能说明为什么不会拿同一个位置配对。这种在每轮某个固定时刻都成立的事实，叫**循环不变量**。

检验一个不变量时，分三步问：

1. 初始化后，它为什么成立？
2. 本轮更新后，它为什么仍然成立？
3. 循环结束时，它怎样帮助我们得到答案？

不必一开始就写形式化证明，但不能只用“这是哈希模板”代替这三个解释。

## 2. 哈希：把需要反复查询的历史保留下来

同样使用字典，两数之和记位置，分组题记同类数据，计数题记次数。真正决定算法的不是容器名字，而是**下一步会反复问什么**。

下面换一个例子：一组乱序数字里，最长的一段连续数值有多长？如果从 1 数过 1、2、3、4，再从 2 重新数 2、3、4，就做了重复工作。能否只从每段的起点开始？

**任务：** 找出最长连续数值段的长度。输入可以乱序、重复或为空，空列表返回 0。例如 `[100, 4, 200, 1, 3, 2]` 返回 4，因为里面有 `1、2、3、4`。

判断一个数是不是起点，只需要检查它前面的数：

- `x - 1` 也在集合中：`x` 位于某段中间，不从它重新计数。
- `x - 1` 不在集合中：`x` 是起点，从它开始向后找 `x + 1`、`x + 2`。

`values` 保存去重后的数字，`best` 保存已经找到的最长长度，`end` 表示本轮正在寻找的下一个数。

> ⚠️ 本题的“连续”指数值相差 1，不要求它们在原列表中相邻。

```python
def longest_consecutive(nums):
    values = set(nums)
    best = 0
    for x in values:
        if x - 1 in values:
            continue              # 不是起点，不重复从中间数
        end = x
        while end in values:
            end += 1
        best = max(best, end - x)
    return best

assert longest_consecutive([100, 4, 200, 1, 3, 2]) == 4
assert longest_consecutive([1, 1, 2]) == 2
assert longest_consecutive([]) == 0
```

在这个样例里，1、100、200 都是各自连续段的起点。从 1 扩展时，依次找到 1、2、3、4，到 5 时停止，长度为 `5 - 1 = 4`。轮到 2、3、4 时，因为它们都有前一个数，就不再重复扩展。

外层每个不同的数检查一次，内层对每个连续段也只完整走一次。按集合操作的平均成本计算，总时间为 O(n)，额外空间为 O(n)。

> ⚠️ 不能看到两层缩进就判断为 O(n²)。要数完整运行过程中，每个元素总共被处理了多少次。

## 3. 双指针：两个位置各自代表什么

回文从左到右和从右到左读，字符顺序相同。除了构造反向字符串，还可以直接比较两端字符：

- `left` 指向尚未比较的最左位置。
- `right` 指向尚未比较的最右位置。

这一对字符相同，就让两端各向中间走一步。如果某一对不同，立即返回 `False`。两端相遇或交错时，所有需要检查的字符对都已相同，返回 `True`。

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

assert is_palindrome("level") is True
assert is_palindrome("hello") is False
assert is_palindrome("") is True
assert is_palindrome("a") is True
```

用 `"level"` 追踪：

1. 比较下标 0 和 4，都是 `"l"`，两端向中间移动。
2. 比较下标 1 和 3，都是 `"e"`，继续移动。
3. 两个下标都到达 2，只剩中间的 `"v"`，循环结束，返回 `True`。

每轮都缩短未检查的区间，所以循环会结束。时间为 O(n)，额外空间为 O(1)，不需要创建反向字符串。

> ⚠️ `left < right` 时才有一对不同位置需要比较。空字符串和单字符字符串都不进入循环，按本题约定返回 `True`。

移动零也可以用两个下标，但这次它们不从两端出发，而是分别负责读取和写入。

**任务：** 保持非零元素的相对顺序，把 `[0, 1, 0, 3, 12]` 原地改为 `[1, 3, 12, 0, 0]`，不创建随 n 增长的额外列表。

- `read`：这轮正在检查哪个位置。
- `write`：下一个非零元素应该放到哪个位置，初始为 0。

读到零就继续读。读到非零元素，就把它交换到 `write` 位置，然后让 `write` 前进一步。

```python
def move_zeroes(nums):
    write = 0
    for read in range(len(nums)):
        if nums[read] != 0:
            nums[write], nums[read] = nums[read], nums[write]
            write += 1

nums = [0, 1, 0, 3, 12]
assert move_zeroes(nums) is None
assert nums == [1, 3, 12, 0, 0]
empty = []
move_zeroes(empty)
assert empty == []
```

> ⚠️ 交换语句先读取右侧两个旧值，再分别写回左侧位置。不能改成两句互相覆盖的赋值，否则可能丢失其中一个旧值。

每轮执行后的结果如下：

| read | 检查值 | 更新后的 write | 列表 |
|---:|---:|---:|---|
| 0 | 0 | 0 | [0,1,0,3,12] |
| 1 | 1 | 1 | [1,0,0,3,12] |
| 2 | 0 | 1 | [1,0,0,3,12] |
| 3 | 3 | 2 | [1,3,0,0,12] |
| 4 | 12 | 3 | [1,3,12,0,0] |

每轮结束时，已读过的部分分成两段：

- `write` 之前：已经放好的非零数字，保持原来的相对顺序。
- 从 `write` 到 `read`：零。如果 `write` 已超过 `read`，这一段就是空的。

`read` 每轮只向前一步，`write` 只在读到非零时前进，因此写入不会越过尚未读取的区域。时间为 O(n)，额外空间为 O(1)。

两个下标在不同题里可以有不同职责：回文里是左右边界，这里是读取与写入进度。解释它们各自在做什么，比记住变量名更重要。

## 4. 滑动窗口：维护连续区间，而不是重复重建

如果已经知道 ab 没有重复，再读到一个 b，不需要把所有子串从头检查一遍。只要修复当前这段区间，让它重新没有重复，就能继续向右扩展。这个会移动边界的连续区间，就是窗口。

**任务：** 返回字符串中不含重复字符的最长连续子串长度。`"abba"` 返回 2，对应 `"ab"` 或 `"ba"`。

窗口用左右边界描述，另存一份窗口状态：

- `left`、`right`：窗口的左右下标。
- `seen`：窗口里已有的字符。
- `best`：已找到的最大长度。

每次准备加入新字符 `ch`，先检查它是否已在 `seen` 中。如果有，就从左端逐个移走旧字符，直到重复消失，再加入 `ch` 并更新长度。

> ⚠️ 子串必须是原字符串中连续的一段，不能跳过中间字符来拼答案。

```python
def longest_unique(text):
    seen = set()
    left = 0
    best = 0
    for right, ch in enumerate(text):
        while ch in seen:
            seen.remove(text[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best

assert longest_unique("abba") == 2
assert longest_unique("abcabcbb") == 3
assert longest_unique("") == 0
```

读到 `"abba"` 的第二个 `"b"` 时，旧窗口是 `"ab"`。这一轮的动作是：

1. 新字符 `"b"` 已在集合里，移走左端的 `"a"`。
2. `"b"` 仍在集合里，继续移走旧的 `"b"`。
3. 重复消失，加入新的 `"b"`。窗口变为这一个字符。
4. 更新 `best`。此前长度 2 更大，所以 `best` 仍为 2。

**每次更新 `best` 时，集合恰好包含窗口 `text[left:right + 1]` 的字符，而且没有重复。**

> ⚠️ 这里必须用 `while` 反复检查。只删除一个字符，并不能保证删掉的就是造成重复的旧字符。

right 向右加入新字符，left 向右移走旧字符。虽然代码里有 while，但两端都不会退回重走，各自至多走完整个字符串，所以总工作仍是线性的，平均时间 O(n)，额外空间最坏 O(n)。

> ⚠️ “连续”不是套用窗口的充分理由。还要证明怎样移动边界不会漏解。例如含负数时，移走左端元素未必使区间和减小，不能照搬“和太大就收缩”的规则。

## 5. 前缀和：先定义边界，再做相减

经常有人问“这几个连续数字的和是多少”，每次重新相加就很浪费。可以先记录从开头累加到各个边界的总和，再用两个总和相减。

先规定一个清楚的含义：**`prefix[i]` 保存原列表前 i 项的和。** 因此 `prefix[0] = 0`，表示还没有取任何元素。

对 `[2, 3, 1, 4]`，要算下标 1 到 2 的和：

1. 前三项的和是 `prefix[3] = 6`。
2. 前一项的和是 `prefix[1] = 2`。
3. 减去共同的前面一项，得到 `6 - 2 = 4`，正好是 `3 + 1`。

一般地，区间 `[l, r)` 的和就是 `prefix[r] - prefix[l]`。

> ⚠️ `[l, r)` 包含 l，不包含 r。如果题目给的是两端都包含的下标 l、r，对应的式子应为 `prefix[r + 1] - prefix[l]`。先看清区间定义，再套式子。

```python
nums = [2, 3, 1, 4]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
assert prefix == [0, 2, 5, 6, 10]
assert prefix[3] - prefix[1] == 4  # nums[1:3] = [3,1]
```

**和为 K 的子数组**要数出所有和为 k 的非空连续区间。假设已经算到某个右边界，前缀和是 `current`，那么：

```text
当前前缀和 - 某个旧前缀和 = k
某个旧前缀和 = current - k
```

所以每轮要问的不是“有没有”，而是“以前有多少个前缀等于 `current - k`”。使用字典 `frequencies` 保存每个前缀和出现的次数。

开始时设为 `{0: 1}`：在读第一个数字之前，存在一个和为 0 的空前缀。它让从原列表下标 0 开始的区间也能被统计。

```python
def subarray_sum(nums, k):
    frequencies = {0: 1}          # 空前缀，让从下标 0 开始的区间也被统计
    current = 0
    answer = 0
    for x in nums:
        current += x
        answer += frequencies.get(current - k, 0)
        frequencies[current] = frequencies.get(current, 0) + 1
    return answer

assert subarray_sum([1, 1, 1], 2) == 2
assert subarray_sum([0, 0], 0) == 3
assert subarray_sum([1, -1, 0], 0) == 3
assert subarray_sum([], 0) == 0
```

用 `[1, 1, 1]`、`k = 2` 追一遍：

| current | 查询 current - k | 旧前缀中出现的次数 | 累计答案 |
|---:|---:|---:|---:|
| 1 | -1 | 0 | 0 |
| 2 | 0 | 1 | 1 |
| 3 | 1 | 1 | 2 |

每轮查完之后，才把本轮 `current` 的出现次数加一，供之后的轮次使用。

> ⚠️ 必须先查询旧前缀，再记录当前前缀。否则 `k = 0` 时，当前前缀会与自身配对，多算一个不包含任何元素的空区间。

平均时间为 O(n)，额外空间为 O(n)。前缀相减的等式对负数也成立，不依赖“区间越长，和越大”。

## 6. 二分：每次排除一段不可能区域

在排好序的一排数字中寻找目标，看到中间值比目标小，就能把中间及其左侧全部排除。排序提供了排除依据，所以一次比较不只解决一个位置，而是缩小整段候选范围。

**任务：** 输入严格递增的整数列表和目标值。找到时返回下标，找不到时返回保持有序所需的插入位置。空列表的插入位置为 0。

本实现把尚未排除的候选放在 `[left, right]` 中，**两端都包含**。只要 `left <= right`，里面就还有位置需要检查。

```python
def search_insert(nums, target):
    left = 0
    right = len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return left

assert search_insert([1, 3, 5, 6], 5) == 2
assert search_insert([1, 3, 5, 6], 2) == 1
assert search_insert([1, 3, 5, 6], 7) == 4
assert search_insert([], 7) == 0
```

每次比较中间值后，只会做以下一种操作：

| 比较结果 | 为什么能排除 | 下一步 |
|---|---|---|
| 等于目标 | 已找到位置 | 返回 mid |
| 小于目标 | mid 及其左侧都更小，不可能是目标 | `left = mid + 1` |
| 大于目标 | mid 及其右侧都更大，不可能是目标 | `right = mid - 1` |

例如在 `[1, 3, 5, 6]` 中找 2。先比较下标 1 的 3，右边界退到 0；再比较下标 0 的 1，左边界进到 1。此时区间为空，`left = 1` 正好是 2 应插入的位置。

每步排除约一半候选。时间为 O(log n)，额外空间为 O(1)。

> ⚠️ 这里使用两端都包含的区间。不要把另一种 `[left, right)` 写法的初始值、循环条件和更新规则混进来。

### 6.1 bisect：理解边界之后再用标准库

有重复值时，可能要找整段相同数字的两侧边界。对已排序的列表：

- `bisect_left` 返回第一个不小于目标的位置。
- `bisect_right` 返回第一个大于目标的位置。

如果这样的元素不存在，就返回列表长度。两者只查位置，不修改列表。

```python
from bisect import bisect_left, bisect_right

nums = [1, 2, 2, 4]
left = bisect_left(nums, 2)      # 1：第一个不小于 2 的位置
right = bisect_right(nums, 2)    # 3：第一个大于 2 的位置
assert right - left == 2
assert bisect_left(nums, 3) == 3 # 插入位置，不代表 nums[3] 等于 3
assert nums == [1, 2, 2, 4]    # 查位置不会修改列表
```

查找位置的时间通常为 O(log n)，真正向列表中间插入仍可能需要移动许多元素。

> ⚠️ 插入位置不代表目标已存在。判断存在性时，先确认下标小于列表长度，再检查该位置的值是否等于目标。

## 7. 单调栈：保存还没有等到答案的位置

**任务：** 对每天的温度，返回再等几天才会遇到更高温度。以后没有更高温度时，返回 0。这是 739 每日温度的任务。

朴素解从每一天向右重新扫描，最坏需要 O(n²) 时间。另一种办法是先记住没有答案的日子：新的一天到来时，看它能为哪些旧日子提供答案。

`waiting` 用栈保存**仍在等待更高温度的下标**。下标让我们既能取出当时的温度，也能用两个下标相减算等待天数。

```python
def daily_temperatures(temperatures):
    answer = [0] * len(temperatures)
    waiting = []
    for today, temperature in enumerate(temperatures):
        while waiting and temperatures[waiting[-1]] < temperature:
            previous = waiting.pop()
            answer[previous] = today - previous
        waiting.append(today)
    return answer

assert daily_temperatures([73,74,75,71,69,72,76,73]) == [1,1,4,2,1,1,0,0]
assert daily_temperatures([30,30]) == [0,0]
assert daily_temperatures([]) == []
```

用 `[73, 71, 72, 74]` 手算，下标从 0 开始：

| 新到来的温度 | 本轮解决谁 | 处理后 waiting 中的下标 |
|---|---|---|
| 下标 0：73 | 暂无旧日子 | [0] |
| 下标 1：71 | 比 73 低，谁也没等到答案 | [0, 1] |
| 下标 2：72 | 下标 1 等了 1 天 | [0, 2] |
| 下标 3：74 | 下标 2 等了 1 天，下标 0 等了 3 天 | [3] |

本轮解决完旧日子以后，今天也要入栈，等待自己的答案。

栈中下标对应的温度从栈底到栈顶不增。如果今天还不够解决栈顶那一天，就更不够解决栈底方向温度更高的日子。

> ⚠️ 题目要求**更高**温度，相同温度不算。因此比较使用 `<`，不是 `<=`。

每个下标入栈一次，至多出栈一次，总时间为 O(n)，额外空间为 O(n)。嵌套的 `while` 并没有让每一天重新扫描全部右侧。

## 8. 递归：子调用结束以后，父调用从哪里继续

**递归是函数在执行时再次调用自身。** 新调用有自己这一次的参数和局部变量，原调用会等待它返回。

例如求 `1 + 2 + ... + n`，约定 n 为非负整数：

- `n = 0` 时直接返回 0，这是停止条件。
- `n > 0` 时，先求前 `n - 1` 个数的和，再加上 n。

每次把 n 减一，问题就离停止条件更近一步。

```python
def sum_to(n):
    if n == 0:
        return 0
    smaller = sum_to(n - 1)
    return smaller + n

assert sum_to(3) == 6
assert sum_to(0) == 0
```

先把调用和返回分成两个方向看：

```text
向下提问：sum_to(3) 等 sum_to(2)，后者等 sum_to(1)，再等 sum_to(0)
向上交回：0 返回 0 → 1 得到 0+1 → 2 得到 1+2 → 3 得到 3+3
```

以 `sum_to(3)` 为例，它停在 `smaller = sum_to(2)` 这一行，等待子调用交回结果。`sum_to(2)` 返回 3 后，原调用才完成赋值 `smaller = 3`，继续执行 `return smaller + n`，得到 6。

> ⚠️ 子调用的 `return` 只结束**那一次调用**，不会顺便结束等待它的父调用。

父调用等待期间，需要保留自己的 n、局部变量和执行位置。这些现场保存在调用栈中。本例调用次数和最大等待层数都随 n 增长，时间与调用栈空间均为 O(n)。

> ⚠️ 输入必须符合这里的非负整数约定。若传入 -1，每次减一只会离 0 更远。即使输入合法，递归过深也可能触发 `RecursionError`；处理深链或大网格时，可使用显式栈，而不是直接把递归限制调得很大。

### 8.1 树的递归：把同一个问题交给两棵小树

**任务：** 计算二叉树的最大层数，空树为 0。如果左子树有 2 层，右子树有 3 层，加上当前根节点，这棵树就是 4 层。

先给函数一句明确承诺：“max_depth(node) 返回以 node 为根的子树有多少层”。这样，父节点不必重写左右子树的全部处理，只需要接收它们的结果。

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def max_depth(root):
    if root is None:
        return 0
    left_depth = max_depth(root.left)
    right_depth = max_depth(root.right)
    return 1 + max(left_depth, right_depth)

root = TreeNode(2, TreeNode(1), TreeNode(3))
assert max_depth(root) == 2
assert max_depth(None) == 0
```

样例树的计算从最小的子树逐层返回：

1. 空节点返回 0。
2. 两个叶子节点的左右孩子都是空节点，所以各自得到 `1 + max(0, 0) = 1`。
3. 根节点接到左、右各 1，得到 `1 + max(1, 1) = 2`。

函数并没有提前知道整棵树的高度。它先把小子树算完，再用这些结果算当前节点。

<details><summary>理解返回过程后，再看中序遍历与翻转</summary>

中序遍历规定“左子树 → 当前节点 → 右子树”；翻转则是在每个节点交换左右子树。不是换了一套递归语法，而是改变每次调用要完成的任务。

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(root):
    answer = []
    def walk(node):
        if node is None:
            return
        walk(node.left)
        answer.append(node.val)
        walk(node.right)
    walk(root)
    return answer

def invert_tree(root):
    if root is None:
        return None
    old_left = root.left
    root.left = invert_tree(root.right)
    root.right = invert_tree(old_left)
    return root

root = TreeNode(2, TreeNode(1), TreeNode(3))
assert inorder(root) == [1, 2, 3]
invert_tree(root)
assert inorder(root) == [3, 2, 1]
```

两段程序复用了递归，但每次调用负责的任务不同：

- `walk` 按左子树、当前节点、右子树的顺序访问，把值追加到外层创建的同一个 `answer` 列表。
- `invert_tree` 返回翻转后的子树。当前节点把原右子树的结果接到左边，把原左子树的结果接到右边。

> ⚠️ 翻转前保存 `old_left`，是为了在 `root.left` 被替换后仍能找到原来的左子树。修改引用前，先检查后续是否还需要旧引用。

这些树操作都要访问全部节点，时间 O(n)，递归栈最多 O(h)，其中 h 是树高。

## 9. DFS 与 BFS：走深一条路，还是先走完一层

搜索的目标相同：把需要访问的节点找全。区别在于下一步先访问谁：

- **DFS，深度优先搜索**：沿一个方向继续深入，走不动再返回，尝试其他方向。
- **BFS，广度优先搜索**：先访问离起点一条边的节点，再访问两条边的节点，逐层扩展。

树、一般图和网格都可以用这两种搜索方式。

### 9.1 网格 DFS：一次处理一个连通块

**任务：** 在矩形网格中统计岛屿数量。字符串 `"1"` 表示陆地，`"0"` 表示水，上下左右相连的陆地属于同一个岛。允许空网格，也允许修改输入。

整体分为两个层次：

1. 外层逐格查看，发现尚未处理的陆地，就把岛屿数量加一。
2. `visit` 从这格出发，把与它连通的全部陆地标记掉。

标记方式是把 `"1"` 改为 `"0"`。这样外层再经过同一座岛的其他格子时，不会重复加一。

```python
def num_islands(grid):
    if not grid or not grid[0]:
        return 0
    rows, cols = len(grid), len(grid[0])

    def visit(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return
        if grid[r][c] != "1":
            return
        grid[r][c] = "0"
        visit(r + 1, c)
        visit(r - 1, c)
        visit(r, c + 1)
        visit(r, c - 1)

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1":
                count += 1
                visit(r, c)
    return count

grid = [["1","1","0"], ["0","0","1"]]
assert num_islands(grid) == 2
assert grid == [["0","0","0"], ["0","0","0"]]
assert num_islands([]) == 0
```

一次 `visit(r, c)` 按以下顺序处理：

1. 坐标超出网格，就返回，不访问对应元素。
2. 这一格不是未访问陆地，就返回。
3. 把本格改为 `"0"`，表示已经处理。
4. 分别探索上下左右四个邻居。

`visit` 能读取外层的 `grid`、`rows` 和 `cols`，修改的也是外层那个网格对象。

> ⚠️ 要先标记当前格，再探索邻居。否则相邻两格可能不断互相访问。调用结束后，原网格已被改变；需要保留原数据时，应另存访问标记或先复制数据。

时间为 O(rows × cols)。最坏情况下，递归调用栈也会随格子数增长，大网格可考虑显式栈实现。

### 9.2 图 BFS：入队时就记录已经发现

**任务：** 返回从起点 `start` 出发的 BFS 访问顺序，图可以有环。同层节点按邻接列表中的先后顺序发现。

这里需要三个容器，各自只做一件事：

- `queue`：已发现、尚未展开邻居的节点。
- `visited`：已经发现过的节点，防止重复入队。
- `order`：实际出队访问的顺序。

```python
from collections import deque

def bfs(graph, start):
    queue = deque([start])
    visited = {start}
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph.get(node, []):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

graph = {1:[2,3], 2:[1,4], 3:[1], 4:[2]}
assert bfs(graph, 1) == [1, 2, 3, 4]
assert bfs({}, 9) == [9]
```

在样例中，先取出 1，把 2、3 加入队尾。再取出 2 时，邻居 1 已被发现，只加入 4。于是出队顺序为 `1、2、3、4`。

> ⚠️ **入队时就记录 visited。** 如果等到出队才记录，同一个节点可能先被多个邻居重复加入队列。

设可达部分有 V 个节点、E 条边，时间为 O(V + E)，队列和访问集合的额外空间为 O(V)。

BFS 的逐层顺序可以用来求无权图的最少边数，但本例只记录访问顺序，没有返回距离。边权不同时，也不能直接把层数当最短距离。

“腐烂的橘子”利用同一个层次关系：所有初始腐烂格作为第 0 层同时入队，一层对应下一分钟。这叫多源 BFS。

## 10. 回溯：做选择以后，返回时必须恢复现场

**任务：** 给出不重复的数字，生成所有排列。`[1, 2]` 得到 `[[1, 2], [2, 1]]`，空列表按本练习约定返回 `[[]]`。

- `path` 保存当前已经选好的前几个数字。
- `used[i]` 记录下标 i 的数字是否已进入当前路径。
- `answer` 保存已经完成的排列。

一条分支的固定动作是：**选择一个未用数字，继续填下一位，返回后撤销这次选择。**

```python
def permutations(nums):
    answer = []
    path = []
    used = [False] * len(nums)

    def visit():
        if len(path) == len(nums):
            answer.append(path.copy())
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            visit()
            path.pop()
            used[i] = False

    visit()
    return answer

assert permutations([1, 2]) == [[1, 2], [2, 1]]
assert permutations([]) == [[]]
```

对于 `[1, 2]`，程序会这样探索：

1. 选 1，路径变成 `[1]`，标记它已用。
2. 下一层选 2，路径变成 `[1, 2]`，保存这一份完整排列。
3. 返回后移走 2、清除它的标记。再回到上一层，移走 1、清除标记。
4. 尝试以 2 开头的另一条分支，得到 `[2, 1]`。

> ⚠️ 保存答案时要用 `path.copy()`。直接保存 `path` 只会留下同一个列表的引用，后续撤销选择会连带改变已经“保存”的答案。

返回结果本身有 n! 个排列，每个长度 n，所以输出相关时间、空间至少 O(n×n!)；不计结果的路径和递归栈 O(n)。题目允许重复数字或重复选取时，选择规则必须重新定义。

## 11. Top K：只维护需要的部分

**任务：** 返回整数列表中第 k 大的元素，保证 `1 <= k <= len(nums)`。重复值要重复计数，例如 `[3, 3, 2]` 的第 2 大仍是 3。

朴素解把全部数字从大到小排序，再取下标 `k - 1`。但如果只需要前 k 大，就可以只留下目前最大的 k 个数。

用大小为 k 的**最小堆**保存它们。堆顶是入选数字里最小的一个，也就是新数字进入前 k 名需要超过的门槛。

本例会用到 `heapq.heapreplace(heap, x)`：移走并返回原堆顶，放入 x，重新维护堆关系，大小保持不变。

> ⚠️ `heapreplace` 要求堆非空，而且不会替你判断 x 值不值得保留。这里必须先确认 `x > heap[0]`，才用它替换。

```python
import heapq

def kth_largest(nums, k):
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return heap[0]

assert kth_largest([3,2,1,5,6,4], 2) == 5
assert kth_largest([3,3,2], 2) == 3
assert kth_largest([7], 1) == 7
```

例如只留最大的 3 个数，当前留下 2、3、4，门槛就是 2。新来 1，可以忽略；新来 5，就替换 2，门槛变成 3。**我们维护的不是全部数字的排序，而是入选前 k 名所需的门槛。**

每个新数字只有三种处理结果：

1. 堆还没装满 k 个数：直接加入。
2. 堆已满，数字大于堆顶：替换堆顶。
3. 堆已满，数字不大于堆顶：忽略，已有 k 个不小于它的数。

扫描结束，堆里是最大的 k 个数，其中最小的堆顶就是第 k 大。额外空间为 O(k)，时间可写为 O(n log(k + 1))，也涵盖 k 为 1 的情况。

## 12. 贪心：当前选择为什么不损害将来

贪心不是“每次选看起来最大”。必须说明保留什么历史足以覆盖所有可能的未来最优答案。

**任务：** 给出按天排列的价格，最多买卖一次，必须先买后卖。返回最大利润，不交易的利润为 0，允许空列表。例如 `[7, 1, 5, 3, 6, 4]` 返回 5。

只考虑“今天卖出”，那么之前的最低买入价一定最好。因此保存两个状态就够了：

- `lowest`：今天之前见过的最低价格。
- `best`：截至目前找到的最大利润，初始为 0。

```python
def max_profit(prices):
    if not prices:
        return 0
    lowest = prices[0]
    best = 0
    for i in range(1, len(prices)):
        price = prices[i]
        best = max(best, price - lowest)
        lowest = min(lowest, price)
    return best

assert max_profit([7,1,5,3,6,4]) == 5
assert max_profit([7,6,4,3,1]) == 0
assert max_profit([]) == 0
```

假设今天价格是 6，之前曾经出现过 7、1、5、3。若今天卖出，买入价 1 一定比其他更高买入价划算，因此历史里只需要保留最低价，而不必记住每一种交易组合。

每轮先算今天能带来的利润，再更新历史：

1. 用 `price - lowest` 计算今天卖出的最好利润，更新 `best`。
2. 用今天的价格更新 `lowest`，供明天使用。

时间为 O(n)，额外空间为 O(1)。代码按下标遍历，没有切片复制剩余价格。

> ⚠️ 这个结论依赖“最多买卖一次、先买后卖”的约束。允许多次交易、收取手续费等条件都会改变问题，不能照搬“只记最低价”作为通用答案。

## 13. 动态规划：先写状态含义，再写递推式

**任务：** 每次走 1 阶或 2 阶，问走到第 n 阶有多少种方法，n 为正整数。

先给状态一个明确含义：**`dp[i]` 表示到达第 i 阶的方法数。**

把所有到达第 i 阶的方法按最后一步分类：

- 最后走 1 阶：之前在第 `i - 1` 阶，有 `dp[i - 1]` 种走法。
- 最后走 2 阶：之前在第 `i - 2` 阶，有 `dp[i - 2]` 种走法。

两类最后一步不同，不会重复，又覆盖全部可能。因此 `dp[i] = dp[i - 1] + dp[i - 2]`。

最小的两个答案可以直接数出来：到第 1 阶只有一种，到第 2 阶可以走两次 1 阶或一次 2 阶，所以初始值是 1、2。

```python
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

assert climb_stairs(1) == 1
assert climb_stairs(2) == 2
assert climb_stairs(5) == 8
```

计算第 5 阶时，表格这样填：

| 阶数 i | 计算依据 | dp[i] |
|---:|---|---:|
| 1 | 直接数出 | 1 |
| 2 | 直接数出 | 2 |
| 3 | 1 + 2 | 3 |
| 4 | 2 + 3 | 5 |
| 5 | 3 + 5 | 8 |

从小到大填写，是因为计算当前答案之前，需要先有前两个答案。遍历方向来自依赖关系，不是写法偏好。

每一步只依赖前两个答案，才可以压缩成两个变量：

```python
def climb_stairs_compact(n):
    if n <= 2:
        return n
    previous, current = 1, 2
    for _ in range(3, n + 1):
        previous, current = current, previous + current
    return current

assert climb_stairs_compact(5) == 8
assert climb_stairs_compact(1) == 1
```

压缩版在每轮开始时，`previous` 和 `current` 保存前两阶的答案。右侧先用两个旧值算出新一阶的方法数，再一起更新两个名字。

> ⚠️ 不要先写 `previous = current`，再计算 `current = previous + current`。第二句会读到已经改过的 previous，丢失原来的前一阶答案。

两个版本的时间都是 O(n)。数组版额外空间为 O(n)，压缩版为 O(1)。压缩之所以成立，是因为后续只需要前两个状态，而不是所有 DP 都能只留两个变量。

## 14. 本章小结与训练方式

每道题的解题卡只需要回答几组问题：

- **任务与起点：** 输入输出是什么，朴素解怎样做？
- **优化依据：** 省掉什么重复工作，保存了什么状态？
- **正确性与成本：** 更新为什么不漏解，实际复杂度是什么？
- **容易失误处：** 哪个边界或更新顺序最需要检查？

卡住时先看一个提示。确实需要看完整答案，也要在看懂之后关掉重写。知道题目所属的专题，不等于能把状态写出来。

这些方法可以按“保存什么信息”连接起来：

| 方法 | 主要保存的信息 |
|---|---|
| 哈希 | 后续需要查询的历史 |
| 双指针、窗口 | 已处理与待处理区间的边界 |
| 前缀和 | 到各个边界的累积结果 |
| 栈 | 尚未完成、需要稍后处理的项 |
| 搜索 | 访问状态、待探索节点或当前路径 |
| 动态规划 | 已经求出的子问题答案 |

一道题可能同时需要几种信息，例如前缀和配合哈希计数。方法不是互相排斥的标签。

继续练习时，用[题目映射](../hot100-map.md)选择对应任务。每次只换一小部分问题条件，观察原状态还能不能用，比一口气背十个专题更容易建立联系。

## 15. 面试怎么答

**问：你是怎样从暴力解想到优化的？**

> 🎯 先找暴力解反复做的具体工作，再考虑能否保留历史、增量更新区间或利用有序性排除候选。选好状态以后，我会解释初始化、每轮更新和结束时为什么能得到答案，再分析实际代码的成本。

**问：递归、回溯和动态规划是什么关系？**

> 🎯 递归是函数调用自身的执行方式；回溯借助搜索尝试选择，并在返回时撤销选择；动态规划保存子问题结果，减少重复求解。它们关注的层面不同，不能只凭代码里有没有自调用来分类。

## 16. ⚠️ 容易混淆的地方

- 两层缩进不一定是平方复杂度，要数全部执行过程中每项被处理几次。
- 窗口遇重复可能要收缩多次；“只删一次”不保证恢复合法状态。
- 递归返回后父调用还要继续；回溯保存路径时要复制，撤销的是当前探索现场。
- 用了算法名字的最优写法，不代表实际代码没有切片、复制或隐藏的线性查找。
