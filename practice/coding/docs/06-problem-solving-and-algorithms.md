# 06｜算法推导：建立能迁移到新题的思考方式

[← 上一章：数据结构](05-data-structures.md) · [Coding 首页](../README.md) · [下一章：Hot100 综合训练 →](07-hot100.md) · [题目映射](hot100-map.md)

两道题都用了字典，一道存下标，另一道存次数。两道题都有两个下标，一道从两端靠近，另一道一起向右走。只记代码的样子，题目稍有变化就可能无从下手。

算法思想帮助我们抓住这些变化背后的共同规律：哈希是在为反复出现的查询组织答案；双指针是在用两个有明确职责的位置推进处理；递归把同一个任务交给更小的输入；动态规划把重复遇到的子问题变成可以复用的答案。**要学的是这种组织问题的方式，例子让它变得看得见、写得出。**

已经认识容器、树和图，接下来要学会选择方法：为什么这里适用，下一步怎样决定，换一道题还能复用什么？各节可以分开学习，重点是说清每种方法的核心与适用条件。

## 1. 从一道题里学走什么

拿到新题，先说清输入、输出和约束，手算一个小例子，再给出直接做法。接着找出困难：不断重查历史、反复计算重叠部分、候选太多，还是问题层层嵌套？困难不同，适合的算法思想也不同。

例如，两数之和要找两个不同位置，使数值之和等于目标。直接枚举所有位置对，最坏要做 O(n²) 次比较。读到当前数 x 时，换一种问法：“之前有没有 `target - x`，它在哪里？”这样改写问题，字典就有了明确用途：按数字查询位置。

学习一种方法时，要分清三层：

- **思想：** 它怎样重新组织这个困难。例如，把重复扫描改成按键查询。
- **实现：** 为本题保存哪些信息，怎样读取、更新。例如，键是数字，值是下标，查询后再记录当前数。
- **适用条件：** 为什么这样做不会破坏题意。例如，查询时只看此前位置，才不会把同一位置用两次。

只记实现，题目换个要求就可能不会做；只记“用空间换时间”，又不知道该存什么。这三层要连起来理解。

### 用状态解释进度，用复杂度衡量代价

变量记录算法的处理进度。先说清它代表什么，再决定怎样读写。比如“两数之和在查询之前，字典保存此前出现的数字及其一个位置”，这句话同时解释了字典内容和查询顺序。

在循环的某个固定时刻持续成立的事实，叫**循环不变量**。检查它时，问：开始时为什么成立，做完一步为什么仍成立，结束时为什么足以得到答案？递归没有同一个循环时刻，就检查每次调用承诺完成什么、怎样到达最小问题、子调用返回后如何接着完成任务。这些问题用于检查思路，不必机械套用证明格式。

复杂度回答另一个问题：输入变大，代价怎样增长？n = 100000 时，线性工作量约为 10⁵，平方工作量约为 10¹⁰。数据范围可以排除明显过慢的直接做法，但不能替你选出算法。

> ⚠️ 这些数量级不是运行秒数。要针对实际操作计数，包含查找、复制、结果存储和调用栈；不能看到两层缩进就认定是平方时间，也不能看见两个变量就忽略背后的递归空间。

本章通常把普通整数运算、比较和下标访问按常数成本估算，哈希操作注明平均成本。每种方法都要结合执行过程说明省了什么工作、增加了什么存储。

## 2. 哈希：围绕反复出现的问题建立索引

反复查询“这个人有没有登记”，每次从头翻名单会重复检查许多人。若先按姓名建立索引，以后就能直接查询登记情况。

**哈希的核心是：把接下来要反复问的问题变成键，为这个键保存足够回答问题的信息。** 先问自己：原来要重新扫描什么，现在能否改成查询一个键？

后续要查什么，决定需要保存什么：

| 下一步真正要问的问题 | 要留下的信息 |
|---|---|
| 有没有出现过 x？ | 集合中的成员资格 |
| x 出现在哪个位置？ | 字典中的 `x → 位置` |
| x 出现了多少次？ | 字典中的 `x → 次数` |
| 与 x 同类的项有哪些？ | 字典中的 `类别键 → 同类项列表` |

键也可以从原始数据中提取。例如分组时，用类别特征作键，但不能把题目要求区分的类别编码成同一个键，否则会错误合并。

### 索引覆盖哪些数据，由查询范围决定

两数之和问的是“此前有没有补数”。读到 `[2, 7, 11]` 中的 7、目标为 9 时，查询键 2，得到旧位置 0。因而字典随扫描逐步建立，并且先查后存。若先记录当前值，单个 3、目标为 6 就可能与自身配对。扫描 n 个数，每轮平均常数成本查询与登记，总时间平均 O(n)，额外空间 O(n)。

另一些问题问“整个输入中有没有这个值”，就应该先建立完整集合，再开始查询。还有的问题只问“当前区间中有没有”，就必须在区间移走数据时同步删除。**查询什么决定键和值，查询哪一部分决定索引怎样更新。** 先明确这两点，再选 `set` 或 `dict`。

### 用最长连续序列看见这套思考

任务是找出最长连续数值段的长度，输入可以乱序、重复或为空，空输入返回 0。`[100, 4, 200, 1, 3, 2]` 返回 4，因为存在 `1、2、3、4`。这里的连续指数值相差 1，不要求在原列表中相邻。

从一个数往后找连续值时，会反复问“下一个数在不在整个输入里”。原下标、出现次数都不影响答案，所以用 `values = set(nums)` 建立完整的存在性索引。

有了快速查询，还要防止重复做同一段工作。从 1 数过 `1、2、3、4`，再从 2 数 `2、3、4`，即使每次查询很快，仍在反复扩展。想让每段只数一次，只需从没有前驱的数开始：

- 查询到 `x - 1` 存在，说明 x 位于某段中间，不从它重新数。
- 查询到 `x - 1` 不存在，说明 x 是段首，再不断查询后继。

`best` 保存已数过各段的最长长度。扩展某个段首 x 时，`end` 指向下一个待确认的值，x 到 end - 1 都已经确认存在。

```python
def longest_consecutive(nums):
    values = set(nums)
    best = 0
    for x in values:
        if x - 1 in values:
            continue              # 不是起点，不重复从中间数
        end = x
        while end in values:
            end += 1
        best = max(best, end - x)
    return best

assert longest_consecutive([100, 4, 200, 1, 3, 2]) == 4
assert longest_consecutive([1, 1, 2]) == 2
assert longest_consecutive([]) == 0
```

单独看遇到段首 1 的这一轮：先查 0，不存在；再依次确认 1、2、3、4，查询 5 时失败。此时已确认的数值是 `[1, 5)`，长度就是 `end - x = 4`。遇到 2、3、4 时，前驱查询会阻止从中间重数。集合不保证按数值顺序遍历，但这不影响结果：每个有限连续段都有一个段首，外层最终一定会遇到它。

这个例子把哈希思想落实成两种查询：查前驱决定是否开始，查后继决定能否延长。集合使每次查询平均 O(1)；只从段首开始，则保证全部连续段的成功扩展合计不超过不同数字的数量。连同建集合，总时间平均 O(n)，额外空间最坏 O(n)。

> ⚠️ 集合负责加快成员查询，不会自动消除重复扩展。若每个数都向后数，仍可能做平方级工作；若把成员查询换回列表扫描，也不能沿用这里的平均线性结论。

遇到新题，仍然先找反复出现的查询，再确定索引内容。有时也不必另建索引，只要安排好处理进度，就能避免回头，这引出了双指针。

## 3. 双指针：让两个位置各自负责一部分进度

扫描序列时，常要同时记录两个进度：尚未比较部分的左右端，或者读取与写入各到哪里。两个位置各司其职，就能协调完成处理。

**双指针的核心是：为两个位置规定清楚的职责，让每次移动都对应一部分工作被完成或一部分候选被排除。** “两个下标”只是外形，它们不一定从两端出发，也不一定每次一起移动。

先划清已确认与未处理的区域，再问当前结果允许哪个位置前进。每次移动都应有“不必回头”的依据。

### 从两端确认：回文判断

回文的两端字符应当相同，去掉这一对之后，里面仍要满足同样的对称要求。因此可以让 `left`、`right` 分别指向尚未比较的左右端。每次向中间推进，都是把一对已经确认的字符留在外面。

本例按原字符精确比较，不忽略标点或大小写。空字符串与单字符都算回文。若构造反向字符串再比较，也需 O(n) 时间，但会多存一份 O(n) 的字符串。

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

assert is_palindrome("level") is True
assert is_palindrome("hello") is False
assert is_palindrome("") is True
assert is_palindrome("a") is True
```

`"level"` 先比较下标 0、4 的 l，再比较下标 1、3 的 e，随后两端都到 2，只剩一个无需配对的 v。这里持续成立的含义是：`[left, right]` 外面的对称字符已经相等，里面仍待处理。

开始时外面为空；确认一对后，两端内移，已确认区域扩大；相遇或交错时，所有必要的字符对都已确认。如果中途不同，已经有反例，可以立刻返回 `False`。最多比较约 n/2 对，最坏时间 O(n)、额外空间 O(1)。这里时间仍是线性，节省的是反向副本的空间。

> ⚠️ 只有 `left < right` 时才有两个不同位置需要配对。空字符串与单字符不进入循环，正好符合本例约定。

### 分开读取与安放：移动零

任务是把所有零移到末尾，保持非零元素的相对顺序，直接修改原列表，函数返回 `None`。例如 `[0, 1, 0, 3, 12]` 变成 `[1, 3, 12, 0, 0]`。

如果另建列表收集非零元素，容易做到，但需要额外 O(n) 空间。要在原列表里完成，就把“查看下一个数”和“安放下一个非零数”分给两个位置：

- `read` 指向当前要读的位置，所有元素都要经过它。
- `write` 指向下一个非零元素的安放位置，只在安放非零数后前进。

读取之前，`[0, write)` 已按原顺序放好读过的非零数，`[write, read)` 都是零，后面还没读。读到零，扩展已读零区间即可；读到非零，就交换到 write，再推进写入进度。

```python
def move_zeroes(nums):
    write = 0
    for read in range(len(nums)):
        if nums[read] != 0:
            nums[write], nums[read] = nums[read], nums[write]
            write += 1

nums = [0, 1, 0, 3, 12]
assert move_zeroes(nums) is None
assert nums == [1, 3, 12, 0, 0]
empty = []
move_zeroes(empty)
assert empty == []
```

| 本轮 read | 读到的数 | 本轮结束后的 write | 列表 |
|---:|---:|---:|---|
| 0 | 0 | 0 | [0, 1, 0, 3, 12] |
| 1 | 1 | 1 | [1, 0, 0, 3, 12] |
| 2 | 0 | 1 | [1, 0, 0, 3, 12] |
| 3 | 3 | 2 | [1, 3, 0, 0, 12] |
| 4 | 12 | 3 | [1, 3, 12, 0, 0] |

处理下标 3 的数 3 时，write 为 1，那里属于已经读过的零区间。交换把 3 紧接在已有非零前缀后面，把零留在原读取位置。若 write 与 read 相同，则只是与自己交换。因为 write 不会超过 read，尚未读取的后缀不会被破坏；非零数又按读到的先后安放，所以顺序保留。

读完全部元素后，已读区域就是整个列表，前面为非零数，后面为零。每个位置读一次，每轮至多交换一次，时间 O(n)、额外空间 O(1)。若改成每遇到零就删除并挪动整个后缀，最坏可能累积 O(n²) 工作。

> ⚠️ 并行赋值先读取右侧两个旧值，再写回。拆成两句互相覆盖的赋值，可能丢掉其中一个旧值。

两题的移动方向不同，却都在扩大已完成区域。遇到新题，要重新定义两个位置的职责；若按大小排除候选，还须有排序或其他关系作依据，保证不丢解。

## 4. 滑动窗口：复用相邻区间，只修复发生变化的部分

如果需要考察很多连续区间，相邻区间往往只差左端出去的一项、右端进来的一项。每换一个区间就重新求和或重新查重复，会浪费它们共享的大部分内容。

**滑动窗口把当前连续区间当作一个整体，维护它需要的统计或性质，通过边界变化增量更新。** 两个指针定义区间，额外状态说明区间里发生了什么。窗口可以固定长度，也可以随条件变化；真正需要推导的是加入和移出元素会怎样影响状态，以及什么时候该移动哪一端。

求“最长合法区间”时，常见做法是右端扩展、左端修复：加入新元素后若不合法，就移动左端直到恢复合法。这要求被排除的窗口继续右扩也不会重新合法，否则左端只向右就可能漏解。

### 用无重复子串理解扩展与修复

任务是求不含重复字符的最长连续子串长度，`"abba"` 返回 2，对应 `"ab"` 或 `"ba"`。子串必须连续，不能跳过中间字符。

我们维护一个已经无重复的旧窗口。右端准备加入 ch 时，反复要问“ch 是否已经在窗口中”，于是借用哈希节的思想，用 `seen` 保存当前窗口的字符。这里查询的是当前窗口，左端移走字符时，集合也必须删除它。

`left`、`right` 给出边界，`best` 保存已经见过的最大合法长度。准备加入下标 right 的字符之前，`seen` 恰好表示 `text[left:right]`，其中没有重复。加入之后，只有把冲突修复好，才能更新答案。

```python
def longest_unique(text):
    seen = set()
    left = 0
    best = 0
    for right, ch in enumerate(text):
        while ch in seen:
            seen.remove(text[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best

assert longest_unique("abba") == 2
assert longest_unique("abcabcbb") == 3
assert longest_unique("") == 0
```

读到 `"abba"` 的第二个 b 时，旧窗口为 ab。先移走左端 a，旧 b 仍在，冲突尚未消失；继续移走旧 b，才可以加入新 b。此时窗口只有新 b，之前记录的最大长度 2 保持不变。再读最后的 a，窗口可以扩为 ba。

这一轮只做了“移出、移出、加入”，复用了旧窗口的检查结果。集合和边界始终描述同一段内容。

为什么修复后留下的窗口足够？对于这次新 b，任何仍包含旧 b 的更长窗口都不合法，所以必须把旧 b 移出去；刚移出去就停止，留下的就是以当前右端结尾的最长合法窗口。更早因重复而丢弃的左边界，继续增加字符也不会消除原来的重复，因此无需回退。对每个右端都考虑一次这样的窗口，`best` 就覆盖了全局最优答案。

> ⚠️ 必须用 `while` 检查冲突是否消失。只移一次左端，不保证移走的就是旧重复字符。此时集合也不能代表一个含重复字符的窗口。

右端使每个位置入窗一次，左端使每个位置至多出窗一次，两端都不回退。按集合平均操作成本计算，总时间 O(n)，空间最坏 O(n)。嵌套 while 的代价已经包含在所有出窗次数里，不能再乘一个 n。

可以复用“保存区间状态、随边界更新”的思想，但每道题的收缩条件都要重新判断。比如含负数时，移走左端未必让区间和减小，不能照搬“和太大就缩窗”。如果需要任意左右端的区间和，而不是沿着可复用的边界移动，就可以考虑下一节的前缀和。

## 5. 前缀和：把一个区间的问题拆成两个边界

想知道一条路上第 3 站到第 7 站有多远，不必重新累加中间每一段。如果知道从起点到两站的累计距离，做一次相减就能去掉共同走过的前半段。

**前缀和保存“从开头到某个边界”的累计结果，把区间求和改写为两个边界结果的差。** 它复用的是共同前缀，与窗口复用相邻区间的变化不同。查询边界可以任意跳动，只要对应的前缀结果已经准备好。

这依赖加法能通过相减取消共同部分。知道两个前缀的最小值，就无法照样相减得到中间区间的最小值。因此先确认运算关系，再决定是否使用前缀结果。

### 先固定累计值的含义

规定 `prefix[i]` 为原列表前 i 项的和，`prefix[0] = 0` 表示空前缀。于是半开区间 `[l, r)` 的和为 `prefix[r] - prefix[l]`。

对 `[2, 3, 1, 4]`，下标 1 到 2 的元素为 3、1。前 3 项的和是 6，前 1 项的和是 2，相减得到 4。这里减的是两个边界，不是把边界上的元素本身相减。

```python
nums = [2, 3, 1, 4]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
assert prefix == [0, 2, 5, 6, 10]
assert prefix[3] - prefix[1] == 4  # nums[1:3] = [3,1]
```

建表时，读过 i 项后，已经保存了从 0 到 i 的全部正确前缀。下一项只需加到上一个累计值上。建立 n + 1 个边界值耗时 O(n)、空间 O(n)，之后每次查询 O(1)。q 次查询合计 O(n + q)，逐区间重新求和则最坏 O(nq)。

> ⚠️ `[l, r)` 不包含 r。若题目给的是两端都包含的下标 l、r，应计算 `prefix[r + 1] - prefix[l]`。另外，这份表对应建表时的输入，修改元素以后不能把旧表继续当作新数据的累计结果。

### 从“求一段和”到“找符合条件的边界”

前缀和的作用不止是加快已经给定的区间查询。它还可以把一个区间条件改写成两个边界之间的关系。

任务是统计和为 k 的非空连续子数组数量，允许负数、零和空输入。只枚举所有左右边界，即使每段和 O(1) 得到，仍有 O(n²) 对。固定右边界后，若当前前缀和为 current，则：

```text
current - 旧前缀和 = k
旧前缀和 = current - k
```

区间求和问题因此变成了查询问题：“此前有多少个边界，前缀和等于 `current - k`？”同一个前缀和出现多次，代表不同左边界，必须存次数，不能只存存在性。用 `frequencies` 建立“前缀和值 → 已出现次数”的索引，就把前缀和与哈希连在了一起。

开始时有一个和为 0 的空前缀，因此初始化 `{0: 1}`。每轮累加得到 current 后，先查询严格更早的边界，统计以本轮右边界结束的区间，再登记当前边界供以后使用。

```python
def subarray_sum(nums, k):
    frequencies = {0: 1}          # 空前缀，让从下标 0 开始的区间也被统计
    current = 0
    answer = 0
    for x in nums:
        current += x
        answer += frequencies.get(current - k, 0)
        frequencies[current] = frequencies.get(current, 0) + 1
    return answer

assert subarray_sum([1, 1, 1], 2) == 2
assert subarray_sum([0, 0], 0) == 3
assert subarray_sum([1, -1, 0], 0) == 3
assert subarray_sum([], 0) == 0
```

在 `[1, 1, 1]`、k = 2 中，current 依次为 1、2、3，查询的旧前缀依次为 -1、0、1，得到次数 0、1、1，总答案 2。

再看 `[0, 0]`、k = 0：第一个零查询到 1 个旧零前缀，登记后频次变为 2；第二个零查询到 2 个，合计 3 个非空区间。要统计不同左边界形成的区间，所以必须保存次数。

> ⚠️ 先登记再查询，会把当前边界与自身配对。k = 0 时，这会多算空区间。查询与更新的顺序，必须符合“只询问旧边界”的状态含义。

每个合法区间有唯一左右边界，只在处理自己的右边界时被统计一次，因此既不漏也不重。每个数做一次累加、一次查询、一次登记，时间平均 O(n)，额外空间 O(n)。不必再保存整张前缀数组，当前值与历史频次已经足够。

负数不影响前缀相减，所以这里不要求区间和随长度单调变化。同样处理连续区间，窗口复用边界移动前后的状态，前缀和则抵消共同部分，两者的依据不同。

## 6. 二分：让一次判断排除一整段候选

顺序查找每次只确认一个位置。若数据具有有序关系，一次判断可以告诉我们更多：中间值已经太小，那么它左边的值也都太小。这时逐个检查那半边已经没有意义。

**二分的核心是：找到一种能把候选分成两侧的判断，每次保留仍可能包含答案的一侧。** 取中点只是为了让剩余范围尽量缩小一半，真正允许排除的是有序性或单调性。

这里的单调可以理解为：判断结果从“不满足”变成“满足”后，不会再变回去。例如在升序列表里，“这个数是否不小于 target”就有这种形状。寻找这个变化边界，也是一种二分，而不一定要恰好命中某个值。

### 区间含义决定更新写法

任务是对严格递增整数列表查找 target，命中返回下标，否则返回保持有序的插入位置，空列表返回 0。

这里用闭区间 `[left, right]` 表示尚未排除的元素位置。要一直保持：left 左边都小于目标，right 右边都大于目标；若目标存在，只可能留在这个区间里。开始时区间覆盖整个列表，两侧都没有被排除的内容。

```python
def search_insert(nums, target):
    left = 0
    right = len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return left

assert search_insert([1, 3, 5, 6], 5) == 2
assert search_insert([1, 3, 5, 6], 2) == 1
assert search_insert([1, 3, 5, 6], 7) == 4
assert search_insert([], 7) == 0
```

每次比较，都把“判断依据”和“排除范围”连起来看：

| 中间值 | 可以确认什么 | 更新 |
|---|---|---|
| 等于 target | 当前就是目标位置 | 返回 mid |
| 小于 target | mid 及左侧都太小 | `left = mid + 1` |
| 大于 target | mid 及右侧都太大 | `right = mid - 1` |

在 `[1, 3, 5, 6]` 找 2，先比较下标 1 的 3，排除它及右侧；再比较下标 0 的 1，排除它及左侧。最终 left = 1、right = 0，候选为空。由已经确认的两侧关系可知，left 前面都小于 2，left 起都大于 2，所以 1 就是插入点。

这也解释了为什么边界要越过 mid：它已经被比较且排除，留着它可能使范围不再缩小。每次候选大约减半，最坏时间 O(log n)，辅助空间 O(1)，空输入为 O(1)。如果每轮复制一段切片，就另有复制成本。

> ⚠️ 初始范围、循环条件和更新规则是一整套区间约定。不能把 `[left, right)` 写法的 `right = len(nums)` 随意混进这里的闭区间代码。

### 相等值归哪一侧，决定查到哪个边界

有重复值时，“命中就返回”不能保证找到第一个或最后一个。要找完整相等段，就把目标改成两个变化边界：

- `bisect_left` 找第一个不小于目标的位置：前面都小于目标，从这里起都大于等于目标。
- `bisect_right` 找第一个大于目标的位置：前面都小于等于目标，从这里起都大于目标。

没有符合条件的元素时返回列表长度。二者只查位置，不修改列表。[Python bisect 文档](https://docs.python.org/3/library/bisect.html)给出了这些划分约定。

```python
from bisect import bisect_left, bisect_right

nums = [1, 2, 2, 4]
left = bisect_left(nums, 2)      # 1：第一个不小于 2 的位置
right = bisect_right(nums, 2)    # 3：第一个大于 2 的位置
assert right - left == 2
assert bisect_left(nums, 3) == 3 # 插入位置，不代表 nums[3] 等于 3
assert nums == [1, 2, 2, 4]    # 查位置不会修改列表
```

样例中 2 的两侧边界是 1、3，所以 `[1, 3)` 的两个位置恰好包含全部 2。找不到的 3 也有插入边界 3，但 `nums[3]` 是 4。

每次边界查询 O(log n)、辅助空间 O(1)；真的向列表中间插入，仍可能移动 O(n) 个元素。判断目标是否存在时，也要先检查下标小于列表长度，再比较该位置的值。

寻找某个条件首次成立的位置，也可使用二分，前提是条件不会反复变化。先找到整段排除的依据，边界更新才有意义。

## 7. 单调栈：把尚未解决的问题排成可逐个结算的顺序

有些问题在读到当前位置时还答不出来。例如“这个元素右边第一个更大的数是什么”，必须等未来元素出现。对每个位置重新向后找，会让许多位置反复观察同一段未来。

可以把方向反过来：先保存尚未得到答案的位置，新元素到来时，看它能解决哪些旧问题。**单调栈在这些未决位置之间维护一个大小顺序，使我们只看栈顶，就能判断是否继续解决下一项。** 普通栈只规定后进先出；这里的单调关系，进一步给出“为什么只处理这一端”的依据。

大小关系的方向和是否允许相等，都要由任务决定。求下一个更大值、下一个更小值，保存的顺序会不同；答案要距离时存下标，要其他信息时也要据此调整。

### 用每日温度理解“等待”和“解决”

任务是返回每天再等几天会遇到更高温度，没有则为 0，对应 739 每日温度。直接从每天向右扫描，最坏 O(n²)。现在让新一天来解决以前的等待。

`waiting` 保存仍未等到更高温度的下标。下标同时提供温度读取位置和天数差。栈底到栈顶，下标递增，温度不增：较新的、较低的温度位于栈顶，更容易先被未来一天解决。

若今天比栈顶更高，就弹出它并填答案，再检查新栈顶；若连栈顶都不够高，就更不够解决下面温度更高或相等的日子。处理完后，把今天也作为未决问题放进去。

```python
def daily_temperatures(temperatures):
    answer = [0] * len(temperatures)
    waiting = []
    for today, temperature in enumerate(temperatures):
        while waiting and temperatures[waiting[-1]] < temperature:
            previous = waiting.pop()
            answer[previous] = today - previous
        waiting.append(today)
    return answer

assert daily_temperatures([73,74,75,71,69,72,76,73]) == [1,1,4,2,1,1,0,0]
assert daily_temperatures([30,30]) == [0,0]
assert daily_temperatures([]) == []
```

对 `[73, 71, 72, 74]`，这个过程是：

| 新来的一天 | 它解决的旧问题 | 剩余等待下标 |
|---|---|---|
| 0：73 | 还没有旧日子 | [0] |
| 1：71 | 不比栈顶高 | [0, 1] |
| 2：72 | 解决下标 1，等待 1 天 | [0, 2] |
| 3：74 | 依次解决下标 2、0，等待 1、3 天 | [3] |

弹出时为何得到的是第一个更高温度？因为这个旧位置此前一直留在“未解决”集合里，说明中间经过的日子都没有解决它；今天又确实更高，所以答案就在今天。新日子加入之前，较低栈顶已被弹完，剩下的栈顶不低于今天，因此压栈后温度不增的关系继续成立。最后仍在等待的位置没有后续答案，保持预设的 0。

> ⚠️ 更高意味着严格大于。相同温度不能解决旧问题，所以代码用 `<` 而不是 `<=`。改变相等条件，就是改变题意。

每个位置只作为未决问题入栈一次，解决后至多出栈一次，总时间 O(n)。辅助栈最坏 O(n)，返回数组另占 O(n)。一次新元素可能弹出很多旧位置，但那些位置以后不会再被处理，不能把每轮都按 n 次相乘。

单调栈把暂时无法回答的问题留下，等新元素到来时从栈顶解决。能否使用它，关键看单调关系是否保证：栈顶不能解决时，下面也不必检查。

## 8. 递归：把同一个任务交给更小的输入

文件夹里还有文件夹，子树也仍然是树。这类问题缩小后仍遵守同样的规则，适合用递归表达。

**递归的核心是：给函数一个明确任务，把其中规模更小的同类任务交给它自己，再用子任务的结果完成当前任务。** 各层调用都遵守同一个任务约定，才能把结果接起来。

写递归时，要先安排清楚三个责任：

1. 哪种最小输入可以直接完成，不再往下调用？这是停止条件。
2. 当前任务怎样缩成更小的同类任务？要保证最终能够到达停止条件。
3. 子调用返回以后，当前调用还要做什么？可能是加上当前值、合并结果，也可能是继续处理另一个分支。

不必同时想几十层。先明确函数任务，再假设更小的调用能正确完成，检查当前层怎样接上结果。最后确认最小情况正确，整条返回链就有了依据。

### 调用向下展开，答案向上接回

先用求 `1 + 2 + ... + n` 看清执行，约定 n 为非负整数。`sum_to(n)` 的承诺是返回这段和；n = 0 直接返回 0，n > 0 时让 `sum_to(n - 1)` 完成前半段，当前层负责再加 n。

```python
def sum_to(n):
    if n == 0:
        return 0
    smaller = sum_to(n - 1)
    return smaller + n

assert sum_to(3) == 6
assert sum_to(0) == 0
```

调用 `sum_to(3)` 时，可以分别观察两个方向：

```text
向下委托：sum_to(3) 等 sum_to(2)，后者等 sum_to(1)，再等 sum_to(0)
向上完成：0 返回 0 → 1 得到 0+1 → 2 得到 1+2 → 3 得到 3+3
```

最外层停在 `smaller = sum_to(2)`。等子调用交回 3，才完成 `smaller = 3`，继续算 `3 + 3`。最外层的 n 仍然是 3，子调用的 n = 2 属于另一份调用现场。

> ⚠️ 一次 `return` 只结束它所在的那次调用。它把结果交给等待者，等待者还会从原位置继续。递归返回也不会自动撤销对共享列表、树或网格的修改。

最小情况返回 0；若子调用算对前 n - 1 项，当前层加上 n 就完成自己的任务。参数每次减一，保证合法输入最终到达 0。

这里有 n + 1 次调用，每次额外做常数工作，时间 O(n)。调用栈保存每个等待者的参数、局部变量和执行位置，最大等待层数为 O(n)，空间也为 O(n)。普通循环累加同样 O(n) 时间，却只要 O(1) 辅助空间；递归本身并不保证更快或更省空间。

> ⚠️ n = -1 不满足本例约定，继续减一永远到不了 0。即使输入合法，调用层数过深也可能触发 `RecursionError`。处理深链或大网格时可考虑显式栈，不要把增大递归限制当作通用修复。

### 树让“同一个小任务”自然出现

任务是返回二叉树的最大层数，空树为 0。先规定 `max_depth(node)` 返回以 node 为根的子树层数。根节点下面的左、右两部分也都是树，正好可以分别交给同一个函数。

当前层只需使用子树返回的层数。左右若为 2、3 层，最长路径走较深的一侧，再加根这一层，结果就是 4。

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def max_depth(root):
    if root is None:
        return 0
    left_depth = max_depth(root.left)
    right_depth = max_depth(root.right)
    return 1 + max(left_depth, right_depth)

root = TreeNode(2, TreeNode(1), TreeNode(3))
assert max_depth(root) == 2
assert max_depth(None) == 0
```

样例里，叶子的左右空树都交回 0，叶子算出 `1 + max(0, 0) = 1`。根的左调用完成后先保存 1，再等待右调用交回 1，最后得到 2。两次调用先后完成，根自己的“取大再加一”不会被子调用代做。

这里的递归约定可以逐层成立：空树直接完成；两棵更小子树若都返回正确层数，选较深的再加根就是当前树的答案。输入要确实是一棵有限树，没有环。每个节点处理一次，时间 O(n)；栈里同时保存一条根到当前节点的路径，空间 O(h)，h 为树高，平衡时约 O(log n)，退化成链时最坏 O(n)。

<details><summary>同一递归思想，换成中序遍历与翻转怎样表达？</summary>

递归约定还可以描述“完成某种修改”，不一定返回一个数字。

- 中序遍历的 `walk(node)` 负责把当前子树按“左子树、根、右子树”的顺序追加到同一个结果列表。
- `invert_tree(node)` 负责原地翻转当前子树，并返回翻转后的根。

任务变了，当前层的动作随之改变，但子调用仍负责更小的同类任务。

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(root):
    answer = []
    def walk(node):
        if node is None:
            return
        walk(node.left)
        answer.append(node.val)
        walk(node.right)
    walk(root)
    return answer

def invert_tree(root):
    if root is None:
        return None
    old_left = root.left
    root.left = invert_tree(root.right)
    root.right = invert_tree(old_left)
    return root

root = TreeNode(2, TreeNode(1), TreeNode(3))
assert inorder(root) == [1, 2, 3]
invert_tree(root)
assert inorder(root) == [3, 2, 1]
```

中序遍历在左调用返回后，左子树已经追加完，当前层才追加根，再把右子树交给右调用。样例结果依次成为 `[1]`、`[1, 2]`、`[1, 2, 3]`。每一层遵守同一个局部顺序，整体就得到中序序列。`walk` 修改外层的 answer，最后由 `inorder` 返回这个列表。

翻转则把“原右子树翻转后的结果”接到左侧，把“原左子树翻转后的结果”接到右侧。子树内部的任务由子调用完成，当前层只负责保存旧引用并重新连接。样例根仍为原节点 2，孩子变成左 3、右 1，因此再中序遍历得到 `[3, 2, 1]`。

> ⚠️ 先保存 `old_left`，才能在 `root.left` 被替换后仍找到原来的左子树。函数调用的独立现场，不代表被引用的树也自动复制了一份。

两种操作时间均为 O(n)，辅助调用栈 O(h)。中序还返回 O(n) 的结果列表；翻转原地修改，没有另建整棵树。每个节点只追加一次或修改常数个引用，不能把“有两个子调用”直接解释成指数级时间。

</details>

求和、树高、遍历与翻转都先约定函数任务，再交给更小的调用。遇到新题，抓住两件事：子调用完成什么，返回后当前层还要做什么。

## 9. DFS 与 BFS：决定下一步探索哪一部分

从一个房间出发，沿门能走到哪些房间？既要记得还有哪些地方没走完，也要避免在有环的走廊中反复兜圈。搜索可以把这类问题组织成“位置、可走到的邻居、尚待探索的部分”。图中位置就是节点，网格中位置可以是坐标，树也可以按孩子关系探索。

DFS 与 BFS 的共同目标是按规则发现需要的节点，核心区别是怎样处理**待探索部分**：

- **DFS，深度优先搜索：** 优先沿当前方向继续深入，走不动再返回，处理其他分支。递归调用栈或显式栈都能表达这个顺序。
- **BFS，广度优先搜索：** 先展开离起点近的一层，再展开下一层。队列把更早发现的待处理节点放在前面。

搜索还必须单独决定重访规则。若同一个节点从哪里到达都不会改变要探索的后续，发现一次后就可以标记，避免重复展开。若到达时携带的信息不同，后续选择也不同，只有节点编号可能不足以代表搜索状态。先定义“一个状态是什么”，才能决定哪些访问算重复。

### DFS：先把一个连通部分走完

统计岛屿时，我们要知道有多少块彼此分离的陆地。一次发现某块陆地，就可以沿上下左右把同一座岛走完，再寻找下一座岛。这里需要的是连通范围，先走哪条路径不影响属于哪座岛，所以适合用 DFS 展开这个过程。

约定输入为矩形网格，字符串 `"1"` 表示陆地、`"0"` 表示水，只允许四邻接，空网格返回 0，允许直接修改输入。外层逐格查看，遇到尚未发现的陆地便计一座岛；内部搜索负责完整标记这座岛。

本例把发现的陆地改为 `"0"`，供所有后续路径共同识别。标记表示“已发现，正在处理或已处理”，不要求等所有邻居走完才写入。

```python
def num_islands(grid):
    if not grid or not grid[0]:
        return 0
    rows, cols = len(grid), len(grid[0])

    def visit(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return
        if grid[r][c] != "1":
            return
        grid[r][c] = "0"
        visit(r + 1, c)
        visit(r - 1, c)
        visit(r, c + 1)
        visit(r, c - 1)

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1":
                count += 1
                visit(r, c)
    return count

grid = [["1","1","0"], ["0","0","1"]]
assert num_islands(grid) == 2
assert grid == [["0","0","0"], ["0","0","0"]]
assert num_islands([]) == 0
```

从样例 `(0, 0)` 开始，先标记自己，再逐个尝试四个邻居。走到 `(0, 1)` 时，它也先标记，然后继续深入。越界或碰到水、已标记位置就返回，父调用接着尝试剩下的方向。第一轮 DFS 完成后，这两个陆地格已经属于同一座数过的岛，外层不会在 `(0, 1)` 再加一；走到 `(1, 2)` 才发现第二座岛。

DFS 决定先深入再换方向，递归负责保存走完后要继续的位置。用显式栈也能保存这些待办位置，因此 DFS 不依赖递归语法。

只要一块陆地被发现，就会尝试它的全部四邻居，因此与起点连通的陆地最终都会被发现。每块陆地只首次展开一次，一次完整搜索结束时，当前岛已经全部标记。外层始终保持“已计数的岛已完整处理”，扫完整个网格就得到岛屿数。

> ⚠️ 必须先标记再访问邻居，否则相邻两格可能不断互相调用。边界检查也必须在读取 `grid[r][c]` 之前。函数修改的是外层同一个网格，若需保留原输入，应另存访问标记或先复制。

外层扫 rows × cols 个格子，每块陆地首次展开时只检查四邻居，总时间 O(rows × cols)。最坏调用路径也可能包含这么多格子，因此原地标记并不意味着 O(1) 空间，辅助栈最坏仍为 O(rows × cols)。显式栈能避开递归深度限制，但仍需存储待探索位置。

### BFS：按到达所需的步数逐层展开

如果问题关心从起点最少走几条边，单纯先走深可能先绕出一条长路。BFS 先展开一步可达的节点，再展开两步、三步可达的节点。因此在无权图中，首次发现一个节点就对应最少边数。

先用返回访问顺序的小程序观察这套层次。图允许有环，同层按邻接列表顺序发现；本函数只返回起点可达部分的顺序，没有额外返回距离。

- `queue` 保存已发现、尚未展开邻居的节点。
- `visited` 保存所有已发现节点，阻止重复入队。
- `order` 保存出队访问的顺序。

```python
from collections import deque

def bfs(graph, start):
    queue = deque([start])
    visited = {start}
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph.get(node, []):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

graph = {1:[2,3], 2:[1,4], 3:[1], 4:[2]}
assert bfs(graph, 1) == [1, 2, 3, 4]
assert bfs({}, 9) == [9]
```

样例从 1 出发，先把 2、3 加入队尾，队列为 `[2, 3]`。取出 2 后发现 4，追加为 `[3, 4]`。这时第 1 层的 3 仍排在第 2 层的 4 前面，因此最终顺序为 `1、2、3、4`。

当第 d 层节点出队时，新发现的邻居追加到下一层，而不会插到尚未展开的本层前面。更浅的层已经全部展开，如果这个邻居能用更少步到达，它本应更早被发现。队列维持这个层次顺序，才保证无权图中的最少边数。

> ⚠️ 入队时就写 visited。若等到出队才标记，同一个节点可能先被多个邻居重复加入。这里标记的是“已发现”，队列中的节点也已属于 visited。

每个可达节点进出队一次，每条邻接关系检查一次。设可达部分有 V 个节点、E 条边，按集合平均操作成本计算，时间 O(V + E)，队列与访问集合辅助空间 O(V)，返回顺序也占 O(V)。使用 `deque.popleft()` 避免了列表头部删除的元素移动。`graph.get(node, [])` 将缺失邻接表视为空，因此 `bfs({}, 9)` 返回 `[9]`。

BFS 的层数代表边数。只有每条边成本相同，层数才直接对应最短路径成本；不同权重不能套这个结论。若只需判断连通或访问全部节点，DFS、BFS 常常都能做到，选择取决于需要的顺序与保存待探索部分的空间。

“腐烂的橘子”把多个起点同时作为第 0 层，称为多源 BFS。所有初始腐烂格先入队，处理完一整层才推进一分钟，入队时标记已感染，防止重复加入。最后仍有新鲜格则不可到达。仍是相同的逐层展开思想，矩形网格中时间和最坏辅助空间均为 O(rows × cols)。

## 10. 回溯：探索一种选择，恢复后再试下一种

当任务是生成所有排列、组合或其他可行方案，搜索的位置不再只是地图中的一个点，而是“已经作出哪些选择”。选第一项后还要选第二项，不同选择向下形成不同分支，整体可以看成一棵选择树。

**回溯的核心是：把部分答案作为搜索状态，尝试一个合法选择，探索它带来的后续，再撤销这个选择，回到同一个起点尝试另一条分支。** 这样才能既共享已有前缀，又让不同分支互不污染。

它常用 DFS 顺序沿一条选择路径走到底，也常用递归表达层次，但三者职责不同：DFS 决定先探索哪条分支，递归保存调用现场，回溯还要求恢复可变的选择状态。函数返回不会自动把你追加到列表里的内容弹出去。

若一个部分答案已经不可能补成合法解，就没必要再深入，这种提前排除无效分支叫剪枝。剪枝需要依据：必须确信这一分支没有目标答案，不能只因为当前看起来不理想就跳过。

### 用全排列看清“选择与撤销”为什么成对

任务是生成不重复数字的所有排列。`[1, 2]` 得到 `[[1, 2], [2, 1]]`，空输入约定返回 `[[]]`。`path` 是已选前缀，`used[i]` 表示原下标 i 是否进入当前前缀，`answer` 保存完成的排列。

每次进入 `visit()`，路径里没有重复使用的位置，used 恰好反映这条路径。函数要列完这个前缀下的全部完成方式，并在返回前恢复进入时的现场。因此每次选择都必须准备对应的撤销动作。

```python
def permutations(nums):
    answer = []
    path = []
    used = [False] * len(nums)

    def visit():
        if len(path) == len(nums):
            answer.append(path.copy())
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            visit()
            path.pop()
            used[i] = False

    visit()
    return answer

assert permutations([1, 2]) == [[1, 2], [2, 1]]
assert permutations([]) == [[]]
```

对于 `[1, 2]`，先选 1，下一层只能选 2，完成 `[1, 2]`。最深层保存副本并返回后，上一层弹出 2、清除它的标记，恢复为 `[1]`；再返回更上一层，弹出 1，恢复空路径。此时才开始另一条以 2 开头的分支，得到 `[2, 1]`。

撤销只恢复工作路径，已经保存的答案不变。每次 `for` 都从相同父前缀开始：漏掉 `pop()` 会混入旧路径，漏掉清除 used 会封锁其他分支的合法选择。

> ⚠️ 保存完整答案要用 `path.copy()`。直接保存 path 留下的是同一个可变列表的引用，之后的撤销会改变已经保存的所有答案。

每个合法排列都对应一条逐位选择路径，所有未用位置都会被尝试，所以不漏解。输入数字互不重复，不同路径也不会得到同一个排列。路径每深入一层就多一项，最多到 n，完成后返回；空输入一开始就是完整空排列。

返回结果有 n! 个排列，每份长度 n，仅复制输出就需要与 n×n! 成正比的工作。本实现总时间 O(n×n!)，输出空间 O(n×n!)；不计结果时，路径、标记与递归栈合计 O(n)。剪掉重复使用数字的分支，并不能把必须输出的阶乘数量答案变成线性大小。

这也说明它与上一节访问标记的区别：图搜索的 visited 表示全局已经发现，同一节点不必再次展开；这里的 used 只约束当前路径，一个分支用过的数，在另一个分支仍可再用。若允许重复数字或重复选取，要先重定合法前缀、去重和撤销规则，再改实现。

## 11. Top K：围绕入选门槛保留候选

“找出前 k 大”“求第 k 大”是一类任务，不是一个固定算法。全部排序再截取是一种做法；若只需要少量优胜者，也可以边扫描边维护入选名单。这里学习的是后一种组织方式。

**有界候选集的核心是：只保留仍有资格影响答案的 k 个候选，用其中最弱的一项作为新候选的入选门槛。** 当新数超过门槛，就替换最弱者；否则已经有 k 个不比它差的数，它无法提高前 k 大的结果。

要反复找到入选者中最弱的一个，就用大小至多 k 的最小堆。求前 k 大时，堆顶提供的是淘汰门槛。

### 求第 k 大时，究竟要维护什么

任务是返回整数列表中第 k 大元素，保证 `1 <= k <= len(nums)`。重复值按次数计入，`[3, 3, 2]` 的第 2 大仍为 3。目标状态是：处理 t 个数后，堆保留其中最大的 `min(k, t)` 个，且始终满足最小堆关系。

`heapq.heapreplace(heap, x)` 会移走原堆顶并放入 x，重新维护堆关系，大小不变。本题必须先判断 x 确实值得入选。

```python
import heapq

def kth_largest(nums, k):
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return heap[0]

assert kth_largest([3,2,1,5,6,4], 2) == 5
assert kth_largest([3,3,2], 2) == 3
assert kth_largest([7], 1) == 7
```

每个新数只有三种情况：名单未满，直接加入；名单已满且超过门槛，替换最弱者；其余情况忽略。假设要留最大的 3 个数，已选成员为 2、3、4，门槛是 2。新来 1 不影响名单，新来 5 则替换 2，门槛升到 3。这里列举的是成员，不是在说堆的内部数组已经全序排列。

为什么丢掉的候选不用再找回？满额以后门槛只会不变或上升，已被 k 个候选压过的旧值不会在未来突然重新超过门槛。由此，扫描结束时仍保有全体输入的前 k 大，其中最小的堆顶就是第 k 大。相等时不替换也安全，因为换入等值候选不会改变第 k 大的值。

> ⚠️ `heapreplace` 要求堆非空，而且不会替你判断新值是否更好。还不能把整个堆直接当成排序后的前 k 名列表；堆只保证堆关系与堆顶最小。

每个值比较门槛 O(1)，入选时最多做 O(log(k + 1)) 的调整，总时间 O(n log(k + 1))，额外空间 O(k)，这个表达也涵盖 k = 1 的线性扫描。全排序一般 O(n log n)。k 接近 n 时堆方法未必更划算；k 较小或数据持续到来时，只维护候选更符合需求。

换一道 Top K 题，先定义优劣与入选门槛，再选结构。重复值是否计数、需要单个值还是有序名单，都会影响状态和输出。

## 12. 贪心：证明一个局部决定仍能通向最优解

每一步都有多种选择，全部尝试可能很贵，随意舍弃又可能错过最优解。贪心要寻找一种可以直接固定的局部选择：作出它之后，仍有机会得到整体最优解。

**贪心的核心是证明当前选择可以安全固定。** 常见依据是：把最优方案中的一步换成我们的选择，结果不会变差；或者一个选择在后续始终不劣于另一个，因此后者可以舍弃。

单次股票买卖可以展示后一种依据：逐步舍弃较差的历史买入机会。

### 固定同一个未来卖出日，再比较买入选择

任务是最多买卖一次，必须先买后卖，不交易利润为 0，允许空输入。`[7, 1, 5, 3, 6, 4]` 返回 5。

若今天卖出，之前价格为 7、1、5、3，同一个卖出价减去 1，利润一定不小于减去其他价格。对于任何尚未来到的卖出日，这些旧买入日也都在它之前，比较仍成立。因此历史买入机会只需留下最低价格。

这里作出的安全选择是“保留哪一个历史买入机会”，并不是立刻决定最终买哪天、卖哪天。为了不丢掉已经完成的好交易，还要另存当前最大利润：

- `lowest` 保存今天之前的最低买入价，服务于今天或未来卖出。
- `best` 保存已考察过的卖出日能得到的最好利润，至少为 0。

```python
def max_profit(prices):
    if not prices:
        return 0
    lowest = prices[0]
    best = 0
    for i in range(1, len(prices)):
        price = prices[i]
        best = max(best, price - lowest)
        lowest = min(lowest, price)
    return best

assert max_profit([7,1,5,3,6,4]) == 5
assert max_profit([7,6,4,3,1]) == 0
assert max_profit([]) == 0
```

第一天只建立历史最低价，从第二天开始考察卖出。对样例，计算过程如下：

| 今天价格 | 用来买入的历史最低价 | 今天卖出的利润 | 更新后的 best |
|---:|---:|---:|---:|
| 1 | 7 | -6 | 0 |
| 5 | 1 | 4 | 4 |
| 3 | 1 | 2 | 4 |
| 6 | 1 | 5 | 5 |
| 4 | 1 | 3 | 5 |

每轮先用旧最低价计算今天卖出的最佳利润，再把今天价格纳入最低价，供下一轮使用。这保住了“买在卖之前”。新低价出现，也不会抹掉此前已经找到的收益，因为 best 单独保存完成交易的结果。

所有合法交易都属于某个卖出日，而针对每个卖出日，最低历史价已代表最佳买入选择。我们逐日比较这些结果，就能得到整体最大利润。价格一直下降时，选择不交易；只有一天或空输入，也没有可完成的交易。

直接枚举所有买卖日期对，最坏 O(n²)。这里用已证明安全的选择压缩历史，每个价格处理一次，时间 O(n)、额外空间 O(1)。按下标遍历也避免了切片复制。

> ⚠️ 这份安全性依赖“最多交易一次”的条件。允许多次买卖、加入手续费或其他限制，需要重新比较选择的后续影响，不能照搬只保存最低价的结论。

不是每个“看起来最优”的局部选择都安全。例如用面值 1、3、4 凑出 6，希望硬币最少：先拿最大的 4 会得到 4+1+1，共 3 枚；选择 3+3 只需 2 枚。可见，眼前最大的选择不一定带来整体最优结果。

尝试贪心时，先找可能使当前选择失效的情况，再证明它为什么安全。若选择不能直接舍弃，却能分成重复出现的子问题，可以考虑动态规划，保存子问题答案后再比较或汇总。

## 13. 动态规划：把足够清楚的子问题变成可复用答案

大问题可以拆成小问题，但不同分支可能再次遇到同一个小问题。每次都重新求解，就产生了重复计算。

**动态规划的核心是：把原问题拆成含义明确的子问题，保存它们的答案，并沿依赖关系复用这些答案。** 同一个子问题只需求解一次，以后直接取用答案。

怎样判断是“同一个”子问题？位置相同，但历史会影响后续选择时，就不能合并成一个状态。状态要保留影响答案的信息，省去无关历史。

一个状态不是数组下标本身，而是一句话描述的任务。它可以表示到某处的方法数、解决前一部分的最低代价，或在若干条件下能够得到的最优值。只有含义明确，才能判断怎样由其他状态得到它、哪些答案要先求、最终该取哪一个。

### 从爬楼梯建立状态和依赖

任务是每次走 1 阶或 2 阶，问到第 n 阶有多少种方法，n 为正整数。只求数量，不要求输出每条路径。因此很多不同走法可以被一个计数概括，不必像全排列那样保存完整路径。

定义 `dp[i]` 为“到达第 i 阶的方法数”。为了计算它，按最后一步分成两类：最后走 1 阶，前面必须到 i - 1；最后走 2 阶，前面必须到 i - 2。每一种旧走法接上固定的最后一步，就得到一条新走法。

两类最后一步不同，互不重复，又覆盖全部可能，所以有 `dp[i] = dp[i - 1] + dp[i - 2]`。递推式是从状态任务与分类关系推出来的，不是遇到台阶就套一个熟悉公式。

如果直接递归计算，到第 5 阶要算第 4、3 阶；计算第 4 阶又要算第 3、2 阶。第 3 阶被反复问到，而这个子问题的规则和答案完全相同，重复算没有新信息。朴素递归会形成指数级增长的重复调用，保存每个阶数的答案才消除了这份重复。

保存并复用通常有两种计算安排：递归遇到某个状态时，先查它是否算过，算完记下，这叫记忆化；也可以先按依赖顺序把小状态填好，再推到大状态，下面采用后者。二者复用的都是同一组子问题。

```python
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

assert climb_stairs(1) == 1
assert climb_stairs(2) == 2
assert climb_stairs(5) == 8
```

第 1 阶只有一种走法，第 2 阶有两次 1 或一次 2，因此初值为 1、2。接下来每次计算 i 时，前面的必要答案都已就绪：

| 子问题 | 已知依赖 | 得到的答案 |
|---|---|---:|
| 到第 1 阶 | 直接数出 | 1 |
| 到第 2 阶 | 直接数出 | 2 |
| 到第 3 阶 | 第 2 阶的 2 种 + 第 1 阶的 1 种 | 3 |
| 到第 4 阶 | 第 3 阶的 3 种 + 第 2 阶的 2 种 | 5 |
| 到第 5 阶 | 第 4 阶的 5 种 + 第 3 阶的 3 种 | 8 |

从小到大填，是依赖关系要求先有前两个答案。循环开始算 i 时，`dp[1]` 到 `dp[i - 1]` 都已正确；按不重不漏的分类得到 `dp[i]`，就把已完成部分延长一格。最后返回的 `dp[n]` 正是任务要求。

共有 n 个有效状态，每个只做常数次读取与加法，时间 O(n)、表格空间 O(n)。其他 DP 也这样计数：有多少状态，每个状态要处理多少依赖？

### 状态含义不变，保存方式可以再缩小

先用表格对应每个子问题，再检查哪些旧答案以后还会用到。本题只依赖前两阶，更早的答案不再使用，所以可缩成两个变量。

```python
def climb_stairs_compact(n):
    if n <= 2:
        return n
    previous, current = 1, 2
    for i in range(3, n + 1):
        previous, current = current, previous + current
    return current

assert climb_stairs_compact(5) == 8
assert climb_stairs_compact(1) == 1
```

准备算第 i 阶时，`previous` 对应 `dp[i - 2]`，`current` 对应 `dp[i - 1]`。右侧先用两个旧值计算，再一起更新为 `dp[i - 1]`、`dp[i]`。比如算第 5 阶前是 3、5，更新后是 5、8，最终返回 current。

> ⚠️ 不能先执行 `previous = current`，再算 `current = previous + current`。第二句读到的 previous 已被覆盖，会丢失原来的前一阶答案。也不能因为本题能压成两个变量，就假定所有 DP 都可以。

压缩后时间仍为 O(n)，只保留常数个计数，按通常状态个数模型称辅助空间 O(1)。Python 整数会随结果变大而增加位数，若计算极大 n 的实际位运算和字节成本，单次加法与单个计数就不能永远视为常数。

### 题目条件变化时，先检查状态是否还足够

如果增加“不能连续两次走 2 阶”，同样站在第 i 阶，上一跳是 1 还是 2，会改变下一跳能否选择 2。只记录阶数已经把不同情况混在一起，需要把上一跳相关信息纳入状态。先补足子问题含义，再谈新的递推式。

如果改成输出所有走法，一个计数也不能替代这些结果；如果只改成每次允许的步长集合，状态仍可能表示到第 i 阶的方法数，但依赖来源要随合法最后一步调整。

换一道 DP 题，仍按这个顺序推导：定义信息充分的状态，找出依赖，说明怎样计数或比较，再安排计算顺序与存储。记忆化、填表和滚动变量只是不同的计算、保存方式。

## 14. 本章小结：方法可以组合，依据不能混用

离开例题后，还要能分清这些方法各自解决什么问题。

**哈希、前缀和与 DP 都保存信息，保存的理由不同。** 哈希先明确将来问什么，再按键组织答案；前缀和利用可抵消的累计关系重写区间量；DP 保存含义相同、会重复用到的子问题答案。和为 K 的子数组需要前缀和把区间条件改写成边界关系，再用哈希查询满足关系的旧边界。一个方法并不排斥另一个。

**双指针、窗口与二分都有边界，移动的依据不同。** 双指针让两个位置协调处理进度，窗口进一步维护整个连续区间的内容或性质，二分则依赖能整段排除候选的有序关系。只有边界变量，没有职责与排除理由，不能说明算法成立。

**递归、DFS/BFS 与回溯属于不同层面。** 递归表达同一任务在更小输入上的调用与组合；DFS/BFS 决定怎样处理待探索部分；回溯在选择树上探索，同时恢复当前分支借用的状态。树高可以用递归，DFS 可以用显式栈，回溯也可以有多种实现。看到函数调用自身，不足以判定它是否在回溯，或者是否重复计算了子问题。

**单调栈、Top K 与贪心都会舍弃信息，必须各有理由。** 单调栈弹出的是已经解决的旧问题；有界 Top K 丢掉的是不可能提高入选结果的弱候选；贪心固定一个选择，要证明仍有整体最优解与它相容。DP 则保留必要子问题，用比较或汇总处理不能直接舍弃的可能性。

回到陌生题时，先明确任务、手算样例、写出直接做法，再追问困难落在哪里。不要只因题目里有“连续”就用窗口，有“最大”就用贪心，有递推式就盲目压成两个变量。选择方法的证据来自题目条件与问题关系。

## 15. 面试怎么答

**问：你怎样从暴力解想到优化？**

> 🎯 我先把直接做法反复处理的内容说清。例如两数之和对每个数重新扫描其他位置，可以改问“此前有没有补数、位置在哪里”，于是建立值到位置的哈希索引。如果问题不是重复查询，而是能利用有序性整段排除候选，我会考虑二分。选定思想后，再明确本题状态、更新顺序和成立条件，最后针对实际实现计算时间与空间。

**问：递归、回溯和动态规划是什么关系？**

> 🎯 递归让函数在更小输入上完成同类任务，当前层在它返回后接着完成自己的工作。回溯搜索不同选择，需要撤销可变现场，保证各分支从同一前缀出发。动态规划识别会重复遇到的子问题，保存答案并按依赖复用。它可以通过记忆化递归实现，也可以填表实现。三者关注的层面不同，不能只凭是否自调用分类。

## 16. ⚠️ 容易混淆的地方

- 结构名字不能代替算法思想。哈希表的键和值要来自查询，栈要说明为什么最近的未决项可以先处理，堆要说明要反复取得哪个候选。
- 指针能够移动，不代表答案可以被安全丢弃。窗口要解释合法性怎样恢复，二分要解释排除哪一段，两个位置都必须有明确含义。
- 循环不变量不是附在代码末尾的一句术语。若它说“查询之前只有旧历史”，先查后存就应在实现和样例里保持一致。
- 递归返回只结束子调用，不会跳过父调用剩下的工作，也不会自动撤销共享对象的修改。回溯要成对恢复选择，保存答案时要复制。
- 两层循环不一定是平方，递归也不一定指数。要数实际处理的元素、边、状态或分支，并计入切片、复制、调用栈和输出大小。
- 能在原例子里运行，不代表条件变化后仍成立。相等是否算更大、边是否带权、选择是否可重复、状态是否缺少历史，都可能改变方法的适用边界。
