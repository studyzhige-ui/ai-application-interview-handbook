# 06｜算法推导：建立能迁移到新题的思考方式

[← 上一章：数据结构](05-data-structures.md) · [Coding 首页](../README.md) · [下一章：Hot100 综合训练 →](07-hot100.md) · [题目映射](../hot100-map.md)

已经会写循环，也认识字典、栈和树，为什么遇到新题仍然不知道怎样开始？通常缺的不是某个 Python 写法，而是中间这一步：**从题目要求出发，决定要记住什么，以及凭什么可以少做一些工作。**

比如找两个和为 9 的数。读到 7 时，逐个回看前面的数当然可以。但我们真正要知道的只有“前面有没有 2”。从重新扫描改成查询，这个变化才是算法思想；字典是实现它的工具。

本章沿着三类困难展开：先看扫描和区间中怎样避免重查，再看树、图与多种选择怎样有序探索，最后看哪些选择可以直接舍弃、哪些子问题需要保存答案。例子用于把方法讲清，不要求靠记住每一道题的代码来识别方法。Hot100 是后续应用这些思想的扩展题库，不是本章必须覆盖全部解法的目录。

## 1. 推导算法：先知道自己在省什么

### 直接做法不是需要跳过的步骤

先明确输入、输出、限制，再手算一个小输入。例如两数之和要的是两个**不同位置**，并不是一个数能否重复使用。直接枚举所有位置对，就能满足要求，只是 n 个数会产生约 n²/2 对，数据多时很慢。

有了直接做法，优化才有具体对象：

- 如果反复查同一批历史，可以留下便于查询的记录。
- 如果相邻两次工作大部分相同，可以只处理变化的部分。
- 如果一次比较能证明一批候选都不可能，可以整批排除。
- 如果不同分支都在求同一个小问题，可以保存它的答案。

这些是找思路的方向，不能只凭题目里某个词就选定算法。还要说明题目的哪些条件允许这样做。

### 变量要记录一个说得清的事实

回想循环求和：读完 `[2, 3]` 时，`total = 5`。这个变量的意义是“已经读过的元素之和”，不是“程序里用来加加减减的一个数”。下一项是 4，就把 total 改成 9。

算法保留的这类信息叫**状态**。状态可以是一个数、一组位置，也可以是一张表。定义得清楚，才知道下一步应该怎样更新。

“每次读新元素之前，total 都等于已读部分的和”是一条**循环不变量**，即在循环的同一个时刻始终成立的事实。它把正确性接成一条连续的理由：

1. 没读任何元素时，总和是 0，初值正确。
2. 读一项就加一项，更新后仍是已读部分的和。
3. 全部读完时，已读部分就是整个输入，total 就是答案。

后面不需要给每段代码套证明格式，但要保留这种检查方式。递归则要检查“每次函数调用负责完成什么”，不能把所有算法都硬解释成同一个循环。

### 复杂度数的是实际工作，不是缩进层数

第 05 章已经介绍 O(1)、O(n)、O(log n) 等增长量级。本章进一步追踪：一个元素到底会被处理几次？一次处理有没有复制或移动很多内容？同时保存了多少东西？

例如每个元素入栈一次、出栈至多一次，总共仍是线性次操作，即使代码里有嵌套循环。递归代码没有显式创建列表，也会用调用栈保存尚未完成的调用。

本章以 n 表示输入元素个数，通常把普通整数运算、比较和下标访问视为常数成本。字典与集合按平均操作成本分析。辅助空间与返回结果占用的空间会分别说明；这些估算不是运行秒数。

## 2. 哈希：围绕反复出现的问题建立索引

反复问“这个人有没有登记”，每次从头翻名单会重复检查许多人。换一种组织方式：按姓名建立索引，下次用姓名就能找到登记情况。算法里的哈希方法也在做这样的转换，把一遍遍扫描历史变成按键查询。

**核心是先确定将来要问什么，再把足够回答它的信息按键保存。** “用空间换时间”只是结果，真正要想清的是键代表什么、每个键下面留下什么：

| 将来要问的问题 | 应当留下的信息 |
|---|---|
| x 有没有出现过？ | 集合中的成员资格 |
| x 出现在哪里？ | 字典中的 `x → 位置` |
| x 出现了多少次？ | 字典中的 `x → 次数` |
| 哪些项与 x 属于同一类？ | 字典中的 `类别特征 → 同类项列表` |

同样重要的是查询范围：此前出现过、整个输入中存在、当前区间内存在，是三个不同问题。范围决定何时建立记录、何时加入和删除；内容决定用集合还是字典。类别特征还必须保留题目要求区分的差别，不能把不同类别错误合并。

下面先看“查此前的位置”，再看“查整个输入的存在性”。两题共用的是按查询组织信息的思想，不是同一张字典的写法。

### 从两数之和看清键、值与先后顺序

读到当前数 x，搭档只能是 `target - x`。若要返回下标，就保存“数值 → 它此前出现的一个下标”。

以 `[2, 7, 11]`、目标 9 为例：

| 当前项 | 向旧记录查询 | 查询后做什么 |
|---|---|---|
| 下标 0，值 2 | 有没有 7？没有 | 登记 `2 → 0` |
| 下标 1，值 7 | 有没有 2？有，在 0 | 返回 `[0, 1]` |

关键不是字典查询很快这一句话，而是**查询时字典只包含此前位置**。因此查到的搭档一定不是当前元素自己。

```python
def two_sum(nums, target):
    positions = {}
    for i, x in enumerate(nums):
        needed = target - x
        if needed in positions:
            return [positions[needed], i]
        positions[x] = i
    return []

assert two_sum([2, 7, 11], 9) == [0, 1]
assert two_sum([3, 3], 6) == [0, 1]
assert two_sum([3], 6) == []
```

本例找到任意一对就返回，没有则返回空列表。如果一对合法位置为 i、j，且 i 在前，那么读到 j 时，i 的数值已经登记，所以不会漏过这一对。即使相同数值的旧下标被覆盖，留下的仍是一个合法的此前位置。

> ⚠️ 先登记当前数再查询，会让 `[3]`、目标 6 与自己配对。不是所有字典题都必须先查后存，而是本题只能查询“此前位置”。

每个元素平均做常数次查询与登记，时间平均 O(n)，辅助空间 O(n)。这里省掉的是重复扫描，代价是保存旧记录。

### 查询整个输入时，先建立完整索引

最长连续序列查的是整个输入，不是此前部分。输入 `[100, 4, 200, 1, 3, 2]` 的答案是 4，因为包含 `1、2、3、4`。这里“连续”指数值相差 1，和原位置是否相邻无关；重复值不增加长度，空输入返回 0。

### 快速查到，不等于不会重复查

先建立 `values = set(nums)`，就能快速问下一个数在不在。但如果从 1 数一遍 `1、2、3、4`，再从 2 数一遍 `2、3、4`，仍有大量重复工作。

要让一整段只数一次，可以先识别段首：**x 的前一个数 x - 1 不存在，x 才是段首。** 这一步是避免重复的依据，集合本身不会自动完成它。

对段首 1，令 `end` 表示下一个要检查的数。依次确认 1、2、3、4 后，end 到 5，查询失败，长度为 `5 - 1 = 4`。遇到 2、3、4 时，因为各自有前驱，直接跳过。

```python
def longest_consecutive(nums):
    values = set(nums)
    best = 0
    for x in values:
        if x - 1 in values:
            continue
        end = x
        while end in values:
            end += 1
        best = max(best, end - x)
    return best

assert longest_consecutive([100, 4, 200, 1, 3, 2]) == 4
assert longest_consecutive([1, 1, 2]) == 2
assert longest_consecutive([]) == 0
```

集合遍历顺序不确定，但每段都有一个段首，外层最终会遇到它，因此所有段都会被数到。每个不同数字只在自己的段里被成功扩展一次，连同建集合与检查段首，总时间平均 O(n)，辅助空间 O(n)。

从这两个例子带走的共同方法是：先明确查询内容和范围，再设计索引。之后还要检查是否在反复做同一批查询，而不能把“用了 set”当成线性时间的保证。

## 3. 双指针：让两个位置各自负责一部分进度

处理一个序列时，一份进度有时不够：对称比较要同时知道左右两端；原地整理要同时知道读到哪里、结果写到哪里。双指针就是让两个位置各自承担一个明确角色，协调完成同一项处理。

**核心不是用了两个下标，而是让每次移动都对应“完成了一部分工作”或“排除了一批候选”。** 先划清已经确认和仍待处理的区域，再决定哪个位置可以前进。两端向中间、同向快慢走都只是这种分工的不同结果。

双指针能减少工作，是因为移动后不必重查已经完成或排除的部分。这必须有依据：对称字符确认后无需再比；读过的元素安放妥当后无需重读；若想按大小排除候选，则还需排序或其他关系。只有移动规则，没有这个依据，两个指针也可能漏解。

### 回文：两端确认后，剩下中间继续判断

回文要求对称位置字符相同。最外面一对相等后，就只剩内部需要判断。让 `left` 指向尚未比较的左端，`right` 指向尚未比较的右端，每次确认一对，再一起内移。

`"level"` 的过程是：

| 待比较下标 | 比较结果 | 剩下什么 |
|---|---|---|
| 0、4 | l 与 l 相同 | 内部 `eve` |
| 1、3 | e 与 e 相同 | 中间一个 v |
| 2、2 | 同一个位置，无需配对 | 所有必要比较完成 |

本例精确比较原字符，不忽略大小写和标点；空字符串与单字符算回文。

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

assert is_palindrome("level") is True
assert is_palindrome("hello") is False
assert is_palindrome("") is True
assert is_palindrome("a") is True
```

循环每次开始时，两端外面的对称字符已经确认相等。比较成功就把这一对归入已确认部分；失败则已经有反例。相遇或交错后，没有未检查的字符对，便可以返回 True。

最多比较约 n/2 对，时间 O(n)，辅助空间 O(1)。反转一份字符串再比较也可以，但会增加 O(n) 的副本空间；这里优化的是空间，不是把时间变成常数。

### 移动零：读取进度与安放进度分开

任务是原地把零移到末尾，保留非零元素顺序，返回 `None`。例如 `[0, 1, 0, 3, 12]` 变成 `[1, 3, 12, 0, 0]`。

每个数都要读，但只有非零数需要安放进前面的结果区域。因此安排两个角色：

- `read` 是本轮要读的位置，每轮都前进。
- `write` 是下一个非零数要放的位置，放好一个非零数才前进。

开始两者都在 0。read 先读到零，write 留在 0；读到下标 1 的数 1，把它与 write 处的零交换，再把 write 移到 1。已经放好的非零部分就成为 `[1]`。

继续读到下标 3 的数 3 时，状态可以画成：

```text
位置：  0   1   2   3    4
数值： [1,  0,  0,  3,  12]
           ↑       ↑
         write    read
```

write 到 read 之前的部分，都是已经读过的零。把 3 换到 write，既接在 1 后面，又不会破坏还没读过的 12。

```python
def move_zeroes(nums):
    write = 0
    for read in range(len(nums)):
        if nums[read] != 0:
            nums[write], nums[read] = nums[read], nums[write]
            write += 1

nums = [0, 1, 0, 3, 12]
assert move_zeroes(nums) is None
assert nums == [1, 3, 12, 0, 0]
empty = []
move_zeroes(empty)
assert empty == []
```

为什么可以一直这样交换？每轮读取之前，三部分的意义始终不变：

1. write 之前，是按原顺序放好的非零数。
2. write 到 read 之前，是已经读过的零。
3. 从 read 起，还没有处理。

读到零，只扩大第二部分；读到非零，把它放入第一部分，换出来的零留在已读区域。write 不会超过 read，所以不会提前改坏未读数据。两者相同时只是自己与自己交换。

读完后，整个列表只剩“非零结果＋零”两部分。每个位置读一次，时间 O(n)，辅助空间 O(1)。

> ⚠️ 并行赋值先取得两个旧值再写回，不能随意拆成两句互相覆盖的赋值。每遇到零就删除并移动后缀，也会把原本线性的处理变成最坏 O(n²)。

两题都没有靠“两个下标”自动获得正确性。回文靠已经确认的对称关系，移动零靠已完成、已读、未读的分区。换题时，需要重新找出这种前进后不必回头的理由。如果根据数值大小移动指针来排除候选，还要有排序或其他大小关系作依据，不能把无序数据直接套进去。

## 4. 滑动窗口：复用相邻区间，只更新进出部分

很多题目考察连续子串或子数组。相邻两段往往共享大部分内容，如果每换一段就重新求和或重新检查重复，前面做过的工作就被浪费了。

**滑动窗口把当前连续区间当作一个整体，保留它的统计或性质；边界移动时，只根据进入、离开的元素更新。** 双指针说明区间在哪里，和、频次表或集合说明区间里有什么。它复用的是相邻区间的共同部分，不是每次重新求解一个独立区间。

窗口有两种常见安排。固定长度时，右端加入一项、左端移出一项，长度不变；长度可变时，边界还要服从题目条件。例如求最长合法区间，可以向右扩展，发生冲突时再从左端缩小。但这不是所有区间题通用的移动规则。

为什么可以只向右、不回头？要能说明被丢弃的左边界将来也不会产生需要保留的答案。无重复区间满足这个条件：已经存在的重复，不会因右边再加字符而消失。下面用这个关系推导收缩规则，再讨论状态怎样跟着边界变化。

### 无重复子串：先保住旧窗口，再处理新字符

任务是求最长无重复连续子串的长度。`"abba"` 返回 2，子串可以是 `"ab"` 或 `"ba"`；不能跳过中间字符。空字符串返回 0。

令旧窗口本来就没有重复。新字符到来后，唯一可能新增的重复，就是这个字符与旧窗口中的某个字符相同。因此：

1. 用 `seen` 保存旧窗口的字符，检查新字符是否在其中。
2. 若在，从左端逐个移出字符，直到旧的同名字符离开。
3. 加入新字符，此时窗口重新无重复，才用长度更新答案。

`left` 指向窗口左端，`right` 是即将加入的位置，`best` 保存见过的最大合法长度。加入前，seen 对应 `text[left:right]`，不包含 right；加入后，窗口才包含 right。

| `"abba"` 新来的字符 | 移入前的窗口 | 如何处理 | 新窗口 / best |
|---|---|---|---|
| 下标 0：a | 空 | 直接加入 | a / 1 |
| 下标 1：b | a | 直接加入 | ab / 2 |
| 下标 2：b | ab | 移走 a 还冲突，再移走旧 b，然后加入 | b / 2 |
| 下标 3：a | b | 直接加入 | ba / 2 |

```python
def longest_unique(text):
    seen = set()
    left = 0
    best = 0
    for right, ch in enumerate(text):
        while ch in seen:
            seen.remove(text[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best

assert longest_unique("abba") == 2
assert longest_unique("abcabcbb") == 3
assert longest_unique("") == 0
```

### 为什么左端不用退回去

读到第二个 b 时，只要还包含旧 b，窗口就一定不合法。删到旧 b 离开便停止，得到的是以新 b 结尾的最长合法窗口。

更早丢掉的左边界也不用重新尝试：一个区间已经含有重复，继续在右边加字符，原来的重复不会消失。因此左端只向右走不会漏掉更优答案。对每个 right 都求一次最长合法窗口，再取最大值，便覆盖全部可能的最优结果。

> ⚠️ 这里必须用 `while`。`"abba"` 中只删一次会删掉 a，旧 b 还在。集合又只能记录存在性，不能把含有两个 b 的区间当成正常窗口继续维护。

### 两层循环为什么仍是线性

right 让每个位置进入一次，left 让每个位置至多离开一次，总更新次数不超过约 2n。集合操作按平均 O(1) 计算，时间平均 O(n)，辅助空间最坏 O(n)。不是每个 right 都从头移动 left，所以不能把两个循环的长度相乘。

能否照搬“右扩、左缩”，要看题目条件。例如含负数的区间，移走左端负数反而会让和变大，不能不加判断地用“和太大就缩窗”。可复用的是随边界维护状态的思想，合法性与收缩规则必须重新推导。

## 5. 前缀和：把区间内部的累加改成两个边界相减

想知道从第 3 站到第 7 站有多远，可以逐段相加，也可以用“起点到第 7 站的累计距离”减去“起点到第 3 站的累计距离”。两份累计值里共同的前半段抵消了，剩下的正是要查询的一段。

**前缀和先保存从开头到各个边界的累计和，再把一个区间的和改写为两个边界累计值之差。** 它与窗口复用相邻区间不同：建好累计值后，查询边界可以任意跳动，不需要从上一个区间一步步移过去。

关键是“共同部分可以抵消”，不只是提前存了一张表。两个前缀最小值不能通过相减恢复中间区间的最小值，所以不能把任意区间问题都套成前缀相减。对加法成立的这条关系，还能反过来使用：已知右边界和目标区间和，推算左边界应该具有哪个累计值。

### 前缀编号是“取了几项”，不是“取到哪个下标”

定义 `prefix[i]` 为前 i 项的和。对 `[2, 3, 1, 4]`：

| i | 前 i 项 | prefix[i] |
|---:|---|---:|
| 0 | 空 | 0 |
| 1 | 2 | 2 |
| 2 | 2、3 | 5 |
| 3 | 2、3、1 | 6 |
| 4 | 2、3、1、4 | 10 |

要求下标 1、2 的 `3 + 1`，就取前 3 项的和 6，减掉前 1 项的和 2，得到 4。一般地，`[l, r)` 包含 l、不包含 r，它的和是 `prefix[r] - prefix[l]`。

```python
nums = [2, 3, 1, 4]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
assert prefix == [0, 2, 5, 6, 10]
assert prefix[3] - prefix[1] == 4
```

每次把下一项加到旧累计值上，便得到多取一项的新前缀。建表时间 O(n)、空间 O(n)，之后每次区间查询 O(1)，q 次查询总共 O(n + q)。

> ⚠️ 两端都包含的下标区间 l 到 r，应使用 `prefix[r + 1] - prefix[l]`。输入改变后，旧表也可能失效。

### 还不知道左边界时，反过来查它应有的累计值

任务改成：统计和为 k 的非空连续子数组有多少个，允许负数、零和空输入。

固定一个右边界，当前累计和是 current。若某个旧边界的累计和是 old，那么这两个边界之间的和就是 `current - old`。要让它等于 k，只需找 `old = current - k`。

这样，原本“试所有左边界”，就变成了“此前有多少个前缀和等于这个数”。用字典 `frequencies` 保存**前缀和值 → 此前边界个数**。值相同的两个前缀，位置可能不同，代表两个不同区间，所以必须记次数。

以 `[1, -1, 0]`、k = 0 为例，边界上的累计值是 `0、1、0、0`。第一次的 0 是读任何元素前的空前缀：

| 新读的元素 | current | 要查的旧前缀 | 新找到的区间 |
|---|---:|---:|---|
| 1 | 1 | 1，旧记录没有 | 无 |
| -1 | 0 | 0，出现过 1 次 | `[1, -1]` |
| 0 | 0 | 0，出现过 2 次 | `[1, -1, 0]` 与最后的 `[0]` |

总共 3 个。每轮查询后，才把本轮的边界登记进去，供下轮使用。

```python
def subarray_sum(nums, k):
    frequencies = {0: 1}
    current = 0
    answer = 0
    for x in nums:
        current += x
        answer += frequencies.get(current - k, 0)
        frequencies[current] = frequencies.get(current, 0) + 1
    return answer

assert subarray_sum([1, 1, 1], 2) == 2
assert subarray_sum([0, 0], 0) == 3
assert subarray_sum([1, -1, 0], 0) == 3
assert subarray_sum([], 0) == 0
```

初始化 `{0: 1}` 是为了让从第一项开始的区间也有一个可减的旧前缀，并不是提前统计了一个答案。每个合法区间只在处理它自己的右边界时计入一次，因此不重不漏。

> ⚠️ 先登记再查询，会允许当前边界与自身配对，在 k = 0 时多算空区间。这里与两数之和一样，要先查询旧历史；但字典的键已变成前缀和，值已变成次数。

每个元素做常数次平均成本的查询与更新，时间平均 O(n)，辅助空间 O(n)。负数不影响相减关系，所以这里不需要“右扩后和只能增加”的条件。前缀和负责改写区间关系，哈希负责快速查询，两种思想可以合作。

## 6. 二分：让一次判断排除一整段候选

顺序查找每次只排除一个位置。有序数据却能让一次比较提供一整段的信息：升序列表的中间值已经太小，它左边的值也都太小，这半段无需逐项检查。

**二分的核心是利用有序或单调关系，把候选分成可以排除的一侧与仍可能有答案的一侧。** 取中点是为了让剩余范围尽量减半；真正允许排除的，是判断结果能代表整段候选。无序数据即使每次取中点，也没有这个保证。

更一般地，若一个条件沿候选顺序先不成立、随后一直成立，就可以二分寻找变化的边界，这叫利用条件的**单调性**。比如升序列表中的“值不小于 target”。因此二分既能找某个值，也能找第一个满足条件的位置；两种任务的相等处理未必相同。

推导时先说清要找什么、哪一段还可能包含它，再确定左右边界与中点更新。不要从背诵 `left`、`right` 的公式开始，边界写法必须服务于这套排除理由。

### 先约定哪一段还没有排除

任务是从严格递增整数列表中查找 target。找到返回下标，找不到返回插入后仍保持有序的位置；空列表返回 0。

用闭区间 `[left, right]` 表示还要查的元素位置，包含两端。每次取 mid 后：

- 相等：已经找到，返回 mid。
- `nums[mid] < target`：mid 及其左边都太小，下一次从 `mid + 1` 开始。
- `nums[mid] > target`：mid 及其右边都太大，下一次查到 `mid - 1` 为止。

查 `[1, 3, 5, 6]` 中的 2：

| 还要查的下标范围 | 中点比较 | 剩余范围 |
|---|---|---|
| 0 到 3 | 下标 1 的 3 大于 2 | 0 到 0 |
| 0 到 0 | 下标 0 的 1 小于 2 | left = 1，right = 0，已空 |

结束时，left 之前都小于 2，从 left 起都大于 2，所以插入位置就是 1。

```python
def search_insert(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return left

assert search_insert([1, 3, 5, 6], 5) == 2
assert search_insert([1, 3, 5, 6], 2) == 1
assert search_insert([1, 3, 5, 6], 7) == 4
assert search_insert([], 7) == 0
```

这里持续成立的是：left 左边都太小，right 右边都太大，可能存在的目标仍留在候选区间中。开始时两侧都为空；每次只排除已经证明不可能的一侧；范围为空时，两侧恰好划出插入位置。

> ⚠️ `left <= right` 表示只剩一个位置也要检查。边界更新要越过已经排除的 mid，否则范围可能不缩小。闭区间的初值、循环条件和更新是一套约定，不要混入半开区间的 `right = len(nums)`。

候选数量每次大约减半，最坏时间 O(log n)，辅助空间 O(1)；空输入为 O(1)。这里只移动下标，没有复制切片。

### 有重复值时，要找的是哪条分界线

对 `[1, 2, 2, 4]`，遇到 2 就返回，只能说明找到了某个 2。要找全部 2，可以分别找两个边界：

- `bisect_left(nums, 2)`：第一个不小于 2 的位置，返回 1。
- `bisect_right(nums, 2)`：第一个大于 2 的位置，返回 3。

于是 `[1, 3)` 正好是所有 2，数量是 `3 - 1 = 2`。

```python
from bisect import bisect_left, bisect_right

nums = [1, 2, 2, 4]
left = bisect_left(nums, 2)
right = bisect_right(nums, 2)
assert (left, right) == (1, 3)
assert right - left == 2
assert bisect_left(nums, 3) == 3
assert bisect_left(nums, 9) == len(nums)
assert nums == [1, 2, 2, 4]
```

这些函数只查位置，不修改列表。找不到符合条件的元素时返回列表长度，因此插入点不保证目标存在；判断存在还要检查下标有效，并比较该位置的值。

这正对应开头的单调条件：“不小于 2”与“大于 2”各有一条从不成立到成立的分界线。相等值归在哪边不同，两条边界才夹出了全部 2。若条件忽真忽假，就不能直接这样排除一半。

边界查询 O(log n)，辅助空间 O(1)；真正往列表中插入，仍可能移动 O(n) 个元素。[bisect 文档](https://docs.python.org/3/library/bisect.html)说明了相等值归在哪侧的约定。

## 7. 单调栈：让未来元素解决按顺序等待的旧问题

有些问题在读到一个元素时还答不出来，例如“它右边第一个更大的数在哪里”。若每个位置都单独向后找，同一段未来会被反复扫描。

可以把提问方向反过来：先保存尚未得到答案的位置，新元素到来时，让它解决能解决的旧问题。**单调栈进一步把这些等待者按大小组织起来，使检查栈顶就能决定：继续解决下一项，还是所有剩余项都暂时解决不了。** 这样既不遗漏旧问题，也不必每次重查所有等待者。

普通栈只规定后进先出，单调栈还需要一个大小关系来说明“为什么只检查这一端”。求下一个更大值和求下一个更小值，所需顺序不同；严格更大与大于等于，对相等元素的处理也不同。若答案需要距离，应保存下标，而不只是数值。

下面的温度例子把旧日子视为等待者，把新一天视为可能的答案。需要理解的是等待顺序为什么有效，而不是记住一个弹栈的比较符号。

### 每日温度：谁最容易先等到答案

任务是返回每天需要再等几天，才有严格更高的温度，没有则为 0。

考虑 `[73, 71, 72, 74]`。第 0 天的 73 还在等；第 1 天出现 71，也只能继续等。第 2 天的 72 先能解决更近的 71，却不能解决 73。

因此让较新、较低的温度位于栈顶。栈里存下标，因为既要取出旧温度比较，也要计算相隔几天。栈底到栈顶的温度**不增**，即后一项可以更低，也可以相等。

新一天到来时：

1. 如果比栈顶那天更高，就给那天填答案并弹出。
2. 继续检查新的栈顶，今天可能同时解决几天的等待。
3. 如果不比栈顶高，就停止。下面的温度更高或相等，今天更不可能解决它们。
4. 把今天压栈，等待未来。

| 今天 | 今天解决的等待 | 处理后栈内的“下标:温度” |
|---|---|---|
| 0:73 | 无 | `[0:73]` |
| 1:71 | 无 | `[0:73, 1:71]` |
| 2:72 | 下标 1 等了 1 天 | `[0:73, 2:72]` |
| 3:74 | 下标 2 等了 1 天，下标 0 等了 3 天 | `[3:74]` |

表中从左到右为栈底到栈顶，不是一个新的 Python 数据格式。

```python
def daily_temperatures(temperatures):
    answer = [0] * len(temperatures)
    waiting = []
    for today, temperature in enumerate(temperatures):
        while waiting and temperatures[waiting[-1]] < temperature:
            previous = waiting.pop()
            answer[previous] = today - previous
        waiting.append(today)
    return answer

assert daily_temperatures([73, 71, 72, 74]) == [3, 1, 1, 0]
assert daily_temperatures([73, 74, 75, 71, 69, 72, 76, 73]) == [1, 1, 4, 2, 1, 1, 0, 0]
assert daily_temperatures([30, 30]) == [0, 0]
assert daily_temperatures([]) == []
```

### 为什么弹出时就是“第一个”更高温度

一个旧位置留在栈里，表示此前还没遇到能解决它的温度。只要某天真的更高，挡在它上面的温度都不高于它，会先被弹掉，它自己也会在那天被处理，不会因为埋在栈里就错失答案。

所以今天将它弹出时，中间没有漏过更早的更高温度。今天压栈前，所有比今天低的栈顶又已经移走，剩下的栈顶不低于今天，温度不增的关系得以保持。扫描结束后还留在栈中的日子，没有未来答案，保留 0。

> ⚠️ 相同温度不算更高，不能用 `<=` 弹出。单调栈该递增还是递减、允许不允许相等，都由任务要求决定，不能只背某个比较符号。

每个下标入栈一次、出栈至多一次，时间 O(n)。等待栈最坏 O(n)，返回数组另占 O(n)。单日可能弹出很多位置，但这些位置以后不会再弹一次。

单调栈适合这类“等待未来比较结果”的问题，关键条件是能建立一种顺序：栈顶不能被解决时，下面的也不必检查。只看到“下一个”三个字，还不足以确定它适用。

## 8. 递归：把同一个任务交给更小的输入

文件夹里还有文件夹，树的左右两部分也仍然是树。这类问题有一个重要关系：缩小后的对象，仍可以用解决原问题的同一套规则处理。

**递归的核心是：给函数定义一个完整任务，把其中规模更小的同类任务交给它自己，再用小任务的结果完成当前任务。** 每次调用都负责它收到的整个问题；“当前层只做本层工作”是实现上的分工，不能理解成这个函数只负责一个节点。

例如求树的层数，函数负责返回整棵子树的层数。左子树多高、右子树多高，可以分别交给同一个函数；当前层用两个结果取大再加一，就得到自己负责的整棵树的答案。这是问题的分解与组合，之后才需要关心程序怎样保存等待中的调用。

### 先想清任务关系，再追踪调用过程

写递归前，把三件事接起来：

1. **最小问题直接完成。** 空树层数是 0，不需要再拆。这是停止条件，也为后面各层提供最初的答案。
2. **子问题仍是同一个任务，而且确实更小。** 求树层数变成求左右子树层数；有限树的子树持续缩小，最终会到空树。只是调用自己，却没有向停止条件接近，并不能完成任务。
3. **当前层能够接上子任务的结果。** 左右层数已知后取大加一；如果是在求和，就把较小范围的和加上当前项。如何组合由原任务决定。

思考时不必把几十层一起展开。先暂且相信更小调用会兑现同一个任务承诺，检查自己这一层能否因此完成任务；再检查最小情况正确、规模确实缩小。这样从最小问题逐层往上，每一层的正确性都有来源，并不是让函数凭空“相信自己”。

递归既可以返回一个计算结果，也可以完成一个明确的修改。它是一种表达分解关系的方式，不自动意味着更快，也不自动意味着正在做回溯。下面先用求和观察调用怎样实现这份分工，再回到树上。

### 求和：把分解关系写成调用，子调用返回后再完成组合

约定 n 为非负整数，`sum_to(n)` 返回 `1 + 2 + ... + n`。对 n = 3，当前层可以把 `1 + 2` 交给 `sum_to(2)`，等它返回后自己再加 3。

```python
def sum_to(n):
    if n == 0:
        return 0
    smaller = sum_to(n - 1)
    return smaller + n

assert sum_to(3) == 6
assert sum_to(0) == 0
```

不要一口气把所有层混在一起。先看调用怎样向下展开：

| 这次调用 | 它暂停在哪件事上 |
|---|---|
| `sum_to(3)` | 等 `sum_to(2)`，回来后加自己的 3 |
| `sum_to(2)` | 等 `sum_to(1)`，回来后加自己的 2 |
| `sum_to(1)` | 等 `sum_to(0)`，回来后加自己的 1 |
| `sum_to(0)` | 不再调用，直接交回 0 |

然后按相反顺序完成：`sum_to(1)` 收到 0，返回 1；`sum_to(2)` 收到 1，返回 3；最外层 `sum_to(3)` 收到 3，返回 6。最外层的 n 一直是 3，不会被子调用的 n = 2 改掉。

这些等待中的调用由**调用栈**保存，包括参数、局部变量和回来后继续的位置。最近暂停的调用先得到结果，与栈的后进先出一致。

> ⚠️ `return` 只结束它所在的那一次调用。`sum_to(0)` 返回，不等于整个求和已经结束，外面的三个调用还各自有加法要完成。

为什么对所有合法 n 都成立？0 的答案正确；假设更小的调用已经算出前 n - 1 项，加上 n 就是当前任务。参数又每次减一，最终一定到 0。这是递归的正确性与终止依据。

共 n + 1 次调用，每层常数工作，时间 O(n)，同时等待的栈深度 O(n)。循环求和也能做到 O(n) 时间且只用 O(1) 辅助空间，所以递归不是自动更快。这个例子用于理解调用过程，不是推荐用它代替所有循环。

> ⚠️ 负数不在输入约定内，一直减一不会到 0。即使是合法的大 n，层数太深也可能触发 `RecursionError`；深链、大网格常应改用显式栈，而不是一味提高递归限制。

### 树高：子树仍是树，两个子结果怎样组成整棵树的答案

任务是求二叉树最大层数，空树为 0。约定 `max_depth(node)` 返回**以 node 为根的整棵子树**的层数。

根的左右子树也是树，分别调用同一个函数就能取得它们的层数。当前根只需选较深的一侧，再加自己这一层。它不用重新遍历子树内部。

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def max_depth(root):
    if root is None:
        return 0
    left_depth = max_depth(root.left)
    right_depth = max_depth(root.right)
    return 1 + max(left_depth, right_depth)

root = TreeNode(2, TreeNode(1), TreeNode(3))
assert max_depth(root) == 2
assert max_depth(None) == 0
```

在这棵三节点树中，执行先后是：

1. 根 2 调左孩子 1。孩子 1 的两棵空树都返回 0，所以孩子 1 返回 1。
2. 根 2 收到左边的 1，保存到自己的 left_depth，再调右孩子 3。
3. 孩子 3 同样返回 1。根的 right_depth 得到 1。
4. 根完成自己的 `1 + max(1, 1)`，返回 2。

每层的任务相同：两个子调用若正确，取大加一就正确；空树直接正确。输入必须是有限树，不能有环。

每个节点只处理一次，两个子调用处理的是不同子树，时间 O(n)，不是“调用两次所以指数级”。同时留在栈里的是一条向下的路径，辅助空间 O(h)，h 为树高；平衡树约 O(log n)，退化成链时 O(n)。

### 返回一个值，与完成一次修改，都是函数承诺

递归不一定要返回数字。下面两种任务仍遵守“子调用做子树，当前层做本层”的分工：

- 中序遍历：先把左子树追加进结果，再追加根，最后追加右子树。
- 翻转二叉树：把原右子树翻转后接到左侧，原左子树翻转后接到右侧。

<details><summary>展开查看中序遍历与原地翻转的完整实现</summary>

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(root):
    answer = []
    def walk(node):
        if node is None:
            return
        walk(node.left)
        answer.append(node.val)
        walk(node.right)
    walk(root)
    return answer

def invert_tree(root):
    if root is None:
        return None
    old_left = root.left
    root.left = invert_tree(root.right)
    root.right = invert_tree(old_left)
    return root

root = TreeNode(2, TreeNode(1), TreeNode(3))
assert inorder(root) == [1, 2, 3]
assert invert_tree(root) is root
assert inorder(root) == [3, 2, 1]
```

`walk(node)` 的承诺是把当前子树完整追加到同一个 answer。左调用返回时，左子树已经追加完，当前层才追加根。因此样例结果先是 `[1]`，再是 `[1, 2]`，最后是 `[1, 2, 3]`。`walk` 不返回序列，最外面的 `inorder` 才返回 answer。

`invert_tree(node)` 的承诺是翻转当前子树并返回它的根。根 2 先把翻好的原右子树 3 接到左边，再把翻好的原左子树 1 接到右边。`old_left` 保留原左引用，否则替换 root.left 后就找不到它了。

两种操作时间均为 O(n)，辅助调用栈 O(h)。中序的返回结果另占 O(n)，翻转则修改原树，不创建副本。

</details>

> ⚠️ 调用现场独立，不代表引用的列表、树也各自复制。子调用修改同一个对象，返回后修改仍然保留。后面的回溯正需要主动恢复某些修改。

求和、树高、遍历与翻转的任务不同，共同关系却没变：较小调用完成同类任务，当前层接上自己的那部分。调用栈解释程序如何执行这份分工，分解与组合才是设计它的出发点。

<a id="graph-search"></a>
## 9. DFS 与 BFS：决定下一步探索哪一部分

从一个房间出发，沿门能到达哪些房间？我们需要知道当前位置能去哪里，还要记住有哪些地方已经发现、但没有继续探索。这把搜索组织成了三个部分：状态、状态之间的连接、尚待探索的状态。

图里的状态可以是节点，网格里可以是坐标，树里可以是子树的根。**DFS 与 BFS 的核心区别，是怎样安排尚待探索的部分：**

- **DFS（深度优先搜索）**优先沿当前分支继续深入；这个分支走完，再回来探索其他分支。递归栈或显式栈保留尚未完成的分支。
- **BFS（广度优先搜索）**先展开距起点边数较少的一层，再展开下一层。队列把较早发现的待处理状态排在前面，因此能保住这种层次顺序。

如果只问连通范围，两种顺序都能发现所有可达位置；如果问无权图的最少边数，BFS 的逐层顺序就有额外价值。DFS 优先找到的一条路，未必是最短的。选哪一种，取决于探索顺序对任务有什么帮助。

重访规则是另一件必须单独想清的事。图中可能有环，也可能多条路通向同一位置。若到达方式不影响后续任务，发现一次后就可以标记，不再重复展开；若携带的钥匙、剩余次数会改变后续选择，只有位置相同就不算同一个搜索状态。先定义什么算“同一种情况”，才能判断哪些访问可以省略。

### DFS 统计岛屿：先把这座岛全部标记完

输入为矩形网格，`"1"` 是陆地，`"0"` 是水，上下左右相邻才算连接。返回岛屿数，空网格返回 0，本例允许修改输入。

外层逐格找陆地。找到一块未访问陆地，就发现了一座新岛；随后沿邻居走，把整座岛标记完，外层才继续。这样同一座岛的其他格子就不会再被计数。

内部 `visit(r, c)` 的任务是：从这块陆地出发，标记所有可到达的尚未标记陆地。用改成 `"0"` 表示已发现，不必另外保存访问集合。

```python
def num_islands(grid):
    if not grid or not grid[0]:
        return 0
    rows, cols = len(grid), len(grid[0])

    def visit(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return
        if grid[r][c] != "1":
            return
        grid[r][c] = "0"
        visit(r + 1, c)
        visit(r - 1, c)
        visit(r, c + 1)
        visit(r, c - 1)

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1":
                count += 1
                visit(r, c)
    return count

grid = [["1", "1", "0"], ["0", "0", "1"]]
assert num_islands(grid) == 2
assert grid == [["0", "0", "0"], ["0", "0", "0"]]
assert num_islands([]) == 0
```

对样例，第一次发现 `(0, 0)`，count 变为 1：

1. visit 先把 `(0, 0)` 标为 0，再尝试邻居。
2. 水或越界会直接返回。走到右邻居 `(0, 1)`，先标记它，再继续它的四个方向。
3. 从 `(0, 1)` 回看 `(0, 0)`，那里已是 0，直接返回，不会来回调用。
4. 这次搜索全部返回后，左上方两块陆地都已标记。外层经过 `(0, 1)` 不再加一，到 `(1, 2)` 才发现第二座岛。

每个首次发现的陆地都会尝试全部四邻居，所以沿陆地路径能到达的格子都会被找到。又因为先标记再深入，每块陆地只展开一次。每次外层增加 count，都对应一座此前没处理过的完整岛。

> ⚠️ 必须先查边界再读网格，先标记再访问邻居。函数会修改原网格；要保留输入，可以用独立访问标记。原地标记也不意味着不占额外空间，递归栈仍然存在。

设网格有 R 行、C 列，外层检查 RC 格，每块陆地至多检查四个方向，时间 O(RC)。最坏搜索路径很长，辅助栈 O(RC)。显式栈能避开 Python 递归深度限制，但同样要存待探索位置。

### BFS：队列为什么产生一层一层的顺序

考虑图中起点 1 连接 2、3，2 再连接 4。先发现 2、3，之后才处理它们的邻居，便会先走完一步可达的位置，再走两步可达的位置。

这里区分三个记录：

- `queue`：已发现但尚未展开邻居的位置。
- `visited`：所有已发现位置，包括还在排队的。
- `order`：已经出队处理的位置顺序。

| 刚出队的位置 | 新发现的位置 | 此时队列 |
|---|---|---|
| 1 | 2、3 | `[2, 3]` |
| 2 | 4，1 已发现 | `[3, 4]` |
| 3 | 无，1 已发现 | `[4]` |
| 4 | 无，2 已发现 | 空 |

4 是两步可达，即使它已经入队，也排在一步可达的 3 后面。这就是队列发挥作用的地方。

```python
from collections import deque

def bfs(graph, start):
    queue = deque([start])
    visited = {start}
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph.get(node, []):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

graph = {1: [2, 3], 2: [1, 4], 3: [1], 4: [2]}
assert bfs(graph, 1) == [1, 2, 3, 4]
assert bfs({}, 9) == [9]
```

本函数返回可达部分的访问顺序，同层按照邻接表顺序发现，不返回距离。没有邻接表的节点按无邻居处理，所以空字典中从 9 出发，也会访问起点自身一次。

为什么 BFS 能求无权图的最少边数？处理第 d 层时，新发现位置排到下一层，尚未处理的第 d 层仍在它前面。更浅的层都已经展开，如果存在更短的路，这个位置本应早已被发现。因此首次发现的层数就是最少边数。若需要距离，可以在发现邻居时记录“当前距离加一”。

> ⚠️ 入队就要标记 visited。等到出队才标记，可能让同一位置被几个邻居重复加入。边的成本不同，则层数不等于总代价，不能直接把这段 BFS 当作带权最短路算法。

每个可达节点进出队一次，每条邻接关系检查一次。可达部分有 V 个节点、E 条边时，按集合平均成本计算，时间 O(V + E)，辅助空间 O(V)，返回顺序另占 O(V)。`deque.popleft()` 不需要移动后面所有元素。

如果有多个同时开始传播的起点，例如“腐烂的橘子”，就把它们全部先放进队列，作为第 0 层。这叫多源 BFS。处理一整层代表过去一分钟，新感染格入队就标记，最终剩余新鲜格表示不可到达。改变的是初始起点数量，一层层扩展的理由没有改变；网格的时间与最坏辅助空间仍为 O(RC)。

递归是一种表达任务的方式，DFS/BFS 是探索顺序。岛屿也能用 BFS，DFS 也能用显式栈，不能把它们当作同义词。

<a id="backtracking"></a>
## 10. 回溯：沿选择树探索，返回后再试另一条路

生成排列、组合等方案时，搜索的位置不再只是地图上的一个点，而是“已经作出哪些选择”。选好第一项以后还要选第二项，各种选择继续分叉，形成一棵选择树。根是尚未选择，边是作出一次选择，完整方案位于走完选择的地方。

**回溯把部分答案作为搜索状态：尝试一个合法选择，探索所有后续，再回到作出选择之前，尝试另一种可能。** 这样便把“列出所有方案”拆成“分别列出每一种开头所能补成的方案”。只要每层考虑所有合法选择，每个完整方案就能沿自己的选择路径被找到。

通常用 DFS 顺序走这棵树，用递归表达逐层选择。三者并不相同：DFS 决定先走哪条分支，递归表达子任务，回溯要求回到原来的选择起点。若分支共用一份可变路径，就必须主动撤销追加、占用等修改；函数返回不会自动恢复共享对象。也可以让每个分支持有独立副本，但复制会增加代价。

如果部分答案已经不可能补成合法答案，就无需深入，这叫**剪枝**。剪枝是在有依据地减少选择树，而不是因为当前看起来不够好就丢掉一个分支。下面用全排列看清选择、深入、恢复怎样衔接。

### 全排列：一种开头下面，包含哪些完整方案

输入数字互不重复，生成全部排列；空输入返回 `[[]]`，表示有一种空排列。比如 `[1, 2]` 返回 `[[1, 2], [2, 1]]`。

先固定第一位：选择 1 后，只需排列剩余的 2；选择 2 后，只需排列剩余的 1。更长输入也是同样的关系：选好一位，把“填完剩余位置”交给下一层。不同第一位的结果不会重合，把所有第一位的分支都走完，就得到全部排列。为了让下一条分支真正从原来的前缀出发，上一条分支的选择必须撤销。实现中分别记录：

- `path` 是当前已经选好的前缀，会不断追加与撤销。
- `used[i]` 表示原下标 i 是否在当前 path 中，阻止同一位置在这条路径里重复使用。
- `answer` 保存已经完成的排列，不应随 path 后续修改而变化。

给 `visit()` 的承诺是：列出当前前缀能补成的全部排列，返回时把 path 与 used 恢复成进入前的样子。它可以向 answer 添加结果，但不能给下一条分支留下脏的工作路径。

```python
def permutations(nums):
    answer = []
    path = []
    used = [False] * len(nums)

    def visit():
        if len(path) == len(nums):
            answer.append(path.copy())
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            visit()
            path.pop()
            used[i] = False

    visit()
    return answer

assert permutations([1, 2]) == [[1, 2], [2, 1]]
assert permutations([]) == [[]]
```

### 返回并不自动撤销选择

跟踪第一条分支及它返回后的动作：

| 动作 | path | 哪些位置标为 used |
|---|---|---|
| 开始 | `[]` | 无 |
| 选择 1 | `[1]` | 下标 0 |
| 选择 2 | `[1, 2]` | 下标 0、1 |
| 保存副本，最深层返回 | `[1, 2]` | 仍是 0、1 |
| 调用者撤销 2 | `[1]` | 下标 0 |
| 再上一层撤销 1 | `[]` | 无 |
| 开始选择 2 的分支 | `[2]` | 下标 1 |

最深层 return 以后，path 还在。是调用者继续执行 `path.pop()` 和 `used[i] = False`，才恢复了现场。下一分支因此可以独立得到 `[2, 1]`。

> ⚠️ `answer.append(path)` 保存的是同一个可变列表的引用。撤销操作会连已保存的结果一起改掉，要保存 `path.copy()`。复制答案和撤销工作路径解决的是两件不同的事。

每层尝试所有未用位置，每个合法排列都对应一条完整路径，因此不漏。数字互不重复时，不同路径对应不同排列，因此不重。每深入一层 path 增长一项，到 n 项就返回，搜索能够结束。

第一位有 n 种选择，第二位有 n - 1 种，依次相乘，得到 n! 个排列。这里 n! 读作“n 的阶乘”，表示 n×(n-1)×…×1，空输入对应 0! = 1。每份排列长 n，仅保存它们就需要 O(n×n!) 的时间与输出空间。本实现总时间也是 O(n×n!)；不计结果，path、used、调用栈合计 O(n)。这类枚举任务不能忽略答案本身可能非常大。

图搜索的 visited 通常是全局发现记录，访问过就一直保留。这里的 used 只属于当前路径，其他分支仍然可以使用同一个数字，所以必须撤销。若题目允许重复数字或重复选择，应重新定义合法选择与去重规则，不能原样使用本例。

<a id="top-k"></a>
## 11. Top K：围绕入选门槛保留候选

“找前 k 大”“求第 k 大”是一类任务，不是一种固定算法。全部排序能解决它，但如果只需要少量入选者，也可以随着数据到来维护一份大小至多为 k 的名单，不再保存所有落选者。

**核心是把入选者中最弱的一项作为门槛。** 名单未满时先收下；名单满后，新值更强就替换最弱者，否则已有 k 个候选不比它差，它无法改善前 k 大。未来只会来更多竞争者，门槛不会降低，已经落选的值也就不必重新考虑。

这解释了为什么“求最大的 k 个”可以用最小堆：要反复查看和替换的是入选名单的末位，不是第一名。最小堆让这个门槛始终在堆顶，内部其余候选不必完全排好序。若要求有序名单，最后再排列入选者；若只要第 k 大，扫描完成后的门槛就是答案。

### 先看一份大小固定的名单

假设只保留最大的 3 个，目前成员是 2、3、4：

- 新来 1：名单中已有 3 个数比它大，忽略。
- 新来 5：换掉最小的 2，成员变成 3、4、5。
- 再来 3：换掉旧 3 也不会改变数值结果，可以忽略。

这里列出的是入选成员，不是在展示堆内部数组的顺序。

任务如果是“求第 k 大”，扫描完成后，前 k 大中的最小值就是答案。约定 `1 <= k <= len(nums)`，重复值按次数计算，所以 `[3, 3, 2]` 的第 2 大是 3。

```python
import heapq

def kth_largest(nums, k):
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return heap[0]

assert kth_largest([3, 2, 1, 5, 6, 4], 2) == 5
assert kth_largest([3, 3, 2], 2) == 3
assert kth_largest([7], 1) == 7
```

`heapreplace(heap, x)` 取走原堆顶、放入 x 并调整堆，大小不变。它不会替我们判断 x 值不值得入选，因此本题先比较，再调用。

### 每次更新怎样维持前 k 大

处理 t 个数后，堆始终保留其中最大的 `min(k, t)` 个。未满时全部保留；满后，新值更大就替换末位，否则继续保留旧名单，这两种情况都维持这个事实。

每个数至少做一次常数比较，入选时调整堆的成本至多 O(log(k + 1))。总时间 O(n log(k + 1))，辅助空间 O(k)；用 k + 1 的写法也涵盖 k = 1 时的 O(n) 扫描。全排序为 O(n log n)，k 较小或数据持续到来时，保留少量候选更合适。

> ⚠️ k = 0、空输入不符合本例约定。若要求第 k 个不同的值，重复值规则也必须改变。

这种思路的前提是能明确比较优劣，并证明门槛之下的候选不会再影响答案。题目只出现“Top K”，不代表一定要选堆。

<a id="greedy"></a>
## 12. 贪心：把一个安全的局部选择直接固定下来

每一步有多种选择时，全部尝试可能很贵。贪心试图找到一种选择规则：当前就选定其中一种，不再回头尝试其他选择，最后仍能得到整体最优解。

**核心不是“挑眼前看起来最好的”，而是局部选择作出后，仍至少保留一个整体最优方案。** 贪心省掉的是对其他选择的探索，因此必须说明为什么舍弃它们不会损失最优结果。

常见的理由有两种。可以让两个选择面对相同后续，证明 A 始终不比 B 差，于是只保留 A；也可以从一个最优方案出发，把其中一步换成自己的选择，证明结果不会变差。关键都在于后续影响，不能只比较眼前收益。

下面的单次股票买卖用第一种理由：较低的历史买入价，对同一个未来卖出日始终更有利。这里安全固定的是“以后保留哪一个历史买入机会”，并不是见到低价就能提前决定最终买卖日期。

### 股票买卖：更便宜的旧买入价为什么可以替代其他旧价格

任务是最多交易一次，先买后卖，不交易利润为 0，允许空输入。`[7, 1, 5, 3, 6, 4]` 的最大利润是 5。

先固定一个卖出日。此前有 7 和 1 两个买入价，面对同一个卖出价 6，买入价 1 的利润总是更高。换成任何其他未来卖出价，这个比较仍成立；两个买入日都早于那个卖出日，较低买入价不会破坏时间要求。

因此，**为了未来卖出，只需留下此前最低买入价**。但它不能代替已经实现过的好利润：新低价出现时，过去的最佳交易仍可能是最终答案。所以保存两项信息：

- `lowest`：今天以前的最低价格，用于考虑今天卖出。
- `best`：此前已考察过的卖出日中，最大可得利润，至少为 0。

| 今天价格 | 今天之前的 lowest | 今天卖出最多获利 | 更新后 best |
|---:|---:|---:|---:|
| 1 | 7 | -6 | 0 |
| 5 | 1 | 4 | 4 |
| 3 | 1 | 2 | 4 |
| 6 | 1 | 5 | 5 |
| 4 | 1 | 3 | 5 |

第一天只建立历史，从第二天开始考虑卖出。每轮先计算利润，再把今天纳入最低价，留给下一轮。

```python
def max_profit(prices):
    if not prices:
        return 0
    lowest = prices[0]
    best = 0
    for i in range(1, len(prices)):
        price = prices[i]
        best = max(best, price - lowest)
        lowest = min(lowest, price)
    return best

assert max_profit([7, 1, 5, 3, 6, 4]) == 5
assert max_profit([7, 6, 4, 3, 1]) == 0
assert max_profit([7]) == 0
assert max_profit([]) == 0
```

每笔合法交易都有一个卖出日。对于每个卖出日，我们都保留了不差于其他历史买入选择的最低价，再比较所有卖出日的最佳利润，因此得到全局最优。价格一直下降、只有一天或为空时，不交易即可。

直接枚举所有日期对最坏 O(n²)，这里每个价格只处理一次，时间 O(n)，辅助空间 O(1)。安全舍弃的是较贵的历史买入机会，不是看到低价就提前承诺最终在哪天交易。

### 为什么“眼前最好”还不够

面值是 1、3、4，要凑出 6 且硬币最少。若每次拿不超过剩余金额的最大面值，会拿 `4 + 1 + 1`，共 3 枚；但 `3 + 3` 只要 2 枚。

这里的局部选择 4 改变了剩余问题，无法证明它面对后续总不比 3 差。这个反例就足以推翻“总拿最大面值”的规则。

> ⚠️ 股票例子的依据也有条件：只交易一次。改成多次交易、有手续费或其他限制，要重新比较后续影响，不能照搬“只记最低价”。

尝试贪心时，应先找反例，再给出安全性的理由。若不能直接舍弃选择，而不同选择又会遇到相同子问题，就可以保存各子问题的答案，再比较或汇总，这引出动态规划。

## 13. 动态规划：把明确的子问题变成可复用答案

把大问题拆成小问题，并不保证计算量就小了：不同分支可能又遇到同一个小问题。如果每次从头求解，就会反复做完全相同的工作。

**动态规划的核心是定义含义明确的子问题，保存它们的答案，沿依赖关系复用。** 一个子问题只计算一次，后面需要它时直接读取。递归负责把任务拆开，动态规划进一步识别其中哪些答案可以共用；既可以递归时记忆答案，也可以按依赖顺序先算小问题。

这里的**状态**首先是一句完整的子问题定义，不是数组下标。例如“到第 i 阶有多少种方法”，或“在某些限制下处理前 i 项的最低代价”。定义不同，保存的答案、合并方式和最终要取的位置都会不同。

判断两个情况能否归为同一状态，要看省略的历史会不会影响答案。若位置相同，但以前做过的选择会改变后续合法动作，只记位置就不够。状态需要保留这些相关条件；无关的历史则可以省掉。这是 DP 能压缩大量路径的前提，而不只是为了少开一个数组。

有了状态，再问一个较大的答案怎样从较小答案得到。计数要说明分类不重不漏；求最优值要说明合法方案都纳入了比较。保存结果只能消除重复计算，不能修复一个漏掉情况的递推关系。下面用爬楼梯把子问题、依赖与复用连起来。

### 先从最后一步拆出子问题

任务是每次走 1 阶或 2 阶，到第 n 阶有多少种走法，n 为正整数。只求数量，不要求列出所有路径。

考虑第 4 阶，任何走法的最后一步只有两种：

- 最后走 1 阶：之前必须到第 3 阶。到第 3 阶的每种走法接一个 1，都得到一种走法。
- 最后走 2 阶：之前必须到第 2 阶。到第 2 阶的每种走法接一个 2，都得到一种走法。

到第 3 阶有 `1+1+1、1+2、2+1` 三种，接一个 1，得到三种到第 4 阶的走法。到第 2 阶有 `1+1、2` 两种，接一个 2，又得到两种。

两类的最后一步不同，不会重复；又没有第三种最后一步，不会遗漏。因此到第 4 阶共有 `3 + 2 = 5` 种。

将这段推理写成一般形式：定义 `dp[i]` 是到第 i 阶的方法数，那么 i 至少为 3 时，`dp[i] = dp[i - 1] + dp[i - 2]`。这个式子来自完整的分类，不是看到台阶就背出来的公式。

### 为什么只存一个数量，能代替那么多走法

到第 3 阶的三条不同路径，下一步允许的选择完全相同。我们又只求数量，不求路径内容，所以知道“有三条”就足够把它们一起接上最后一步，无须保留每条路径的细节。

若增加“不能连续两次走 2 阶”，到第 3 阶的 `1+2` 与 `2+1` 就不能再不加区分：前者下一跳不能选 2，后者却可以。此时除了阶数，还要记录上一跳是否为 2。这正是开头所说的：省略的历史一旦影响后续，原状态就不够用了。

### 递归重复了什么，表格怎样省掉它

按同一个关系直接递归，会出现这些依赖：

```text
求第 5 阶的方法数 → 要第 4 阶、第 3 阶
求第 4 阶的方法数 → 又要第 3 阶、第 2 阶
```

两次问“第 3 阶有几种走法”，输入、规则、答案都相同，第二次重算没有新信息。继续展开还会有更多重复，朴素递归的调用量会指数级增长。

保存答案有两种常见安排：

- **记忆化**：仍然递归，遇到一个子问题先查是否算过。算过直接返回，没算过才计算并保存。
- **从小到大填表**：先算好依赖项，后面的子问题直接读取。爬楼梯只依赖更低的阶数，适合这种顺序。

下面采用填表。第 1 阶有 1 种，第 2 阶有 2 种，先放好它们：

| 接下来计算的子问题 | 读取哪两个已知答案 | 写入什么 |
|---|---|---|
| 第 3 阶 | 第 2 阶为 2，第 1 阶为 1 | `dp[3] = 3` |
| 第 4 阶 | 第 3 阶为 3，第 2 阶为 2 | `dp[4] = 5` |
| 第 5 阶 | 第 4 阶为 5，第 3 阶为 3 | `dp[5] = 8` |

```python
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

assert climb_stairs(1) == 1
assert climb_stairs(2) == 2
assert climb_stairs(5) == 8
```

本实现从第 1、2 阶起算，dp[0] 只是未使用的位置。n 必须是正整数，不能拿函数对其他输入的偶然返回值当作题意。

每次计算 i 时，所需的两个较小答案都已经正确。按不重不漏的最后一步分类相加，就得到正确的 dp[i]。最后取 dp[n]，正好对应原任务。

共有 n 个有效状态，每个只读取两个旧答案并做一次加法，时间 O(n)，表格空间 O(n)。分析其他 DP 也要数状态数量和每个状态的计算工作，而不是只看有没有递推式。

### 先知道依赖，再决定能删掉哪些存储

算第 5 阶只需第 3、4 阶；算完后，第 3 阶也不会再用。于是可以只保留相邻两个答案，不必永久保存整张表。

令 `previous` 是较早的一阶，`current` 是较近的一阶。准备算第 5 阶时，它们分别为 3、5；算出 8 后，把保留的两项换成 5、8。

```python
def climb_stairs_compact(n):
    if n <= 2:
        return n
    previous, current = 1, 2
    for i in range(3, n + 1):
        previous, current = current, previous + current
    return current

assert climb_stairs_compact(1) == 1
assert climb_stairs_compact(2) == 2
assert climb_stairs_compact(5) == 8
```

在算第 i 阶之前，两个变量分别代表 dp[i - 2]、dp[i - 1]；更新后代表 dp[i - 1]、dp[i]。子问题的含义没变，只是存储位置不再固定。

> ⚠️ 不能先写 `previous = current` 再计算 `previous + current`，那会读到两个相同的新值。空间压缩只允许删掉后面不会再读的信息，不能把所有 DP 都套成两个变量。

时间仍为 O(n)，按保存的状态个数计，辅助空间从 O(n) 降为 O(1)。若讨论极大 n 的真实位运算成本，Python 整数位数会增长，加法与单个计数的存储就不能永远视为常数。

换成求最低代价或最大收益时，子问题中存的会是最优值，合并时可能取最小或最大；换成输出全部走法时，一个数量又不再够用。可迁移的是“定义子问题、找出依赖、保存并复用”的思路，不是爬楼梯这一条递推式。

## 14. 本章小结：先看关系，再认方法名字

本章的算法并不是互斥的盒子。一个题目可以同时用几种思想，选择依据也不只是题目表面的关键词。

**减少重查时，先分清要保存什么。** 哈希保存以后要查的信息；窗口保存当前区间的内容或统计；前缀和保存到边界为止的累计值。和为 K 的子数组先用前缀和改写关系，再用哈希查旧边界。

**减少候选时，先说明为什么能舍弃。** 双指针移动必须有完成或排除的依据，二分靠有序或单调关系排除整段。单调栈弹出已经得到答案的位置，Top K 丢掉无法提高名单的候选，贪心还需要证明一个选择能保住全局最优。

**拆分任务时，分清调用、顺序与答案复用。** 递归规定每次调用怎样完成较小的同类任务；DFS/BFS 规定先探索哪部分；回溯负责选择后恢复工作状态；DP 保存相同子问题的答案。它们可以一起出现，但各自解决的问题不同。

回到一道新题，直接做法能帮助你找出浪费在哪里。为关键变量写一句准确含义，再说明更新、终止与不漏解的理由，最后数实际操作和存储。这比只记“此题属于某个模板”更能应对条件变化。

## 15. 面试怎么答

**问：你怎样从暴力解想到优化？**

> 🎯 我先说明直接做法在反复做什么。例如两数之和对每个数重新扫描旧元素，其实只需查补数是否出现以及下标，所以用值到下标的字典。查询时字典只放此前位置，先查后存就不会复用当前元素。这样每个数平均做常数次操作，时间从平方降到线性，代价是线性额外空间。

**问：怎样说明一种做法是对的，而不只是样例恰好通过？**

> 🎯 我会说清状态代表什么，以及每一步为什么保持这个含义。例如无重复窗口加入新字符前本来合法，只需从左边删到旧重复字符离开。包含这次重复的更长窗口都不合法，继续右扩也消不掉重复，所以左边界不必回退。对每个右端都保留最长合法窗口，再取最大值，就没有遗漏最优答案。测试则用于核对实现和边界。

**问：递归、回溯和动态规划是什么关系？**

> 🎯 递归让函数调用更小的同类任务，返回后当前层继续。回溯探索不同选择，常借助递归，但还要撤销共享工作路径的修改。动态规划识别重复子问题并保存答案，可以记忆化递归，也可以按依赖填表。不能只凭代码里是否调用自己来判断它属于哪一种。

## 16. ⚠️ 容易混淆的地方

- **状态正确，不等于更新顺序随意。** “只存旧历史”要求先查后存；“只保存当前窗口”要求出窗时同步删除；“只属于当前路径”要求分支结束后撤销。
- **一个方法的名字不替你证明条件。** 连续区间不一定适合右扩左缩，存在最大值不一定能贪心，二分需要可以整段排除的关系。
- **同样使用两个下标，职责可能完全不同。** 回文对比两端，移动零分开读写，窗口维护整段。必须先解释区域和移动条件。
- **共享对象不会随函数返回恢复。** 调用的局部变量独立，不代表树和列表有副本。修改、复制与撤销需要分别考虑。
- **时间看总工作，空间看同时保留的内容。** 窗口与单调栈的内层操作会被整体次数限制；递归要算调用栈；排列要算输出大小；切片也有复制成本。
- **原例子正确，不代表新限制自动成立。** 相等是否算更大、边是否带权、选择是否可重复、过去的选择是否影响未来，都可能改变状态或排除依据。

8. BFS 的 visited 为什么不删除，而全排列的 used 为什么必须撤销？保存 path 时还需要解决什么问题？

10. 爬楼梯增加“不能连续两次走 2 阶”，只保存阶数为什么不够？为什么不能在定义状态之前就决定只用两个变量？

3. 第一次只删掉 a，旧 b 仍在，加入新 b 仍然重复。删到旧 b 离开就保留了以当前右端结尾的最长合法窗口。更左的窗口已包含重复，再右扩不会消除重复，不必回头。
