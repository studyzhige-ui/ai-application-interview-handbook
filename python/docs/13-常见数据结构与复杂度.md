# 13. 常见数据结构与复杂度

Python 面试里经常把语言基础和数据结构一起问。这里不追求算法岗深度，而是让你能把“Python 容器为什么这样选”和基础数据结构、复杂度联系起来。

---

## 1. 为什么要看复杂度

复杂度不是精确运行时间，而是描述输入规模增大时资源消耗的增长趋势。

| 复杂度 | 直观理解 | 例子 |
|---|---|---|
| O(1) | 基本不随 n 增长 | 数组按索引访问 |
| O(log n) | 增长很慢 | 二分查找 |
| O(n) | 线性增长 | 遍历列表 |
| O(n log n) | 常见高效排序级别 | 比较排序 |
| O(n²) | 双重遍历常见 | 朴素两两比较 |

⚠️ 面试说某操作是 O(1) 时，常常指平均、均摊或典型情况，要结合具体实现。

---

## 2. Dynamic Array / Python list

Python `list` 从面试角度可以理解成动态数组。

特点：

- 按索引访问快；
- 尾部追加通常高效；
- 中间插删通常需要搬移后续元素；
- 元素本质上保存对象引用。

| 操作 | 典型复杂度 |
|---|---:|
| `lst[i]` | O(1) |
| `append()` | 均摊 O(1) |
| `pop()` 尾部 | O(1) |
| `insert(0, x)` | O(n) |
| `x in lst` | O(n) |

### 为什么 append 是均摊 O(1)

容量不足时偶尔需要扩容并搬移已有引用，这一次会更贵；但扩容不是每次发生，把多次 append 平均起来通常视为均摊 O(1)。

---

## 3. Linked List

```text
[value | next]
      ↓
[value | next]
      ↓
[value | next]
```

### Array vs Linked List

| 对比 | 数组 | 链表 |
|---|---|---|
| 随机访问 | O(1) | O(n) |
| 内存局部性 | 通常较好 | 通常较差 |
| 中间插删 | 可能搬移 | 已定位节点后改链接 |

⚠️ “链表删除一定 O(1)”是不完整的。只有已经拿到目标节点和所需前驱信息时，改链接本身才可能 O(1)；如果还要查找，整体仍可能 O(n)。

## 4. Stack

后进先出 LIFO。

```python
stack = []
stack.append(1)
stack.append(2)
print(stack.pop())  # 2
```

典型场景：

- DFS；
- 括号匹配；
- 表达式解析；
- Undo；
- 函数调用栈的抽象理解。

---

## 5. Queue / deque

先进先出 FIFO。

不要大量使用：

```python
lst.pop(0)
```

因为头部删除通常需要搬移元素。

更适合：

```python
from collections import deque

q = deque()
q.append(1)
q.append(2)
print(q.popleft())
```

`deque` 为两端插入删除设计。

## 6. Hash Table

Python 的 `dict` / `set` 与哈希表密切相关。

核心抽象：

```text
key
→ hash
→ candidate slot
→ equality check
→ target
```

平均查找、插入、删除通常接近 O(1)，但不是数学意义的最坏情况保证。

Hash、冲突、删除 tombstone/slot 等 Python dict 具体实现细节在第 02 章讲，这里关注数据结构层抽象。

## 7. Tree / BST

树用于表达层次结构。

```python
class TreeNode:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None
```

常见遍历：

```text
Preorder  Root → Left → Right
Inorder   Left → Root → Right
Postorder Left → Right → Root
Level     BFS
```

BST 在平衡较好时查找接近 O(log n)，极端退化成链表时可能 O(n)。

## 8. Heap

堆常用于 Priority Queue。

```python
import heapq

heap = []
heapq.heappush(heap, 3)
heapq.heappush(heap, 1)
heapq.heappush(heap, 2)
print(heapq.heappop(heap))  # 1
```

Python `heapq` 默认是最小堆。

| 操作 | 典型复杂度 |
|---|---:|
| `heap[0]` | O(1) |
| push | O(log n) |
| pop min | O(log n) |

---

## 9. Top K：为什么用大小为 K 的最小堆

例如：一亿个数找最大的 100 个。

不需要对所有数据排序。

```python
import heapq


def top_k(data, k):
    heap = []

    for x in data:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)

    return sorted(heap, reverse=True)
```

思路：

```text
heap size = K
heap top = 当前 Top K 中最小值
新值 <= heap top → 不可能进入 Top K
新值 > heap top → 替换最小候选
```

复杂度大致：

```text
Time  O(n log k)
Space O(k)
```

当 `k << n` 时比全量排序更适合。

## 10. BFS vs DFS

### DFS

通常用递归或显式栈。

```python
def dfs(node):
    if node is None:
        return
    visit(node)
    dfs(node.left)
    dfs(node.right)
```

### BFS

通常用队列。

```python
from collections import deque

q = deque([root])
while q:
    node = q.popleft()
    visit(node)
```

记忆：

```text
DFS → depth → stack
BFS → level → queue
```

## 12. 🎯 面试怎么回答

### 为什么 Top K 常用 Heap

> 当只需要最大的 K 个而 K 远小于 N 时，可以维护大小为 K 的最小堆。堆顶是当前候选中最小值，新元素只有大于堆顶才需要进入，单次调整 O(log K)，总体大约 O(N log K)，空间 O(K)，避免全量排序和保存全部候选。

### Array vs Linked List

> 动态数组随机访问 O(1)、缓存局部性好，但中间插删常需要搬移；链表随机访问 O(n)，但在已经定位节点时修改链接成本低。不能简单说“链表删除永远 O(1)”。

---

## 13. ⚠️ 易错点

- O(1) 不等于实际永远一样快；
- `list.append` 是均摊 O(1)；
- `list.pop(0)` 不是高效队列；
- 链表删除 O(1) 需要“已经定位”这个前提；
- Python `heapq` 默认最小堆；
- “stack / heap” 可能指数据结构，也可能指运行时内存语境；
- Hash Table 平均 O(1) 不是最坏情况绝对保证。

<details>
<summary>1. 为什么 `deque.popleft()` 比大量 `list.pop(0)` 更适合队列？</summary>

`list.pop(0)` 通常需要搬移后续元素，是 O(n)；`deque` 为两端操作设计，左端弹出通常 O(1)。

</details>

<details>
<summary>2. 一亿个数取最大 100 个为什么不需要全量排序？</summary>

维护大小为 100 的最小堆即可；每个新元素最多做 O(log 100) 的堆调整，空间也只需 O(100)。

</details>

<details>
<summary>3. “链表删除是 O(1)”什么时候成立？</summary>

当已经拿到待删除位置以及所需前驱/链接信息时，修改链接本身可以 O(1)；如果还需要遍历查找目标节点，整体仍可能 O(n)。

</details>
