# 08. 面向对象、Duck Typing、Protocol 与魔术方法

这一章不是为了背“封装、继承、多态、抽象”四个词，而是建立 Python 中**对象如何通过行为契约参与协作**的心智模型。

真人面经里 `PY-005` 会直接追 Duck Typing，因此这次整改把它从原来的一个段落提升成完整的 Protocol Thinking，而不是额外拆一个新文件。

---

## 1. 类和对象

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def introduce(self):
        return f"I am {self.name}"

p = Person("Tom", 22)
```

- **class**：描述一类对象的结构与行为；
- **instance/object**：具体创建出来的对象。

---

## 2. `self` 是什么

```python
p.introduce()
```

可以近似理解：

```python
Person.introduce(p)
```

`self` 是社区约定名，不是语法关键字。

---

## 3. 封装 / 继承 / 多态 / 抽象

### 封装

把状态和相关操作组织在一起，通过稳定接口暴露能力。

### 继承

子类复用父类行为。

```python
class Animal:
    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):
        return "wang"
```

### 多态

```python
def make_sound(animal):
    return animal.speak()
```

调用方关心：

```text
这个对象能不能完成 speak
```

而不是一定要写：

```text
if type == Dog
elif type == Cat
```

### 抽象

隐藏实现细节，只暴露调用者需要的契约。

---

## 4. Duck Typing 的核心不是“随便传对象”

经典说法：

> If it walks like a duck and quacks like a duck, treat it like a duck.

Python 更关注一个对象**是否提供调用方需要的行为**，而不是一定属于某个具体继承树。

```python
class FileWriter:
    def write(self, data: str):
        print("file", data)

class MemoryWriter:
    def write(self, data: str):
        print("memory", data)


def save(writer, data):
    writer.write(data)
```

`save()` 不要求 `writer` 必须继承同一个父类，只要求它有合适的 `write()`。

---

## 5. Duck Typing 的收益

### 低耦合

调用方依赖能力，而不是具体类。

### 可替换

测试时可以替换成 Fake / Mock 对象。

### 适合 Adapter

AI Application 里常见：

```text
OpenAIProvider
AnthropicProvider
LocalProvider
```

只要都提供：

```python
async def generate(...): ...
```

上层服务就可以统一调用。

---

## 6. Duck Typing 的 Failure

动态灵活也有代价。

```python
save(object(), "hello")
```

运行时才会发现：

```text
AttributeError: object has no attribute write
```

风险包括：

- 接口拼写错误；
- 参数签名不兼容；
- 返回值类型不一致；
- 错误直到运行时路径真正执行才暴露。

所以大型 Python 工程往往会结合：

```text
Duck Typing
+ Type Hint
+ Protocol / ABC
+ Test
```

而不是完全依赖“运行时试试看”。

---

## 7. `typing.Protocol`：显式表达结构化接口

```python
from typing import Protocol

class Writer(Protocol):
    def write(self, data: str) -> None:
        ...


def save(writer: Writer, data: str) -> None:
    writer.write(data)
```

`FileWriter` 不需要显式继承 `Writer`；只要结构满足协议，静态类型工具就可以把它视为兼容。

这可以理解为：

> **把 Duck Typing 的隐式行为要求写成可检查的结构化契约。**

---

## 8. Protocol vs Abstract Base Class

### Protocol

更偏结构化：

```text
只要你长得像这个接口，就可以兼容
```

### ABC

```python
from abc import ABC, abstractmethod

class WriterBase(ABC):
    @abstractmethod
    def write(self, data: str) -> None:
        ...
```

更偏显式继承和名义关系。

### 怎么选

如果你只需要：

```text
一个可替换行为契约
```

Protocol 很自然。

如果还需要：

- 共用实现；
- 显式继承层级；
- 运行时抽象基类语义；

ABC 可能更合适。

---

## 9. Liskov / 可替换性在 Python 项目里的直觉

一个对象“方法名一样”还不够。

例如：

```text
Provider A.generate → 返回 str
Provider B.generate → 返回 None
```

虽然都有 `generate()`，上层仍无法安全替换。

真正的接口契约还包括：

```text
参数语义
返回值语义
异常语义
副作用
生命周期
```

这也是为什么 AI Provider Adapter、Tool Adapter 不能只靠同名函数。

---

## 10. 实例属性与类属性

```python
class Person:
    species = "human"

    def __init__(self, name):
        self.name = name
```

### 易错点：可变类属性共享

```python
class Team:
    members = []
```

所有实例可能共享同一个列表。

如果每个实例独立：

```python
class Team:
    def __init__(self):
        self.members = []
```

---

## 11. 实例方法 / 类方法 / 静态方法

```python
class Demo:
    def instance_method(self):
        ...

    @classmethod
    def class_method(cls):
        ...

    @staticmethod
    def static_method(x):
        ...
```

| 类型 | 隐式参数 | 常见用途 |
|---|---|---|
| Instance Method | `self` | 操作实例状态 |
| Class Method | `cls` | 类状态、Alternative Constructor |
| Static Method | 无 | 与类语义相关的普通函数 |

---

## 12. `__new__` vs `__init__`

```text
__new__
→ 创建并返回实例

__init__
→ 初始化已经创建好的实例
```

普通业务类大多数只需要重写 `__init__`。

---

## 13. `super()` 和 MRO

`super()` 不是简单“直接调用父类”。

它按照 Method Resolution Order 继续查找实现。

```python
print(MyClass.mro())
```

在多继承场景尤其重要。

---

## 14. `_name` 和 `__name`

- `_name`：约定“内部使用”；
- `__name`：触发 Name Mangling，主要用于降低子类命名冲突。

不要说双下划线提供真正安全的私有访问控制。

---

## 15. `property`

```python
class Person:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError
        self._age = value
```

它让你在保留属性式 API 的同时增加校验/计算逻辑。

---

## 16. `__slots__`

```python
class Point:
    __slots__ = ("x", "y")
```

常见作用：

- 限制常规实例属性集合；
- 某些大量实例场景下降低属性存储开销。

⚠️ 继承会影响 `__dict__` 等行为，不要说“有 slots 就绝对没有 dict”。

---

## 17. 魔术方法 = Python Data Model Protocol

| 方法 | 接入的语法/协议 |
|---|---|
| `__len__` | `len(obj)` |
| `__iter__` | iteration |
| `__next__` | iterator next |
| `__getitem__` | indexing |
| `__call__` | callable object |
| `__enter__` / `__exit__` | context manager |
| `__eq__` | equality |
| `__repr__` | developer representation |

真正有价值的理解是：

> Python 很多“语法特性”其实是在调用对象协议。

这和 Duck Typing / Protocol Thinking 是同一条主线。

## 19. 🎯 面试怎么回答：Duck Typing

> Duck Typing 表示调用方更依赖对象是否提供需要的行为，而不是强制它继承某个具体类。它提高可替换性和低耦合，但纯动态方式会把很多接口错误推迟到运行时。大型 Python 工程通常会结合 Type Hint、`typing.Protocol`、ABC 和测试，把隐式行为契约变得更明确。Protocol 偏结构化兼容，ABC 更偏显式继承和共用抽象实现。

---

## 20. ⚠️ 易错点

- Duck Typing ≠ 不需要接口设计；
- 方法名一样 ≠ 完全可替换，还要看参数、返回值和错误语义；
- Protocol 主要帮助表达/检查结构契约，不等于 Runtime Schema Validation；
- ABC 和 Protocol 不是谁“更高级”，而是抽象方式不同；
- 双下划线不是安全访问控制；
- `super()` 按 MRO 工作，不等于“直接父类”。

收益是调用方依赖能力而不是具体类型，替换和扩展更容易；风险是接口不兼容可能推迟到运行时才暴露，因此大型工程常结合类型提示、Protocol/ABC 和测试。

Protocol 更偏结构化接口，只要对象具备所需属性/方法即可兼容；ABC 更强调显式继承和抽象基类体系，也更适合提供共享实现或名义层级。

</details>

</details>
