# 07. 装饰器与上下文管理器

这两类工具看起来“高级”，但核心思想其实不复杂：

- **装饰器**：在不改原函数主体的前提下，为函数/类增加额外行为；
- **上下文管理器**：把“资源进入”和“资源退出”这类固定流程自动管理起来。

---

# 一、装饰器 Decorator

## 1. 为什么装饰器能存在

因为 Python 中函数是对象，可以：

- 赋值给变量；
- 作为参数传入函数；
- 作为返回值返回。

```python
def hello():
    print("hello")

f = hello
f()
```

---

## 2. 最简单的装饰器

```python
def decorator(func):
    def wrapper():
        print("before")
        func()
        print("after")
    return wrapper

@decorator
def hello():
    print("hello")

hello()
```

输出：

```text
before
hello
after
```

`@decorator` 基本等价于：

```python
hello = decorator(hello)
```

💡 **新手理解**：把原函数交给装饰器，装饰器返回一个“包装后的新函数”，以后调用的其实是这个包装函数。

---

## 3. 为什么 wrapper 通常要写 `*args, **kwargs`

如果原函数有参数：

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)
        print("after")
        return result
    return wrapper
```

这样 wrapper 才能较通用地接收原函数的各种参数。

---

## 4. `functools.wraps`

直接包装会让函数元信息丢失：

```python
print(hello.__name__)  # 可能变成 wrapper
```

标准写法：

```python
from functools import wraps

def decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

`@wraps(func)` 会帮助保留 `__name__`、`__doc__` 等元信息。

🎯 面试时如果你能主动提 `functools.wraps`，通常说明不是只记住了装饰器语法。

---

## 5. 带参数的装饰器

```python
from functools import wraps

def repeat(n):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def hello():
    print("hello")
```

可以拆开理解：

```python
hello = repeat(3)(hello)
```

即：

1. `repeat(3)` 先返回真正的装饰器；
2. 装饰器接收 `hello`；
3. 返回 wrapper。

---

## 6. 装饰器常见用途

- 日志记录；
- 权限检查；
- 缓存；
- 性能计时；
- 重试；
- Web 框架路由注册；
- API 鉴权。

例如计时：

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        cost = time.perf_counter() - start
        print(f"cost: {cost:.6f}s")
        return result
    return wrapper
```

---

## 7. 多个装饰器顺序

```python
@A
@B
def f():
    pass
```

等价于：

```python
f = A(B(f))
```

因此可以记成：**靠近函数的装饰器先包，调用时外层先进入。**

# 二、上下文管理器 Context Manager

## 8. `with` 为什么常用于文件

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

`with` 结束后文件会被正确关闭，即使内部抛异常，也能执行清理逻辑。

如果不用 `with`，通常要手动：

```python
f = open("data.txt")
try:
    content = f.read()
finally:
    f.close()
```

所以 `with` 的价值不是“写法短”而已，而是更可靠地管理资源生命周期。

---

## 9. 上下文管理协议

类可以通过：

- `__enter__`
- `__exit__`

实现上下文管理器。

```python
class MyContext:
    def __enter__(self):
        print("enter")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("exit")

with MyContext() as ctx:
    print("working")
```

执行顺序：

```text
__enter__
  ↓
with 内部代码
  ↓
__exit__
```

---

## 10. `contextlib.contextmanager`

也可以用生成器风格写上下文管理器：

```python
from contextlib import contextmanager

@contextmanager
def resource():
    print("acquire")
    try:
        yield "resource"
    finally:
        print("release")

with resource() as r:
    print(r)
```

`yield` 前是进入阶段，`yield` 后通常负责清理。

---

## 11. 装饰器 vs 上下文管理器

| 对比 | 装饰器 | 上下文管理器 |
|---|---|---|
| 主要对象 | 函数/类 | 一段代码块、资源 |
| 典型语法 | `@decorator` | `with ...:` |
| 典型用途 | 日志、缓存、权限 | 文件、锁、连接、事务 |
| 核心思想 | 包装行为 | 管理进入/退出 |

---

## 12. 高频面试题

### Q1：什么是装饰器？

🎯 **回答框架**：装饰器本质上是一个接收函数或类并返回新函数或类的可调用对象。它可以在不修改原函数主体的情况下扩展行为，常用于日志、缓存、鉴权、计时等。`@decorator` 可以理解为语法糖。

### Q2：为什么要用 `functools.wraps`？

为了尽量保留被装饰函数的元信息，如 `__name__`、`__doc__` 等，也利于调试和工具识别。

### Q3：`with` 做了什么？

它使用上下文管理协议，在进入代码块时调用进入逻辑，在离开代码块时执行退出和资源清理逻辑，即使发生异常也能更可靠地释放资源。
