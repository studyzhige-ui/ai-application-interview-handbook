# 03. 可变对象、对象身份与深浅拷贝

[← 上一章：容器](02-核心数据类型与容器.md) · [模块主页](../README.md) · [下一章：函数与作用域 →](04-函数-参数-作用域-闭包.md)

复制一份列表以后修改它，为什么原列表有时跟着变、有时不变？函数拿到列表后修改它，为什么调用者也能看到？这不是几种互不相关的“坑”，而是同一个问题：**这一步改了名字的绑定、外层容器的引用，还是共享的内部对象？**

本章沿用前两章的对象图，从最简单的两个名字，逐步走到嵌套容器和函数调用。

```text
对象是否允许原地改变
→ 多个名字是否共享同一对象
→ 复制外层还是复制对象图
→ 函数中的名字与调用方怎样共享
→ 默认参数为何产生跨调用共享
```

## 1. 先判断“原地改变”还是“重新绑定”

### 1.1 可变性是对象类型的能力，不是变量名的能力

💡 **新手理解**：Mutable（可变）表示同一个对象的内容可以原地修改；Immutable（不可变）表示其自身的值／元素绑定不能原地修改。名字重新指向另一个对象，是另一回事。

| 对象类型 | 可否原地修改自身 |
|---|---|
| `int` 整数、`float` 浮点数、`bool` 布尔值 | 不可以 |
| `str` 字符串 | 不可以 |
| `tuple` 元组 | 不可以替换自身元素引用；内部对象可能可变 |
| `list` 列表、`dict` 字典、`set` 集合 | 可以 |

```python
x = 10                       # x 引用整数对象 10
before = x                   # 保留对旧对象的引用，避免混入对象销毁后的编号复用
x += 1                       # 得到值为 11 的整数对象，再把 x 绑定过去
print(before, x)             # 10 11：没有把旧对象 10 原地变成 11
print(x is before)           # False：两个存活的整数对象身份不同

items = [1, 2]               # 创建可变列表
old_id = id(items)           # 记录这个存活对象的身份编号
items.append(3)              # 在同一个列表对象里追加元素
print(id(items) == old_id)   # True：身份没有变化，不是“可能恰好相同”
print(items)                 # [1, 2, 3]：内容变了
```

`x += y` 是增强赋值语法，实际行为由类型决定。对整数，它不会改变旧整数；对列表，`+=` 通常原地扩展列表。**不能只看同一个符号，就断言一定创建新对象或一定原地修改。**

### 1.2 身份与相等：先问自己在验证什么

```python
a = [1, 2]                   # 第一个列表
b = [1, 2]                   # 第二个内容相等的列表
c = a                        # c 与 a 共享同一个列表
print(a == b)               # True：比较内容
print(a is b)               # False：比较身份
print(a is c)               # True：a 和 c 是同一对象的两个名字
```

`==` 使用类型定义的相等规则，`is` 判断身份。不要依赖小整数缓存或字符串驻留来比较业务值：错误写法是 `x is 100`，正确写法是 `x == 100`。`id()` 与内存地址、生命周期的边界见第 01 章。

## 2. 赋值为什么不是拷贝

```python
a = [1, 2]                   # 创建一个列表
b = a                        # 新增一条引用，不复制列表
b.append(3)                  # 通过 b 修改共享对象
print(a)                    # [1, 2, 3]
b = [999]                   # 现在只是把名字 b 改绑到另一个列表
print(a)                    # [1, 2, 3]：a 仍然引用原列表
```

```text
执行 b = a 后：
    a ──┐
        ├──> list A [1, 2]
    b ──┘

执行 b = [999] 后：
    a ─────> list A [1, 2, 3]
    b ─────> list B [999]
```

赋值右侧的表达式可能先创建对象，例如 `[999]` 创建新列表；但把右侧结果绑定给左侧名字这一步，不会再自动复制那个对象。后面看到“赋值不是拷贝”，说的是这个绑定动作。

## 3. 浅拷贝：新外层，旧子对象

### 3.1 先跟踪复制之后的对象图

**Shallow Copy（浅拷贝）** 对本例列表创建新的外层列表，再把原列表里的元素引用逐个放入副本。复制的是外层结构，不是每个内部对象的内容。

```python
import copy                  # 导入标准库 copy，提供浅拷贝和深拷贝工具

a = [[1, 2], [3, 4]]        # 外层列表包含两个内部列表
b = copy.copy(a)             # 创建新的外层列表，内部元素引用仍指向原来的子列表
print(a is b)               # False：外层对象不同
print(a[0] is b[0])          # True：第一个内部列表仍是同一个
```

```text
a ──> 外层列表 A ──slot0──┐
                         ├──> 内部列表 X [1, 2]
b ──> 外层列表 B ──slot0──┘

A、B 的 slot1 同样都指向内部列表 Y [3, 4]
```

### 3.2 三种修改，沿箭头判断影响

以下是三个独立实验，每次都从相同初始状态开始。

```python
a = [[1, 2], [3, 4]]        # 原列表
b = a.copy()                 # list.copy() 创建浅拷贝
b.append([5, 6])             # 改的是 B 的外层结构，A 没有这个新槽位
print(a)                    # [[1, 2], [3, 4]]
```

```python
a = [[1, 2], [3, 4]]        # 重新开始实验
b = a.copy()                 # 再创建浅拷贝
b[0] = [9]                   # 替换 B 的 slot0 引用，不替换 A 的 slot0
print(a)                    # [[1, 2], [3, 4]]
print(b)                    # [[9], [3, 4]]
```

```python
a = [[1, 2], [3, 4]]        # 重新开始实验
b = a.copy()                 # 外层不同，内部共享
b[0].append(100)             # 沿共享引用找到 X，修改 X 的内容
print(a)                    # [[1, 2, 100], [3, 4]]：A 也能看到 X 的变化
```

对列表，`a.copy()`、`list(a)`、`a[:]` 和 `copy.copy(a)` 都是常见浅拷贝方式。它们不是“浅拷贝算法一定相同”，而是本例具有同样的外层复制、内部共享语义。

## 4. 深拷贝：沿对象图复制需要复制的对象

### 4.1 递归复制解决哪一层共享

**Deep Copy（深拷贝）** 会继续查看内部对象，需要复制时再向下复制，而不只停留在第一层。

```python
import copy                  # 使用 copy.deepcopy

a = [[1, 2], [3, 4]]        # 原对象图
b = copy.deepcopy(a)         # 为这里的嵌套可变列表建立独立副本
b[0].append(100)             # 修改副本中的内部列表
print(a)                    # [[1, 2], [3, 4]]
print(b)                    # [[1, 2, 100], [3, 4]]
print(a[0] is b[0])          # False：这个内部列表已经独立
```

```text
a → 外层 A → 内部 X [1, 2]
b → 外层 B → 内部 X' [1, 2, 100]
```

| 对比（以本章嵌套列表为例） | 赋值 | 浅拷贝 | 深拷贝 |
|---|---|---|---|
| 新的外层列表 | 没有 | 有 | 有 |
| 内部可变列表独立 | 否 | 否 | 是 |
| 主要工作 | 新增名字绑定 | 复制外层引用 | 遍历并复制需要复制的对象图 |
| 适合用途 | 明确共享 | 独立修改外层组织方式 | 需要更深入的数据隔离 |

### 4.2 深拷贝不是把所有共享关系全部打碎

```python
import copy                  # 引入深拷贝工具

shared = [1]                 # 一个内部列表
original = [shared, shared]  # 两个位置本来就引用同一个内部列表
cloned = copy.deepcopy(original)  # 复制对象图，并记录已经复制过的对象
print(cloned[0] is cloned[1])     # True：副本内部保留原有的共享关系
print(cloned[0] is shared)        # False：副本的子列表与原对象隔离
```

深拷贝维护 **Memo（已复制对象记录）**，避免对同一对象无休止地重复复制，也能处理循环引用。不可变对象、函数等可能直接复用；自定义类型还可定义复制行为。因此不能承诺“深拷贝以后每一个对象的 id 都不一样”。

### 4.3 为什么不应把 deepcopy 当默认解决方案

对象图越大，遍历、分配和存储成本通常越高。文件、网络连接、锁、数据库会话等资源，也不能简单理解为“复制内容就得到另一个等价资源”。更合理的是先确定需要隔离哪一层：只改外层就浅拷贝；只改少量字段可以显式复制这些字段；真正需要独立数据图才考虑深拷贝，并检查类型行为。

## 5. 函数参数：再新增一组局部名字

第 01 章已经介绍：`def` 定义函数，参数名是函数接收输入时使用的名字，`return` 返回结果。这里先用三个小实验理解对象共享；参数语法与作用域在下一章完整展开。

### 5.1 原地修改共享对象，调用方可见

```python
def add_item(items):          # items 是本次函数调用里的局部名字
    items.append(100)        # 修改 items 引用的列表本身

nums = [1, 2]                # 调用方的列表
add_item(nums)               # 调用开始时，items 与 nums 引用同一个列表
print(nums)                 # [1, 2, 100]
```

```text
调用方名字 nums ──┐
                  ├──> 同一个 list 对象
函数形参 items ───┘
```

### 5.2 重新绑定局部名字，不会替调用方改名

```python
def reset(items):             # 接收到对调用方列表的引用
    items = [999]            # 只让局部名字 items 改绑，不改变 nums 的绑定

nums = [1, 2]                # 原列表
reset(nums)                  # 调用函数
print(nums)                 # [1, 2]：外部绑定和对象都没有被修改
```

需要调用者采用新对象时，明确返回并接收：

```python
def make_reset():            # 不假装修改调用方名字，而是返回一个新列表
    return [999]             # 把新对象交还调用者

nums = make_reset()          # 调用方自己决定重新绑定 nums
print(nums)                 # [999]
```

### 5.3 不可变参数也遵循同一个规则

```python
def add_one(x):              # 局部名字 x 最初引用传入的整数
    x += 1                   # 重新绑定 x，不修改外部名字 n

n = 10                       # 调用方的整数绑定
add_one(n)                   # 没有接收新的返回值
print(n)                    # 10
```

这常被称为 **Call by Sharing（对象共享传参）** 或“传递对象引用”。不是把整个对象内容自动复制一份，也不是让函数有能力直接改写调用者变量的绑定。

🎯 **面试回答**：

> Python 既不适合简单说成纯值传递，也不适合说成传统意义的引用传递。更准确的理解是传递对象引用。形参与实参最初引用同一个对象；如果函数原地修改可变对象，外部能看到变化；如果只是给形参重新赋值，则不会改变调用者变量的绑定。

## 6. 把共享模型用于两个高频错误

### 6.1 可变默认参数：共享跨越了多次调用

先看错误示例：

```python
def add_item(x, items=[]):    # 执行 def 时创建默认列表，不是每次调用都创建
    items.append(x)          # 修改被多次调用复用的默认对象
    return items             # 返回同一个默认列表

print(add_item(1))           # [1]
print(add_item(2))           # [1, 2]：第二次调用看到了第一次留下的数据
```

默认表达式在**函数定义语句执行时**求值。这里函数对象一直持有默认列表，未传 `items` 的调用就不断复用它。这不是解释器偶尔缓存了列表，而是确定的默认参数语义。

正确写法：

```python
def add_item(x, items=None):  # 用 None 表示调用者没有提供列表
    if items is None:        # 精确判断缺失，不把调用者传入的空列表误认为缺失
        items = []           # 这次调用创建自己的新列表
    items.append(x)          # 原地修改本次选定的列表
    return items             # 返回结果对象

print(add_item(1))           # [1]
print(add_item(2))           # [2]：默认调用之间不再共享列表
```

如果调用方明确传入一个列表，函数仍会原地修改它；`None` 默认值只解决“不小心共享默认对象”，不自动保证函数无副作用。**Side Effect（副作用）** 是函数除返回值以外产生的可见变化。

### 6.2 重复列表：复制引用，不是每次创建新行

```python
rows = [[0, 0]] * 3          # 先创建一行，再把对这一行的引用重复放入三个位置
rows[0][0] = 1               # 修改共享行的第一个元素
print(rows)                 # [[1, 0], [1, 0], [1, 0]]
```

正确做法是每轮创建一行：

```python
rows = []                    # 独立的外层列表
for _ in range(3):           # 重复三次；_ 表示本例不需要使用循环编号
    rows.append([0, 0])      # 每轮求值 [0, 0]，得到一个新的内部列表
rows[0][0] = 1               # 只修改第一行
print(rows)                 # [[1, 0], [0, 0], [0, 0]]
```

第 05 章会把这个循环写成列表推导式。现在先理解“表达式执行几次，创建了几个对象”，不急着压成一行。

## 7. 🎯 高频面试题

### Q1：浅拷贝和深拷贝有什么区别？

🎯 **简洁回答**：浅拷贝只复制外层结构，嵌套对象仍可能共享引用；深拷贝会递归复制内部对象，使副本更独立。浅拷贝成本较低，深拷贝隔离性更强但成本更高。

### Q2：为什么 `a = b` 不算拷贝？

因为只是新增一个名字引用同一个对象，没有创建新对象。

### Q3：tuple 不可变，为什么里面的 list 还能改？

tuple 不允许替换它保存的元素引用，但如果某个元素引用的是可变对象，可以修改那个内部对象。

## 8. ⚠️ 易错点

- 错误：变量重新赋值，就是修改原对象。正确：先看名字是否改绑，原对象可能完全未变。
- 错误：浅拷贝后所有修改都会影响原对象。正确：外层结构独立；修改共享子对象才会沿共享引用被看见。
- 错误：深拷贝保证所有身份都不同。正确：不可变对象可能复用，副本内部的共享关系也可能被保留。
- 错误：用 `if not items` 就能修复默认参数。正确：使用 `None` 哨兵，并写 `if items is None`，保留调用方传入的合法空列表。
- 错误：多行列表可以随意用乘法复制。正确：需要独立行时，每轮创建一个新列表。

## 9. 本章自测

<details>
<summary>1. 为什么 `a = b`、浅拷贝、深拷贝不能混为一谈？</summary>

`a = b` 只增加一个名字绑定，不创建副本；浅拷贝创建新的外层对象，但嵌套对象仍可能共享；深拷贝递归复制需要复制的内部对象，隔离更强但成本也更高。

</details>

<details>
<summary>2. 函数收到 list 后执行 `lst.append()` 与执行 `lst = []` 为什么对调用方影响不同？</summary>

前者修改形参与实参共同引用的列表对象，外部可见；后者只是让函数局部名字重新绑定到新列表，不改变调用方变量的绑定。

</details>

<details>
<summary>3. 为什么可变默认参数容易产生跨调用状态污染？</summary>

默认参数对象在函数定义时创建一次，后续调用会复用同一个对象，因此对 list/dict 等默认值的原地修改会被后续调用看到。

</details>
