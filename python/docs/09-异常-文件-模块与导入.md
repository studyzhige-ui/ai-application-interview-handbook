# 09. 异常、文件、模块与导入

## 1. Python 如何处理异常

基本结构：

```python
try:
    risky_operation()
except ValueError as e:
    print("处理异常", e)
else:
    print("没有异常时执行")
finally:
    print("无论是否异常都执行")
```

| 关键字 | 作用 |
|---|---|
| `try` | 放可能抛异常的代码 |
| `except` | 捕获并处理异常 |
| `else` | `try` 没有抛异常时执行 |
| `finally` | 无论如何通常都会执行，用于清理资源 |

## 2. 不要滥用裸 `except`

不推荐：

```python
try:
    ...
except:
    ...
```

更推荐捕获明确异常：

```python
try:
    int("abc")
except ValueError:
    ...
```

原因：裸捕获可能吞掉你本来不应该忽略的问题，也会让调试困难。

## 3. `raise`

主动抛异常：

```python
def set_age(age):
    if age < 0:
        raise ValueError("age must be >= 0")
```

重新抛出当前异常：

```python
try:
    ...
except ValueError:
    logger.exception("bad value")
    raise
```

## 4. 自定义异常

```python
class BusinessError(Exception):
    pass
```

自定义异常通常继承 `Exception` 或其更具体的子类。

# 5. `assert`

```python
assert x > 0, "x must be positive"
```

`assert` 主要用于开发阶段检查程序内部假设。

⚠️ 不要把 `assert` 当作关键业务校验或安全校验，因为 Python 可以在优化模式下移除断言。

# 6. 文件读写

推荐始终优先使用 `with`：

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

写文件：

```python
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("hello")
```

## 7. 常见文件模式

| 模式 | 说明 |
|---|---|
| `r` | 读取 |
| `w` | 写入，通常会覆盖 |
| `a` | 追加 |
| `x` | 创建新文件，存在则报错 |
| `b` | 二进制模式 |
| `t` | 文本模式，默认 |
| `+` | 读写模式 |

例：

```python
open("image.jpg", "rb")
```

## 8. `read` / `readline` / 迭代文件

```python
f.read()       # 读取内容
f.readline()   # 一行
```

大文件常见写法：

```python
with open("big.log", encoding="utf-8") as f:
    for line in f:
        process(line)
```

这样可以逐行处理，不必一次把整个文件加载到内存。

## 9. 删除文件

```python
import os
os.remove("data.txt")
```

现代代码也常使用 `pathlib`：

```python
from pathlib import Path
Path("data.txt").unlink()
```

# 10. 模块和包

一个 `.py` 文件通常可以作为模块。

```python
import math
print(math.sqrt(4))
```

导入指定名字：

```python
from math import sqrt
```

别名：

```python
import numpy as np
```

## 11. 常见 import 顺序

通常按 PEP 风格分组：

```python
# 1. 标准库
import os
import sys

# 2. 第三方库
import numpy as np
import pandas as pd

# 3. 本地项目模块
from myproject.utils import helper
```

组与组之间空一行。

## 12. `if __name__ == "__main__"`

```python
def main():
    print("run")

if __name__ == "__main__":
    main()
```

当文件被直接运行时，`__name__` 通常为 `"__main__"`；当它作为模块导入时，`__name__` 是模块名。

所以这个判断常用来区分：

- 文件是被直接执行；
- 还是被其他代码导入。

## 13. Python 导入模块时发生什么

面试基础层面可以这样理解：

1. 查找模块；
2. 如果需要，加载并执行模块顶层代码；
3. 创建/获取模块对象；
4. 将模块绑定到当前命名空间。

已导入模块通常会被缓存到 `sys.modules`，因此重复 `import` 一般不会每次都重新完整执行模块代码。

## 14. 循环导入

例如：

```text
a.py import b
b.py import a
```

可能导致模块处于“尚未初始化完成”的状态，从而出现导入错误或属性缺失。

常见解决思路：

- 重构公共依赖到第三个模块；
- 调整模块职责；
- 在确有必要时局部导入。

## 15. 高频面试题

### Q1：`finally` 一定执行吗？

面试基础回答可以说：正常的异常处理流程中，`finally` 用于保证清理逻辑执行。但遇到进程被强制终止、解释器崩溃、机器断电等极端情况时，不应该把“一定”理解成物理意义上的绝对保证。

### Q2：为什么文件推荐 `with open(...)`？

因为上下文管理器会更可靠地管理文件资源，即使读取过程抛异常，也能执行关闭逻辑。

### Q3：`import module` 和 `from module import name` 有什么区别？

前者把模块对象绑定到当前命名空间，使用时写 `module.name`；后者直接把指定名字绑定到当前命名空间。前者通常更清楚名字来自哪里，也更少产生命名冲突。
