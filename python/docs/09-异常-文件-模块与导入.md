# 09. 异常、文件、模块与导入

这一章负责把“程序正常工作时怎么写”推进到“失败时怎么保持可理解、可清理、可维护”。它也是下一章 Structured Data Validation 的前置：外部输入解析失败、Schema 不合法、文件读取异常，本质上都要进入清晰的错误语义。

---

## 1. Python 如何处理异常

基本结构：

```python
try:
    risky_operation()
except ValueError as e:
    print("处理异常", e)
else:
    print("没有异常时执行")
finally:
    print("无论是否异常都执行")
```

| 关键字 | 作用 |
|---|---|
| `try` | 放可能抛异常的代码 |
| `except` | 捕获并处理异常 |
| `else` | `try` 没有抛异常时执行 |
| `finally` | 通常用于资源清理 |

---

## 2. 不要滥用裸 `except`

不推荐：

```python
try:
    ...
except:
    ...
```

更推荐捕获明确异常：

```python
try:
    int("abc")
except ValueError:
    ...
```

原因：裸捕获可能吞掉本来不应该忽略的问题，也会让调试困难。

尤其不要写：

```python
try:
    ...
except Exception:
    pass
```

然后完全丢失错误上下文。

---

## 3. `raise` 与重新抛出

主动抛异常：

```python
def set_age(age):
    if age < 0:
        raise ValueError("age must be >= 0")
```

记录后重新抛出当前异常：

```python
try:
    ...
except ValueError:
    logger.exception("bad value")
    raise
```

如果要保留异常因果链：

```python
try:
    raw = int(text)
except ValueError as e:
    raise BusinessInputError("invalid age") from e
```

这比简单丢掉底层异常更利于排障。

---

## 4. 自定义异常与错误分类

```python
class BusinessError(Exception):
    pass
```

真实工程中建议让异常类别表达语义，例如：

```text
ValidationError
PermissionError
ProviderTimeout
NotFound
BusinessRejected
```

而不是所有失败都抛一个 `RuntimeError("failed")`。

这样上层才能决定：

```text
返回 4xx / 5xx？
是否重试？
是否告警？
是否 fallback？
```

---

## 5. `assert` 的边界

```python
assert x > 0, "x must be positive"
```

`assert` 适合开发阶段检查程序内部假设。

⚠️ 不要把它当关键业务或安全校验，因为优化模式下断言可能被移除。

---

## 6. 文件资源为什么用 `with`

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

`with` 的价值不是“写法更短”，而是把：

```text
open
→ use
→ close
```

变成一个明确的资源生命周期。

即使中间抛异常，退出 Context Manager 时仍会执行对应清理逻辑。

---

## 7. 大文件不要无脑一次 `read()`

```python
with open("big.log", encoding="utf-8") as f:
    for line in f:
        process(line)
```

逐行或分块读取可以避免一次把整个文件放进内存。

这会直接连接后面的：

- RAG ingestion；
- CSV / JSONL processing；
- 大文件 upload；
- Streaming pipeline。

---

## 8. Text vs Binary

文本文件：

```python
open("data.txt", "r", encoding="utf-8")
```

二进制：

```python
open("image.jpg", "rb")
```

AI 项目里 PDF、图片、音频通常先以 bytes 进入，再交给 parser / model / storage。

不要把二进制数据误当普通字符串直接处理。

---

## 9. `pathlib` 更适合现代路径操作

```python
from pathlib import Path

path = Path("data") / "input.json"
if path.exists():
    text = path.read_text(encoding="utf-8")
```

比手工字符串拼路径更清晰，也更跨平台。

## 10. 模块和包

一个 `.py` 文件通常可以作为模块。

```python
import math
print(math.sqrt(4))
```

```python
from math import sqrt
```

大型项目通常会区分：

```text
standard library
third-party package
local application package
```

---

## 11. `if __name__ == "__main__"`

```python
def main():
    print("run")

if __name__ == "__main__":
    main()
```

直接执行文件时，`__name__` 通常为 `"__main__"`；作为模块导入时则是模块名。

---

## 12. Import 时发生什么

应用层可以这样理解：

```text
find module
→ create/load module object
→ execute module top-level code if needed
→ cache in sys.modules
→ bind name in current namespace
```

所以重复 import 通常不会每次完整重新执行顶层模块代码。

---

## 13. Circular Import

```text
a.py imports b
b.py imports a
```

可能出现：

```text
module partially initialized
→ expected name not ready
```

常见修复：

- 重构公共依赖；
- 调整模块职责；
- 只在确有必要时做局部 import。

循环导入通常是模块边界问题的信号，不应该只靠“把 import 移到函数里”永久掩盖。

---

## 14. AI Application 的错误边界

例如一次 LLM/RAG 请求：

```text
read file
→ parse JSON
→ call model
→ parse structured output
→ write state
```

不同失败应区分：

```text
FileNotFound
JSONDecodeError
ValidationError
Timeout
PermissionError
BusinessRejected
```

这样才可能在后续 FastAPI / Backend 层做稳定 Error Contract。

## 15. 🎯 面试怎么回答

### 为什么推荐 `with open()`

> 因为 Context Manager 把资源获取和释放绑定到明确生命周期，即使内部抛异常也能执行退出清理，比手工 open/close 更不容易泄漏资源。

### `finally` 是否一定执行

> 正常异常控制流中，`finally` 用于保证清理逻辑执行；但进程被强杀、解释器崩溃、机器掉电等极端情况不能承诺物理意义上的“一定”。

### import 为什么不会每次都重新执行

> 已加载模块通常会存在 `sys.modules` 中，后续 import 会优先复用模块对象；第一次导入时顶层代码可能执行，因此模块 import 本身也可能有副作用。

---

## 16. ⚠️ 易错点

- 裸 `except` 容易吞错误；
- `except Exception: pass` 会让排障非常困难；
- `assert` 不能当安全校验；
- 大文件不要无脑 `read()`；
- import 会执行顶层代码，模块初始化也可能失败；
- 循环导入通常意味着职责边界需要重新设计；
- Error Type 应影响 Retry / HTTP Status / Alert，而不是所有错误统一一个字符串。

---

## 17. 本章自测

<details>
<summary>1. 为什么捕获异常后直接 `pass` 通常很危险？</summary>

因为它会隐藏真实失败，使调用方误以为操作成功，也会丢失排障上下文。只有明确知道某个异常可以安全忽略时才应该这样处理。

</details>

<details>
<summary>2. 为什么大文件逐行读取比一次 `read()` 更稳？</summary>

逐行/分块处理可以限制峰值内存，不必把整个文件同时加载到内存中，尤其适合日志、CSV、RAG ingestion 等大数据流。

</details>

<details>
<summary>3. Circular Import 为什么不只是“Python import 写法问题”？</summary>

它往往说明模块职责彼此依赖过重或边界不清。局部 import 可以临时缓解，但更根本的做法是重构共享依赖和模块职责。

</details>
