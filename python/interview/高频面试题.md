# Python 高频面试题

> 建议使用方式：先遮住答案口述 30~60 秒，再展开答案。真正的面试准备不是“看懂”，而是“能自己说出来”。

## 1. Python 是动态类型还是静态类型？强类型还是弱类型？

**答：** Python 是动态类型、强类型语言。变量不需要提前声明类型，运行时可引用不同类型对象；但不兼容类型不会被随意隐式转换，例如 `"1" + 1` 会抛 `TypeError`。

---

## 2. Python 中变量和对象是什么关系？

**答：** 变量名本质上是对象的引用/绑定。`a = b` 通常只是让 `a` 和 `b` 指向同一个对象，不等于复制对象。

```python
a = [1, 2]
b = a
b.append(3)
print(a)  # [1, 2, 3]
```

---

## 3. `is` 和 `==` 有什么区别？

**答：** `==` 比较值是否相等；`is` 判断是否为同一个对象，即对象身份是否相同。判断 `None` 推荐 `is None`。

---

## 4. list 和 tuple 有什么区别？

**答：** list 可变，tuple 本身不可变；两者都支持有序、索引、切片和重复元素。list 适合动态序列，tuple 适合固定记录。只包含可哈希元素的 tuple 可以作为 dict key，list 不行。

**追问：tuple 一定可哈希吗？** 不一定，内部如果包含 list 等不可哈希对象，整个 tuple 也不可哈希。

---

## 5. set 有什么特点？

**答：** 元素唯一，适合去重、成员判断以及交并差等集合运算。不要依赖 set 的遍历顺序作为业务逻辑。

---

## 6. dict 为什么查找快？

**答：** dict 通常基于哈希表实现，通过 key 的哈希值快速定位候选位置，平均查找、插入和删除接近 O(1)。最坏情况不能简单保证 O(1)。

---

## 7. dict 的 key 为什么必须可哈希？

**答：** 哈希表依赖稳定的哈希值和相等关系定位 key。列表等可变对象内容可原地改变，因此通常不可哈希；整数、字符串和满足条件的 tuple 常可哈希。

---

## 8. `append` 和 `extend` 区别？

**答：** `append(x)` 把 `x` 整体作为一个元素添加；`extend(iterable)` 将可迭代对象中的元素逐个加入。

---

## 9. `remove`、`pop`、`del` 有什么区别？

**答：** `remove(x)` 按值删除第一个匹配元素；`pop(i)` 按索引删除并返回元素，默认末尾；`del` 是语句，可删除名字、列表元素/切片、对象属性等。

---

## 10. 可变对象和不可变对象是什么？

**答：** 可变对象创建后可以原地修改内容，如 list/dict/set；不可变对象的值不能原地改变，如 int/str/tuple。变量重新赋值不等于修改原对象。

---

## 11. 浅拷贝和深拷贝有什么区别？

**答：** 浅拷贝创建新的外层对象，但嵌套对象仍可能共享引用；深拷贝会递归复制内部对象，使副本更独立，但成本更高。

---

## 12. `a = b`、浅拷贝、深拷贝怎么区分？

**答：** `a = b` 不创建副本；浅拷贝复制一层；深拷贝递归复制需要复制的内部对象。

---

## 13. Python 参数是值传递还是引用传递？

**答：** 更准确地说是对象引用传递/call by sharing。形参与实参最初引用同一个对象；原地修改可变对象时外部可见，给形参重新赋值则不会改变调用者变量的绑定。

---

## 14. 为什么默认参数不能随便写 `[]`？

**答：** 默认参数在函数定义时求值一次，可变默认对象会被后续调用复用，从而出现状态共享。

```python
def f(x, items=None):
    if items is None:
        items = []
```

---

## 15. `*args` 和 `**kwargs`？

**答：** `*args` 收集额外位置参数为 tuple；`**kwargs` 收集额外关键字参数为 dict。调用时 `*` 和 `**` 又可分别展开序列和映射参数。

---

## 16. Python 的 LEGB 是什么？

**答：** 名字查找通常按 Local → Enclosing → Global → Built-in 顺序。

---

## 17. `global` 和 `nonlocal` 区别？

**答：** `global` 用于模块级全局名字；`nonlocal` 用于外层函数作用域中的名字。

---

## 18. 什么是闭包？

**答：** 内部函数捕获外层函数作用域中的变量，即使外层函数已经返回，内部函数仍能使用这些变量。常用于状态保存、函数工厂和装饰器。

---

## 19. lambda 是什么？

**答：** lambda 是定义短小匿名函数的语法，适合一次性的简单表达式，如 `sorted(..., key=lambda x: ...)`。复杂逻辑更适合普通 `def`。

---

## 20. 列表推导式是什么？

**答：** 使用 `[expr for x in iterable if condition]` 简洁构造列表。优点是表达映射/筛选逻辑紧凑，但复杂逻辑不应强塞进一行。

---

## 21. `map`、`filter`、`reduce` 分别做什么？

**答：** `map` 对每个元素做映射；`filter` 保留满足条件的元素；`reduce` 逐步累计成一个值。现代 Python 中 `map/filter` 返回惰性迭代对象。

---

## 22. `sorted()` 和 `list.sort()` 区别？

**答：** `sorted()` 接收任意可迭代对象并返回新 list；`list.sort()` 只用于 list，原地排序并返回 `None`。

---

## 23. Iterable 和 Iterator 区别？

**答：** Iterable 可以通过 `iter()` 获取迭代器；Iterator 保存迭代状态并支持 `next()`。list 是 Iterable，但本身不是 Iterator。

---

## 24. 生成器是什么？

**答：** 生成器是一类特殊迭代器，可由含 `yield` 的生成器函数或生成器表达式创建，按需产生值，适合大数据流和惰性计算。

---

## 25. `yield` 和 `return` 区别？

**答：** `return` 返回结果并结束函数；`yield` 产生一个值并暂停生成器，保存执行状态，下次继续执行。

---

## 26. 生成器为什么省内存？

**答：** 因为它惰性地产生元素，不需要像列表那样一次性保存全部结果。

---

## 27. 什么是装饰器？

**答：** 装饰器通常接收函数/类并返回包装后的函数/类，在不修改原主体代码的前提下扩展行为。`@decorator` 是语法糖，常用于日志、缓存、鉴权、计时。

---

## 28. 为什么装饰器要用 `functools.wraps`？

**答：** 为了保留原函数的 `__name__`、`__doc__` 等元信息，利于调试、反射和工具识别。

---

## 29. 多个装饰器的顺序？

```python
@A
@B
def f():
    pass
```

等价于 `f = A(B(f))`。

---

## 30. 上下文管理器是什么？

**答：** 管理进入/退出某段代码时的资源生命周期，典型语法是 `with`。类可实现 `__enter__` / `__exit__`，常用于文件、锁、数据库连接、事务等。

---

## 31. 为什么文件操作推荐 `with open()`？

**答：** 它利用上下文管理器保证退出代码块时执行关闭逻辑，即使内部抛异常也能更可靠地释放文件资源。

---

## 32. 面向对象的核心思想？

**答：** 常讨论封装、继承、多态、抽象。Python 还常体现鸭子类型：调用者更关心对象是否提供所需行为，而不是一定属于某个具体继承体系。

---

## 33. 实例方法、类方法、静态方法？

**答：** 实例方法通过 `self` 操作实例；类方法使用 `@classmethod` 并通过 `cls` 操作类，常用于替代构造器；静态方法使用 `@staticmethod`，没有隐式 `self/cls`，适合与类语义相关但不依赖类/实例状态的函数。

---

## 34. `__new__` 和 `__init__` 区别？

**答：** `__new__` 负责创建并返回实例；`__init__` 对已经创建的实例进行初始化。普通类大多只需重写 `__init__`。

---

## 35. `__str__` 和 `__repr__` 区别？

**答：** `__str__` 偏用户友好输出；`__repr__` 偏开发和调试，通常应尽量明确、无歧义。

---

## 36. `__slots__` 是什么？

**答：** 可用于限制实例常规属性集合，并在大量实例等特定场景减少属性存储开销。不要绝对化地说“使用 slots 后一定没有 `__dict__`”，继承等情况会影响。

---

## 37. Python 如何处理异常？

**答：** 使用 `try / except / else / finally`。`except` 捕获异常；`else` 在 try 无异常时执行；`finally` 通常用于清理资源。

---

## 38. `assert` 用来做什么？

**答：** 检查开发阶段的程序内部假设。它不应承担关键业务/安全校验，因为优化模式下断言可能被移除。

---

## 39. `if __name__ == "__main__"` 是什么？

**答：** 用于区分模块被直接执行还是被导入。直接执行时 `__name__` 为 `"__main__"`。

---

## 40. Python 导入模块时为什么不会每次都重新执行？

**答：** 已加载模块通常缓存于 `sys.modules`，重复 import 时会优先复用已有模块对象。

---

## 41. CPython 的垃圾回收机制？

**答：** 面试基础可回答：CPython 主要使用引用计数管理对象生命周期，并配合循环垃圾回收机制处理容器之间的循环引用问题。

---

## 42. `del` 会立刻删除对象吗？

**答：** 不一定。`del` 删除的是名字、属性或容器元素的引用关系。只要对象仍有其他引用，就仍然存在。

---

## 43. GIL 是什么？

**答：** 在传统 CPython/GIL 模式中，同一解释器进程通常同一时刻只有一个线程执行 Python 字节码。它简化了部分解释器内部共享状态同步，但会限制纯 Python CPU 密集多线程的并行能力。GIL 是 CPython 实现相关概念，不是 Python 语言规范要求。

---

## 44. 有 GIL，多线程还有意义吗？

**答：** 有。I/O 密集任务中线程经常在等待网络、磁盘、数据库，此时其他线程可以继续运行；纯 Python CPU 密集任务则通常更适合多进程或能释放 GIL 的底层计算库。

---

## 45. 有 GIL 为什么还要线程锁？

**答：** GIL 不等于你的业务操作是原子的。多个线程仍可能在多步骤共享状态操作之间交错执行，产生竞态，所以共享可变状态仍可能需要锁。

---

## 46. 进程和线程区别？

**答：** 进程拥有较独立的地址空间，隔离性强、开销更高；同一进程内线程共享内存，通信方便但需处理同步问题。传统 CPython 下 CPU 密集常用多进程，I/O 密集常用线程。

---

## 47. 协程是什么？

**答：** 协程是用户态轻量并发方式，任务在等待时主动让出控制权，由事件循环调度其他任务。特别适合大量可异步 I/O。

---

## 48. `async` 和 `await` 是什么？

**答：** `async def` 定义协程函数；`await` 在协程中等待 awaitable，并允许当前协程挂起，让事件循环调度其他任务。

---

## 49. `async def` 里面写 `time.sleep()` 有问题吗？

**答：** 有，它会阻塞事件循环。异步代码应使用支持异步等待的 API，例如 `await asyncio.sleep()`；同步阻塞 API 可考虑线程池桥接。

---

## 50. 线程、进程、协程怎么选？

**答：** 常见经验：I/O 密集可选线程或 asyncio；纯 Python CPU 密集优先多进程；大量高并发且库提供 async API 的网络任务很适合协程。最终还要看库支持、数据共享、部署和资源成本。

---

## 51. 数组和链表区别？

**答：** 数组随机访问 O(1)，但中间插删常需移动元素；链表随机访问 O(n)，已定位节点后的链接修改可很快。数组通常缓存局部性也更好。

---

## 52. 栈和队列区别？

**答：** 栈是 LIFO 后进先出；队列是 FIFO 先进先出。

---

## 53. Python 实现队列为什么推荐 `deque`？

**答：** `list.pop(0)` 需要搬移后续元素，通常 O(n)；`collections.deque.popleft()` 更适合队头删除。

---

## 54. 一亿个数找 Top 100 怎么做？

**答：** 维护大小为 100 的最小堆。先放入 100 个元素，之后只有新元素大于堆顶时才替换堆顶。时间约 O(n log k)，空间 O(k)。

---

## 55. 面试表达技巧

遇到 Python 问题，尽量按这个顺序答：

1. **一句话定义**；
2. **核心区别/原理**；
3. **给一个简单例子**；
4. **补边界条件**；
5. 等面试官追问再深入。

不要一上来堆实现细节，也不要只说一句“list 可变，tuple 不可变”就停下。
