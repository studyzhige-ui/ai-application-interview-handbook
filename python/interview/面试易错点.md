# Python 面试易错点

> 这一页不是新知识，而是专门收集“看起来会，其实容易说错”的地方。面试前建议重点复习。

## 1. `is` 不是简单等于“比较内存地址”

更准确：`is` 判断两个引用是否指向**同一个对象**。

```python
a = [1, 2]
b = [1, 2]

print(a == b)  # True
print(a is b)  # False
```

面试最好说“对象身份 identity”，不要只背“内存地址”。

---

## 2. `a = b` 不是拷贝

```python
a = [1, 2]
b = a
```

这里只是让两个变量名引用同一个对象。

---

## 3. tuple 不可变，不代表内部所有对象都不可变

```python
t = ([1, 2], 3)
t[0].append(4)
print(t)  # ([1, 2, 4], 3)
```

不可变的是 tuple 自己保存的元素引用结构。

---

## 4. tuple 不一定能作为 dict key

```python
hash((1, 2))        # 可以
# hash(([1, 2], 3)) # TypeError
```

只有当 tuple 内部元素也满足可哈希要求时才可哈希。

---

## 5. set 去重可能破坏顺序

```python
list(set(nums))
```

只适合“不关心顺序”的场景。

保序去重常用：

```python
list(dict.fromkeys(nums))
```

---

## 6. dict 的 key 不是“必须不可变”，准确要求是“可哈希”

面试里常用不可变类型解释 key，但最准确的规则是 key 必须可哈希。

---

## 7. 默认参数在定义时求值，不是调用时

错误：

```python
def add(x, items=[]):
    items.append(x)
    return items
```

正确常用模式：

```python
def add(x, items=None):
    if items is None:
        items = []
```

---

## 8. Python 参数传递不要简单说“引用传递”

更稳妥：**对象引用传递 / call by sharing**。

```python
def f(lst):
    lst.append(1)   # 修改对象，外部可见

def g(lst):
    lst = [999]     # 重新绑定局部变量，外部绑定不变
```

---

## 9. `list.sort()` 返回的是 `None`

错误：

```python
nums = [3, 1, 2]
nums = nums.sort()
print(nums)  # None
```

正确：

```python
nums.sort()
```

或者：

```python
new_nums = sorted(nums)
```

---

## 10. `(x for x in data)` 不是 tuple 推导式

它是**生成器表达式**。

```python
g = (x * x for x in range(5))
```

真正转换成 tuple：

```python
t = tuple(x * x for x in range(5))
```

---

## 11. 生成器通常消费后不能自动重来

```python
g = (x for x in range(3))
print(list(g))  # [0, 1, 2]
print(list(g))  # []
```

如果要重新遍历，需要重新创建生成器。

---

## 12. `yield` 不是“返回后继续”这么简单

更准确：`yield` 产出值并暂停生成器，保存当前执行状态；下一次请求值时从暂停位置恢复。

---

## 13. 装饰器 `@A @B` 的顺序别说反

```python
@A
@B
def f():
    pass
```

等价于：

```python
f = A(B(f))
```

靠近函数的 `B` 先包装。

---

## 14. 装饰器别忘了返回原函数结果

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return result
    return wrapper
```

如果忘了 `return result`，被装饰函数原本的返回值就丢了。

---

## 15. 装饰器最好用 `functools.wraps`

```python
from functools import wraps

@wraps(func)
def wrapper(...):
    ...
```

否则原函数的 `__name__`、`__doc__` 等元信息可能被 wrapper 覆盖。

---

## 16. 多态不只是“子类覆盖父类方法”

更好的表述：不同类型对象可以通过统一接口被调用，各自执行自己的实现。Python 的鸭子类型使这种能力不一定依赖显式继承。

---

## 17. `__new__` 和 `__init__` 别说反

```text
__new__  -> 创建并返回实例
__init__ -> 初始化已创建的实例
```

---

## 18. `__slots__` 不要绝对化

基础作用可以说：限制常规实例属性集合，并可能降低大量实例的属性存储开销。

不要说：

> “只要用了 `__slots__`，实例一定没有 `__dict__`。”

继承等情况会影响。

---

## 19. `assert` 不是业务校验工具

断言主要检查开发阶段程序内部假设。优化模式下可能被移除，因此用户输入校验、权限判断等不能依赖 `assert`。

---

## 20. `finally` 不要机械说“任何情况下 100% 执行”

正常 Python 异常流程里，`finally` 用于确保清理逻辑执行；但进程被强杀、机器断电、解释器崩溃等情况下谈不上绝对保证。

---

## 21. `del` 不是“立即删除对象”

```python
a = [1, 2]
b = a
del a
print(b)
```

对象还在，因为 `b` 仍然引用它。

---

## 22. 不要说“Python 垃圾回收就是 GC”而忽略引用计数

针对 CPython，面试常见回答：**引用计数为主 + 循环垃圾回收辅助处理循环引用。**

---

## 23. GIL 不等于“Python 不是线程安全的”

这是过度简化。

更好地说：传统 CPython 的 GIL 简化了解释器内部共享状态和对象管理的同步，但限制多个线程同时执行 Python 字节码。

---

## 24. GIL 不等于“Python 多线程没用”

I/O 密集型任务里，多线程依然常见且有效。

---

## 25. GIL 不等于“所有 Python 永远不能多核”

- 多进程可以利用多个 CPU 核；
- 一些 C/科学计算库会释放 GIL；
- GIL 是 CPython 实现相关概念；
- 现代 CPython 还有 free-threaded 构建方向。

---

## 26. 有 GIL 也可能需要线程锁

GIL 不是你的业务数据锁。多步骤共享状态操作仍可能发生竞态条件。

---

## 27. `async` 不等于“自动开线程”

```python
async def f():
    ...
```

只是定义协程函数，不意味着自动创建线程或进程。

---

## 28. `await` 不等于“所有函数都能 await”

`await` 需要等待 awaitable 对象。同步阻塞函数不会因为写在 `async def` 中就自动变成异步。

---

## 29. `time.sleep()` 放在 async 函数里会阻塞事件循环

错误：

```python
async def f():
    time.sleep(5)
```

异步场景应优先：

```python
await asyncio.sleep(5)
```

---

## 30. 协程不是一定比线程快

它们适用场景不同。大量可异步 I/O 是协程优势场景；CPU 密集任务、没有 async API 的同步库则未必适合。

---

## 31. “链表删除 O(1)”要带条件

如果你还需要先从头查找待删除节点，总成本可能是 O(n)。只有已经定位节点并具备必要前驱信息时，改链接本身才可视为 O(1)。

---

## 32. Python `list` 不是链表

面试中通常把 Python list 理解为动态数组结构，因此索引 O(1)、中间插入删除 O(n)。

---

## 33. 队列不要用 `list.pop(0)` 当最佳答案

它通常 O(n)。推荐：

```python
from collections import deque
q.popleft()
```

---

## 34. “堆”和“内存堆”不是一回事

面试官问“栈和堆区别”时先判断语境：

- 数据结构 stack vs heap；
- 运行时内存 stack vs heap。

不要混在一起答。

---

## 35. Top K 不要上来就全排序

如果 n 非常大、k 很小，常见思路是维护大小 k 的堆，将复杂度从全排序的 O(n log n) 改为约 O(n log k)，空间 O(k)。

---

# 最后一个最重要的易错点

不要把“背了一句话”当成“掌握了”。

例如回答：

> “list 可变，tuple 不可变。”

面试官很可能继续问：

- 什么叫可变？
- tuple 里为什么能放 list？
- tuple 一定可哈希吗？
- list 和 tuple 使用场景？
- 二者性能/存储有什么差异？

真正掌握的标准是：**定义能说、代码能写、边界能解释、追问能接。**
