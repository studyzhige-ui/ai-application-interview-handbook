# 04. 工具契约：模型提出什么，程序检查什么

给模型一个 `read_document` 名字，它仍不知道该传文件路径还是文档编号、能读多长、找不到时会返回什么。给程序一个格式正确的编号，也不代表当前用户有权读取。

工具需要同时说清“怎样请求”与“请求怎样被执行”。这份关于输入、结果和执行边界的约定，就是工具契约。

## 1. 说明书和执行程序是两份东西

模型选择工具，需要名称、用途和参数说明；宿主要真正执行，需要处理函数、连接、凭证和运行策略。

| 内容 | 谁使用 | 文档读取例子 |
|---|---|---|
| 名称与用途 | 模型、应用 | read_document：读取授权文档，不修改原件 |
| 输入格式 | 模型、校验程序 | document_id 必填，必须是非空字符串 |
| 真实实现 | 宿主程序 | 根据编号访问文档服务 |
| 身份与权限 | 授权程序 | 从已登录用户取得可信身份 |
| 结果与错误 | 模型、程序、诊断系统 | 内容、来源，或不存在、无权限等明确结果 |

处理函数可以用 Python、Java 或其他语言实现。语言函数签名只是实现的一部分，不能代替模型说明和业务授权。工具模型端格式随供应商 API 变化；共同原则是**模型得到可理解的说明，执行代码与凭证留在可信程序中**。

## 2. 一次调用要经过哪些检查

设模型提出 `read_document(document_id="B", max_chars=2000)`。以下检查各回答一个不同问题：

| 阶段 | 检查对象 | 能发现的错误 | 下一步 |
|---|---|---|---|
| JSON 解析 | 输入能否读成数据 | 引号缺失、语法损坏 | 不执行，返回可修复反馈 |
| Schema 校验 | 数据是否满足已声明的规则 | 缺字段、类型错、超过上限 | 不执行，说明违反哪条规则 |
| 业务校验 | 当前环境中是否有意义 | B 的指定版本不存在 | 按业务返回不可用或请求补充 |
| 授权 | 可信身份能否访问目标 | B 属于另一个用户 | 拒绝，不允许模型自报身份绕过 |
| 执行与结果校验 | 动作和返回是否满足约定 | 服务超时、内容不完整 | 分类反馈，不冒充成功 |

**解析成功不等于符合 Schema；符合 Schema 也不等于业务有效或获得授权。** 这些门可以在同一处理链实现，但不能互相替代。

## 3. Schema 能检查范围，不只是检查类型

JSON Schema 是描述数据规则的一种标准。它可以声明数字范围、字符串长度、必填字段和允许取值，不是只能判断“是不是整数”。

下面是金额参数的教学片段，不是一份完整模型 API 请求：

```json
{
  "type": "object",
  "properties": {
    "amount": {"type": "integer", "minimum": 0}
  },
  "required": ["amount"],
  "additionalProperties": false
}
```

| 输入 | 结果 | 原因 |
|---|---|---|
| `{"amount": 10}` | 通过这份 Schema | 整数且不小于 0 |
| `{"amount": -100}` | 拒绝 | 违反 minimum |
| `{"amount": "10"}` | 拒绝 | 字符串不是整数 |
| `{}` | 拒绝 | 缺少必填字段 |

[JSON Schema 的数值约束](https://json-schema.org/understanding-json-schema/reference/numeric)明确支持这类范围检查。模型服务可能只支持标准的某个子集，需要分别确认“模型端约束”与“宿主端校验”的实际能力。

余额是否足够、账户是否属于当前用户，则需要查询可信业务状态。即使某项权限能被编码成当前允许编号集合，也仍要考虑权限变化并在执行时校验。

> ⚠️ `amount=-100` 不是 Schema 天生发现不了，而是没有声明或没有执行相应规则时发现不了。不要把标准能力、实际配置和运行授权混为一谈。

## 4. 工具说明要帮助选择，而不只是填参数

`run(command)` 范围很宽；`run_tests(target, timeout_seconds)` 更容易让模型理解用途。说明还应交代目标范围、结果含义与重要限制。例如“读取授权清单内的文档；找不到返回不存在；不自动搜索其他目录”。

清楚的名称和描述降低误选，但不能约束恶意或错误实现。声明只读的工具如果实际上发送邮件，是契约与实现失配；应修实现并测试，不能因为描述写了只读就自动授权。

宿主可以保存是否只读、是否有外部副作用、超时和并发策略。**这些是程序使用的执行信息，不应默认全部发送给模型。** 只读也可能读取秘密，仍有权限与外传风险。

## 5. 返回内容也需要约定

空字符串可能代表资料为空、目标不存在、无权访问或网络中断。把这些情况全变成空结果，模型就无法正确决定下一步。

一个足够简单的成功结果可以是：

```json
{"status": "ok", "document_id": "A", "text": "发布日期待确认", "source": "A:v1"}
```

失败则明确原因，例如 `{"status":"denied"}`。大结果可提供摘要与可授权读取的引用。程序内部日志、凭证和堆栈不应不加选择地进入模型结果。

区分两层完成：工具执行结束，不等于返回内容满足结果契约；满足工具契约，也不等于整项报告任务完成。退出码为 0 但目标文件不存在，仍需报告产物缺失。

## 6. 参数修复和接口升级都有边界

对于格式或静态规则错误，可以告诉模型“max_chars 应为 1 到 5000 的整数”，允许有限次重新构造参数。权限拒绝则不能靠改用户编号修复；同一错误反复出现，应澄清或停止，不无限回转。

接口升级时，要检查字段含义是否变化。把 v1 的 `path` 从“文档编号”改为“任意系统路径”，即使还是字符串，也改变了执行边界。长任务可以固定一份兼容工具配置；恢复时不兼容则明确迁移、重新发现或停止。版本号服务真实变更，不要求每次调用都复制全部配置。

## 本章小结

工具契约连接模型说明与程序执行。解析、静态规则、环境业务检查、授权和结果验收各有对象；清楚的描述帮助选择，可信程序落实保证。字段多不代表契约完整，关键是输入、结果与失败含义是否明确。

## 🎯 面试怎么回答

### Schema 合法为什么仍不能直接执行？

Schema 可以检查类型、范围和必填等已声明规则，但资源是否存在、可信身份是否有权操作、目标是否已变化，需要业务状态与授权检查。应先解析，再校验规则和实际执行条件。

### 工具契约与普通函数有什么不同？

函数负责实际实现；工具还需要供模型理解的用途和参数说明，以及结果、错误和运行影响的约定。宿主绑定处理器、可信身份与控制策略，不能把模型生成的参数当成授权。

### 参数错误后应该怎么办？

给出脱敏、可行动的规则反馈，允许有限修复；重复失败就澄清或停止。权限拒绝不是换身份重试的理由，结果未知的写操作也不能当成未执行直接重做。

## ⚠️ 易错点

> ⚠️ 无效 JSON 属于解析问题，数值越界可以属于 Schema 规则问题；二者不是同一步。

> ⚠️ 工具的只读描述不是安全证明，真实实现、身份和访问范围仍需检查。

> ⚠️ 一个参数类型没变但含义改变，也可能破坏接口兼容和原有批准。
