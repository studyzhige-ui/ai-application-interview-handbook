# 规范化、去重与频率

[← 策略入口](README.md) · [当前分析](../02-analysis/README.md)

## 输入与流程边界

所有正式 Sxxx 流程均被遍历。批次一、二级标题划分来源区块；明确指向旧 source_id 的 extension 合并回该流程。采集总结、排除清单和批次观察不归给末尾来源。当前一手数据文件与迁移前正式来源区块都有独立 SHA-256 校验，任何来源区块改写都会令 check 失败。文本使用 UTF-8 / LF，与保留的 Git 内容一致；仓库 .gitattributes 约束跨平台检出换行，不通过比较时静默忽略改写。

## 记录类型

1. technical_question：披露了具体技术问法，计入题族候选
2. technical_topic：仅有技术主题或短记，保留原样，不补写为完整问句；其题族支持单独标识
3. background：自我介绍、经历、求职安排、HR 等
4. candidate_question：候选人反问，含技术性反问
5. author_answer：作者回答、反馈与复盘，不当作额外提问
6. author_inference：题面缺失后的作者推断，含一条内部分推断而不能可靠拆分的记录
7. undisclosed：未披露题面、编号范围占位
8. explicitly_excluded：原材料明确声明不计确定技术题频
9. review_required：内容或说话角色不足以自动确定；不计频率，等待有依据的复核
10. editorial：采集和审核说明，不计频率

排除只影响统计，绝不删除原文、续文、URL 或顺序。[排除登记](../02-analysis/exclusion-register.json)提供每一条的定位。review_required 不等同于确认非技术题，当前统计对这些条目采取保守下界。

## 两层去重与题族

字面规范化保留大小写、代码运算符和条件。这一层不宣称完成了全量人工语义等价审核。不根据相似向量、题号相近或关键词共现合并成同一道问题，也不把 a*b 与 ab、x_y 与 xy 合并。复合问法保持一个原始记录；无法确认的题意不补写。

[question-families.json](question-families.json)有两类规则：topic 是领域内主题检索层；question_family 是更窄的问题意图层，例如 B+ 树选择、联合索引、MVCC、Context 压缩、MCP 协议等，分开计算。中文与英文同概念别名显式列出；规则只从真实题面产生正匹配，小节只用于约束语境。Agent 小节下的一条 MySQL 题不会因为标题而直接增加 Agent 命中。

细粒度 question_family 仍表示问题意图/能力范围，不表示一组问法都是语义等价的同一道原子题。topic 是较宽检索线索，不进入正式知识域频率。

题族允许多标签，一条复合问题可以支持多个真实涉及的题族。题族内问法不保证逐字相同，也不保证每个条件、业务约束和追问深度都相同。严格同义归并需要人工核对，不能把未做的人工审核包装为已完成。

[record-decisions.json](record-decisions.json)可保存带理由的明确复核决定，包括排除有歧义的 React/ReAct 归类。规则、决定与重建结果同时版本化。

## 频率口径

- 分母：获批输入中的独立招聘流程数，当前为 399
- 分子：符合记录类型过滤且命中某题族的唯一 source_id 集合
- 同流程多轮、重复问法、补充来源：一个题族最多贡献一次
- 独立候选人遇到同类问题：分别贡献来源支持
- 知识域频率：仅对细粒度问题意图族的域内来源取并集，排除宽主题检索线索；不能直接累加题族数
- 原始技术记录数、字面问法组数、主题数、问题族数分别呈现，不能互相冒充
- 未匹配规则的技术记录照常保留，不能强塞已有题族追求覆盖率
- 旧冻结频率和人工补充断言不进入本轮频率计算

此为已收录样本的描述性统计。来源采样、可访问性、平台与公司分布存在偏差，不用百分比宣称求职市场客观概率。
