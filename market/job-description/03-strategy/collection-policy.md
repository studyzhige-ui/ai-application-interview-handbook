# 官方岗位采集与保存

1. 范围是官方校招、应届与实习。毕业届次依原文保留，不限 2027；明确社招或工作经验门槛与校园身份冲突且无其他官方资格依据的岗位不进入当前正式库。
2. 正式收录依据完整职责和任职要求，判断候选人是否实际承担 AI Agent、LLM 应用、RAG、AI 后端/全栈、相关运行平台或评测/测试工具研发。产品、运营、算法研究交叉岗只有存在明确工程交付时才可能纳入，完整原文和边界说明同时保留。
3. 自动采集代码只负责第一方来源传输、分页、详情、真实 ID、URL、原文、哈希、失败状态和增量比较。它不使用标题/正文关键词决定正式纳入；自动 `triage` 只给待审事件排序，低优先级事件同样保留。
4. 公开链接移除可安全去除的来源追踪参数，保留岗位路径与真实 ID。每个当前正式岗位保存官方链接、真实岗位 ID、所有地点、招聘类型与资格依据、核验时间、完整来源正文及哈希。快手校园与日常实习属于不同 ATS 命名空间，同号岗位可分别保留；不同 req 不因同标题合并；同 req 的地点和发布信息不丢失。母岗位下官方独立意向保留父子 ID，数量不解释成招聘人数。
5. 覆盖分别标为声明范围完成、未能证明全量、访问受限。缺失正文、403、登录要求、WAF、超时或适配器错误不能写成零岗位。动态分页变化必须保留证据，不能称为同一时刻的完整快照。
6. GitHub Actions 每周二、周五扫描 69 个登记入口。首次成功观察某来源只建立自动化基线，不把历史职位批量当新增；后续新身份和正文/字段指纹变化进入累计待审队列。只有采集器明确报告完整扫描时，缺失身份才可标记为“可能消失”，且仍不能自动删除正式岗位。
7. 自动扫描的 raw 响应和请求记录作为 Actions artifact 短期保全；需要人工/模型审核的新增和变化岗位在 `01-data/automation/review-queue.json` 中保留完整提取字段。正式岗位库只接收完成完整 JD 语义复核的记录，自动 workflow 不直接修改正式库。
8. 本轮成功重采可以替换对应旧证据；未重新取得的必要一手事实留在非当前保全文件中并排除当前计数。旧规则分析不作为新的岗位判断继续传播。
9. 任一来源失败只影响该来源。本次非完整扫描继续保留上一次基线，不因为一次网络错误产生删除事件。工作流写回前还会检查 `main` 是否在采集期间发生变化；若发生变化则保留 artifacts、跳过发布，下一轮重新执行。
