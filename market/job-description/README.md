# AI应用开发岗位 JD

从官方校招、应届和实习入口，寻找实际承担 AI Agent、LLM 应用、RAG、AI 后端/全栈、运行平台及相关评测工具研发的岗位。岗位标题只是线索，正式收录依据是完整职责、任职要求和官方招聘类型。

- [岗位索引](01-data/岗位JD.md)：按公司浏览已经完成语义审核并正式纳入的岗位，直接打开官方详情。
- [综合分析与69入口覆盖](02-analysis/README.md)：工程职责、交叉方向、资格边界和实际缺口。
- [岗位数据入口](01-data/README.md)：当前正文、ID、地点、届次和逐条判断；较大的字节跳动岗位及历史事实独立存储，由哈希引用连接。
- [采集与保存原则](03-strategy/collection-policy.md)：自动采集、正式纳入、历史材料和失败口径。
- [自动采集与离线校验](04-scripts/README.md)：GitHub Actions 定时扫描 69 个官方入口，维护增量待审队列，不自动污染正式岗位库。
- [自动化状态](02-analysis/automation-status.md)：最近一次扫描、来源健康状态和累计待审事件。

公司覆盖并非全部完整，访问受限不会写成“没有岗位”。正式库只纳入校招、应届与实习范围内、完整 JD 已确认包含目标工程职责的岗位；研究/运营/产品交叉岗只有实际承担应用工程交付时才收录，并明确保留其混合边界。自动采集发现的新职位和变化职位先进入待审队列，经过完整 JD 审核后才能进入正式库。
