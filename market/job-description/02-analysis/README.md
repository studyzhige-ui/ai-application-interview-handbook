## 从岗位职责看，需要交付什么

以下是本轮已读官方 JD 的能力归纳，不是全行业占比或招聘人数统计。不同公司的岗位粒度、招聘池完整度和同岗多地发布方式不同，不能直接用收录条数判断哪家公司更缺人，也不能把岗位要求当作已经发生的面试题。

### 1. 能把业务任务做成可运行的 Agent 系统

核心工作包括任务拆解、上下文与记忆、工具接入、执行状态与异常恢复，以及与现有业务系统的集成。蚂蚁的“智能体与大模型应用工程”把需求归因、系统架构、知识环境、SDK/API、观测与迭代连在一起；小红书“点点 Agent 研发工程师”进一步明确任务规划、工具执行、状态恢复和生成式交互。它们要求能够解释并实现整个任务链路，而不只是会调用一个框架接口。

依据：[蚂蚁：智能体与大模型应用工程](https://talent.antgroup.com/campus-position?positionId=260721011006030)、[小红书：点点 Agent 研发工程师](https://job.xiaohongshu.com/campus/position/22020)。

### 2. 能将模型能力接入完整的软件产品

AI 应用岗位仍包含常规软件工程责任：接口、数据库、前后端交互、部署、并发、监控和故障处理。美团的 AI 全栈岗位把界面与后端、RAG、Agent 编排、流式响应、效果评估放在同一交付链路中；智谱的 Java 应用岗位则突出 MaaS 后端、分布式服务、数据库与生产稳定性。语言选择取决于产品和团队，不应把 AI 应用开发等同于只写 Python。

依据：[美团：AI 全栈工程师](https://zhaopin.meituan.com/web/position/detail?jobUnionId=4697320043&highlightType=campus)、[智谱：大模型应用开发工程师（Java）](https://app.mokahr.com/campus-recruitment/zphz/148984#/job/07d7076c-cbe2-46fc-b33e-fe60ff9e3955)。后者原文面向 2026 届，应按自己的毕业时间判断适配性。

### 3. 能验证效果，并解释为什么值得上线

评测工程不是只给答案打分。智谱 Code Agent 岗位明确要求真实开发任务基准、隔离环境、并行执行、过程观测、失败诊断与回归用例。小红书的产品工程岗位还要求说明个人贡献、技术决策、验证结果，并权衡效果、延迟、成本、稳定性和安全。这些要求可以转化为项目验收：给定明确任务与失败样本，能够复现问题、比较方案、证明改善，并说明代价。

依据：[智谱：GLM-Code Agent 算法工程师](https://app.mokahr.com/campus-recruitment/zphz/148984#/job/124aa3c6-e4a8-4e7d-a63b-ec8b915611a8)、[小红书：社区内容 Product Engineer](https://job.xiaohongshu.com/campus/position/21861)。

## 如何理解研究与运营交叉岗位

岗位名称不能替代正文判断。“算法工程师”可能实际负责 Agent 框架与自动化评测；“AI 全栈”也可能只是使用 AI 编程工具做普通业务开发。正式岗位库依据实际职责保留具体的应用工程方向。

- 核心应用工程：本人负责 Agent、RAG、模型接入、应用前后端、运行系统或评测工具的设计实现。
- 研究工程交叉：有明确应用系统交付，同时承担后训练、奖励建模、多模态或其他算法研究。申请时仍需满足原文的论文、学位和训练经验要求，不能按普通开发岗理解。
- 产品、设计或运营与工程交叉：只有明确要求本人编码、开发部署或交付软件功能时才按交叉方向保留。仅配置无代码工具、撰写 Prompt、制作产品原型或推动研发协作，不自动构成开发岗位。

例如蚂蚁“大模型智能体优化算法”同时要求应用架构、Agent 工程、评测上线和后训练能力，应完整保留其研究要求。不能因为其中出现 RAG 或工具调用，就把训练部分从岗位画像中删掉。

依据：[蚂蚁：大模型智能体优化算法](https://talent.antgroup.com/campus-position?positionId=260721010991745)。

## 校招、实习和毕业届次要分别看

官方招聘池决定招聘类别，岗位正文决定具体资格。校招正式岗位、日常实习、转正实习与博士研究项目不能相互替代；同一招聘池内也可能同时存在不同毕业届次。库中保留原文届次、学历和出勤要求，缺失时不补推。

当前能够读取官方页面，只证明核验时页面可读；不等同于岗位仍有名额、一定开放投递或适合所有应届生。旧届次岗位仍按原始届次展示，不改写成最新届次。申请前应再次打开官方页面确认投递状态、毕业时间、实习时长和到岗条件。

## 对学习与面试准备的启示

以下是根据上述职责提出的学习建议，不能据此宣称某知识点是高频面试题。课程的知识体系和技术事实仍应建立在官方文档、规范与论文上；JD 用于校准工程任务覆盖和实践深度，真人面经另行提供实际提问证据。

1. 先掌握能独立交付的基础。至少深入一门语言，能完成接口、数据库、异步任务、测试与部署，并读懂故障日志。AI 框架不能替代这些基础。
2. RAG 学到能定位链路问题。能说明资料如何进入系统，检索结果如何影响回答，如何通过失败样本区分数据、召回、上下文和生成问题；能用评测对比优化，而不是只列组件名称。
3. Agent 学到能解释运行过程。围绕一次任务讲清模型输入、工具权限、状态变化、记忆更新、失败恢复和完成判定；再扩展到多任务和多 Agent 协作。
4. 评测与可靠性贯穿项目。保留可复现任务、执行轨迹和回归测试，比较质量、时延、成本及失败率。指标应服务真实任务，不为展示数字而设置。
5. 按目标岗位增加专项深度。全栈方向补齐交互与端到端交付；平台方向深化调度、隔离、权限和观测；研究工程交叉方向再补后训练、数据实验与论文复现。无需让所有学习者先掌握全部训练技术。

课程重构时，可据此检查“是否覆盖实际工程问题、是否给出足够解释与验证方法”；面试资料则将这些工程能力与真人面经交叉核对，再决定题目优先级。避免直接把某份 JD 的技术词表改造成课程目录。
