## 5. 主体独立与迁移检查

## 7. 并行边界与共享同步

模块原五份文件的基线 Git blob 与候选文件内容一起记录。`prepare_patch.py` 读取用户指定的本地仓库，用原文件摘要保护模块正文；共享文件只按唯一的 DeerFlow 行做最小替换，保留其他产品后来修改的内容。工具只生成差异文件，不执行 git apply、commit、push 或任何远端写入。冲突即停止，不使用强制覆盖。

共享同步仅涉及 `products/agent/README.md` 的 DeerFlow 固定快照，以及 `references/agent/README.md` 的同一行和核验日期的适用范围。未改变课程章节数，原五份教学文件不改名；实验位于 labs 子目录，不影响现有非递归正文清单。根入口、学习路线和知识地图的顺序无需因本轮改变，不做装饰性改写。

本地环境未取得整个私有仓库的原始工作树：连接器读取成功，但容器直接下载受 DNS 限制。交付包因此提供完整候选文本、语义差异、精确共享行变更和只读补丁生成器；**不把缺少基线字节的手写 diff 冒充已经验证可直接应用的完整补丁**。全仓库集成、完整链接锚点和真实 CI 必须在具备工作树后验证。

最终主干核验发现手册 main 已由开始基线前进到 `157bc4bfaa34efdf611b8fa2f858d9123ad22c13`，合入了另一对话的 LLM Foundation 修改。重新读取 DeerFlow 目录、两处共享索引和公共语义校验相关区间，五份模块文件、两份共享文件及校验器的 Git blob 均与开始基线一致。本轮没有把旧根目录、全局计数或其他模块文本装进覆盖稿。上游 main 仍为固定快照。详细 SHA 与三方核对状态见交付包 `review/baseline.json`；这些结论只描述核验时刻，不承诺后续并行编辑没有冲突。
