## 发现的问题

章节顺序已经调整，但不少小节仍把一般规则留给读者从例子猜，或把定义、过程、例外、提醒混在同一段。标点还承担了不应该承担的排版职责，例如用分号堆并列要求、用斜杠表示输入换行。问题不是只缺少项目符号，而是需要重新安排小节内部的信息先后。

此次保留九章职责、核心操作范围、练习和知识课程回看，逐节调整规则表述、状态说明、过程追踪与局部提醒。没有重新扩成 API 百科，也没有把每个小节机械套成相同模板。

| 章 | 主要处理 |

| 02 | 每种容器先给核心规则，再解释修改、返回和输出的区别。解包、enumerate、get、计数、排序、切片、拼接、判重分别展开关键动作，错误边界就地提示。 |
| 03 | 22 道题的任务、样例、预期分别排版，保持测试和参考实现不变。解释按实际步骤或容器职责组织，答案中的警示仍默认折叠。 |

| 05 | 在示例前说明结构、变量和操作职责。括号、节点连接、链表反转、堆与图用具体状态解释，空容器和引用丢失等风险放在相关位置。 |

## Notebook 同步与生成器修复

第 03 章仍是题目、测试、答案的唯一维护源。原生成器把解释统一转成一个 HTML p 元素，新增的编号、项目符号和警示会失去结构。生成器已改为保留本课程实际使用的段落、平级有序列表、无序列表、引用提醒、行内代码和加粗，并转义原始 HTML。

## 验证边界

这是本地代码、生成和排版证据，不是 GitHub main 更新或全仓库 CI 通过声明。自制 HTML 阅读预览与 GitHub、JupyterLab 的样式并不完全相同；截图只抽查指定位置，不声称验证了所有查看器和每一种屏幕尺寸。

语法测试、渲染检查、增加分点或警示均不能证明讲解已经没有阅读障碍。最终仍要看读者能否先说清规则，再用规则解释例子，而不必反向猜测术语、变量和分支的含义。
