## 1. 为什么使用 Redis，而不是只用业务数据库？

具体说明哪些重复读取或跨实例共享状态需要较低延迟，以及副本能否重建。选择由访问模式和故障后果决定，不是先认定 Redis 比所有数据库更好。

## 2. 五种常用类型怎么选？

String 表达整体值与计数，Hash 表达字段更新，List 保留顺序与重复，Set 表达精确成员关系，ZSet 增加分数顺序。选择以后还要控制对象大小和一次返回的范围。

## 3. HSET 回复 0，是不是没有写成功？

不是。通常表示没有新增字段，已有字段仍可能更新成功。应区分新增数、修改后的值和错误回复。

**继续追问：** DEL 与 HDEL 的删除范围有何不同？

回看 [02｜同一份数据，怎样保存才方便使用](../../curriculum/04-redis/docs/02-键与常用数据类型.md)。

## 4. TTL 怎样变化，GET 会自动续期吗？

普通 GET 不续期，SET 默认覆盖时移除原期限，EXPIRE 设置期限，PERSIST 取消期限。续期必须是明确的应用规则，不是服务器根据访问自动猜测。

**继续追问：** 需要绝对到期时，为什么不能每次都续完整时长？

回看 [03｜数据什么时候应该消失](../../curriculum/04-redis/docs/03-过期与内存淘汰.md)。

## 5. Hash 字段能否独立过期？

7.4 起可用 HEXPIRE 等字段期限命令；整键过期仍会让所有字段消失。不能把旧版本能力边界写成永久规则，也不应为每个 Hash 默认增加复杂期限。

**继续追问：** 更新字段以后，要核对的是字段 TTL 还是键 TTL？

回看 [03｜数据什么时候应该消失](../../curriculum/04-redis/docs/03-过期与内存淘汰.md)。

## 6. 过期与淘汰有什么不同？

前者由数据期限触发，后者是内存压力下按策略移走候选。带 TTL 不代表一定保留到期；noeviction 也不代表无限接受写入。

**继续追问：** volatile 策略能保护带 TTL 的重要任务记录吗？

回看 [03｜数据什么时候应该消失](../../curriculum/04-redis/docs/03-过期与内存淘汰.md)。

## 7. LRU 与 LFU 怎样理解？

前者偏向较久没访问，后者偏向低频并考虑衰减。Redis 采用近似选择，不为每个键维护全局精确排序。策略先取决于哪些数据允许被淘汰。

**继续追问：** 经常淘汰又回填时，还应检查什么？

回看 [03｜数据什么时候应该消失](../../curriculum/04-redis/docs/03-过期与内存淘汰.md)。

## 8. Cache Aside 怎样读写？

应用先查副本，未命中再回源并填入；更新先在权威来源成功，再安排缓存失效。两条路径会交错，删除失败和旧读晚回填需要处理。

**继续追问：** 为何删除成功还会重新出现旧值？

回看 [04｜把 Redis 用作缓存：读与更新怎样配合](../../curriculum/04-redis/docs/04-缓存读取与更新.md)。

## 9. 穿透、击穿、雪崩分别怎样治理？

先分清不存在反复回源、同热点重复重建、大范围流量转移。再选择负缓存和筛查、合并重建、过期分散与整体来源保护，不用一个锁解决全部问题。

**继续追问：** 随机 TTL 为什么不足以阻止单热点被同时重建？

回看 [05｜缓存帮不上忙时，怎样保护数据来源](../../curriculum/04-redis/docs/05-缓存故障与流量保护.md)。

## 10. 布隆过滤器为什么有误判？

不同成员可能映射到相同标记位置，因此全命中只能说明可能存在。用它否定业务数据还要保证应当存在的成员已正确同步，不能忽略更新延迟。

**继续追问：** 新商品漏加入过滤器，会出现什么业务后果？

## 11. 本地缓存与 Redis 怎样配合？

本地缓存减少网络访问，但每个应用都有副本。失效通知、有限 TTL 和重连校验要配合；统计每层命中率时也要保持分母一致。

**继续追问：** 通知丢失后，本地旧值靠什么最终失效？

## 12. 语义缓存比精确缓存多了什么风险？

意思相近的问题不一定适用同一答案。除了期限和权限，还需验证错误复用，用相似但答案不同的反例评价阈值，而不是只展示命中率。

**继续追问：** 企业退款与个人退款相似，能直接复用吗？

## 13. Redis 为什么快，单线程指什么？

常见命令在合适的内存结构上执行，路径较短；事件驱动管理连接，主要串行的数据修改减少部分竞争。整个进程仍有网络和后台执行资源，慢操作也会阻塞其他请求。

**继续追问：** 很多连接为什么不要求一连接一线程？

回看 [07｜Redis 为什么快，请求又为什么会慢](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md)。

## 14. I/O 多路复用和命令执行有什么区别？

前者帮助操作系统发现哪些连接可读写，后者才真正处理请求和修改数据。连接就绪不能证明命令完成或能够任意并行。

**继续追问：** epoll 与事件循环各承担什么角色？

回看 [07｜Redis 为什么快，请求又为什么会慢](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md)。

## 15. Pipeline 与事务有什么区别？

Pipeline 减少逐条等待，事务定义一组命令的连续执行。客户端可能把两者组合，但名字相同不代表保证相同；一批回复丢失后还要考虑部分已执行。

**继续追问：** 批次为什么不能无限增大？

回看 [07｜Redis 为什么快，请求又为什么会慢](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md)。

## 16. 逻辑类型与内部编码为什么要分开？

类型定义可用操作，编码为不同规模优化实现。小对象紧凑表示与大对象查找结构可以不同，客户端的字段接口无需因此变化。

**继续追问：** 容量估算为什么不能只按业务字节数？

回看 [08｜内存怎样花出去：编码、大小与数据表示](../../curriculum/04-redis/docs/08-内部编码与数据规模.md)。

## 17. ZSet 一定是跳表吗？

较大对象的经典实现结合成员定位的字典与有序查询的跳表，小对象可采用紧凑表示。即使查找起点快，返回大量结果仍有相应成本。

**继续追问：** 排名查询和按分数查询怎样区别？

回看 [08｜内存怎样花出去：编码、大小与数据表示](../../curriculum/04-redis/docs/08-内部编码与数据规模.md)。

## 18. Bitmap、Set、HyperLogLog 怎样选择？

精确成员关系用 Set，稳定位置的布尔标记可用 Bitmap，只需估算唯一数时考虑 HLL。它们保留的信息不同，不能只按占用最小选择。

**继续追问：** 稀疏巨大编号为什么不适合直接当位偏移？

回看 [08｜内存怎样花出去：编码、大小与数据表示](../../curriculum/04-redis/docs/08-内部编码与数据规模.md)。

## 19. 大键、热键分别怎样发现和治理？

大键关注大小、全量操作和迁移成本，热键关注访问集中。治理可以是限制值与结果范围、按实体拆分、本地缓存或合并请求，但拆分也会改变聚合和并发语义。

**继续追问：** 为什么增加 Cluster 节点不自动分散单个热键？

回看 [08｜内存怎样花出去：编码、大小与数据表示](../../curriculum/04-redis/docs/08-内部编码与数据规模.md)。

## 20. Redis 事务会自动回滚吗？

排队阶段错误可以使事务被拒绝；执行时某项出错，不提供通用回滚，其他项仍可能成功。必须看各条结果与最终状态。

**继续追问：** QUEUED 与执行成功有何区别？

## 21. WATCH 是锁住数据不让别人改吗？

不是。它在提交时检查观察期间是否发生变化，有冲突则放弃本次提交。其他写者仍可工作；重试应重读并重新计算，而且要有限。

**继续追问：** 键过期或淘汰会不会影响观察？

## 22. Lua 与 Functions 应放什么逻辑？

聚焦依赖少量 Redis 数据的短检查与修改，显式传入键并限制工作量。函数库改善部署和复用管理，不把外部业务提交一起纳入原子边界。

**继续追问：** 脚本先写后报错，之前写入会撤销吗？

## 23. RDB 与 AOF 怎样比较？

RDB 保存某时刻的数据，AOF 提供恢复写入的记录；丢失窗口分别受快照位置和同步策略等影响。重写、写时复制和磁盘也有代价，必须按恢复目标选择。

**继续追问：** AOF 重写为什么不必保留所有旧命令？

回看 [10｜服务重启后，数据从哪里回来](../../curriculum/04-redis/docs/10-持久化与恢复.md)。

## 24. 持久化、复制和备份为什么不能互相替代？

持久化帮助本机恢复，复制保存其他节点的副本，备份保留独立历史恢复点。误删除可能同时进入持久文件与副本，所以还要有验证过的历史恢复步骤。

**继续追问：** 开启了 AOF 是否等于任何故障都不丢？

回看 [10｜服务重启后，数据从哪里回来](../../curriculum/04-redis/docs/10-持久化与恢复.md)。

## 25. 复制和 WAIT 保证什么？

复制通常异步，WAIT 能等待当前连接此前写入达到一定副本确认程度，但不把系统变成严格强一致，也不默认保证落盘或任意故障后的保留。

**继续追问：** WAIT 超时，前面的写入会自动回滚吗？

## 26. Sentinel 怎样切换，quorum 与多数有什么区别？

Sentinel 观察故障、协调选举、提升副本并供客户端发现新主。故障判断所需的 quorum 与选出切换执行者的多数授权是两个条件，不能混为一个数字。

**继续追问：** 切换成功为何仍可能少了最近一次写入？

## 27. Cluster 怎样分片，与一致性哈希有什么不同？

键先映射到 16384 个槽，槽再分配到节点。扩缩容调整槽归属；不是把固定槽模型等同于经典一致性哈希环，也不能把一个热点键任意拆开。

## 28. Hash Tag、MOVED 和 ASK 分别解决什么？

Hash Tag 控制相关键同槽；MOVED 提示槽归属路由，ASK 用于迁移中的单次临时重定向。它们影响数据位置与客户端路由，不提供跨槽通用事务。

**继续追问：** 为什么把全部键都设同一个标签会适得其反？

## 29. 分布式锁最基本怎样实现？

原子创建带唯一持有者值和有限期限的记录；安全释放或续期时原子检查归属。单条 SET NX PX 解决取得租约，不代表外部工作自动在租期内完成。

**继续追问：** 为什么 SETNX 后再 EXPIRE 有风险？

## 30. 安全释放和续租为什么仍不保证业务正确？

旧进程可能暂停超过期限，新工作者接手后旧进程继续运行。归属检查保护锁键，不终止外部工作；下游条件写、幂等和可信版本检查仍需按风险设计。

**继续追问：** 主从切换前锁尚未复制会发生什么？

## 31. Fencing 与 owner token 是一回事吗？

owner token 区分持有者，fencing token 还需要可靠的顺序，由下游记录并拒绝旧版本。普通异步复制计数不自动满足可靠单调保证，下游不检查也不会生效。

**继续追问：** 下游还未见到新版本时，旧写一定会被拒绝吗？

## 32. Pub/Sub 与 Streams 怎样区别？

Pub/Sub 不为离线订阅者保存历史；Stream 保存带 ID 的事件，消费组另跟踪交付与确认。保留、接管和业务去重仍需设计，不靠 ACK 自动保证恰好一次。

## 33. 共享限流怎样避免并发超限？

先定义时间范围、计数口径和身份粒度，再原子完成检查与更新。固定窗口、滑动记录和令牌桶各有不同成本；Redis 不可用时要明确全局规则还能保证多少。

**继续追问：** 只限制每台实例的次数，为什么不等于全局上限？

## 34. 会话、最近消息和 Agent 热状态有什么不同？

会话关联可信身份与有效期，最近消息是有限展示窗口，热状态表达执行进度。完整历史、任务恢复和长期记忆各有额外语义，不能凭同一存储媒介混为一谈。

## 35. Redis 慢或大键迁移时怎样验证判断？

先拆应用等待、网络和服务端执行，按证据选工具。迁移时核对复制期间的新写与删除、切换和回退条件；安全扫描与异步删除不替代一致性协议。
