# Redis｜易混易错点

[本域入口](README.md) · [课程](../../curriculum/04-redis/README.md)

## 存储与类型

| 容易混淆的表述 | 应怎样理解 | 回看 |
|---|---|---|
| Redis 只是更快的本地对象。 | 它是独立共享服务，会引入网络、权限和恢复问题。 | [01](../../curriculum/04-redis/docs/01-Redis是什么.md) |
| 用了 Redis，所有数据就都可丢。 | 可丢的是明确定义的可重建副本，唯一记录有不同后果。 | [01](../../curriculum/04-redis/docs/01-Redis是什么.md) |
| HSET 返回 0 就失败了。 | 它可能更新了已有字段，只是没有新增。 | [02](../../curriculum/04-redis/docs/02-键与常用数据类型.md) |
| List 会自动按消息 ID 去重。 | 重复加入会保存重复元素，业务去重另行设计。 | [02](../../curriculum/04-redis/docs/02-键与常用数据类型.md) |
| ZSet 同分时按加入时间排。 | 默认同分按成员的字节字典序，时间顺序需明确建模。 | [02](../../curriculum/04-redis/docs/02-键与常用数据类型.md) |

## 期限与缓存

| 容易混淆的表述 | 应怎样理解 | 回看 |
|---|---|---|
| GET 会刷新 TTL。 | 普通读取不续期，续期必须显式安排。 | [03](../../curriculum/04-redis/docs/03-过期与内存淘汰.md) |
| SET 覆盖后总保留 TTL。 | 默认会移除原期限，应明确新期限或保留要求。 | [03](../../curriculum/04-redis/docs/03-过期与内存淘汰.md) |
| Hash 字段永远不能单独到期。 | 7.4 起有字段期限能力，要核对版本。 | [03](../../curriculum/04-redis/docs/03-过期与内存淘汰.md) |
| 有 TTL 就保证活到到期。 | 主动删除、淘汰和其他失败可能更早使键消失。 | [03](../../curriculum/04-redis/docs/03-过期与内存淘汰.md) |
| volatile 能保护带 TTL 的锁。 | 它恰以键级 TTL 筛候选，重要状态不应据此认定被保护。 | [03](../../curriculum/04-redis/docs/03-过期与内存淘汰.md) |
| maxmemory 就是进程物理内存硬上限。 | 缓冲、后台工作和系统开销仍需留余量。 | [03](../../curriculum/04-redis/docs/03-过期与内存淘汰.md) |
| Redis miss 说明商品不存在。 | 还需查询权威来源，缓存未命中不是业务事实。 | [04](../../curriculum/04-redis/docs/04-缓存读取与更新.md) |
| 删除成功后不可能再有旧值。 | 旧读取可能在删除之后才回填。 | [04](../../curriculum/04-redis/docs/04-缓存读取与更新.md) |
| 布隆过滤器命中说明数据库一定有数据。 | 它可能误判存在，还需保证维护和来源查询。 | [05](../../curriculum/04-redis/docs/05-缓存故障与流量保护.md) |
| 随机 TTL 能解决所有缓存故障。 | 它主要分散到期，不能单独控制热点重建或整体故障。 | [05](../../curriculum/04-redis/docs/05-缓存故障与流量保护.md) |
| Redis 故障就让所有请求直接回源。 | 可能放大下游负载，需要明确容量与降级。 | [05](../../curriculum/04-redis/docs/05-缓存故障与流量保护.md) |
| 两层命中率可以直接相加。 | 第二层以到达该层的请求为分母。 | [06](../../curriculum/04-redis/docs/06-多级缓存与结果复用.md) |
| 相似度高就可以复用答案。 | 还需权限、版本和实际答案适用性验证。 | [06](../../curriculum/04-redis/docs/06-多级缓存与结果复用.md) |
| 缓存旧成功响应等于本次动作成功。 | 新动作与同操作重试要区分，缓存不证明外部副作用。 | [06](../../curriculum/04-redis/docs/06-多级缓存与结果复用.md) |

## 执行与内存

| 容易混淆的表述 | 应怎样理解 | 回看 |
|---|---|---|
| 单线程表示进程只有一个线程。 | 普通数据执行与网络、后台执行资源是不同层面。 | [07](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md) |
| 网络已就绪说明命令在并行执行。 | 就绪只代表可读写，仍需排队处理。 | [07](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md) |
| Pipeline 会整体回滚。 | 它主要减少等待，命令可能部分已执行。 | [07](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md) |
| Pipeline 越大越好。 | 大批次增加缓冲、交付延迟与失败核对成本。 | [07](../../curriculum/04-redis/docs/07-执行模型与Pipeline.md) |
| 每个类型永远只有一种内部结构。 | 实现随规模、配置和版本而变化。 | [08](../../curriculum/04-redis/docs/08-内部编码与数据规模.md) |
| 位图空间只按设置了几个 1 计算。 | 最大偏移可能产生大范围分配。 | [08](../../curriculum/04-redis/docs/08-内部编码与数据规模.md) |
| HLL 能还原所有成员。 | 它仅保留估计唯一数的信息。 | [08](../../curriculum/04-redis/docs/08-内部编码与数据规模.md) |
| UNLINK 返回后 RSS 必须立即下降。 | 逻辑移除、异步回收和归还物理页不是同一时刻。 | [08](../../curriculum/04-redis/docs/08-内部编码与数据规模.md) |

## 并发与恢复

| 容易混淆的表述 | 应怎样理解 | 回看 |
|---|---|---|
| QUEUED 代表写入成功。 | 表示登记进队列，应继续看 EXEC 结果。 | [09](../../curriculum/04-redis/docs/09-事务与服务端逻辑.md) |
| WATCH 会阻止别的客户端写。 | 它允许并发，只在提交时检查变化。 | [09](../../curriculum/04-redis/docs/09-事务与服务端逻辑.md) |
| Lua 报错会撤销前面全部写入。 | 脚本没有通用错误回滚，校验尽量在修改前完成。 | [09](../../curriculum/04-redis/docs/09-事务与服务端逻辑.md) |
| AOF always 保证任何故障不丢。 | 持久策略仍受设备、配置和故障条件影响。 | [10](../../curriculum/04-redis/docs/10-持久化与恢复.md) |
| 有副本就无需独立备份。 | 误写和删除也可能被复制。 | [10](../../curriculum/04-redis/docs/10-持久化与恢复.md) |
| WAIT 超时会回滚之前写入。 | 它报告确认程度，不撤销已执行写。 | [11](../../curriculum/04-redis/docs/11-复制与Sentinel.md) |
| quorum 就是 Sentinel 选举多数。 | 故障判断与切换授权条件不同。 | [11](../../curriculum/04-redis/docs/11-复制与Sentinel.md) |
| Cluster 就是经典一致性哈希环。 | 官方机制是固定槽及槽到节点的分配。 | [12](../../curriculum/04-redis/docs/12-Cluster与分片.md) |
| Cluster 自动解决单热键。 | 一个键仍归一个槽，不能自动拆成多份写。 | [12](../../curriculum/04-redis/docs/12-Cluster与分片.md) |
| 唯一 token 就解决旧工作者副作用。 | token 可保护释放与续期，不停止旧外部进程。 | [13](../../curriculum/04-redis/docs/13-分布式锁.md) |
| watchdog 保证永远续得上。 | 进程长暂停或网络问题仍可能让租期过去。 | [13](../../curriculum/04-redis/docs/13-分布式锁.md) |
| 任意 INCR 都能产生可靠 fencing 序号。 | 故障后的顺序保证与下游检查必须同时成立。 | [13](../../curriculum/04-redis/docs/13-分布式锁.md) |

## 消息、状态与排查

| 容易混淆的表述 | 应怎样理解 | 回看 |
|---|---|---|
| XACK 自动删除原事件。 | 它主要移除待确认记录，原事件有独立保留规则。 | [14](../../curriculum/04-redis/docs/14-通知与Streams.md) |
| 接管任务会自动停止旧消费者。 | 交付归属变了，旧执行者不一定停止。 | [14](../../curriculum/04-redis/docs/14-通知与Streams.md) |
| 本地限流保证全服务总限额。 | 没有共享或明确分配，就只有各自视角。 | [15](../../curriculum/04-redis/docs/15-共享限流.md) |
| 每次续期不必看绝对过期时间。 | 滑动期限不能越过本来规定的最长有效期。 | [16](../../curriculum/04-redis/docs/16-会话与运行状态.md) |
| 最近 20 条足够补齐所有离线历史。 | 展示窗口不提供无限历史重放。 | [16](../../curriculum/04-redis/docs/16-会话与运行状态.md) |
| SCAN COUNT 等于固定页大小。 | 它只是工作量提示，空结果也可能还需继续。 | [17](../../curriculum/04-redis/docs/17-安全与问题定位.md) |
