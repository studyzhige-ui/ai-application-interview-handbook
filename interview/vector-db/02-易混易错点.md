# Vector DB｜易混易错点

[本域入口](README.md) · [展开问答](01-高频面试题.md) · [面试速查](03-面试速查.md)

文中链接通向对应完整回答及面经样本；标为“教学补足”的内容用于补齐机制，不代表新增原题。

## 1. “同维度向量就能混在一个空间里”

维度只约束形状。[不同模型、前缀或归一化协议](01-高频面试题.md#vector-db-q02)可以产生同维度但不可比较的表示。写入和查询必须使用兼容配置，升级时把编码器与索引共同迁移。

## 2. “归一化后，任何距离都一样”

仅当[两边都是单位向量](01-高频面试题.md#vector-db-q03)时，余弦、内积与平方 L2 存在明确关系。未归一化、零向量、模型依赖模长或不同度量不满足同一结论。排序等价也不代表分数阈值等价。可核对 [Faiss 的度量定义](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances)。

## 3. “高相似度就是高置信度，ANN Recall 就是业务召回率”

相似度是模型空间里的比较；[ANN Recall 是相对于同规则精确近邻的覆盖](01-高频面试题.md#vector-db-q05)。业务 Recall 的相关集合来自任务标签。三个量分别回答“近不近”“索引漏没漏”“业务证据找齐没有”，不能互相替代。

## 4. “HNSW 查询是沿一条边贪心走到底，永远 O(log N)”

分层导航只是起点，[底层通常维护多个候选进行扩展](01-高频面试题.md#vector-db-q06)。复杂度与访问量受参数、分布、图结构和过滤影响，不是每次固定保证。`M`、建图搜索宽度和查询搜索宽度也不是同一个数。

## 5. “efSearch 越大一定能找回正确业务答案”

扩大搜索只针对索引搜索误差，无法修复嵌入不匹配、错误权限、数据未可见或业务标签错误。[先用同一合法集合的精确查询诊断](01-高频面试题.md#vector-db-q08)，再调 ANN 参数。

## 6. “IVF_FLAT 里的 FLAT 表示全库精确搜索”

它可以只探测部分列表，在这些列表内使用原向量距离。[未探测列表中的真近邻仍会遗漏](01-高频面试题.md#vector-db-q09)。`nlist` 是建库列表数，`nprobe` 是查询探测数；列表不均匀时扫描量不能按二者比例精确推断。

## 7. “nprobe 等于 nlist，IVF_PQ 也完全精确了”

[覆盖所有列表解决的是候选覆盖](01-高频面试题.md#vector-db-q10)，PQ 编码仍可能带来距离误差。只有数据完整、无扫描截断、使用原向量及相同规则计分等条件满足，才可谈退化为穷举。检索范围与距离精度要分开核验。

## 8. “PQ 是把 float32 无损变成短整数，最后重排能补回一切”

PQ 用码字近似子向量，压缩有损。[精算只修复已经入选候选内部的距离](01-高频面试题.md#vector-db-q11)，不能召回候选之外的记录。原向量、码本和额外查询读放大都需计入成本，见 [Faiss 的量化与精算说明](https://github.com/facebookresearch/faiss/wiki/Implementation-notes)。

## 9. “WHERE 写上去，所有向量产品都先过滤再 ANN”

SQL 或 JSON 条件描述了逻辑要求，不自动证明物理执行顺序。pgvector 近似扫描后的过滤可能造成短结果；Elasticsearch kNN 子句内与外层过滤也不同。[按具体接口、执行计划和版本核实](01-高频面试题.md#vector-db-q13)，不能跨产品借用结论。

## 10. “过滤越严格越快；结果不满 K 就扩大权限”

严格过滤可能让图搜索探索更多节点才凑够合法候选，也可能使精确扫描小集合更合算。结果不足需要检查基数、搜索预算和计划。[权限绝不能作为质量调参项](01-高频面试题.md#vector-db-q14)，任何扩候选仍须在原授权范围内。

## 11. “写入成功就已经落盘、建索引且对所有查询可见”

[接收、执行、持久化、索引和查询视图可能分离](01-高频面试题.md#vector-db-q16)。按 ID 读取与相似查询也有不同路径。以 [Milvus 的一致性级别](https://milvus.io/docs/consistency.md)为例，不同配置对应不同可见性与延迟边界；不能从 Session 推导所有客户端强一致。

## 12. “同 ID Upsert 能解决重复和所有并发乱序”

同 ID 有助于避免重复实体，但旧版本仍可能晚到覆盖新版本。要设计[修订号与条件提交](01-高频面试题.md#vector-db-q17)，并确认字段是替换还是合并。文档变短时，新块写完还需清理已经失效的旧块。

## 13. “删除后磁盘不变，就是没删除；回滚可恢复所有旧状态”

[逻辑不可见与物理回收是两件事](01-高频面试题.md#vector-db-q17)。缓存、旧视图、后台回收和错误删除范围分别排查。[内容回滚也不应恢复旧权限](01-高频面试题.md#vector-db-q18)；已撤销授权、已删除敏感内容仍需受到当前规则限制。

## 14. “各分片 Top-K 合并，在任何索引和去重策略下都正确”

[证明依赖局部精确、同分数规则、同范围与快照、无跨片重复等条件](01-高频面试题.md#vector-db-q19)。ANN 漏检、压缩差异、候选去重和分片超时会破坏这些前提。应明确全局结果是否完整，而不是把失败分片当成空数据。

## 15. “副本就是备份，Collection、Partition、Shard 都表示物理隔离”

副本可能同步错误删除，备份应提供独立历史恢复点。[逻辑集合、产品分区、数据分片与副本的实现不同](01-高频面试题.md#vector-db-q15)，也不自动提供应用鉴权。产品名称相同不足以推出事务或隔离能力相同。

## 16. “N×D×4 就是集群内存，低平均延迟足以证明选型”

这个公式只估算 float32 原始数值。还要[计索引、元数据、ID、缓存、副本与重建峰值](01-高频面试题.md#vector-db-q20)。性能必须在[相同 Recall 或质量门槛、并发和写入负载](01-高频面试题.md#vector-db-q23)下比较，观察尾延迟；没有统一质量条件的速度排名没有可比性。

## 17. “HNSW 的图就是知识图谱，向量库能自然回答所有关系问题”

[HNSW 边用于搜索导航，知识图谱边表达业务关系](01-高频面试题.md#vector-db-q22)。相似不等于因果、调用、隶属或引用。关系查询需要自己的实体身份、边类型和证据；选一个兼容多种模型的数据库也不会自动完成这些建模工作。
