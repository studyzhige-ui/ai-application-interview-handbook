# System Design｜易混易错点

[本域入口](README.md) · [课程](../../curriculum/10-system-design/README.md)

## 完成与证据

| 容易说错的判断 | 条件、后果与正确做法 | 回看 |
|---|---|---|
| 收到 202 就算任务完成 | 受理、结果生成和外部完成是不同阶段。先查持久任务，再查真实结果；HTTP 状态不自动提供可靠任务。 | [第 04 章](../../curriculum/10-system-design/docs/04-API数据模型与StateOwnership.md) |
| 模型说已发送，就把 Run 标成功 | 工具回执与可核对外部记录才支持动作结果；模型文字不是执行证据。 | [第 18 章](../../curriculum/10-system-design/docs/18-ProductionAgentBackend.md) |
| 供应商接受通知等于用户已读 | 渠道可能没有送达或已读证明，只记录确有依据的状态。 | [第 14 章](../../curriculum/10-system-design/docs/14-RealtimeReadHeavySystems.md) |
| 版本齐全就能完全重放 | 输入、工具状态、随机性与时间仍可能变化；区分回看历史、隔离回放与重新执行。 | [第 12 章](../../curriculum/10-system-design/docs/12-ObservabilityEvaluation与Evolution.md) |

## 数量、窗口与资源

| 容易说错的判断 | 条件、后果与正确做法 | 回看 |
|---|---|---|
| 把输入 Token 和输出 Token 连乘 | 分别计算吞吐，各乘对应单价；总量可按合适口径求和，不能产生无意义的平方单位。 | [第 03 章](../../curriculum/10-system-design/docs/03-Workload与CapacityEstimation.md) |
| 并发槽位数等于每秒吞吐 | 结合每项占用时间，区分在途数量、完成速率和排队时间。 | [第 03 章](../../curriculum/10-system-design/docs/03-Workload与CapacityEstimation.md) |
| 平均处理量等于到达量就足够 | 没有消化积压的余量；随机时长与突发还会放大等待。 | [第 09 章](../../curriculum/10-system-design/docs/09-QueueBackpressure与LongRunningTask.md) |
| 把 P99 相加当全链路 P99 | 用同一次请求的关键路径与端到端分布；并行阶段和样本相关性都不能忽略。 | [第 12 章](../../curriculum/10-system-design/docs/12-ObservabilityEvaluation与Evolution.md) |
| 修改 SLO 分母让错误率变好看 | 资格范围在故障之前确定；本应受理却因自身容量拒绝的请求不能事后剔除。 | [第 02 章](../../curriculum/10-system-design/docs/02-Requirement与SLO.md) |
| 文件 1 TB 就能直接算 embedding 费用 | 先抽样得到文本、OCR 比例、块数与 Token；字节数包含图片与压缩开销。 | [第 17 章](../../curriculum/10-system-design/docs/17-EnterpriseRAGSystemDesign.md) |

## 重复、并发与恢复

| 容易说错的判断 | 条件、后果与正确做法 | 回看 |
|---|---|---|
| 超时就是失败，可以换键再来一次 | 保留未知，沿原业务身份核对；暂时查询未找到也可能与旧请求竞争。 | [第 08 章](../../curriculum/10-system-design/docs/08-Consistency与Idempotency.md) |
| 有锁就永久防重 | 锁约束并发窗口，幂等约束同一意图跨时间重复；旧执行者还需要提交边界保护。 | [第 08 章](../../curriculum/10-system-design/docs/08-Consistency与Idempotency.md) |
| 发出递增 fencing 数字就安全 | 实际资源必须认可执行权转移并原子拒绝旧代际；不参与协议的外部服务不会自动受保护。 | [第 08 章](../../curriculum/10-system-design/docs/08-Consistency与Idempotency.md) |
| 消息系统确认就是业务提交 | 发布确认和消费确认不是同一个事实；结果已写、ACK 前退出仍可能重投。 | [第 09 章](../../curriculum/10-system-design/docs/09-QueueBackpressure与LongRunningTask.md) |
| 有 Outbox 就获得端到端恰好一次 | 它保存可靠派发依据，不消除派发重投，也不把外部世界纳入本地事务。 | [第 05 章](../../curriculum/10-system-design/docs/05-DataFlow与StateMachine.md) |
| 补偿等于数据库回滚 | 补偿是新的业务动作，也可能失败；对账要检查真实结果并分配修复责任。 | [第 08 章](../../curriculum/10-system-design/docs/08-Consistency与Idempotency.md) |
| 检查点提前记到最大 ID 更高效 | 目标未提交或较早批次未完成时会永久跳过数据；保存连续完成边界并允许安全重复。 | [第 15 章](../../curriculum/10-system-design/docs/15-LargeScaleDataProcessingSystems.md) |
| Session、Lease、Progress 全部可丢 | 按丢失对撤销、排他和恢复的影响分类，不按对象名字分类。 | [第 04 章](../../curriculum/10-system-design/docs/04-API数据模型与StateOwnership.md) |

## 缓存、分片与实时结果

| 容易说错的判断 | 条件、后果与正确做法 | 回看 |
|---|---|---|
| 更新数据库再删缓存就绝不会读旧 | 慢读者可能在删除后回填旧值；按新鲜度和安全要求选择失效、版本与权威核对。 | [第 06 章](../../curriculum/10-system-design/docs/06-Cache与HotPath.md) |
| 缓存值含版本号就自动防覆盖 | 写入者还要在实际边界检查版本是否有效；空缓存不证明旧版本仍可写入。 | [第 06 章](../../curriculum/10-system-design/docs/06-Cache与HotPath.md) |
| 哈希均匀就能优化全部查询 | 查询若缺少路由键可能扇出所有分区，增加尾延迟与部分失败。 | [第 07 章](../../curriculum/10-system-design/docs/07-PartitionRouting与Fanout.md) |
| 局部 Top K 永远不够或永远足够 | 精确一致排序、过滤已完成、记录不重复等条件决定证明是否成立；后置过滤和跨片聚合会改变问题。 | [第 07 章](../../curriculum/10-system-design/docs/07-PartitionRouting与Fanout.md) |
| 窗口里没有事件，就说明从未处理 | 旧事件可能已被挤出窗口；窗口、去重寿命和可恢复日志需要分别定义。 | [第 14 章](../../curriculum/10-system-design/docs/14-RealtimeReadHeavySystems.md) |
| 防抖可以阻止旧响应覆盖新输入 | 防抖减请求，响应适用性还需当前输入或请求序号判断。 | [第 14 章](../../curriculum/10-system-design/docs/14-RealtimeReadHeavySystems.md) |

## 授权、预算与外部协议

| 容易说错的判断 | 条件、后果与正确做法 | 回看 |
|---|---|---|
| 命中用户缓存就不必重新确认权限 | 用户的资格和来源适用性会变化；缓存身份不是授权凭证。 | [第 11 章](../../curriculum/10-system-design/docs/11-MultiTenancy与Security.md) |
| 回滚索引也把 ACL 一起回滚 | 内容资源与当前安全状态分开；旧代际不能复活撤权或已删除资料。 | [第 17 章](../../curriculum/10-system-design/docs/17-EnterpriseRAGSystemDesign.md) |
| 限流本地化一定超发 | 守恒额度可维护硬上限；关键是分配、消耗、回收和旧额度失效协议，代价是闲置与协调。 | [第 13 章](../../curriculum/10-system-design/docs/13-HighConcurrencyTransactionalSystems.md) |
| 刷新失败后重用旧 Refresh Token 总安全 | 轮换与重用检测取决于供应商；协调锁不能改变其协议。 | [第 13 章](../../curriculum/10-system-design/docs/13-HighConcurrencyTransactionalSystems.md) |
| 二维码未被 TTL 清理就有效 | 交换边界必须查当前有效期、绑定和状态；已交换与已过期不是同一条成功路径。 | [第 13 章](../../curriculum/10-system-design/docs/13-HighConcurrencyTransactionalSystems.md) |
| 流式用量块丢了，就按零结算 | 记录尝试身份和待核对费用；预留暂不释放，真实超支不能靠截断账本隐藏。 | [第 16 章](../../curriculum/10-system-design/docs/16-LLMGateway与MultiTenantAIPlatform.md) |
| 沙箱允许联网就等于允许导出数据 | 环境能力与业务授权是两个边界，高风险动作还需对象、参数与批准绑定。 | [第 11 章](../../curriculum/10-system-design/docs/11-MultiTenancy与Security.md) |

## 验证与架构取舍

| 容易说错的判断 | 条件、后果与正确做法 | 回看 |
|---|---|---|
| 多 Agent 比单 Agent 必然更强 | 要证明分工独立性、协调成本与实际质量收益；不能用框架数量替代结果。 | [第 18 章](../../curriculum/10-system-design/docs/18-ProductionAgentBackend.md) |
| 确定性代码算对，业务结论就对 | 仍需正确口径、权限、数据和因果证据；渠道贡献不等于原因。 | [第 19 章](../../curriculum/10-system-design/docs/19-VerticalAIAgentPatterns.md) |
| 离线准确率高，就全部换慢方案 | 看样本不确定性、场景、时限、完成率和成本，分流与灰度验证。 | [第 12 章](../../curriculum/10-system-design/docs/12-ObservabilityEvaluation与Evolution.md) |
| 逻辑模型通过就叫生产级验收 | 明确哪些是手算、单元、模拟、多连接、外部集成和真实负载；未运行的层级不能报通过。 | [第 12 章](../../curriculum/10-system-design/docs/12-ObservabilityEvaluation与Evolution.md) |
