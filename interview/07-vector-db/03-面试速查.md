## 一分钟口述

“先保证文档与查询在[兼容向量空间](01-高频面试题.md#vector-db-q02)中，明确距离和合法候选范围，再建立精确搜索基准。数据和负载需要时，用 HNSW、IVF 或量化换取资源优势，并测近邻召回、业务质量与尾延迟。上线还要[管理记录身份、更新删除、查询可见性和模型迁移](01-高频面试题.md#vector-db-q18)，不能只证明单次近邻搜索很快。”

## 数学与机制：一句结论带一个条件

| 问到什么 | 直接回答 |
|---|---|
| [余弦与内积](01-高频面试题.md#vector-db-q03) | 余弦除去两边模长；两边单位化时等于内积。零向量需单独处理。 |
| L2 排名 | 单位向量有 `L2²=2−2 dot`；排序可等价，数值阈值不能照搬。 |
| [索引真值](01-高频面试题.md#vector-db-q05) | 在同快照、编码、度量、过滤与并列规则下算精确 Top-K。 |
| ANN Recall | 近似结果与精确目标的交集比例；空目标单列，和业务相关性不同。 |
| [HNSW](01-高频面试题.md#vector-db-q06) | 高层导航、底层候选扩展；M 管连接，建图和查询各有搜索宽度。 |
| IVF | 先选区域再扫列表；nlist 是总列表，nprobe 是探测列表数。 |
| [IVF_FLAT](01-高频面试题.md#vector-db-q09) | 已选列表内原向量计分，未选列表仍可能有真近邻。 |
| [PQ](01-高频面试题.md#vector-db-q11) | 子向量用码字编码，查询查表估距离；候选漏检与量化误差分开看。 |
| 精算 | 只能修复候选内排序，不能找回候选外真近邻。 |

度量接口以 [Faiss 定义](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances)等实际实现为准，不能把 distance、平方 distance 与负内积混成一个分数。

## 结果差：按三层定位

**第一层，数据与表示**：记录是否真正存在且可见？文档和查询是否同一编码协议？度量、归一化、版本和租户过滤是否正确？

**第二层，索引近似**：[同一合法集合的精确搜索能找到吗](01-高频面试题.md#vector-db-q08)？能找到才继续查 HNSW 搜索宽度、图质量，或 IVF 探测列表、量化和扫描上限。

**第三层，业务相关性**：精确近邻也不相关时，检查嵌入模型、领域语义、精确术语和数据结构。此时单纯扩大 ANN 搜索通常不解决问题。

## 结果不满 K：不要先怪数据库

1. 合法集合本来有 K 条吗？
2. 使用的是[前过滤、后过滤、过滤感知搜索还是迭代扫描](01-高频面试题.md#vector-db-q13)？
3. 候选被过滤、去重或扫描预算截断了吗？
4. 执行计划是否使用预期索引，数据是否在所需一致性视图中？
5. 同范围精确搜索返回什么？

[pgvector 的迭代扫描](https://github.com/pgvector/pgvector#iterative-index-scans)与 [Elasticsearch 的 filtered kNN](https://www.elastic.co/docs/solutions/search/vector/knn/filtered-knn-search)是不同产品接口的解法，不可互换配置名或保证。

## 更新与重建：五句话

- 稳定 ID 标识对象，内容版本与嵌入版本标识状态。
- 同 ID 重试处理重复，版本条件防止旧写覆盖；文档缩短还要清旧块。
- [新代际先回填并追上连续增量](01-高频面试题.md#vector-db-q18)，删除和权限变化不能漏。
- 编码器与索引联合切换，故障后先核实际提交状态。
- 回滚前验证旧代际的新鲜度和当前授权，旧文件存在不代表可恢复。

[写入确认、持久化、索引完成、查询可见和空间回收](01-高频面试题.md#vector-db-q16)分别说明。当前授权不得因内容回滚而倒退。

## 分布式回答的证明边界

[局部精确 Top-K 可组成全局 Top-K](01-高频面试题.md#vector-db-q19)，需要同计分和并列规则、同范围与快照、无跨片重复。ANN、量化、去重和失败分片都可能破坏前提。超时要明确失败或部分结果，不伪装成空集。

[分片拆数据，副本复制数据，备份保存可恢复历史](01-高频面试题.md#vector-db-q15)。三者不能互相替代。

## 估算与选型

[原始 float32 向量](01-高频面试题.md#vector-db-q20)为 `N×D×4` 字节；再加索引结构、元数据、ID、缓存、副本和构建临时空间。明确 GB/GiB、单机/集群、稳态/峰值。

选型顺序：业务质量和权限边界 → 精确基准 → 库或数据库形态 → 索引参数曲线 → 更新/故障实验。Faiss、PostgreSQL 扩展、搜索引擎与专用向量服务各有职责，[不能按品牌永久排名](01-高频面试题.md#vector-db-q21)。

最后一句要能落到证据：“我在[同一数据、过滤、质量目标和负载](01-高频面试题.md#vector-db-q23)下比较了哪些方案，哪些条件尚未验证。”没有做过的压测与线上收益应明确为计划。
