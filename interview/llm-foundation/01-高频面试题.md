## LLM-001｜Token 是什么，为什么不直接按汉字或单词处理？

Token 是 Tokenizer 根据固定词表和切分规则得到的处理单位，模型接收的是对应 ID。它可能是词、子词、字节片段或特殊标记；文本长度不能直接当 Token 数。切分规则与模型训练配套，ID 本身不表示大小或相似程度。实际请求还包括消息模板和工具描述，因此预算应以目标模型的实际编码结果为准。

**追问：同一句中文换了模型，为什么长度和预算可能改变？**

推理依据：[第 02 章](../../curriculum/06-llm-foundation/docs/02-TokenContext与LongContext.md)。

## LLM-002｜窗口很长，为什么仍然不能无限塞材料？

先区分输入上限、输出上限与共享总窗口的具体约定。即使能装下，输入计算、KV 容量和有效证据利用率仍有限。应先保留本次任务必需的信息，再用实际模板计数并预留输出和余量；不能把一个通用字符比例当成服务保证。压缩改变的是送入模型的信息，丢掉关键条件也会改变正确答案。

**追问：上下文还没满，为什么仍可能值得检索或压缩？**

推理依据：[第 02 章](../../curriculum/06-llm-foundation/docs/02-TokenContext与LongContext.md)。

## LLM-003｜Lost in the Middle 是否意味着中间信息一定读不到？

不是。相关研究表明，特定模型和任务对信息位置敏感，长输入中的相关材料处于中间时表现可能下降。这是有效利用能力的问题，不等于一条机械的“中间不可见”规则。验证时应固定问题、证据与总长度，只改变关键证据的位置，并区分未装入、被截断与装入后未利用。

**追问：如何设计实验排除材料内容差异的影响？**

推理依据：[第 02 章](../../curriculum/06-llm-foundation/docs/02-TokenContext与LongContext.md)。

## LLM-004｜从 Prompt 到一段回答，底层发生了什么？

应用先按模型的消息模板组织输入，Tokenizer 得到 ID。模型把 ID 映射成表示，经过 Transformer 得到下一位置的 logits，再由解码规则选 Token。选中的 Token 加入已生成序列并在后续步骤参与条件生成；达到停止条件后结束。普通路径下首个输出来自输入 Prefill 的末位置分布，后续通常逐步 Decode。推测解码可以批量验证候选，因此不能说任何实现一次前向都只输出一个 Token。

**追问：流式分片、模型 Token 与一次前向是否一一对应？**

推理依据：[第 05 章](../../curriculum/06-llm-foundation/docs/05-Generation与Decoding.md)。

## LLM-005｜Transformer 中 Attention、FFN、残差和归一化怎样配合？

Attention 根据可见位置间的匹配把信息混合到当前表示。FFN 对每个位置的表示做带非线性的变换；位置之间的交换不是由这一独立的 FFN 完成。残差把子层输入与其输出相加，归一化调整特征尺度。具体 Pre-Norm、Post-Norm、LayerNorm、RMSNorm 要看架构，不能把一张示意图当成所有模型的固定顺序。

**追问：三个 Token 的隐藏维度为 8，最后词表投影为何不是一个 8 维的段落向量？**

推理依据：[第 03 章](../../curriculum/06-llm-foundation/docs/03-TransformerBlock.md)。

## LLM-006｜Q、K、V 从哪里来，Attention 怎样算？

隐藏表示通过不同的学习投影得到 Q、K、V。某位置的 Q 与可见位置 K 做匹配，除以缩放因子，加入因果及填充掩码，经 softmax 得到权重，最后对 V 加权求和。Q/K 决定“从哪里取多少”，V 提供取回的内容；因果上不可见的位置权重应为零。

**追问：为什么把不可见位置的分数乘零并不正确？**

推理依据：[第 04 章](../../curriculum/06-llm-foundation/docs/04-Attention与Position.md)。

## LLM-007｜为什么使用多个 Attention Head？

多个 Head 使用不同投影，在不同表示子空间中并行建立关系，结果拼接或合成后再投影回隐藏表示。它们不保证各自固定负责某种语法。还要区分查询 Head 与 KV Head：标准 MHA 不共享 KV，GQA 在一组查询头间共享，MQA 进一步共享，主要影响容量与计算取舍，并不是随意改头数就保持原模型效果。

**追问：计算 KV 容量时应代入哪一种 Head 数？**

推理依据：[第 04 章](../../curriculum/06-llm-foundation/docs/04-Attention与Position.md)。

## LLM-008｜为什么有 Attention 还需要 FFN？

Attention 主要完成位置间的信息选择和混合，FFN 对混合后的每个位置进行非线性特征变换，常先扩维再降回隐藏维度。只有不断混合现有表示，并不能替代这些逐位置的学习变换。实际 FFN 也可能采用门控等结构；解释时先说作用，再结合具体模型，不把所有参数都归给 Attention。

**追问：FFN 会直接把第三个位置的数据搬到第一个位置吗？**

推理依据：[第 03 章](../../curriculum/06-llm-foundation/docs/03-TransformerBlock.md)。

## LLM-009｜RoPE 怎样让 Attention 感知位置？

RoPE 按位置对 Q、K 的成对维度做旋转。两个不同位置的旋转向量做点积时，关系可以写成与相对位置差相关的形式，因此位置信息进入匹配过程。它不是把页码作为自然语言贴在 Token 上，也不意味着训练长度之外一定可靠；延长上下文仍需检查具体位置扩展与模型能力。

**追问：为什么理解相对位置不等于无限长度泛化？**

推理依据：[第 04 章](../../curriculum/06-llm-foundation/docs/04-Attention与Position.md)。

## LLM-010｜多模态模型如何接收图片，和 OCR 有什么差别？

常见视觉语言模型先把图像分块或缩放，经视觉编码器得到特征，再通过投影或融合与语言表示结合，并通过训练学会联合使用。OCR 主要提取文字，不能完整表达曲线、空间或版面关系；直接视觉也不自动保证小字与表格识别正确。排障应分别检查输入区域、感知、图文对应、计算和输出，预算与预处理按具体模型确认。

**追问：图表增长率答错，怎样区分读错数字和算错？**

推理依据：[第 10 章](../../curriculum/06-llm-foundation/docs/10-MultimodalFoundation.md)。

## LLM-011｜KV Cache 为什么有效，为什么又限制并发？

在固定前缀、权重和位置规则下，因果模型历史位置的 K/V 无需因后来追加 Token 而重算。新位置计算自己的 Q/K/V，读取历史 K/V 并追加新缓存。缓存节省重复计算，却随层数、KV 头数、维度、精度和所有请求的缓存长度增长；标准全注意力的原始容量是这些量相乘并计入 K、V 两份。其他架构必须换成对应估算。

**追问：为什么不必同样保存全部历史 Q？**

推理依据：[第 06 章](../../curriculum/06-llm-foundation/docs/06-KVCache与PrefillDecode.md)。

## LLM-012｜Prefill 与 Decode 分别做什么，分离它们就一定快吗？

Prefill 处理输入前缀并建立缓存，末位置的分布可用于选出首个输出。Decode 在后续生成中反复处理新增位置并访问历史缓存。二者的资源瓶颈常不同，因此可以分别调度或部署；但跨设备搬运 KV、排队、网络和输入输出长度都会影响收益。分离是具体负载下的方案，不是无成本加速。

**追问：首 Token 很慢与后续 Token 很慢，调查方向有何不同？**

推理依据：[第 06 章](../../curriculum/06-llm-foundation/docs/06-KVCache与PrefillDecode.md)。

## LLM-013｜PagedAttention、FlashAttention 与推理引擎解决什么？

PagedAttention 将请求逻辑 KV 映射到物理块，并配合分页访问计算，减少连续预留和重复存储带来的浪费，但仍有尾块与管理开销。FlashAttention 主要优化注意力的内存读写，不等于给请求做分页。推理引擎还会调度多个请求、复用前缀、处理资源限制；默认行为须按版本核对。它们不能替代输入预算和真实负载测试。

**追问：连续批处理为什么不等于一次 HTTP 提交多条请求？**

推理依据：[第 07 章](../../curriculum/06-llm-foundation/docs/07-ServingEngine与性能.md)。

## LLM-014｜怎样拆解模型请求延迟？

先说明观测位置，再拆排队、网络、预处理、输入计算、逐步生成和完成事件。TTFT 是到首个输出 Token 的时间；平均 TPOT 可按首尾 Token 间隔除以剩余间隔数计算，不能用分片间隔冒充逐 Token 指标。还应记录输入输出长度、并发、缓存命中及错误；吞吐改善可能以某些请求的尾延迟为代价。

**追问：总耗时变长，但每个 Token 的速度没变，可能是什么原因？**

推理依据：[第 07 章](../../curriculum/06-llm-foundation/docs/07-ServingEngine与性能.md)。

## LLM-015｜Temperature、Top-k、Top-p 如何改变输出？

Temperature 调整同一步 logits 的相对差距，正温度下不会改变其大小排序；采样分布会变得尖锐或平缓。Top-k 按数量截断候选，Top-p 按累计概率选择最小前缀，之后重新归一化。实际执行顺序和支持范围由实现决定。温度零常作为贪心选择的接口约定，不能代入除零公式，也不能保证跨设备、版本和服务负载绝对复现。

**追问：候选概率为 0.92、0.05、0.03，Top-p=0.9 会保留几项？**

推理依据：[第 05 章](../../curriculum/06-llm-foundation/docs/05-Generation与Decoding.md)。

## LLM-016｜Model API 应怎样抽象？

上层组织任务输入和所需能力，下层适配模型、消息模板、流事件、输出限制、使用量和错误。适配器要保留不同提供方的重要差异，而不是静默忽略不支持的参数。应用必须区分 HTTP 成功、生成完整、可解析、符合业务规则与外部动作完成；工具参数需完整组装、校验和授权后才能执行。

**追问：JSON 结构正确，但订单 ID 与当前用户不匹配，谁负责拒绝？**

推理依据：[第 08 章](../../curriculum/06-llm-foundation/docs/08-ModelAPI与Selection.md)。

## LLM-017｜怎样证明模型选型合理？

先定义任务、质量门槛、输入长度、延迟、预算和数据约束，再在同一套有代表性的任务上比较。开发集用于迭代，保留独立测试集，避免近重复和同来源泄漏。比较每个成功任务的成本，并纳入重试、拒绝、失败和尾延迟，而非只看单次调用价。成对评审需盲化顺序并检查长度等偏差；排行榜不能替代本任务验证。

**追问：多花一分钟换更高准确率，交互查询与离线分析应怎样分别判断？**

推理依据：[第 08 章](../../curriculum/06-llm-foundation/docs/08-ModelAPI与Selection.md)。

## LLM-018｜Embedding 怎样把一段文本变成一个向量？

文本经 Tokenizer 与编码器得到各位置的上下文表示，再用模型训练约定的池化方法形成段落表示，可能继续投影和归一化。相似性来自训练信号塑造的空间，不是把 Token ID 平均；均值池化应排除填充位置。更换模型、池化、模板或归一化约定都可能改变空间，同维不等于兼容，也不保证更高维一定更好。

**追问：句子末尾加很多 Padding，为什么不应改变有效文本的均值表示？**

推理依据：[第 09 章](../../curriculum/06-llm-foundation/docs/09-Embedding与Reranker.md)。

## LLM-019｜Bi-Encoder 与 Cross-Encoder 的取舍是什么？

双塔分别编码查询与文档，因此文档表示可以预计算并建索引，适合大规模候选召回。交叉编码把一个查询与一篇候选联合计算相关性，使两者充分交互，但每对输入都要计算，常用于较小候选集合的重排。成本与收益要在任务中验证，重排也不一定都使用交叉编码。它不能找回从未进入候选集的正确文档。

**追问：交叉编码的分数可以直接当正确概率，或与余弦相似度相加吗？**

推理依据：[第 09 章](../../curriculum/06-llm-foundation/docs/09-Embedding与Reranker.md)。

## LLM-020｜应用工程师应怎样组织一次微调？

先确认是稳定行为缺口，而不是事实缺失、权限或运行故障。整理覆盖正常、缺失、冲突和边界情况的高质量样本，按来源或任务隔离开发与测试，确认模板、截断及损失作用位置。训练时看任务评测，不只看训练损失；部署时绑定基础模型、Adapter、Tokenizer 与模板版本，并验证缓存、回退和线上分布变化。

**追问：训练损失下降但业务成功率下降，为什么不应直接增加训练轮数？**

推理依据：[第 13 章](../../curriculum/06-llm-foundation/docs/13-FineTuning与LoRA.md)。

## LLM-021｜SFT、LoRA、PPO、DPO、GRPO 和蒸馏有什么关系？

这些名称不在同一分类轴。SFT 是示范学习目标；LoRA 是减少可训练参数的方式，可与不同目标组合。PPO 是强化学习算法，DPO 使用偏好对相对参考策略的比较，GRPO 用同一问题的多次采样奖励建立组内相对信号。蒸馏描述向目标模型迁移教师信息，可使用分布或过滤后的示范。应先问拥有什么数据、约束和验证方式，再选择方法。

**追问：GRPO 一组奖励全部相同，组内比较还能提供什么区分信号？**

推理依据：[第 14 章](../../curriculum/06-llm-foundation/docs/14-PostTraining与Distillation.md)。

## LLM-022｜为什么会幻觉，怎么选择干预层？

生成模型优化的是条件生成，并不天然保证每句话被当前事实支持。错误可能早在数据新鲜度、检索、输入截断或权限处发生，也可能是模型误读、计算或编造。先保留当时输入，定位最早可观察的失败；分别评估事实正确性、对证据的忠实度、覆盖率和误拒。RAG 提供证据，Prompt 说明边界，训练改善行为，但真实引用与流利表达都不能单独证明结论。

**追问：引用确实存在，为什么还可能是不受支持的答案？**

推理依据：[第 12 章](../../curriculum/06-llm-foundation/docs/12-Hallucination与干预边界.md)。

## LLM-023｜Prompt Engineering 怎样迭代，怎样证明有效？

先明确任务、允许使用的材料、成功输出和缺信息时的行为，再给必要且一致的示例。用实际发送给模型的完整输入查错，而不是只看编辑器中的 Prompt。改动后在开发样本和保留测试集上检查事实、结构、缺失与冲突处理，以及原来已正确的任务。Prompt 不负责授予权限，增加一句“不要幻觉”也不能替代证据或确定性校验。

**追问：错误承诺减少，但无必要的澄清增多，算优化成功吗？**

推理依据：[第 11 章](../../curriculum/06-llm-foundation/docs/11-PromptEngineering.md)。
