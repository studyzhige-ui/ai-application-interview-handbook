# LLM Foundation｜易混易错点

[本域入口](README.md) · [完整口述答案](01-高频面试题.md) · [面试速查](03-面试速查.md)

本页用错误判断检验机制是否真正理解。以下是教学纠偏，不是对候选人回答的逐字复述，也不代表每一条具有相同出现频次。项目参数、模型版本和未披露条件应按[真实面试来源](../../market/interview-experience/02-analysis/README.md)分别保留。

## 一、输入、结构与注意力

这些纠偏对应[输入与生成](01-高频面试题.md#input-generation)及[Transformer问答](01-高频面试题.md#transformer)，其中逐题链接保留了概念题与手写题的面经边界。

| 容易混淆的判断 | 正确边界 | 怎样现场检验 |
|---|---|---|
| 字符数或单词数可以直接当Token数 | 切分依赖Tokenizer、词表、语言和模板；工具与系统消息也占预算。 | 编码最终请求，不只编码用户正文；更换模型后重新计数。 |
| 长窗口意味着材料都会被同样可靠地利用 | 容量上限与有效利用能力不同，位置、干扰和截断均可能影响结果。 | 固定问题、证据和总长度，移动证据位置做对照。 |
| Lost in the Middle意味着中间位置被硬屏蔽 | 原研究是特定任务与模型上的表现现象，不是通用Mask规则。 | 先确认输入是否实际到达，再测位置效应，不能只凭一次失败下结论。 |
| Token ID接近就表示语义接近 | ID只是词表索引，语义来自学习到的表示。 | 不用ID差或ID均值做相似度。 |
| Encoder不能生成，Decoder-only总是更好 | Encoder—Decoder同样能生成；任务、目标和系统约束决定结构取舍。 | 区分Encoder、Decoder组件与整个Encoder—Decoder模型。 |
| Q/K/V都是从同一个地方产生 | Self-Attention通常同源；Cross-Attention的Q与K/V来源不同。 | 画出被查询侧与被读取侧，再标投影矩阵。 |
| 把未来位置的分数乘0就完成了Mask | exp(0)仍非零；目标是使被屏蔽位置的最终注意力权重为零。 | 改动未来Token，检查此前位置输出是否不变；单测全屏蔽行。 |
| 除以sqrt(dk)是因为向量长度固定要归一化 | 它对点积尺度作调整；常用解释依赖分量方差等简化假设，不是单位向量归一化。 | 区分缩放点积、softmax和向量L2归一化。 |
| 多头保证每个头固定负责某种语法 | 多投影提供不同表示子空间，具体分工是训练结果，不能预设。 | 解释投影、分头、并行Attention、合头和输出投影。 |
| FFN直接在Token之间交换内容 | 标准FFN逐位置做特征变换，Attention承担主要跨位置信息混合。 | 保持其他位置不变，说明哪一层引入了跨位置依赖。 |
| RoPE能保证无限长外推 | 位置表示不消除训练分布和资源边界。 | 核对目标模型的位置扩展配置，并测长输入任务。 |

位置效应的适用范围见[Lost in the Middle](https://arxiv.org/abs/2307.03172)，旋转位置表示见[RoFormer](https://arxiv.org/abs/2104.09864)。深入推导回到[Attention与Position](../../curriculum/06-llm-foundation/docs/04-Attention与Position.md)。

## 二、采样、缓存与性能

先对照[采样、KV与服务性能问答](01-高频面试题.md#inference-serving)中的原始问法；本节将机制转成检查项，不把教学边界测试计为新增原题。

| 容易混淆的判断 | 正确边界 | 怎样现场检验 |
|---|---|---|
| 低温可以保证事实正确 | 温度改变分布尖锐程度，错误答案也可能获得最高概率。 | 固定证据与模型，分别统计一致性、正确性和覆盖率。 |
| 正温度缩放会重新排列同一组logits | 正数缩放保持排序，但改变采样概率差距。 | 对一小组logits计算不同正温度下的softmax。 |
| 所有接口都能把temperature直接设为0 | 服务可能用0表示贪心；特定库的温度变换器可能只接受正数。 | 查实际接口；Transformers采样还需确认do_sample。 |
| 温度0能在任何部署上绝对复现 | 模型、模板、服务版本、数值内核与执行环境都需受控。 | 记录版本和完整请求，多次运行；不要将固定seed当跨平台保证。 |
| 流式分片数就是Token数 | 网络事件可以合并、拆分或携带控制信息。 | 使用Token级观测或usage，不用SSE事件数代算TPOT。 |
| KV保存历史文本或全部Q/K/V | 标准缓存保存各层K/V张量；历史Q通常无需为后续匹配重复保存。 | 区分文本历史、前缀KV、语义检索和回答缓存。 |
| 缓存以后每个新Token都是常数成本 | 仍需读取和匹配可见历史；完整注意力的缓存与访问随长度增长。 | 分开测不同长度下的Decode速度和KV占用。 |
| 前缀文字相同就可以跨模型或Adapter复用KV | 权重、实际Token、位置与实现约定必须兼容。 | 用缓存键和版本约束验证；不兼容时隔离或失效。 |
| PagedAttention让显存不再成为限制 | 分块减少特定浪费，真实KV、权重及管理开销依然存在。 | 对照容量模型、活跃序列和尾块开销，而非只看总显存。 |
| 4位权重意味着总运行显存同比缩小 | KV、激活、工作区、量化元数据及计算精度不按同一比例变化。 | 分项估算，再测实际峰值。 |
| TTFT降低意味着用户全程更快 | 输出更长、后续生成变慢或尾延迟变大，都可能抵消收益。 | 固定长度与并发，同时报告TTFT、TPOT、完成时间和失败率。 |
| 客户端断开就是GPU计算已经取消 | 取消需到达实际执行器，并确认请求停止和资源回收。 | 关联请求ID查看服务端终态，不只观察浏览器。 |

采样参数的具体接口边界见[Transformers生成工具](https://huggingface.co/docs/transformers/internal/generation_utils#transformers.TemperatureLogitsWarper)；缓存张量和推理复用机制见[官方KV说明](https://huggingface.co/docs/transformers/cache_explanation)。

## 三、输出契约、选型与检索

对应面经入口在[模型应用问答](01-高频面试题.md#application-quality)，涵盖成功判断、Prompt、Judge、模型与Embedding选型；综合多模态排障已单独标注教学补足。

| 容易混淆的判断 | 正确边界 | 怎样现场检验 |
|---|---|---|
| HTTP 200、合法JSON和业务成功是一回事 | 传输、生成终态、结构、事实、权限和动作结果是不同层。 | 分别记录完成原因、解析结果、规则/授权检查与实际回执。 |
| Schema通过就可以执行工具 | Schema能约束已声明的类型与范围，不能自动知道当前用户有无权限。 | 用合法格式但越权的对象ID测试。 |
| 只写“不要幻觉”就足够 | 缺事实、错误证据和推理失误需要不同干预。 | 找到最早失败环节，再选择检索、工具、验证或拒答。 |
| 引用存在就代表结论有依据 | 引用可能不支持该陈述，时间、对象或条件也可能不一致。 | 做逐陈述的证据支持检查。 |
| Judge高分就是事实正确率 | 评价器可能受标注标准、顺序或偏好影响。 | 用人工金标和确定性检查校准，高低分区间都抽样。 |
| 每次调用最便宜的模型总成本最低 | 重试、失败、长输出和人工处理都会增加成功任务成本。 | 按相同质量门槛计算成功任务总成本。 |
| 7B/32B或某个模型名字足以证明选型 | 参数规模和产品名不能替代任务评测；版本与部署条件也需记录。 | 比较真实任务、边界失败、延迟、资源和成本。 |
| 任何文本表示平均后都能成为好Embedding | 需要匹配模型训练约定的编码、池化与归一化。 | 排除Padding，核对query/document模板及实际检索效果。 |
| 同维Embedding可以混入同一空间 | 模型、模板和归一化改变后，几何含义可能不同。 | 重建或验证兼容性，不能仅比较维度。 |
| Reranker能找回召回阶段漏掉的文档 | 它只能处理收到的候选。 | 将召回覆盖与重排排序分开测。 |
| 0到1的相关性分数就是校准概率 | 数值范围不能证明概率含义或跨查询可比性。 | 查训练目标、输出定义与校准结果。 |
| Vision模型就是OCR，多抽帧总能改善 | 视觉关系、文字识别、时间对应是不同问题；更大输入也增加成本和干扰。 | 分别测感知、证据对齐、推理与输出。 |

Embedding的任务和编码设置见[Sentence Transformers语义检索说明](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)。输出执行边界继续看[Agent工具执行](../../curriculum/09-agent/docs/06-ToolExecutionAndFailure.md)。

## 四、训练：不要混淆数据、目标和参数方式

原始问法及其未披露条件见[模型适配问答](01-高频面试题.md#adaptation-training)：重点区分方法比较、项目动机和收益归因，保留S334没有训练配置的边界。

| 容易混淆的判断 | 正确边界 | 怎样现场检验 |
|---|---|---|
| Few-shot是在当前请求里训练模型参数 | 提示示例作为条件输入，普通推理不自动做梯度更新。 | 指出示例在哪个输入位置，是否真的调用训练过程。 |
| LoRA和SFT需要二选一 | SFT是学习目标，LoRA是参数更新方式，可以组合。 | 分别回答学什么、用什么数据、更新哪些参数。 |
| LoRA把基础权重强制变成低秩 | 低秩限制的是新增更新量BA，基础权重仍保留。 | 写出W加ΔW，并核对A、B形状。 |
| LoRA参数占比就是总训练显存占比 | 冻结权重仍参与前向，激活及其他训练开销仍存在。 | 分列权重、梯度、优化器、激活，而非套单矩阵参数比。 |
| 所有LoRA部署都没有额外推理开销 | 合并、量化、多Adapter及服务实现各有条件。 | 报告是否合并、模型版本和实测路径。 |
| DPO就是丢掉坏答案再做SFT | 标准DPO使用同一输入的偏好对及相对参考策略概率比较。 | 解释chosen/rejected和reference分别提供什么信息。 |
| DPO损失下降等于好答案概率或真实性一定上升 | 优化的是相对偏好目标，标签和参考分布会影响结果。 | 看独立任务集与事实标准，不能把sigmoid分数当业务准确率。 |
| GRPO不用critic，所以不需要奖励或采样 | 原始方法仍采样同题多份输出、计算奖励和相对优势。 | 区分奖励模型/规则、价值估计和生成策略。 |
| GRPO一组奖励相同仍能区分组内优劣 | 相对信号为零，零方差需要数值处理；其他正则项可能仍有影响。 | 单测全同奖励，不把“无区分”说成整个训练绝不更新。 |
| loss下降或跑满轮数即可宣布收敛并上线 | 优化状态、验证表现、预算和业务门槛是不同判断。 | 核对数据泄漏、保留集、关键边界和检查点选择。 |
| SFT后成功率上升即可归因于SFT | 同时增加检索轮次、Token或更换工具会混淆因果。 | 固定预算对照，再分别改变训练与推理预算。 |
| 教师更强，蒸馏数据便全部正确 | 教师也可能错；合成标签需要过滤和独立验证。 | 不仅让同一个教师自评自己生成的数据。 |
| MoE激活参数少，权重显存就等于激活参数量 | 被选中参与计算的参数与需存储/分布的总参数不是同一量。 | 按实际专家放置、精度和通信方案估算。 |

机制可核对[LoRA](https://arxiv.org/html/2106.09685v2#S4)、[DPO](https://arxiv.org/html/2305.18290v3#S3)和[DeepSeekMath的GRPO定义](https://arxiv.org/html/2402.03300v3#S4)。这些事实不证明任何未测试项目已获得收益。
