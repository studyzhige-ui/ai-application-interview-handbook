# LLM Foundation｜面试速查

[本域入口](README.md) · [口述答案](01-高频面试题.md) · [易混易错点](02-易混易错点.md) · [课程](../../curriculum/06-llm-foundation/README.md)

用一条链回忆：**任务与材料 → 模板和Token → 表示与Attention → 下一Token分布 → 解码 → 服务交付 → 应用校验。** 出错时先找最早失败的层，再决定改什么。以下是教学压缩，不是频次榜或某个项目的实测报告。

## 1. 一分钟解释一次生成

可沿[输入到生成的原题与答案](01-高频面试题.md#input-generation)复述，再补[服务性能](01-高频面试题.md#inference-serving)和[应用验收](01-高频面试题.md#application-quality)的条件。

1. 应用按目标模型模板组织消息、工具和材料；实际编码后检查输入与输出预算。
2. 模型将Token ID变成表示，通过网络得到下一位置logits。Self-Attention混合可见位置，FFN逐位置变换特征。
3. 解码器按贪心或采样规则选Token。Temperature调分布，Top-k限制数量，Top-p限制累计概率候选集。
4. Prefill建立输入前缀缓存，后续Decode复用历史K/V并处理新增位置；停止原因与网络分片要分开识别。
5. 应用检查生成终态、结构、事实、业务条件和权限，最后验证真实任务结果。模型文本本身不会执行代码或授权写操作。

## 2. 几组必须说清的机制

具体面经证据随[Transformer问答](01-高频面试题.md#transformer)、[应用与检索问答](01-高频面试题.md#application-quality)和[训练边界问答](01-高频面试题.md#adaptation-training)逐题给出；这里压缩回答，不新增题目统计。

| 被问到什么 | 可直接组织的回答 |
|---|---|
| Token与窗口 | Token是模型配套Tokenizer的单位；完整输入还包括模板和工具。能放下不等于能可靠利用。 |
| Q/K/V | 隐藏表示经不同投影形成Q/K/V；匹配QK、缩放、加Mask、softmax，再聚合V。Cross-Attention要说明不同来源。 |
| Mask | 因果Mask排除未来，Padding Mask排除补齐；保证禁止位置权重为零，处理全屏蔽行。 |
| 多头、FFN、残差 | 多头提供不同关系子空间；FFN逐位置做非线性变换；残差保留加法路径。具体归一化顺序按模型。 |
| 位置 | 位置编码让模型使用顺序；RoPE把位置差带入Q/K匹配，不保证无限长外推。 |
| Encoder与Decoder | 区分组件与整个模型：原Decoder含因果自注意力和读取Encoder的交叉注意力；Decoder-only采用前缀续写。 |
| KV Cache | 复用历史各层K/V，避免重复计算；仍有历史访问与线性增长的缓存，不是回答缓存。 |
| Embedding与Rerank | 分开编码便于大规模召回；联合评分常用于较小候选重排。先有候选，才能重排。 |
| SFT与LoRA | SFT决定示范学习目标；LoRA限制参数更新方式。它们可以组合。 |
| DPO与GRPO | DPO使用偏好对及reference比较；原GRPO同题多采样、组内奖励优势，省去单独critic。效果仍由数据、奖励和评测决定。 |

Attention机制见[原Transformer论文](https://arxiv.org/html/1706.03762v7#S3)，缓存见[官方KV说明](https://huggingface.co/docs/transformers/cache_explanation)。这些概念不能替代目标模型的实际配置。

## 3. 四个量，先说明分母和前提

资源与时延问法见[推理服务部分](01-高频面试题.md#inference-serving)，低秩原理见[模型适配部分](01-高频面试题.md#adaptation-training)；公式、参数手算与统一成本口径用于教学，不是原场提供的实测值。

**标准全注意力的原始KV字节数**

`2 × 层数 × KV头数 × 头维度 × 元素字节数 × 所有请求缓存长度之和`

不含权重、激活、工作区、量化元数据或尾块浪费。查询头数可能不同于KV头数；滑动窗口和特殊缓存架构需改公式。

**单请求平均TPOT**

`(最后Token时刻 − 首Token时刻) / (输出Token数 − 1)`

只有一个输出Token时不适用。网络分片不一定对应Token；先定义观测位置，再比较TTFT、TPOT、完成时间与尾延迟。

**LoRA单矩阵参数量**

`r × (输入维度 + 输出维度)`，原矩阵为`输入维度 × 输出维度`。

这只是可训练矩阵参数比较，不是总显存节省比例。[LoRA原理](https://arxiv.org/html/2106.09685v2#S4)

**成功任务成本**

`全部相关调用、重试及其他纳入成本 / 满足验收条件的成功任务数`

零成功不能得到有限的成功成本。不要将一次便宜调用与一条昂贵但成功的完整任务直接相比；先统一验收和成本范围。

## 4. 选型题：把“我选了谁”变成可复核论证

可从[7B/32B与TinyBERT选型原题](01-高频面试题.md#application-quality)以及[Prompt、RAG与微调取舍原题](01-高频面试题.md#adaptation-training)进入，具体项目和模型约束不要抹掉。

- **先定约束：** 任务、输入长度、质量门槛、错误代价、延迟、成本、部署和数据权限。
- **再做同条件比较：** 保留测试集，记录模型/模板/工具版本、采样与输入输出长度；必要时区分同模板测试和各模型适配后的测试。
- **最后讲取舍：** 哪些任务小模型已足够，哪些失败必须升级；质量改善是否值得额外时延、Token和运维成本。没有数据就说待验证，不编造收益。

| 问题缺口 | 优先考虑什么 | 验证是否选对 |
|---|---|---|
| 目标、格式或边界不清 | Prompt、示例、输出契约 | 改动后做正常、缺失、冲突和回归测试 |
| 事实缺失或经常变化 | 数据、检索与证据更新 | 查召回覆盖、证据时效及引用支持 |
| 需要准确计算或真实动作 | 确定性工具与服务端检查 | 查参数、业务条件、授权、幂等及回执 |
| 稳定行为缺口且有可靠样本 | 评估SFT及合适参数更新方式 | 与原方案同预算对照，检查独立任务集 |
| 只需更低成本或更高吞吐 | 路由、缓存、批处理或部署优化 | 质量不回退前提下比较成功成本与尾延迟 |

## 5. 排障题：从症状走到证据

下表由[推理性能](01-高频面试题.md#inference-serving)、[应用质量](01-高频面试题.md#application-quality)和[训练归因](01-高频面试题.md#adaptation-training)的问答组织成教学排障路径；每个症状不都对应一道直接披露的原题。

| 症状 | 先取什么证据 | 下一步怎么判断 |
|---|---|---|
| 输入超限 | 最终编码序列、工具Schema、服务预算规则 | 区分正文、历史、工具和输出预留；再裁剪、检索或压缩 |
| 材料已给却答错 | 实际输入、证据位置、截断、输出引用 | 分开验证感知/检索、证据利用和推理，不立即归咎模型大小 |
| 首Token慢 | 排队、网络、输入长度、Prefill与缓存命中 | 固定负载后看是等待、长输入还是计算瓶颈 |
| 首Token快但整体慢 | 输出长度、Token间隔、转发与终态时间 | 区分更啰嗦、Decode慢、网络缓冲和后处理 |
| OOM | 权重精度、活跃序列、KV长度和峰值工作区 | 分项估算，减少或调度负载；分页不能创造无限显存 |
| JSON合法却任务失败 | 拒绝/截断终态、Schema、事实与业务校验 | 结构正确只通过一层，不跳过归属、权限和结果核对 |
| Prompt修改看似有效 | 改前改后完整请求、固定测试集和失败分布 | 查是否减少一种错误却增加误拒、澄清或成本 |
| Judge与人工相反 | 评分标准、原输入、顺序及高低分样本 | 校准并分层抽样；不能只复查低分 |
| 训练loss下降、业务变差 | 样本来源、标签、模板、截断、独立验证集 | 先查学错目标或泄漏，不先增加轮数 |
| SFT后效果提升 | 同基座、同工具、同检索预算的对照 | 再分别增加轮次，隔离训练收益与推理预算收益 |

## 6. 版本与回答边界

回到[采样与缓存](01-高频面试题.md#inference-serving)、[Attention实现](01-高频面试题.md#transformer)及[训练方法](01-高频面试题.md#adaptation-training)核对原问与教学展开，再按实际版本作答。

- 采样参数必须按服务或库核对。此次核验的Transformers生成工具源码指向v5.19.0；其温度变换器要求正数，且采样温度须配合do_sample，不能直接移植别家服务的0值约定。[官方接口说明](https://huggingface.co/docs/transformers/internal/generation_utils#transformers.TemperatureLogitsWarper)
- 原始DPO和GRPO的机制不等于每个库版本的默认损失、采样或KL设置。实现问题要给版本和配置；收益问题要给独立评测。[DPO](https://arxiv.org/html/2305.18290v3)、[GRPO](https://arxiv.org/html/2402.03300v3)
- 口述到手写Attention/RoPE时，补上形状、Mask、位置与边界测试；数学式写对不代表广播和缓存位置写对。
- 未披露的模型版本、训练超参、数据量和实际效果保持未知。解释通用机制、给教学手算和介绍个人实测时，明确区分三者。
