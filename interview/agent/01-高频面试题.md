# Agent｜高频面试题

[本域入口](README.md) · [课程](../../curriculum/09-agent/README.md)

以下保留已有课程归纳题与实质回答，适用于口述训练；教学问法不等同于逐字原题。原始流程与模型整理进度见[一手面试分析](../../market/interview-experience/02-analysis/README.md)，目前未完成全部资料的逐题语义整理或正文重写。



### 1. Agent 和普通 LLM Application / Workflow 有什么区别？

核心是主要控制路径由谁决定。工作流可以包含模型、分支和循环，仍按开发者预定义规则推进；Agent 允许模型根据中间观察选择行动。实际应用可以混合控制，按任务收益、风险与验收选择。

[回看第2章的机制](../../curriculum/09-agent/docs/02-WorkflowAutonomyAndRuntimeBoundary.md#core-1)

### 2. 什么是 Agent Harness / Runtime？为什么 Model 外面还要这一层？

模型产生判断或调用候选，但读取、执行、保存、取消与验证要由程序完成。本书用 Runtime 强调推进工作的机制，用 Harness 强调模型外围的执行支撑；二者可重叠，不是必须拆成两个服务。

[回看第1章的机制](../../curriculum/09-agent/docs/01-AgentSystemAndResponsibilities.md#core-2)

### 3. 一个 Minimal Agent Loop 怎么写？

先组织当前输入，请模型提出工具、澄清或完成候选；工具校验执行后将结果回填，再进入下一轮。完成候选要验收，等待、错误、取消和预算停止分别处理。教学例子用固定函数模拟模型，只验证反馈和有限停止。

[回看第3章的机制](../../curriculum/09-agent/docs/03-AgentLoopAndExecutionScopes.md#core-2)

### 4. Run / Turn / Step 怎么区分？

先声明项目口径：Session 是持续会话，Run 是一个目标的执行，Turn 在本书中是一轮判断—行动—观察，Step 是其中操作。产品命名可能不同，例如 Codex Turn 可跨多次推理与工具交互，应按作用域映射。

[回看第3章的机制](../../curriculum/09-agent/docs/03-AgentLoopAndExecutionScopes.md#core-4)

### 5. Runtime Message 和 Event 有什么区别？

Message 表示模型交互，Event 还记录排队、授权、工具开始与取消等程序事实。一次工具调用可对应多个事件，用 call_id 关联请求和结果；不需要把所有事件都放进模型输入。

[回看第3章的机制](../../curriculum/09-agent/docs/03-AgentLoopAndExecutionScopes.md#core-5)

### 6. Agent 为什么会 Dead Loop？怎么防？

常见原因是缺少有效停止条件、反复同一错误，或者工具互相指向形成振荡。联合观察最近动作、错误与实际进展，触发换策略、澄清或停止，并用总预算兜底；合法分页不应因重复工具被禁止。

[回看第8章的机制](../../curriculum/09-agent/docs/08-PlanningGoalAndControl.md#core-4)

### 7. Tool Calling 完整链路是什么？

程序先解析模型候选并找到处理器，检查参数、业务条件和权限，执行后验证返回，再记录必要状态并形成模型可用的观察。模型调用表示与真实执行是两步，HTTP 成功也不自动等于工具或任务验收通过。

[回看第6章的机制](../../curriculum/09-agent/docs/06-ToolExecutionAndFailure.md#core-1)

### 8. Tool schema 为什么不等于安全？

Schema 可以校验已声明的类型、范围和必填规则，例如 minimum=0 可拒绝负数；但对象是否存在、当前身份是否有权操作，需要实际业务与授权检查。解析、规则校验和授权不能互相替代。

[回看第4章的机制](../../curriculum/09-agent/docs/04-ToolContractAndValidation.md#core-3)

### 9. Tool Result 应返回字符串还是结构化对象？

依据结果用途选择表示，不要求所有工具返回复杂 JSON。至少要能区分取得内容、目标为空、权限拒绝和执行失败；模型收到可行动的安全信息，宿主保留必要控制数据，大结果提供可授权回读的引用。

[回看第4章的机制](../../curriculum/09-agent/docs/04-ToolContractAndValidation.md#core-5)

### 10. Tool Failure 怎么分类？

按解析与 Schema、业务输入、权限、临时依赖、取消、宿主故障和未知副作用分开。分类的用途是确定处理者与下一步：有限修参数、程序恢复、澄清、拒绝或核对，不能全部交模型自救。

[回看第6章的机制](../../curriculum/09-agent/docs/06-ToolExecutionAndFailure.md#core-3)

### 11. 哪些 Tool 可以自动 Retry？

只有错误可能暂时恢复、动作可安全重复或下游提供有效幂等契约，并且剩余时间与重试预算允许时，才适合自动重试。500、429 或 timeout 本身不证明安全；结果未知的写操作需查询原动作或在同一有效幂等键下重试。

[回看第6章的机制](../../curriculum/09-agent/docs/06-ToolExecutionAndFailure.md#core-4)

### 12. Tool 已成功但响应超时怎么办？

本地超时不表示远端没执行。保留原业务操作身份，查询下游回执；确认成功就补齐状态，不再创建新动作。可以按有效幂等契约重试；既不能查询也不能安全去重时保持未知并请求核对。

[回看第6章的机制](../../curriculum/09-agent/docs/06-ToolExecutionAndFailure.md#core-5)

### 13. 为什么 Tool 需要 read-only / destructive / concurrency-safe metadata？

这些元数据帮助程序判断副作用、资源冲突和中断风险，但不是授权本身，也不应默认全部发送给模型。只读可能泄密，可并发还要看本次参数、实际资源、依赖与下游配额。

[回看第7章的机制](../../curriculum/09-agent/docs/07-ToolConcurrencyAndCancellation.md#core-2)

### 14. 用户在 Tool 执行中发新消息怎么办？

应用先接收并绑定正确任务，区分补充、修改约束、新任务和取消；在合适决策点追加输入，或按风险停止派发并中断当前活动。已发送模型请求通常不能原地插入，已经发生的动作不会因新消息撤销。

[回看第3章的机制](../../curriculum/09-agent/docs/03-AgentLoopAndExecutionScopes.md#core-6)

### 15. Tool 很多时怎么处理？

先测工具说明成本和误选。少量工具可以直接暴露，目录大时可用权限过滤、任务预筛选或渐进发现，再加载候选的完整说明。分别测候选召回与模型选择，不能只看最终成功率。

[回看第5章的机制](../../curriculum/09-agent/docs/05-ToolRegistrationAndDiscovery.md#core-4)

### 16. ReAct 是什么？和 Plan-and-Execute 区别？

ReAct 将推理、行动与观察交替组织，下一步能够使用新反馈；Plan–Execute–Replan 强调显式阶段和阶段后的计划修订。两者可组合，区别在组织方式，不是一个必须展示思考、另一个必须计划永不变。

[回看第8章的机制](../../curriculum/09-agent/docs/08-PlanningGoalAndControl.md#core-2)

### 17. Planning 越详细越好吗？

不是。计划应足以明确阶段、依赖和验收；过细的预定步骤可能很快失效，也增加维护与输入负担。动态任务随观察更新计划，简单任务可以隐式决定下一步，不必单独设置规划器。

[回看第8章的机制](../../curriculum/09-agent/docs/08-PlanningGoalAndControl.md#core-2)

### 18. Agent Context 由什么组成？

可能来自稳定指令、当前目标与约束、相关历史、状态、记忆、检索证据、工具说明和观察，但按本次需要选择。来源与 API 载体不同，tools 可独立传入；先检查权限、时效、重复与总预算。

[回看第9章的机制](../../curriculum/09-agent/docs/09-ContextAssemblyAndCache.md#core-3)

### 19. Prompt Engineering、Context Engineering、Harness Engineering 区别？

提示词设计改善指令与示例；上下文工程选择模型这次收到的资料和观察；Harness 工程还组织真实执行、状态、限制、恢复与验证。提示是沟通，程序和环境负责落实不能由文字保证的动作边界。

[回看第2章的机制](../../curriculum/09-agent/docs/02-WorkflowAutonomyAndRuntimeBoundary.md#core-5)

### 20. Context Window 大了还需要 Compaction 吗？

更大窗口可以推迟容量上限，不消除重复、陈旧信息、时延和费用，也不保证模型有效利用所有内容。是否压缩取决于任务和实测；可先缩小读取或外部化，不能因窗口大就永久发送全部历史。

[回看第10章的机制](../../curriculum/09-agent/docs/10-CompactionAndContinuation.md#core-1)

### 21. Context Compaction 完整链路？

先按预算或阶段选择需要处理的历史，生成并验证交接摘要，保留目标约束、进度、未决项和可回读引用，再安装更短且符合协议的输入视图，重新计量后继续。只追加摘要没有缩短输入，只保留摘要又可能丢关联。

[回看第10章的机制](../../curriculum/09-agent/docs/10-CompactionAndContinuation.md#core-2)

### 22. Compaction 后怎么保证关键约束没丢？

先定义不可丢的目标、约束和引用，做结构与语义检查，再比较压缩前后继续执行及长任务回归。关键授权和回执独立可靠保存；文字通顺、字段存在和 Token 下降都不能单独证明正确。

[回看第10章的机制](../../curriculum/09-agent/docs/10-CompactionAndContinuation.md#core-4)

### 23. Tool Result 太长怎么办？

缩小读取范围，或把必要完整结果外部化到有权限和期限的产物存储，在上下文中保留摘要、关键片段与引用。需要时再读取相关区段；可丢噪声才截断，不要不可逆地丢掉以后核验需要的内容。

[回看第9章的机制](../../curriculum/09-agent/docs/09-ContextAssemblyAndCache.md#core-6)

### 24. Stale Context / Stale Memory 怎么处理？

先核对来源、范围与版本。当前上下文里的旧资料需要刷新并说明新旧适用关系；长期记忆还要更新或失效原记录及派生索引缓存。无法确认时保留不确定性，高风险事实回权威系统核对。

[回看第11章的机制](../../curriculum/09-agent/docs/11-MemoryLifecycle.md#core-5)

### 25. Context、Memory、State、History 有什么区别？

Context 是本次模型可用输入；Memory 是为以后复用而维护的信息；State 是程序继续或停止需要的当前情况；History 是过去交互记录。同一事实可服务不同视图，不是所有保存的数据都叫长期记忆。

[回看第12章的机制](../../curriculum/09-agent/docs/12-StateHistoryAndPersistence.md#core-3)

### 26. Memory 应该怎么分层？

可按工作、经历、事实和过程记忆理解用途。当前工作信息常与状态或上下文重叠，经历和事实要检查时效，过程知识可由 Skill 或指令文件承载。这是用途分类，不是必须建立四张表。

[回看第11章的机制](../../curriculum/09-agent/docs/11-MemoryLifecycle.md#core-4)

### 27. 错误 Memory 写进去怎么办？

回原始来源确认哪里提取或泛化错误，修正有效范围和内容，并让旧记录、派生整合、索引与缓存失效。必要时向用户澄清；不能只在 Prompt 里再说一遍正确值而保留错误召回路径。

[回看第11章的机制](../../curriculum/09-agent/docs/11-MemoryLifecycle.md#core-5)

### 28. Checkpoint 保存什么？

保存一个可继续的位置及必要目标、进度、未决工作、控制状态和产物引用；具体字段从恢复承诺推导。不可盲重做的外部动作另有稳定身份与可靠回执，检查点不是全量内存或日志备份。

[回看第13章的机制](../../curriculum/09-agent/docs/13-CheckpointResumeAndRecovery.md#core-1)

### 29. Resume 为什么不能只重放 messages？

消息只能表达过去交互，未必包括最新取消、执行权、可靠回执和未决外部结果。恢复先核对身份、状态兼容、权限及已发生动作，重建环境与上下文，再从安全位置继续，不是把旧 Prompt 再发一次。

[回看第13章的机制](../../curriculum/09-agent/docs/13-CheckpointResumeAndRecovery.md#core-4)

### 30. Tool 成功但 Checkpoint 失败，恢复后怎么办？

检查点不会回退外部世界。以原逻辑操作身份查询或按下游有效幂等契约核对，确认成功则补齐本地记录，不创建新动作；结果仍未知且不能安全去重时暂停处理，提高检查点频率也不能消除此窗口。

[回看第13章的机制](../../curriculum/09-agent/docs/13-CheckpointResumeAndRecovery.md#core-3)

### 31. Pause、Cancel、Fail 有什么区别？

Pause 表示等待必要输入或批准，可按条件继续；Cancel 是终止意图，要传播并确认当前动作范围；Fail 表示错误导致目标未达成。三者都不等于成功，是否能够重新尝试需另看具体契约。

[回看第3章的机制](../../curriculum/09-agent/docs/03-AgentLoopAndExecutionScopes.md#core-3)

### 32. Fork / Branch 需要决定哪些继承语义？

确定哪些状态、指令、记忆和工作区引用可继承，并明确新身份、权限、预算和写入范围。已发生外部动作不会被复制或撤销；分叉后的新动作仍需自己的授权与逻辑身份。

[回看第13章的机制](../../curriculum/09-agent/docs/13-CheckpointResumeAndRecovery.md#core-6)

### 33. Permission、Approval、Sandbox 区别？

Policy/Permission 判断可信身份与任务允许做什么，Approval 确认需要人参与的具体动作，Sandbox 限制代码实际接触的文件、网络和资源。参数合法不自动授权，用户批准不能扩大自身没有的权限。

[回看第14章的机制](../../curriculum/09-agent/docs/14-PermissionApprovalAndSandbox.md#core-1)

### 34. HITL 为什么不是一个 confirm 弹窗？

HITL 是人在执行关键位置参与决策，需要绑定具体对象与参数、保存等待、处理拒绝或过期，恢复时复核目标和权限。弹窗只是交互入口，不能代替后端批准记录与执行控制。

[回看第14章的机制](../../curriculum/09-agent/docs/14-PermissionApprovalAndSandbox.md#core-3)

### 35. Prompt Injection 怎么防？

区分指令与低可信资料，限制可见能力与资源；在真实动作前校验授权、范围和必要批准，执行环境限制文件与网络，秘密由受控工具使用，输出和记忆写入另行保护。检测器漏报不应直接获得更高权限。

[回看第15章的机制](../../curriculum/09-agent/docs/15-InjectionAndContainment.md#core-2)

### 36. RAG / Tool Result 为什么也是 untrusted context？

检索或工具传回的是资料，不自动拥有给程序下指令的资格。内容可能来自恶意网页、第三方说明、内部被污染文件或旧记忆。应保留来源，避免提升其指令优先级，并用实际授权限制后续行动。

[回看第15章的机制](../../curriculum/09-agent/docs/15-InjectionAndContainment.md#core-1)

### 37. Secret 为什么不要直接放 Context？

模型输入可能被输出、工具和日志复制，也可能受注入诱导。凭证尽量由可信执行侧代持并限定范围，模型只得到必要业务结果；环境变量也可能被 Shell 或堆栈暴露，不能当绝对安全保证。

[回看第15章的机制](../../curriculum/09-agent/docs/15-InjectionAndContainment.md#core-4)

### 38. 怎样限制 Agent blast radius？

限制单次错误能影响的资源：最小工具与凭证、受限工作区、必要网络出口、资源配额和敏感动作批准。限制读取与外传要配合，沙箱配置和下游权限都需验证，不能只依赖模型承诺。

[回看第14章的机制](../../curriculum/09-agent/docs/14-PermissionApprovalAndSandbox.md#core-5)

### 39. MCP 是什么？解决什么？

MCP 是 AI 应用与外部工具、资源和提示模板之间的开放交互协议，减少重复接入约定。Host 仍负责模型调用、任务与授权，协议不定义整个 Agent 的规划、记忆和循环。

[回看第16章的机制](../../curriculum/09-agent/docs/16-MCPArchitectureAndLifecycle.md#core-1)

### 40. MCP Tool、Resource、Prompt 怎么区分？

Tool 提供可执行能力，Resource 提供可读取材料，Prompt 提供可复用交互模板。Host 按协议发现和获取，再决定如何进入任务。资源不自动注入模型，Tool 也不一定有写副作用。

[回看第16章的机制](../../curriculum/09-agent/docs/16-MCPArchitectureAndLifecycle.md#core-3)

### 41. MCP 和 A2A 区别？

MCP 常用于应用接入具体能力、资源和模板；A2A 常用于独立 Agent 系统的任务委派、状态与产物交互。两者可以组合，都不能用是否绝对同步或是否支持长任务作简单区分。

[回看第19章的机制](../../curriculum/09-agent/docs/19-MultiAgentAndA2A.md#core-6)

### 42. Tool、Skill、MCP、Command 有什么区别？

Tool 是动作接口，Skill 组织某类任务的方法与资源，MCP 是外部能力连接协议，Command 通常是用户显式触发应用行为的入口。命令可启动技能或工具流程，但它们不因此成为同一种对象。

[回看第17章的机制](../../curriculum/09-agent/docs/17-SkillsHooksAndExtensions.md#core-1)

### 43. Hook / Plugin 在 Runtime 里怎么定位？

Hook 在生命周期事件触发受控处理，Plugin 管理扩展打包、安装与启用。需要明确触发顺序、修改范围、失败与升级语义；可选插件禁用不能悄悄移除唯一安全门，后置 Hook 不能撤销已发生动作。

[回看第17章的机制](../../curriculum/09-agent/docs/17-SkillsHooksAndExtensions.md#core-3)

### 44. Intent Routing 怎么实现？

先定义意图类别与误分后果。明确命令可用规则，标签稳定且有数据可比较分类器，开放表达可使用模型；工具说明已经足够时未必需要独立分类服务。用代表请求和未知输入评估，不让分类结果自行授予权限。

[回看第18章的机制](../../curriculum/09-agent/docs/18-RoutingAndProviderResilience.md#core-1)

### 45. Model Routing 看哪些因素？

先满足工具调用、模态、上下文和部署等硬条件，再用代表任务比较质量、时延、每个合格任务的总成本与风险。单次便宜未必整体便宜，模型切换还要保留当前消息关联和已完成动作。

[回看第18章的机制](../../curriculum/09-agent/docs/18-RoutingAndProviderResilience.md#core-2)

### 46. Multi-Agent 什么时候值得？

子任务相对独立、可并行、上下文可隔离且结果可检查时可能值得。还要与单 Agent 或工具并行比较 Token、协调、部分失败和共享资源成本；线性强依赖任务不一定有收益。

[回看第19章的机制](../../curriculum/09-agent/docs/19-MultiAgentAndA2A.md#core-1)

### 47. Manager、Agent-as-Tool、Handoff 区别？

Agent as Tool 返回子任务结果，由父级继续；Handoff 转移当前处理权；Manager/Worker 由协调者分配多项工作、跟踪和汇总。它们描述控制关系，不自动决定通信协议或部署位置。

[回看第19章的机制](../../curriculum/09-agent/docs/19-MultiAgentAndA2A.md#core-2)

### 48. 多 Agent 同时修改 Repo 怎么办？

先确定写入权，可采用单整合者或实际独立 checkout/worktree；并发补丁检查基线，合并后验证行为。不同分支名称但共享同一目录不构成隔离，上下文分开也不能阻止文件覆盖。

[回看第19章的机制](../../curriculum/09-agent/docs/19-MultiAgentAndA2A.md#core-3)

### 49. A2A 需要哪些关键语义？

能力卡片、认证与版本、带类型消息、可跟踪任务、产物、补充输入和取消都要有明确语义。简单请求可直接返回 Message，长工作以 Task 跟踪；调用方最终验收，不把卡片声明或远端 completed 当完整业务证明。

[回看第19章的机制](../../curriculum/09-agent/docs/19-MultiAgentAndA2A.md#core-5)

### 50. Agent Trace 应记录什么？

按问题记录任务与调用关联、阶段耗时、状态、错误和必要配置或产物引用；需要深查时再取得授权的脱敏输入。关键业务回执另存，明确采样、权限和保留期限，不默认永久保存全部原始载荷。

[回看第20章的机制](../../curriculum/09-agent/docs/20-TraceReplayAndDiagnosis.md#core-3)

### 51. Replay 时为什么不能直接重执行所有 Tool？

证据回看、状态重建、模型重演和真实动作重做风险不同。历史工具已经产生过效果，再执行可能重复发送、修改或扣款。默认诊断使用已有记录或模拟，真实重做须另行授权并核对幂等与环境。

[回看第20章的机制](../../curriculum/09-agent/docs/20-TraceReplayAndDiagnosis.md#core-5)

### 52. Agent Eval 和普通 LLM Eval 有什么不同？

除了文本质量，还要检查环境状态、产物、工具选择与参数、恢复、成本和安全。Agent 的完成不能只靠自述，评分器与评测环境也要验证，并按任务类型观察退化。

[回看第21章的机制](../../curriculum/09-agent/docs/21-EvaluationBenchmarkAndImprovement.md#core-2)

### 53. LLM Judge 可以作为唯一 Agent Grader 吗？

通常不宜作为唯一依据。模型评审适合开放内容，但可能偏好风格或共享错误；可检查的文件、记录、测试和权限应使用相应证据。Judge 需要评分细则、人工校准和局限说明。

[回看第21章的机制](../../curriculum/09-agent/docs/21-EvaluationBenchmarkAndImprovement.md#core-4)

### 54. Coding Agent 怎样证明 Patch 可交付？

定位真实调用路径与失败条件，在适用基线上作最小完整修改；用能够暴露原问题的测试验证新行为，再运行相关回归并审查 diff、安全和用户已有工作。交付列出实际检查及未验证范围。

[回看第22章的机制](../../curriculum/09-agent/docs/22-CodingAgentDelivery.md#core-3)

### 55. Production Agent Runtime 怎么拆？

从连接寿命、任务时长、恢复、并发和隔离承诺推导入口、可靠记录、Worker、模型工具接入、执行环境与产物。先明确职责，只有独立扩容或隔离有收益才拆服务，不照抄完整微服务图。

[回看第23章的机制](../../curriculum/09-agent/docs/23-ProductionRuntime.md#core-1)

### 56. LangGraph / Agents SDK / 自研 Loop 怎么选？

先把状态、控制流、工具、批准、恢复和部署要求写成可验证问题，再对照 Runner、状态图和高层集成。自研可以轻量或只接管特殊部分，也要承担可靠性；用相同任务与故障窗口比较并保留迁移能力。
