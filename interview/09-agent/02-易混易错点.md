# Agent｜易混易错点

[本域入口](README.md) · [完整问答](01-高频面试题.md) · [面试速查](03-面试速查.md) · [课程](../../curriculum/09-agent/README.md)

这里练的是“听到一个看似合理的结论，能否指出它在哪个条件下失效”。先尝试解释反例，再回看对应机制。

## 1. “能调用工具、有 while 循环，就是 Agent”

展开机制与题面依据：[1. Agent、普通模型调用与 Workflow 的关键区别是什么？](01-高频面试题.md#q01)。

定时脚本也能调用工具、循环执行。关键是任务路径是否由模型根据观察动态选择，以及程序怎样约束这种选择。固定 Workflow 可以包含模型、条件分支与循环。面试时应举出一个真实决策点，例如排障后选择继续查日志还是读取源码；不要拿框架名称当定义。[控制路径的区别](https://www.anthropic.com/engineering/building-effective-agents)比是否用了某个包更可靠。

## 2. “模型返回 Tool Call，说明工具执行成功”

展开机制与题面依据：[6. 工具从定义到调用，完整链路是什么？](01-高频面试题.md#q06)。

调用候选可能还没通过参数和权限检查，甚至找不到对应实现。至少区分候选生成、受理执行、远端完成和结果验收。模型响应、协议请求、业务操作还可能各有不同 ID；`call_id` 用来回填，不自动承担退款防重。

纠正后的说法是：我用执行器回执与权威业务状态确认动作，再把观察交给模型。最终文本“任务完成”不能替代这个证据。

## 3. “合法 JSON 就是可靠结构化输出”

展开机制与题面依据：[7. Schema 校验通过，为什么仍可能越权？](01-高频面试题.md#q07)。

`{"amount": -100}` 可以是合法 JSON，却可能不满足 Schema。满足金额范围后，还可能对应别人的订单。解析、Schema、业务约束、授权、批准是不同检查。

同样，`HTTP 200` 可能装着业务错误；空结果不等于执行失败。工具结果应让宿主区分这些情况，模型侧只收到必要且安全的解释。不要把堆栈、秘密和内部路径一股脑回填。

## 4. “read-only 工具不用授权，也适合任意并发”

展开机制与题面依据：[7. Schema 校验通过，为什么仍可能越权？](01-高频面试题.md#q07)；[22. 多 Agent 怎样传状态，怎样避免互相覆盖代码？](01-高频面试题.md#q22)。

读取人事文档不会改数据库，却可能泄密；两个只读查询还可能来自不同版本，无法拼成一致结论。并发需要检查资源版本、依赖、配额与结果合并，不只看 `async` 或工具注解。

[MCP 2026-07-28 Tools 规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)要求对非可信服务器的工具注解保持不信任。注解帮助调度，不能覆盖实际身份与资源检查。

## 5. “所有异常都交给模型重试，框架会自己修好”

展开机制与题面依据：[9. Tool Failure 应怎样分类，哪些可以重试？](01-高频面试题.md#q09)。

参数错误可能适合有限修参；权限拒绝继续尝试可能越权；退款超时后重发可能多退一次。先判断错误是否暂时、动作是否已经发生、重复是否安全，再决定由模型、程序、用户还是人工处理。

至少有总 deadline、总尝试次数和重试流量预算。每层各重试三次，会造成尝试放大，不是更可靠；把下游压得更慢以后，上游又会产生更多超时。

## 6. “有分布式锁或 Checkpoint 就能 Exactly Once”

展开机制与题面依据：[10. 工具已经成功，但响应或 Checkpoint 丢了怎么办？](01-高频面试题.md#q10)；[11. Checkpoint、Resume 与重放聊天记录有什么区别？](01-高频面试题.md#q11)。

锁只控制一段时间内的竞争，Checkpoint只记录本地恢复位置。工具可能已经扣款，本地还没来得及保存就崩溃。恢复时换新幂等键再调用，会将同一业务意图变成新操作。

正确边界是：稳定操作身份、下游防重或查询契约、可靠结果记录、未知状态核对。某个数据库事务内能原子提交，不代表外部邮件或支付也在该事务里。无法建立这些条件，就不能承诺外部效果恰好一次。

## 7. “取消成功，意味着任何副作用都没发生”

展开机制与题面依据：[12. 五分钟工具还在运行，用户又说话或点取消，怎么处理？](01-高频面试题.md#q12)。

用户取消、本地协程停止、远端收到取消、远端最终状态，是不同事件。正在途的请求可能随后成功。系统要停止新动作，继续核对已发动作，并如实呈现结果；不能因为 UI 显示 cancelled 就丢弃迟到回执。

补偿也是新操作。撤销本地文件修改与撤回已送出的邮件不是同一种能力。

## 8. “批准了 Agent，就批准了它后来想到的所有操作”

展开机制与题面依据：[13. HITL 为什么不是一个确认弹窗？](01-高频面试题.md#q13)。

批准要对应具体对象、参数与用途。等待期间收件人、金额或数据范围变化，不能沿用旧确认。批准一个子 Agent 的委派，也不自动批准它内部所有工具写入。

[Agents SDK 当前 HITL 流程](https://openai.github.io/openai-agents-python/human_in_the_loop/)可在外层 RunState 暴露嵌套调用的 interruption；这要求恢复原顶层运行并处理相应调用批准。产品接口支持传播，不意味着业务可以省略逐动作绑定与执行时复核。

## 9. “保存所有 messages 就能从任意位置恢复”

展开机制与题面依据：[11. Checkpoint、Resume 与重放聊天记录有什么区别？](01-高频面试题.md#q11)；[13. HITL 为什么不是一个确认弹窗？](01-高频面试题.md#q13)。

messages 未必包含当前取消、执行代际、外部回执、批准参数版本和未决操作。恢复若只重发历史 Prompt，模型可能再次提出已经完成的写入。

[LangGraph interrupt](https://docs.langchain.com/oss/python/langgraph/interrupts)恢复时会重新进入节点开头，中断前代码可能再运行。把非幂等副作用写在 `interrupt()` 前面，再以为恢复只执行后半段，是具体实现陷阱。代码升级后还需验证状态格式兼容。

## 10. “Context、Memory、Checkpoint都是一份历史，合并存就行”

展开机制与题面依据：[14. Context、State、History、Memory 怎样区分？](01-高频面试题.md#q14)；[17. LangGraph State 为什么会膨胀？Session 能代替 Checkpoint 吗？](01-高频面试题.md#q17)。

当前提示是模型输入视图；长期记忆是可维护知识；Checkpoint承担继续执行的责任。一个事实可能被多处引用，但不能让模型摘要成为唯一操作账本。

短期、工作、长期是用途划分，不必每层一张表；线程级与跨线程范围也不能混用。[LangGraph 的 Checkpointer 与 Store](https://docs.langchain.com/oss/python/langgraph/persistence)有明确作用域区别。Session缓存键里带用户 ID，不等于读写时已经验证当前用户权限。

## 11. “Token少了，说明压缩成功”

展开机制与题面依据：[15. 上下文很长时，怎样压缩且证明没压坏？](01-高频面试题.md#q15)。

压缩可能把“只能读，不能改”丢掉，也可能留下旧目标却遗漏用户后来新增的约束。只检查摘要字段和语言流畅度发现不了这些问题。

要核对目标、约束、未决事项和来源，再跑压缩后的继续执行测试。把摘要追加到未裁剪的历史末尾甚至不算缩短输入。全文逐字重要时，应保留可回读原件，不能让模型保证有损压缩无损。

## 12. “更大的窗口、Prompt Cache、向量记忆能解决同一个问题”

展开机制与题面依据：[14. Context、State、History、Memory 怎样区分？](01-高频面试题.md#q14)；[15. 上下文很长时，怎样压缩且证明没压坏？](01-高频面试题.md#q15)。

窗口决定可容纳输入规模；前缀缓存减少重复计算或相应费用；记忆检索选择候选信息。缓存命中不证明资料有效，向量相似不证明事实正确，大窗口也不能阻止陈旧信息干扰决策。

先判断是在容量、相关性、时效、成本还是授权层出错，再选方案。重复出现的同一来源也不是多份独立证据。

## 13. “删除记忆原文就完成纠错”

展开机制与题面依据：[16. 长短期记忆怎样设计，错误记忆怎么删除？](01-高频面试题.md#q16)。

旧内容可能已经进入整合摘要、向量索引、缓存或另一个用户画像。需要沿派生链修正或失效，并验证后续检索不再返回错误内容。反过来，不能因为新消息与旧记忆不同就一律覆盖，先判断权限、时间和事实来源。

真实订单状态要回订单系统；用户曾说“好像已退款”只能作为待核对信息。

## 14. “MCP必先initialize；MCP就是SSE；MCP一定无长任务”

展开机制与题面依据：[19. MCP 的初始化、SSE、Streamable HTTP，版本怎么回答？](01-高频面试题.md#q19)。

这三句话都忽略版本或职责。2026-07-28使用每请求元数据；2025-11-25旧生命周期使用初始化握手。stdio、旧HTTP+SSE、Streamable HTTP不是三个同义词。协议层无状态也不排除有状态业务或可选任务扩展。

对照[官方版本兼容页](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)报清版本，再检查安装的 SDK。当前规范出现的新能力，不应被写成所有历史产品快照的既有行为。

## 15. “Skill加载成功就会被遵守，Skill可以代替工具”

展开机制与题面依据：[20. Skill 怎样渐进披露，为什么不能保证百分之百触发？](01-高频面试题.md#q20)。

加载只让方法可见。模型可能误选、漏读或忽略；脚本执行仍要经过真实工具与权限边界。高合规要求应由程序在执行前强制，而不是把更多禁止语句写进 Skill。

Hook是程序触发点，也要看具体时机。动作之后拦截输出，无法撤销动作；可选Plugin被禁用后，系统不能失去唯一安全门。[Skills规范](https://agentskills.io/specification)规定的是内容与资源组织，不是百分之百正确触发的数学保证。

## 16. “多Agent各自有Context，就已经隔离”

展开机制与题面依据：[22. 多 Agent 怎样传状态，怎样避免互相覆盖代码？](01-高频面试题.md#q22)。

它们仍可能写同一文件、争同一数据库行、共享凭证或同时消耗同一预算。上下文隔离、工作区隔离、写入协调和权限隔离必须分开落实。

[独立worktree](https://git-scm.com/docs/git-worktree)可隔离文件修改，但两个补丁合并后仍可能行为冲突。父代理也不能因为每个子任务自称完成，就跳过整体缺口、依赖与来源检查。

## 17. “内部文档可信；把秘密放环境变量就安全”

展开机制与题面依据：[23. Prompt Injection、权限、批准与 Sandbox 怎样协同？](01-高频面试题.md#q23)。

内部内容也可能被污染，第三方工具说明也可能夹带指令。环境变量可能被Shell、调试信息或工具结果读出。授权与网络出口必须在实际执行层生效，避免一次误读扩大成外传。

输出过滤可以减轻泄露风险，却不能代替读取范围限制，更不能修复已经发到外部服务的数据。可对照[OWASP防注入分层建议](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)检查每条攻击路径，而非只测一个检测Prompt。

## 18. “Trace齐全就能安全Replay；测试全绿就能交付”

展开机制与题面依据：[26. Agent 变慢或答错，Trace 应怎样帮忙？](01-高频面试题.md#q26)；[27. Coding Agent 怎样证明可交付，怎样安全“自进化”？](01-高频面试题.md#q27)。

重看历史、用录制工具结果重演模型、重新调用真实工具，有不同风险。默认回放不应再次发信或扣款；版本齐全也不保证随机模型重演输出相同。业务回执不能依赖可能采样丢失的诊断Span。

测试绿色只说明那些断言通过。还要确认测试能暴露原问题、没有被生成代码同时改错期望，并说明集成、权限、并发和生产负载哪些没有验证。评测集被用于反复调参后，不再是独立效果证明。

## 19. “我能复述架构，所以项目一定算我做的”

展开机制与题面依据：[27. Coding Agent 怎样证明可交付，怎样安全“自进化”？](01-高频面试题.md#q27)；[28. LangGraph、SDK、自研 Loop 最后怎么选？](01-高频面试题.md#q28)。

架构理解、模块实现、线上负责是不同贡献。回答个人项目题时，明确使用的开源框架、本人改动、AI生成部分、验证范围与实际用户规模。不会的细节可以说明尚未涉及。

产品源码题应给出读过的版本和具体调用链；不要把本文的教学退款、工作流或沙箱设计改写为个人生产经历。
