## 60秒讲清一次执行

展开机制与题面依据：[3. 一个最小 Agent Loop 应怎样实现？](01-高频面试题.md#q03)；[5. 怎样判断任务完成，怎样阻止死循环？](01-高频面试题.md#q05)。

“用户目标进入持久任务，Runtime选择本轮上下文并调用模型。模型提出工具、澄清或完成候选。执行器校验参数、业务条件和权限，必要时等待批准，再执行、核对结果并回填。循环依据观察推进；完成由产物或业务事实验收，取消、失败和预算停止分别记录。”

接着给一个自己真正做过的例子：输入是什么，哪一步由模型决定，什么规则由程序强制，怎样知道最后做对。不要先背框架清单。

## 问到这些词，立即落到责任

展开机制与题面依据：[1. Agent、普通模型调用与 Workflow 的关键区别是什么？](01-高频面试题.md#q01)；[2. 模型外面为什么还需要 Runtime / Harness？](01-高频面试题.md#q02)；[14. Context、State、History、Memory 怎样区分？](01-高频面试题.md#q14)；[18. MCP、Function Calling、Skill 各解决什么问题？](01-高频面试题.md#q18)。

- **Workflow / Agent：** 看主要路径由程序还是模型依据观察决定；有循环不是充分条件。
- **Harness / Runtime：** 真实执行、状态、权限、恢复、预算和验收的宿主支撑。
- **Context / Memory：** 本轮输入与未来可复用信息；存着不等于这轮已注入。
- **State / History：** 当前可执行事实与过去交互；聊天记录不能代替操作账本。
- **Checkpoint / Compaction：** 可恢复执行位置与缩短模型输入；后者不能裁定外部动作是否发生。
- **Skill / Tool / MCP：** 任务方法资源、动作接口、能力连接协议。Skill不自动执行，也不授予权限。

## 工具失败：按结果状态走分支

展开机制与题面依据：[9. Tool Failure 应怎样分类，哪些可以重试？](01-高频面试题.md#q09)；[10. 工具已经成功，但响应或 Checkpoint 丢了怎么办？](01-高频面试题.md#q10)。

1. **还没执行：** 参数格式或业务输入错误，有限修复；权限拒绝就停止或请求正确授权。
2. **只读依赖暂时失败：** 看deadline、配额和总重试预算，再退避重试。
3. **写操作可能已发生：** 保留原operation_id，先查回执或按有效幂等契约重试。
4. **无法核对：** 保持未知并请求人工处理，不换新键“再试一次”。

追问“Checkpoint丢了呢”：检查点不回退外部世界，先核对真实动作，再补齐本地状态。

## 循环、变慢、忘目标：先看哪个事实

展开机制与题面依据：[5. 怎样判断任务完成，怎样阻止死循环？](01-高频面试题.md#q05)；[8. 工具太多、名字相似、参数总错，分别怎么处理？](01-高频面试题.md#q08)；[15. 上下文很长时，怎样压缩且证明没压坏？](01-高频面试题.md#q15)；[26. Agent 变慢或答错，Trace 应怎样帮忙？](01-高频面试题.md#q26)。

| 现象 | 第一个检查 | 接着怎么做 |
|---|---|---|
| 同一工具反复调用 | 参数、错误和观察是否真的改变 | 区分合法分页与无进展重复；换策略、澄清或终止 |
| 原本很快却长时间不结束 | 排队、模型、工具、重试的阶段耗时 | 查最慢路径，不先加模型并发 |
| 找不到正确工具 | 工具是否进入候选集合 | 先修候选召回，再修主模型选择 |
| 压缩后做错 | 初始目标、新约束、未决项是否保留 | 回读来源，修摘要并跑继续执行回归 |
| 记忆持续答错 | 原记录及派生索引版本 | 修正或失效整个召回路径 |
| 多Agent改坏代码 | 是否共享目录、基线是否一致 | 隔离工作树或单整合者，合并后测行为 |

## 安全问题的三句话

展开机制与题面依据：[7. Schema 校验通过，为什么仍可能越权？](01-高频面试题.md#q07)；[13. HITL 为什么不是一个确认弹窗？](01-高频面试题.md#q13)；[23. Prompt Injection、权限、批准与 Sandbox 怎样协同？](01-高频面试题.md#q23)。

“身份授权决定能做什么。批准绑定这一次具体对象和参数。沙箱限制代码真正能接触的文件、网络与资源。”

随后加边界：只读也会泄密；工具注解不是授权；第三方资料不能升级为指令；后置拦截撤不回已发生动作；取消请求不证明远端已停。

## 压缩与记忆的口述顺序

展开机制与题面依据：[15. 上下文很长时，怎样压缩且证明没压坏？](01-高频面试题.md#q15)；[16. 长短期记忆怎样设计，错误记忆怎么删除？](01-高频面试题.md#q16)。

先控制输入量，再决定摘要或外部化。保留目标、约束、进度、未决项和可回读证据；重要业务状态独立保存。换成更短输入以后，用实际继续执行验证，不能只看Token下降。

短期服务当前任务，长期保存跨会话值得复用的信息。每条长期记忆有范围、来源、版本与失效规则。多会话隔离不等于跨用户授权，三层记忆也不是必须有三种数据库。

## 多Agent取舍：先证明增益

展开机制与题面依据：[21. 为什么要拆多 Agent，怎样证明不是徒增复杂度？](01-高频面试题.md#q21)；[22. 多 Agent 怎样传状态，怎样避免互相覆盖代码？](01-高频面试题.md#q22)。

“子任务独立、能并行、上下文可隔离、结果能验收时考虑拆分。我会和单Agent基线比较成功率、总Token、尾延迟与部分失败成本。通信传目标、约束、引用和结果契约，不广播所有历史。父级负责冲突、缺口和最终交付。”

明确共享文件和数据库的写入协调。A2A是跨系统任务互操作，不会自动完成业务授权或保证远端结果正确。

## 评测与个人项目最后核对

展开机制与题面依据：[25. Agent Eval 应怎样构建，几个真实案例反复跑够不够？](01-高频面试题.md#q25)；[27. Coding Agent 怎样证明可交付，怎样安全“自进化”？](01-高频面试题.md#q27)。

- 成功定义来自任务产物或业务事实，不能来自模型自述
- 数据集分任务类型、失败恢复与安全边界；重复跑少量案例不能替代覆盖
- 改动前后用同口径对照，留独立集合；LLM Judge用人工与可执行事实校准
- Trace记录阶段和关联，敏感载荷按需脱敏；业务回执另存
- 说明本人设计、框架能力和AI生成代码的边界，列实际验证与未覆盖范围

## 必须带版本的三个实现点

展开机制与题面依据：[13. HITL 为什么不是一个确认弹窗？](01-高频面试题.md#q13)；[17. LangGraph State 为什么会膨胀？Session 能代替 Checkpoint 吗？](01-高频面试题.md#q17)；[19. MCP 的初始化、SSE、Streamable HTTP，版本怎么回答？](01-高频面试题.md#q19)。

- **MCP：** 2026-07-28采用每请求版本/能力元数据；2025-11-25旧生命周期采用initialize。以[官方兼容页](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)和实际SDK为准。
- **LangGraph：** 持久Checkpointer＋相同thread_id恢复；被interrupt的节点会从开头重新执行，之前副作用要幂等。见[interrupt语义](https://docs.langchain.com/oss/python/langgraph/interrupts)。
- **Agents SDK：** Session会话历史与RunState批准恢复是不同职责；嵌套批准可在外层处理。见[Session](https://openai.github.io/openai-agents-python/sessions/)与[HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)。
