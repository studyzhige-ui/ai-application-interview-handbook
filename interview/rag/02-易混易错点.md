# RAG｜易混易错点

[本域入口](README.md) · [课程](../../curriculum/08-rag/README.md)

## 语料与解析

| 容易说出的结论 | 更可靠的判断 |
|---|---|
| 文件上传成功，知识就更新了 | 上传、处理、索引写入、查询可见与版本激活是不同完成状态。 |
| 向量库就是唯一知识源 | 索引是派生状态，应保留可回溯的权威来源与重建能力。 |
| 最新编辑的文档一定适用 | 编辑时间、生效时间、事件时间与适用对象要分开。 |
| 内容哈希相同就能跨租户合并 | 相同字节不证明来源身份与授权相同；处理复用也需隔离。 |
| 删除来源后不再同步即可 | 旧索引、摘要和答案缓存仍可能暴露内容，需删除标记与清理。 |
| PDF 抽出了所有字就正确 | 阅读顺序、表格行列、脚注与关系仍可能出错。 |
| OCR 对所有页面都更准确 | 已可靠提取的文本未必需要再识别；按页或区域质量选择。 |
| 表格转成纯文本就可以丢原表 | 表头、单位、条件与回源位置必须保留，比较时可能需完整表。 |
| 图片摘要等于原始图像证据 | 摘要是派生解释，数字、箭头和图例要回到原图核对。 |
| 清洗越彻底越好 | 否定、单位、日期、脚注可能决定答案，不能当噪声删除。 |

## 切分与关系

| 容易说出的结论 | 更可靠的判断 |
|---|---|
| 最佳块长是一个固定范围 | 长度取决于单位、结构、模型限制、问题与评测结果。 |
| 字符、Token、字节可以直接互换 | 不同编码与语言比例不同，需记录实际测量方法。 |
| 大块一定更完整 | 可能混合主题并被截断，局部证据仍需明确关系。 |
| 小块一定检索更好 | 可能失去对象、条件和例外，召回相关性也需评测。 |
| Overlap 越大越安全 | 重叠增加计算与重复，解决不了远处依赖。 |
| 递归切分必须调用语义模型 | 它可以只按层次化分隔符拆分超长部分。 |
| 语义切分能自动识别所有业务依赖 | 话题差异与条件依赖不是同一规则。 |
| 有多级标题就不会失去上下文 | 标题帮助确定范围，但不能替代具体条件与例外。 |
| 命中一个子块就能读取整个父文档 | 父块、邻居和附件仍需按实际授权粒度检查。 |
| 按文档 ID 去重最干净 | 同文档中的不同片段可能共同支持结论，不能只留一条。 |

回看 [04](../../curriculum/08-rag/docs/04-ChunkingDesign.md)、[05](../../curriculum/08-rag/docs/05-AdvancedChunkStructure.md)。

## 查询、召回与排序

| 容易说出的结论 | 更可靠的判断 |
|---|---|
| 短问题一定要扩写 | 对象明确时可能已足够；扩写不能猜测缺失事实。 |
| 改写后不需要保留原句 | 原问题是意图、硬条件、回退和诊断的重要依据。 |
| 多问法就是多个独立子问题 | 变体覆盖表达差异；分解覆盖不同信息需求。 |
| HyDE 生成的答案可直接引用 | 它只提供检索线索，可能含虚假细节。 |
| Dense 一定优于词项检索 | 精确编号、稀有术语和语义变体需要不同信号。 |
| Sparse 就等于 BM25 | BM25 是一种词项评分方法，稀疏表示还可来自其他构造或学习方法。 |
| BM25 只看词出现次数 | 它还涉及词频饱和、长度归一化和 IDF。 |
| 两路原分数相加就是可靠融合 | 原分数通常不可直接比较，需排名融合或经验证的校准策略。 |
| 向量、BM25、Hybrid 是三条必备独立路 | Hybrid 是组合方式；重复组合可能重复放大同一信号。 |
| RRF 常数与 Top-K 是普遍最佳默认 | 公式参数和产品默认要区分，业务预算需本地对照。 |
| 重排能找回没有进入候选的文档 | 它只处理输入集合，漏召回要先定位上游。 |
| 加重排必然提高质量 | 领域、截断、目标错位与预算都可能造成负收益。 |
| 相似度 0.8 就是答案有 80% 把握 | 分数不是未经校准就可解释的概率，也不说明必要证据完整。 |
| 多样性高就一定证据充分 | MMR 可以减少冗余，但不保证覆盖每个业务条件。 |

## 证据与评测

| 容易说出的结论 | 更可靠的判断 |
|---|---|
| Top-K 就是最终上下文块数 | 各路召回、融合、重排与证据装包有不同预算。 |
| 窗口越满回答越可靠 | 重复、噪声和无关内容可能挤走关键例外。 |
| 引用 ID 合法就代表结论受支持 | 还要核对当前授权、来源适用性与具体支持关系。 |
| 忠实回答就是正确回答 | 忠实于过期或错误材料，仍可能给出错误结论。 |
| 检索失败就说没有答案 | 运行错误、部分结果与完成检索后的知识不足要区分。 |
| 写一个防注入 Prompt 就能保证安全 | 需要确定的授权、能力边界、数据与输出检查。 |
| Recall 高就证明答案完整 | 找回部分相关证据不一定覆盖全部必要事实。 |
| Hit 或 MRR 可以代替多证据覆盖 | 它们主要看任一相关结果或首个相关结果的位置。 |
| NDCG 的理想排序只看已返回结果 | 理想排序基于已知相关性标签，否则漏掉高价值证据会被掩盖。 |
| 空相关集合可以算 Recall=1 | 分母为零，不适用；不可回答任务应另有拒答标签。 |
| 切分变化后直接用旧块 ID 评测 | 应标注稳定的原文事实与范围，再映射到新块。 |
| 一个 LLM Judge 就是 Ground Truth | 需校准偏差并用人工标注核验重要切片。 |
| 准确率提升 8 就是提升 8% | 百分点与相对提升不同，还需明确样本分母。 |
| 总分更高就可以上线 | 权限与关键类别退化、成本和尾延迟可能阻断发布。 |

## 更新、运行与复杂方案

| 容易说出的结论 | 更可靠的判断 |
|---|---|
| 幂等键能解决所有并发覆盖 | 重复去重与防止旧版本晚写入不同，后者需要版本检查及原子提交。 |
| 更新必须先删除旧块 | 普通内容更新先构建验证再切换；紧急撤权与删除要先阻止可见。 |
| 单库别名切换保证所有存储原子一致 | 跨系统还需一致的版本组合、可见性确认与请求绑定。 |
| 内容回滚时权限也应回滚 | 当前撤权和删除独立生效，不能恢复旧授权。 |
| 超时就说明远端没有执行 | 结果可能未知，需要幂等、查询或对账，而非盲重试。 |
| 加线程一定提高摄取吞吐 | 瓶颈配额不变时只会增加排队、内存和失败。 |
| 阶段 P95 相加得到端到端 P95 | 必须按完整请求统计，阶段分位数不具备简单可加性。 |
| 语义相似即可共享答案缓存 | 日期、否定、产品、会话与授权条件可能改变答案。 |
| GraphRAG 就是某个具体项目的所有实现 | 通用方法与 Microsoft GraphRAG 等产品边界不同。 |
| 图中的依赖意味着实际故障必然传播 | 方向、环境、有效期、隔离与实际运行证据共同决定。 |
| 多搜几次就能解决所有不确定性 | 可能重复、漂移、超预算；新增信息和缺失条件需要显式跟踪。 |
| 达到步骤上限就是完成任务 | 预算耗尽只是停止条件，仍要说明缺少的证据。 |
