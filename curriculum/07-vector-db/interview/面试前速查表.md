## 一条总线

**兼容表示 → 距离规则 → 合法目标集合 → 精确对照 → 近似来源 → 数据维护 → 分布式与资源 → 架构选择。**

## 数学与索引

| 主题 | 需要立即想起的规则 | 必须带上的条件 |
|---|---|---|
| 点积 | 逐项乘积之和，受模长影响 | 固定查询的正比例缩放不改内积排名，但会改分数 |
| 余弦 | 点积除以两边模长 | 零向量无定义；不是正确概率 |
| 单位化 | `L2²=2−2 dot` | 两边单位向量时与余弦排序等价 |
| 接口 | L2、平方 L2、负内积、余弦距离不同 | 排序方向与阈值一并检查 |
| 精确目标 | 合法集合中的前 `min(K, 合法记录数)` 个 | 同快照、距离、表示、过滤、并列规则 |
| 索引 Recall | ANN 与精确目标的集合重合比例 | 空目标单独报告；不是业务相关性 |
| HNSW | 高层导航、底层保留多个候选并扩展邻居 | M 建连接；efConstruction 建图；efSearch 查图 |
| IVF | 先比中心，再查若干倒排列表 | nlist 是总列表数，nprobe 是本次探测数 |
| PQ | 分段编码，查询查表累加近似距离 | 码本共享但不免费；全候选不等于原向量精确距离 |
| 精算 | 用原向量修复候选内的排序 | 无法恢复候选外的近邻 |

## 数据与正确性

| 主题 | 必须检查 |
|---|---|
| 记录 | 一条记录对应谁；稳定 ID、来源定位、权限、内容与嵌入版本 |
| 更新 | Upsert 的替换/合并语义；旧块清理；旧版本不能覆盖新状态 |
| 过滤 | 在同一合法集合内做精确对照；后过滤可能不满 K |
| 多租户 | 身份推导条件，覆盖检索、按 ID 读写、删除、导出和缓存 |
| 完成 | 接收、执行、可见、持久化、空间回收分别确认 |
| 重建 | 快照位置 + 有序增量 + 删除 + 校验 + 编码器/索引联合切换 |
| 回滚 | 保留旧索引还需维护其新鲜度与权限，不能恢复已撤销内容 |
| 分片 | 数据拆开；同规则的局部精确 Top-K 才可直接合并 |
| 副本 | 数据复制；不等于独立历史备份 |
| 超时 | 明确失败、重试或部分结果；不可伪装成空集 |

## 性能与选择

未压缩 float32 数值字节数是 `N×D×4`，不是产品总内存。按实际布局加索引、元数据、运行开销、临时空间和副本；区分 GB 与 GiB，区分单机与集群，区分稳态与重建峰值。

先看编码、排队、过滤、搜索、网络、合并各阶段，再看 P95/P99、并发与持续写入。不使用同一质量目标和数据范围的“速度排名”没有可比性。

选型顺序是：**业务约束 → 能力形态 → 候选产品与版本 → 质量—成本曲线 → 更新和故障验证。** Faiss、pgvector、Elasticsearch、Milvus/Qdrant 是不同形态的候选，不是固定优劣顺序。

最后记住：向量相似不是业务关系，HNSW 图不是知识图谱。向量基础设施证明“怎样找到这些表示”；完整 RAG 还要证明“这些证据能否支持回答”。
