# Vector Database｜面试易错点

[← 面试表达训练](高频面试题.md) · [模块主页](../README.md)

这些误区的共同点是丢掉了成立条件。不要只把“错误”替换成另一句口诀；应能指出具体哪一步推理不成立。

| 容易说错的判断 | 应恢复的条件与机制 | 回看章节 |
|---|---|---|
| 把表示当作知识事实 | 相似向量不证明事实正确、版本有效或有权限。分别检查编码、来源、业务状态与授权。 | 01、09、10 |
| 相同维度就混搜 | 维度相同仅表示形状相同；配套的查询与文档编码方式也必须兼容。 | 02、12 |
| 文本一定用余弦，维度越大越好 | 先遵循模型约定，再在任务质量与数值、存储、计算成本之间验证。高维不是效果保证。 | 02、14 |
| 把分数当概率，或混用阈值 | 余弦、余弦距离、负内积、L2 与平方 L2 的数值含义不同。排序一致也不意味着阈值相同。 | 02 |
| ANN 就是随机搜索，精确搜索永远不能上生产 | ANN 用受限探索或近似表示降低某些成本；精确搜索仍适用于小规模、强过滤后候选少、或有合适算力的场景。 | 03、04 |
| ANN 召回高，就证明 RAG 好 | ANN 召回对照精确近邻；业务召回对照标注相关性，回答质量还有后续环节。 | 03、14 |
| HNSW 是树，层级代表语义分类 | 它是多层图；高层稀疏用于导航，不代表文档目录。图上的近邻边也不是知识关系边。 | 05、16 |
| M 是每个节点精确边数，ef 是访问次数 | 这些参数约束连接和搜索宽度，具体图层与实现有各自规则。返回 K、保留宽度、访问点数不是同一个量。 | 05 |
| 把参数一律调大 | 通常会增加某些资源开销，质量收益也非无限。先排除数据、表示和权限错误，再沿质量—成本曲线选择。 | 05、06、08 |
| IVF 就是训练 KMeans | 聚类只负责建立粗中心，还需要记录到列表的归属、查询中心选择和列表内搜索。训练样本与线上分布不同也会影响效果。 | 06 |
| PQ 是一种相似度；探测全部列表就没有误差 | PQ 近似向量表示和距离。IVF_PQ 扫全列表仍可能有压缩误差，原向量精算也只能修复已进入候选的记录。 | 07 |
| 前过滤等于每次复制出一个小索引 | 前过滤描述查询约束如何进入搜索，不限定具体物理执行；过滤感知遍历、位图、迭代扫描和精确回退各有条件。 | 10 |
| 返回满 K 条就是过滤正确 | 需要同时检查授权、合法集合的精确目标和结果质量。合法记录不足 K 时不应扩大权限补齐。 | 03、10、11 |
| 有 tenant_id 或独立集合就不需要鉴权 | 字段和布局不等于可信身份。还需覆盖按 ID 读写、删除、导出、缓存和管理路径，资源配额也另行设计。 | 09、11 |
| 稳定 ID 保证并发幂等与顺序正确 | 同 ID 可减少重复记录，却不能阻止旧版本覆盖新版本。文档变短还需要回收旧分块，删除还可能被迟到旧写入复活。 | 09、12 |
| 返回成功就表示落盘、可见和物理删除全部完成 | 请求确认、执行完成、查询可见、耐久性和后台空间回收必须按实际产品语义拆开验证。 | 12 |
| Shard 越多越快；Replica 就是备份 | 分片增加并行机会也增加扇出和合并成本；副本可能同步错误，不能替代历史恢复点。部分结果不能假装完整。 | 13 |
| 原始向量大小就是 RAM 下限，P50 快就证明 SLA 达标 | 压缩、磁盘驻留、共享布局会改变 RAM；构建又可能产生额外峰值。延迟还要看尾部、负载和分层成本。 | 07、14 |
| 算法库、数据库扩展、搜索引擎是一条从差到好的梯子 | 能力形态不同，应匹配工作负载和团队责任。某产品支持向量或文本，不意味着所有组合查询都有合适索引与成本。 | 15 |
| Hybrid/Rerank 不在本模块，所以检索失败都交给 RAG | 本模块必须先查清索引与合法范围内的近邻误差，再把表示、融合与生成问题交给对应模块。边界不能成为不解释必要前提的理由。 | 03、10、14、16 |

各章的完整过程见[模块目录](../README.md)；版本和接口语义见[References](../../../references/vector-db/README.md)。
