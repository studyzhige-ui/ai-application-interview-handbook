# Vector Database｜可核对的实验

[← 模块主页](../README.md) · [Review](../review/README.md) · [技术依据](../../../references/vector-db/README.md)

先证明计算和条件正确，再验证具体库与服务。这里分成三种实验，输出会标记实际运行对象；不存在自动把真实数据库替换为内存模拟的降级。

所有命令从仓库根目录执行。Python 目标为 3.11 及以上；本轮实际解释器版本与运行结果记在模块维护记录。每次运行重新读取 `data.json`，不依赖前一次进程的变量。命令里的路径也可以替换为绝对路径。

<a id="numeric"></a>
## 1. 无第三方依赖的数值与状态实验

**任务与条件。** `data.json` 保存正文 02、03、10 章的六条构造记录与查询。运行脚本后，先核对精确 Top-3，再比较过滤位置、图搜索宽度、IVF 区域与 PQ 距离。图、IVF 小例子使用正文给定图与中心，不声称实现了产品建索引算法；版本状态仅模拟单进程事件顺序，不代表数据库并发安全。

```bash
python curriculum/07-vector-db/labs/numeric_lab.py
python -m unittest discover -s curriculum/07-vector-db/labs -p "test_*.py" -v
```

预期可检查结果：全库平方 L2 前三是 A、C、F，alpha 前三是 A、C、D；全库余弦先取三条再过滤只剩 A、C。图宽度 1 返回 A，宽度 2 返回 T；IVF 探测一个列表返回 4，两个列表返回 5.1；PQ 近似距离为 0.30，原始平方距离为 0.15。删除版本 8 后，迟到版本 7 不被状态模拟接受。

测试还直接提取正文 02、03 的 Python 代码块并执行，而不是维护第二份相同程序。其余测试复用 `numeric_lab.py` 中的函数，核对输入边界、并列、空目标和新情境。若移动正文代码，应同步检查提取测试，而不是删除断言。

`test_reader_refinement.py` 直接读取第 06 章的中心训练输入、更新表与新条件自测，核对分配和均值；再读取第 09 章状态表中的向量，核对更新前后的距离排名。中心手算应得到 1、9，新条件得到 2、10；记录示例在完整 upsert 后返回 C，仅改标签且不加标签过滤时仍返回 A。这些仍是数值和顺序演示，不是实际数据库 CRUD、索引训练或并发测试。

**结果边界。** 这些测试通过，证明的是指定数值与单进程模拟行为，不证明 Faiss、数据库并发、持久化或 RAG 效果。输出到屏幕的 JSON 不是持久化业务状态。

<a id="faiss"></a>
## 2. 真实 Faiss 的索引比较

**任务与条件。** 目标库固定为 Faiss 1.15.1。脚本创建固定种子的 4096 条 32 维随机向量和 128 条查询，比较 Flat、HNSW 的不同搜索宽度，以及 IVF_FLAT 的不同探测数。这是另一个明确声明的合成工作负载；六条功能数据太少，不适合作为 ANN 性能结论。

```bash
python curriculum/07-vector-db/labs/faiss_lab.py
```

此可选脚本面向已有 Faiss 1.15.1 与兼容 NumPy 的独立环境；脚本打印实际版本。版本不同或依赖不可用时，结果应记为未运行，不影响正文阅读。

**检查结果。** Flat 是精确对照；HNSW 与 IVF 的召回由真实运行计算，不预填数字。探测全部列表的 IVF_FLAT 应在浮点容差内匹配 Flat 的排序距离。参数增大后的召回变化用于观察，不把严格单调当成所有实现的断言。

脚本只输出批量总耗时和摊销每查询耗时，**不是 P95/P99**，也不是单请求网络延迟。未验证真实文本质量、服务端并发、过滤执行计划、更新、持久化或生产负载。结束后内存对象随进程释放，不创建外部数据库。

<a id="service"></a>
## 3. 真实 Qdrant 的记录与过滤操作

**任务与条件。** 使用独立的本机 Qdrant 1.19.1 服务。运行参考假定服务已就绪且仅绑定本机地址；不复用生产集合，也不暴露未鉴权端口到公网。脚本只接受回环地址，通过标准库 REST 请求访问服务，不使用 Local Mode 模拟。

```bash
# 无 --run：明确跳过，不连接服务、不修改数据。
python curriculum/07-vector-db/labs/qdrant_lab.py

# 仅在独立本机服务准备好后运行。
python curriculum/07-vector-db/labs/qdrant_lab.py --run --url http://127.0.0.1:6333
```

执行时读取服务版本，创建随机命名的临时集合，写入六条数据并用 `wait=true` 等待操作完成；相同 ID 重放后计数应仍为 6。随后执行 alpha 范围内的**精确**搜索，预期 A、C、D，再验证按 ID 读取、元数据更新、删除后的读取。所有操作仅作用于新建的临时集合，`finally` 中清理；若清理失败，程序报错，不伪装成完成。创建请求本身超时时，服务可能已经创建集合；脚本会报告本次随机名称与结果不确定状态，需要按这个确切名称核对，不会宣称没有产生外部状态。

余弦集合可能规范化内部向量，因此按 ID 读取原向量时，不应要求 B 仍以 `[10,0]` 的原始模长保存。业务记录标识 A～F 放在 payload 中，服务主键使用整数 1～6，二者的职责不同。

**结果边界。** 这只是单机服务功能验证。六条数据与 `exact=true` 不证明 HNSW 真的参与了检索；等待完成不证明重启耐久性、跨副本可见性或多连接并发顺序。脚本没有验证数据库条件写入和快照迁移，正文对应机制不能拿这个实验冒充集成验证。

## 状态约定

退出码 0 表示所声明实验成功，77 表示依赖或运行前提缺失而跳过，其他非零表示失败。版本不匹配属于错误，不静默跳过。跳过必须单列，不能计入通过。

运行真实服务实验还应保留服务配置与日志。要验证并发、故障恢复或生产性能，需要另外设计多连接、进程重启、复制故障和负载测试；本实验不声称已经覆盖这些层次。
