本页只用于唤醒已学机制。遇到不理解的边界，回正文与综合推演，不把速记词当成解释。

## 一次任务的主线

```text
目标与约束 → 本次输入 → 模型候选 → 受控执行
                  ↑                    ↓
                  └────── 观察与状态 ───┘

结果候选 → 验收 → 交付
等待 / 取消 / 预算停止 / 失败 ≠ 成功
```

## 容易混淆的责任

| 概念 | 一句话 | 必要边界 |
|---|---|---|
| Workflow / Agent | 主要路径由程序预定义，或模型依据观察选择 | 有工具、有循环都不是充分分类条件 |
| Context | 本次模型得到什么 | 存着不等于已经发送 |
| State | 程序下一步需要知道的当前情况 | 也可以记录结果未知 |
| History | 发生过的交互 | 不必全部进入下一次输入 |
| Memory | 未来复用的经过维护的信息 | 有范围、来源、纠错与删除 |
| Compaction | 安装更短的可继续输入视图 | 不是业务恢复备份 |
| Checkpoint | 可继续的位置与必要状态/引用 | 不回退外部世界 |
| Trace | 定位阶段与相关证据 | 不是唯一业务账本 |
| Eval | 依据任务要求判断结果 | 评分器也需要验证 |

## 工具从说明到结果

```text
注册实际实现 → 选择模型说明 → 发现/选择候选
→ 解析 → Schema → 业务条件 → 授权与必要批准
→ 执行 → 结果校验 → 状态记录 → 模型观察
```

Schema 可校验已声明的数值范围；合法数据不自动获得权限。只读可能泄密，不同工具可能冲突，结果必须按调用 ID 关联。

## 失败后先问三件事

1. 失败发生在参数、权限、依赖还是结果阶段？
2. 动作是否可能已经产生效果，能否查询或安全重复？
3. 是否仍在原任务范围与总预算内？

修参数、重试同一请求、改用后备路径和停止，是不同处理。新尝试不应产生新的业务操作身份。

## 恢复与取消

```text
读当前取消与执行权
→ 核对未决操作及下游回执
→ 补齐已确认事实，未知就保留未知
→ 恢复必要环境与产物
→ 重建输入，按权限与预算继续或停止
```

检查点频繁也有跨系统窗口；planned 不证明从未发送。取消是停止意图，迟到成功仍要记录；补偿是新的动作，也会失败。租约过期不保证旧 Worker 物理停止。

## 三种安全判断

| 判断 | 问题 |
|---|---|
| Policy / Authorization | 这个可信身份在此任务能做吗 |
| Approval | 需要确认的具体对象与参数获准了吗 |
| Sandbox | 代码实际允许访问哪些资源 |

输入来源、最小凭证、网络出口、结果脱敏和记忆写入各有责任。输出拦截不能撤销已有动作，容器名称不证明隔离正确。

## 接入与协作

| 机制 | 目的 |
|---|---|
| MCP | Host 经 Client 接入 Server 的工具、资源和模板 |
| Skill | 按需加载任务方法与资源 |
| Hook | 在定义的生命周期事件触发处理 |
| Plugin | 安装、启用和分发一组扩展 |
| Agent as Tool | 子任务返回，父级继续 |
| Handoff | 转移当前处理权 |
| A2A | 独立 Agent 系统的消息、任务与产物互操作 |

MCP 按本章目标 2026-07-28 区分旧版初始化；A2A 按 1.0.0 核对绑定。实际 SDK 与产品快照不自动支持所有新规范。

## 交付前回顾

核心知识应能解释新情境：调用是否真的执行，外部结果是否已核对，资料是否适用，任务是否通过验收。框架功能表、模型自信、绿色单测和创建 PR，都不能单独替代最终交付状态。
