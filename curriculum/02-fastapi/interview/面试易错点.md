# FastAPI 面试易错点

> 这些不是“语法错误”，而是 AI Application / Agent Service 面试里最容易暴露工程边界不清的表达。

1. ❌ FastAPI 就是 Web Server。→ ✅ FastAPI 是 ASGI Application Framework，Uvicorn 等承担 Server 角色。
2. ❌ Starlette 和 FastAPI 没关系。→ ✅ FastAPI 构建在 Starlette Web/ASGI 基础之上。
3. ❌ Pydantic 只是 IDE 类型提示。→ ✅ 它承担 Runtime Validation / Serialization / Schema。
4. ❌ ASGI 就是 asyncio。→ ✅ ASGI 是 Server/Application 协议，asyncio 是 Python 异步 Runtime 之一。
5. ❌ 会写 `@app.get()` 就会 FastAPI。→ ✅ 真正重点是 Request/Resource/Async/Streaming 生命周期。
6. ❌ Router 里把所有业务写完最直接。→ ✅ Router 主要做 Web Contract，核心业务应进入 Service/Runtime。
7. ❌ GET/POST 只是名字不同。→ ✅ Method 是 HTTP Contract 的一部分。
8. ❌ 所有输入都来自 JSON Body。→ ✅ Path/Query/Header/Cookie/Body 来源不同。
9. ❌ OpenAPI 只是 Swagger 页面。→ ✅ 它还是机器可读 Contract，可用于文档/客户端生成。
10. ❌ 所有失败都返回 200 + success=false。→ ✅ HTTP Status 本身有语义。
11. ❌ Request Model = ORM Model = Response Model。→ ✅ 三者边界不同。
12. ❌ JSON 能解析就代表数据有效。→ ✅ 还需要 Schema / Business / Authorization Validation。
13. ❌ response_model 只是文档。→ ✅ 还会参与验证、序列化和字段过滤。
14. ❌ HTTPException 应该从 Repository 深层直接抛。→ ✅ Domain Error 与 Web Error 应分层映射。
15. ❌ Middleware 和 Dependency 都只是“前置函数”。→ ✅ Middleware 是 Application 横切栈，Dependency 是 Route-aware graph。
16. ❌ Current User 一定要放 Middleware。→ ✅ Route-aware Authentication/Authorization 通常更适合 Dependency。
17. ❌ Request ID 应该每个 Handler 自己生成。→ ✅ 它是典型 Middleware 横切上下文。
18. ❌ Middleware 添加顺序不影响行为。→ ✅ 它们是嵌套栈，请求/响应顺序相反。
19. ❌ yield Dependency 的 cleanup timing 永远固定不变。→ ✅ 这是 FastAPI 历史上演进过的版本行为，当前还支持不同 scope。
20. ❌ Handler return 就等于 Streaming Response 发完。→ ✅ Stream 可能继续很久。
21. ❌ Background Task 可以继续使用 Request-scoped DB Session。→ ✅ 应建立自己的资源生命周期。
22. ❌ 每个请求 new 一个 HTTP/LLM Client 更干净。→ ✅ 会破坏连接复用并放大资源成本。
23. ❌ `async def` 一定更快。→ ✅ async 的优势主要来自等待 I/O 时可让出执行权。
24. ❌ FastAPI 会自动异步化所有同步 helper。→ ✅ 只有框架主动调用的普通 Path Operation/Dependency 会被线程池处理。
25. ❌ Thread Pool 无限。→ ✅ 会饱和和排队。
26. ❌ `asyncio.gather()` 自动限流。→ ✅ gather 不控制并发上限。
27. ❌ CPU-heavy PDF/OCR 包成 async 就行。→ ✅ 仍可能堵 Event Loop，应考虑 Process/Worker。
28. ❌ Semaphore 可以做全局多实例限流。→ ✅ 进程内 Semaphore 只管本地并发。
29. ❌ FastAPI 是 async，所以数据库必须 async。→ ✅ 驱动选择取决于 workload、成熟度和执行边界。
30. ❌ SSE 就是不断返回字符串。→ ✅ Production 应设计 typed event protocol。
31. ❌ SSE 只能 GET。→ ✅ 当前 FastAPI 官方 SSE 支持包括 POST 等方法。
32. ❌ SSE 一定比 WebSocket 差。→ ✅ 两者适配不同通信方向与复杂度。
33. ❌ Stream 已经开始后还能切换成 HTTP 500。→ ✅ Status 通常已发送，需要流内 error event。
34. ❌ Client Disconnect 后 LLM/Agent 一定自动停止。→ ✅ Transport Disconnect 和 Business Cancellation 不同。
35. ❌ WebSocket 连接存在某 Worker，所以 Session State 也应该放 Worker 内存。→ ✅ 多 Worker/多实例下关键状态需外置。
36. ❌ 登录 WebSocket 一次后所有消息都自动有权限。→ ✅ 高风险动作仍需 Policy/Authorization。
37. ❌ CORS 是 API Authentication。→ ✅ CORS 是浏览器跨 Origin 控制。
38. ❌ tenant_id 请求参数可以直接信任。→ ✅ Tenant Context 应从可信身份映射并贯穿数据层。
39. ❌ Prompt 里写“不要越权”就是权限系统。→ ✅ 权限必须落在后端策略和数据访问边界。
40. ❌ Secret 打到 Trace 里方便排错没关系。→ ✅ 需要 Redaction。
41. ❌ `BackgroundTasks` = 可靠异步任务队列。→ ✅ 它是进程内响应后任务。
42. ❌ `UploadFile` 所有内容都永远在内存。→ ✅ 使用 spooled temporary file，可在超过阈值后落盘。
43. ❌ 大文件直接 `await file.read()` 总是可以。→ ✅ 可能造成大内存峰值，应分块处理。
44. ❌ RAG Ingestion 应让 HTTP 一直等到索引完成。→ ✅ 更适合 202 + task_id + durable worker。
45. ❌ Timeout 表示下游没有执行成功。→ ✅ 只说明本地等待超时，副作用可能已发生。
46. ❌ CancelledError 当普通 Exception 吞掉即可。→ ✅ Cancellation 是控制流，需要正确传播和 cleanup。
47. ❌ Browser Disconnect = Durable Agent Cancel。→ ✅ Run 可能继续并支持重连。
48. ❌ 测试只需要 happy path 200。→ ✅ 还要 Validation/Auth/Error/Stream/Disconnect/Provider Failure。
49. ❌ dependency_overrides 会自动在每个测试后清空。→ ✅ 要显式管理测试隔离。
50. ❌ Streaming Test 只比较最终拼接文本。→ ✅ 还要检查 event order/error/terminal schema。
51. ❌ 平均延迟低就是性能好。→ ✅ P95/P99 才能暴露 Tail Latency。
52. ❌ SQL 20ms 所以 FastAPI 请求不可能 2s。→ ✅ 可能卡在 Pool Acquire / Queue / Downstream。
53. ❌ request_id 适合做 Metrics Label。→ ✅ 高 Cardinality，应放 Log/Trace。
54. ❌ 多 Worker 共享普通 Python 全局变量。→ ✅ 每个进程独立内存。
55. ❌ Worker 越多越快。→ ✅ 还受 CPU/Memory/Pool/Provider QPS 限制。
56. ❌ Liveness 和 Readiness 是同一个接口语义。→ ✅ 一个判断活着，一个判断是否应接流量。
57. ❌ Health Check 每秒应该完整打 DB/LLM/Vector。→ ✅ 深度 Probe 会放大依赖流量，应分层。
58. ❌ Lifespan 能自动完成 Kubernetes Drain。→ ✅ Application cleanup 与 Orchestrator traffic drain 是不同层。
59. ❌ FastAPI 负责 Agent Memory/Checkpoint。→ ✅ 那属于 Agent Harness Runtime。
60. ❌ `/chat` 一个接口就能表达 Long-running Agent。→ ✅ Durable Run 通常需要 run_id、state、events、cancel、approval 等 API。
