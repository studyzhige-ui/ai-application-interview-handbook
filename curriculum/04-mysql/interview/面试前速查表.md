# MySQL 面试前速查表

> 目标：面试前 20～30 分钟快速过一遍，不用于第一次学习。

## 1. 查询性能主线

```text
SQL
→ Optimizer
→ Access Path
→ B+Tree
→ Clustered / Secondary
→ Composite Index
→ Covering / ICP
→ EXPLAIN
→ Slow SQL
```

必须能一句话说清：

- B+Tree：高扇出、低树高、叶子有序，适合页式存储和范围扫描。
- 聚簇索引：叶子是完整 Row；二级索引叶子通常是 Secondary Key + PK。
- 回表：二级索引拿到 PK 后回聚簇索引取非覆盖列。
- 覆盖：查询所需列都能从当前索引获得。
- ICP：先用索引里可判断条件过滤，再决定是否读完整行。
- 联合索引：按左到右字典序组织，不是多个独立索引。
- 不走索引：可能是真正无法利用，也可能是 Optimizer 成本选择。

## 2. EXPLAIN 最少看什么

```text
Access Type
Key
Rows / Actual Rows
Extra
Join Order
filesort / temporary
```

不要只回答“看 key 是否为空”。

## 3. 事务主线

```text
ACID
→ Isolation
→ MVCC
→ Lock
→ Deadlock
→ Redo / Undo / Binlog
```

四种隔离：

```text
RU → 可能脏读
RC → 每次 Consistent Read 新 Snapshot
RR → 同事务 Consistent Read 通常保持 Snapshot
SERIALIZABLE → 更强锁语义
```

InnoDB 默认：`REPEATABLE READ`。

## 4. MVCC

```text
当前版本
→ 检查事务信息
→ ReadView 判断可见性
→ 不可见则沿 Undo 找历史版本
```

记住：

```text
MVCC ≠ 不需要锁
Undo ≠ 只用于回滚
```

## 5. 锁

```text
Record Lock → 已有索引记录
Gap Lock → 索引间隙
Next-Key Lock → Record + Gap
```

分析锁范围必须看：

```text
Isolation + Index + Condition + Access Path + Statement
```

Deadlock：

```text
循环等待
→ InnoDB 检测
→ 回滚 Victim
→ 应用安全 Retry
```

降低方法：固定访问顺序、短事务、好索引、少不必要锁。

## 6. 三种日志

```text
Undo   → Rollback + MVCC
Redo   → WAL + Crash Recovery + Durability
Binlog → Replication + PITR + CDC
```

两阶段提交：协调 **InnoDB/Redo 与 Binlog**，不是解决 Redis 一致性。

## 7. Deep Pagination

```sql
LIMIT 100000, 20
```

慢点：前 100000 条仍要定位 / 跳过。

更好：

```text
Keyset / Seek Pagination
last_key → next page
```

多列排序要稳定 Tie-breaker，如 `(created_at,id)`。

## 8. Schema

先问访问模式：

```text
怎么查？
怎么排序？
怎么更新？
数据多大？
生命周期？
```

再定：

```text
PK / Unique / Column / Index / Split / Archive
```

AI 常见：Conversation/Message 分表，Run/Step 分表，大 Payload 与核心元数据分层。

## 9. Replication

```text
Source Binlog
→ Replica Receive
→ Apply
```

关键风险：Replication Lag。

```text
刚写后读 / 权限 / 余额
→ Source 或等待 Replica 追上
```

Replication ≠ Backup。

## 10. Sharding

学习顺序：

```text
先单库优化
→ Replication
→ 确认单节点瓶颈
→ Sharding
```

必须会：

```text
Sharding Key
Hot Shard
Cross-shard Query
Global Pagination
Global Unique
Cross-shard Transaction
Re-sharding
```

## 11. CDC

```text
MySQL Commit
→ Binlog
→ CDC
→ MQ / Search / Analytics / Vector Index
```

关键：

```text
Duplicate
Order
Idempotency
Schema Evolution
Snapshot + Incremental
Lag
Replay
```

## 12. Bulk Write

```text
Multi-row Insert / LOAD DATA
+ 合理 Batch
+ 合理 Transaction
+ Checkpoint
+ Idempotency
+ Backpressure
```

同时看：Secondary Index、随机 PK、Redo/Binlog、Disk、Replica Lag。

## 13. AI 数据分层

```text
MySQL    = Business Truth / Durable Structured State
Redis    = Cache / Session / Ephemeral State
VectorDB = Semantic Retrieval Index
Object   = Large Artifact / File
```

Vector DB 通常不是 User、Permission、Billing 的 Source of Truth。

## 14. MySQL + Redis

常见 Cache Aside：

```text
Read: Cache → Miss → DB → Cache
Write: DB Commit → Delete Cache
```

目标通常是可控最终一致，不是强原子一致。

Failure Window 用：

```text
TTL
Retry
Outbox / MQ
Binlog CDC
Monitoring / Repair
```

## 15. 面试最后自检

如果被追问，永远先补条件：

```text
哪个 Isolation？
哪个 Index？
Snapshot 还是 Locking Read？
单库还是分片？
Source 还是 Replica？
一致性允许多旧？
```

避免绝对化回答。
