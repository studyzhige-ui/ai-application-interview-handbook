# 01｜数据库、MySQL 与关系表

[MySQL 目录](../README.md) · [用 SQL 查询、增加、修改和删除记录 →](02-单表查询与增删改.md)

你和同事共用一份任务清单：谁负责哪件事，哪些已经完成，什么时候创建。只有几条时，一张表格就能看明白；记录多起来以后，你希望快速找出自己的待办，也希望两个人同时操作时，不会把对方的修改弄丢。

数据库正是围绕“把数据组织好，并让人可靠地使用它”来工作的。先看清它保存什么、怎样被访问，比一开始记索引和事务的名字更重要。

## 1. 数据库保存数据，MySQL 负责管理它

**数据库是一组有组织的数据；数据库管理系统是负责保存、查询和修改这些数据的软件。** MySQL 属于后者。日常说“我们用了 MySQL 数据库”，通常是在把软件与它管理的数据合起来说。

文件也能保存数据。区别不是“文件会丢，数据库不会丢”，而是使用文件时，往往需要自己处理按条件查找、多人同时修改、关系约束和故障恢复等工作。数据库提供这些通用能力，让应用不必每次重新实现。

例如，“编号 1 的任务改成完成”只需要描述改哪一条、改成什么。至于怎样找到它、怎样协调同时到来的请求，则由数据库按相应规则执行。业务仍要决定谁有资格修改、什么状态转移合法，数据库不会自动理解这些要求。

## 2. 关系型数据库把同类事实组织成表

先看一张名叫 `first_tasks` 的任务表：

| id（编号） | title（标题） | status（状态） |
|---:|---|---|
| 1 | 整理笔记 | pending |
| 2 | 练习 SQL | pending |

一条任务占一**行**；编号、标题和状态分别是一**列**。列也常称为字段。表规定了每条任务要用哪些属性描述，而不只是一片可以随意填写的格子。

这里 `pending` 是我们为“待办”选择的文字，`done` 表示“完成”。它们是业务约定，不是 MySQL 自带的两个特殊状态。`id` 是记录的身份：两条任务可以同名，但应有不同编号，这样修改标题以后仍能找到同一条任务。

如果要保存负责人，还可以有一张成员表，任务通过成员编号与它对应。**关系型数据库不仅能保存表，还能按列值把不同表中的记录关联起来。** “任务属于哪个成员”不需要把成员的全部资料再复制进每条任务。

表、列和记录的基本组织方式见[官方建表与使用教程](https://dev.mysql.com/doc/refman/9.7/en/database-use.html)。需要记住的是：表有统一的列结构，但查询结果并没有天然固定的显示顺序；要求按编号或日期排列，需要显式说明。

## 3. 怎样把要求交给 MySQL

你通常通过**客户端**连接 MySQL **服务器**。服务器实际管理数据；客户端提供输入语句和查看结果的界面。客户端可以是图形工具，也可以是 `mysql` 命令行。

```text
你或应用程序 → 客户端发送 SQL → MySQL 服务器执行 → 客户端显示结果
```

**SQL 是表达数据操作的语言。** 它告诉数据库“需要哪些结果”，不是要求你逐条编写扫描文件的步骤。比如下面这句会读取任务编号和标题。这里先看读法；下一章建好表以后再运行：

<a id="sql-basics_select"></a>

<!-- mysql-example: basics_select -->
```sql
SELECT id, title FROM first_tasks;
```

先把它读成一句话：“从 `first_tasks` 表里，取 `id` 和 `title` 两列。”它只查询，不会删掉没有被选中的 `status`。具体写法在下一章逐步使用，不要求先学某种应用编程语言。

一个服务器可以管理多个数据库，每个数据库可以包含多张表。建立连接后，还要选择操作哪个数据库。**连接到服务器、选择数据库、查询一张表，是三个不同的动作。**

## 4. 什么时候才算保存成功

假设任务已经改成 `done`，客户端显示操作成功。要判断修改是否已保存，还需要知道它是否已经**提交**：提交就是确认这组修改正式成立。提交以前，可以按事务规则撤销；提交以后，关闭客户端不是撤销按钮。

本课程最初的练习使用自动提交连接：没有显式开始一个事务时，一条成功的数据修改语句就会提交。后面需要“扣额度和写流水一起成立”时，再用显式事务把几条语句组成一个整体。无需在此先背全部事务特性。

关闭图形工具通常只是断开客户端；服务器和已提交的数据仍然存在。服务器重启、机器断电、磁盘损坏则是不同故障，需要日志、备份等机制应对，不能用一次重新连接代替这些验证。[提交与回滚规则](https://dev.mysql.com/doc/refman/9.7/en/innodb-autocommit-commit-rollback.html)。

> ⚠️ 正文里的修改只在专用练习库操作，不要对工作数据库试验。准备服务器、账号和连接的步骤集中在[实验环境](../examples/README.md)，不需要先学 Docker 或任何应用框架。

本课程采用 MySQL 的 InnoDB 存储引擎。可以先把它理解为 MySQL 内部管理表数据、索引和事务的部分；后面的这些机制都以它为语境。明确的课程版本与运行限制见[资料索引](../../../references/mysql/README.md)。

## 本章小结

数据库管理系统不只是保存文件，还提供查询、约束、并发和恢复能力。关系表用行描述记录、用列描述属性；客户端通过 SQL 向服务器提出要求，提交则确认修改成立。

## 🎯 面试怎么回答

### 数据库、MySQL 和 SQL 是什么关系？

数据库是有组织的数据；MySQL 是管理它的软件；SQL 是向它表达查询和修改要求的语言。客户端负责传递请求，服务器实际处理和保存数据。

## ⚠️ 易错点

> ⚠️ 关闭客户端不等于删除已提交数据；未提交修改不能按同样方式判断。

> ⚠️ 标题等业务属性可能重复或改变，记录身份应由明确的编号承担。
