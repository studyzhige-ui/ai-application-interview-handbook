# 14｜后训练与蒸馏：示范、偏好和奖励分别在教什么

[← SFT、LoRA 与训练判断](13-FineTuning与LoRA.md) · [模块首页](../README.md) · [综合复习 →](../review/README.md)

两份回答都符合 JSON 格式。一份礼貌但编造到达日期，另一份明确说明日期未知。只有“生成合法 JSON”的奖励，分不出这两个结果；只有模仿少数标准答案，也未必覆盖不同措辞下的取舍。

**Post-training（后训练）** 是在预训练之后进一步改善任务行为、指令遵循、偏好或推理表现的训练活动。SFT 是其中一种；偏好优化与强化学习可以使用不同的反馈信号。蒸馏则关注如何把教师模型的行为或分布传给学生模型。本章比较它们改变什么，不展开大型训练集群。

## 1. 先区分三种学习材料

| 材料 | 订单例子 | 给模型的学习信号 |
|---|---|---|
| 示范答案 | 输入缺日期，人工写一份正确回答 | 学习这份期望输出 |
| 成对偏好 | 同一输入下，选“明确未知”优于“编造明天” | 学习两份回答的相对取舍 |
| 奖励分数 | 给多份采样结果按事实、格式和风险评分 | 调整策略，使高奖励行为更常出现 |

偏好或奖励可以来自人、模型评审、确定性程序或组合。来源不同，误差和成本不同。模型评审并不天然客观；单一规则也可能只覆盖任务的一部分。

**Policy（策略）** 在这里就是生成模型在给定输入下选择输出的概率分布；训练策略是改变这个分布，不是另加一个神秘的“策略系统”。

## 2. 一条经典 RLHF 路线怎样工作

**RLHF（基于人类反馈的强化学习）** 是一类利用人类反馈改善策略的方法。经典语言模型流程通常先做 SFT，再收集同一问题的回答对和人类偏好，用这些比较训练 **Reward Model（奖励模型）**，最后通过强化学习提高生成回答的奖励。

```text
任务输入 → 当前策略采样回答 → 奖励模型或规则评分
             ↑                       │
             └──── 根据反馈更新 ──────┘
```

直接无约束地追求高分，模型可能偏离原有语言能力，或利用奖励模型的弱点。因此常用参考策略限制偏离程度。**KL 散度**在这里用于衡量两个概率分布的差异，是约束或惩罚的一种方式；它不是事实正确性的证明。

**PPO（近端策略优化）** 是经典实现中常用的强化学习算法之一，通过限制或裁剪相对于采样时策略的更新幅度，减小训练不稳定风险；经典 Actor-Critic 路线还训练价值估计来帮助评价行动相对基线的好坏。RLHF 不是 PPO 的别名，也不是所有后训练都需要单独奖励模型。经典流程与其他方法的关系见 [DPO 论文的背景部分](https://arxiv.org/html/2305.18290)。

## 3. DPO 为什么不等于“只保留好答案继续 SFT”

**DPO，Direct Preference Optimization（直接偏好优化）** 使用同一输入下的偏好回答与非偏好回答，直接更新生成模型，不需要先拟合一个显式奖励模型再跑经典在线 RL 流程。

但它不是单纯删除坏答案。标准 DPO 会比较当前策略相对于参考策略，在好、坏回答上的对数概率差异。记输入为 x，偏好回答为 y+，非偏好回答为 y−：

```text
s = β × { [log π(y+|x) − log π_ref(y+|x)]
          − [log π(y−|x) − log π_ref(y−|x)] }
损失 = −log sigmoid(s)
```

`π` 是当前生成策略，`π_ref` 是参考策略，`β` 是控制这一相对比较尺度的超参数。`sigmoid(s)=1/(1+exp(−s))` 把比较分数映射到 0 到 1 之间；在这个成对学习目标中，s 越大，损失越小。这里的值表达偏好比较，不是事实正确概率。回答的 log 概率来自各 Token 的条件 log 概率之和；不是先给整段文本查一个概率字段。

直观上，训练希望更支持偏好回答相对于非偏好回答的取舍，同时以参考策略为基准。只把 y+ 当示范做 SFT，没有使用同样的成对比较信号。标准推导与适用假设见 [DPO 原论文](https://arxiv.org/html/2305.18290)。

如果偏好标注偏向“语气自信、篇幅长”，模型也可能学会这些偏差，而不是更诚实。必须明确比较标准并检查跨任务泛化，不能把偏好优化理解成自动提高所有能力。

## 4. GRPO 用一组回答建立相对基线

**GRPO，Group Relative Policy Optimization（组相对策略优化）** 对同一个问题采样一组回答，用组内奖励的相对差异构造优势信号。经典设计不需要额外训练一个与 PPO 路线相同的价值模型，但仍需要采样、奖励计算和策略更新。

**Advantage（优势）** 表示一个结果比基线好多少。为了看清“相对”二字，假设同一问题的四份回答奖励为 `[0,1,1,2]`，采用本例明确规定的总体标准差：

```text
均值 = 1
减均值后 = [-1,0,0,1]
总体标准差 = sqrt((1+0+0+1)/4) = sqrt(0.5)
归一化优势 ≈ [-1.4142,0,0,1.4142]
```

低于组平均的回答得到负优势，高于平均的得到正优势。实际目标还包含相对采样策略的概率比、裁剪和参考策略约束，不是简单把这四个数字直接加到模型参数上。来源见 [DeepSeekMath 的 GRPO 定义](https://arxiv.org/html/2402.03300v3)。

若一组奖励完全相同，减均值后没有相对区分信号，标准差也为零；实现需要数值稳定处理。不能据此说整次训练绝对没有任何更新，因为仍可能存在其他损失项；能够确定的是这组奖励没有区分优劣。

## 5. 奖励得分提高，为什么任务可能更差

**Reward Hacking（利用奖励缺陷）** 指模型学会提高代理分数，却没有真正完成目标。例如只奖励 JSON 通过率，模型可能一直输出最简单合法对象；只奖励“回答很完整”，可能生成更多没有依据的细节。

可以用多种相互补充的检查：格式合法、必要字段正确、事实有证据、权限边界满足、关键动作有真实结果。它们仍需要明确定义权重与失败门槛，不是指标越多越安全。

**结果奖励**评价最终输出或任务完成情况；**过程奖励**评价可检查的中间步骤。过程奖励可能提供更细反馈，也更需要可靠标注和防止“写出像正确步骤的文字却没有正确结果”。不能把模型自述的过程当成真实内部轨迹。

训练评价必须与奖励设计保持一定独立性。用奖励模型自身分数既当训练目标又当唯一验收，就可能看不到它的盲点。保留未参与训练的题目、任务测试和必要人工审查，才有机会发现代理目标被钻空子。

## 6. 蒸馏是在把什么传给学生

**Knowledge Distillation（知识蒸馏）** 让学生模型学习教师模型提供的监督信号。教师不必在所有任务都最好，学生也不必在所有场合都更小，但常见目标是在特定任务上获得更低成本或更易部署的模型。

两种常见形式需要区分：

| 形式 | 教师提供什么 | 学生学什么 | 实际限制 |
|---|---|---|---|
| 分布蒸馏 | 候选类别或 Token 的概率分布 | 匹配教师对多个候选的相对判断 | 需要可访问的分布及兼容表示 |
| 序列蒸馏 | 教师生成的答案、标注或可验证解法 | 用筛选后的结果做监督训练 | 可能复制教师错误与风格偏差 |

分布蒸馏常用温度平滑，让非最高项的相对信息更可见；这里的温度服务于训练监督，不等于线上随意调高采样温度。经典思路见 [知识蒸馏原论文](https://arxiv.org/abs/1503.02531)。

托管 API 不一定提供完整 logits 或概率分布，不同 Tokenizer 的词表也可能不能直接逐项对齐。因此拿教师生成文本做训练，不应包装成已经完成了 Token 分布蒸馏。

## 7. 一条可检查的蒸馏流程

先固定目标任务与基础学生模型，保留真实评测集。然后让教师处理有代表性的输入，使用确定性规则、可靠证据和必要人工检查过滤错误，再用通过筛选的样本训练学生。

最后同时比较原学生、训练后的学生和教师：目标质量是否达到门槛，未见输入是否泛化，安全与拒答是否退化，端到端延迟和单位成功任务成本是否改善。应把教师生成、筛选与训练成本计入项目总成本，不能只报告学生一次推理更便宜。

对于持续变化的订单事实，蒸馏可以教学生怎样依据记录回答，不能代替实时查询。对于编程任务，教师代码应经过任务测试，而不是仅凭可解析或解释流畅就进入训练。

## 8. 应用工程师怎样选择，而不先选一个热门算法

有稳定任务规则和高质量示范，可先评估 SFT；更容易标注好坏取舍时，可评估偏好方法；有可靠奖励且有必要训练预算时，再考虑强化学习。需要让更适合部署的模型获得特定任务能力，可以评估蒸馏。LoRA 等参数高效方法又可以与某些训练目标组合。

这些选择之前，仍要排除数据没有提供、检索遗漏、工具调用错误和评价失真等应用问题。训练结果对任务、数据和计算条件敏感；算法名称不能替代与更简单方案的对照。

## 9. 本章小结

SFT 学示范输出，偏好优化学回答之间的取舍，强化学习根据奖励调整策略，蒸馏学习教师信号。DPO 与 GRPO 使用不同的数据和优化过程，不能混为“都是偏好打分”。所有方法都可能放大反馈里的错误；独立评测与业务结果验证是不可省略的条件。

## 10. 🎯 面试怎么回答

**问：SFT、DPO、GRPO 与蒸馏怎样区分？**

> SFT 根据输入与期望答案做监督训练。DPO 使用同一问题的偏好与非偏好回答，比较当前策略相对参考策略的对数概率差，直接优化偏好，不需要经典显式奖励模型加在线 RL 流程。GRPO 对同一问题采样多份回答，用组内相对奖励形成优势，再做受约束的策略更新。蒸馏关注教师信号向学生的传递，可以用概率分布，也可以用筛选后的生成文本。它们解决的不是同一维度的问题，选择依据是数据、奖励可信度、资源和任务收益。

## 11. ⚠️ 易错点

- 把 RLHF 等同于 PPO，或把全部后训练都叫强化学习。
- 把 DPO 说成简单丢弃负例，把 GRPO 说成不需要奖励。
- 把训练奖励提高当成真实质量提高；用同一个评审既训练又独立验收。
- 把教师输出不加过滤地当真值，或把序列训练称作已获得完整分布蒸馏。

## 12. 自测

**任务 1：** 某偏好数据总把较长回答标为更好，即使它有未获支持的日期。DPO 能否自动发现这种标注错误？指出应修改的数据标准与一项独立评测。

<details><summary>答案与解释</summary>

不能期待目标函数自动知道偏好标签背离业务。应把事实支持、缺失处理和简洁完整等标准分开，不因篇幅长就胜出；在未参与训练的有证据/缺证据样本中独立测无依据承诺和误拒。

</details>

**任务 2：** 两组奖励分别为 `[0,0,2,2]` 与 `[1,1,1,1]`。按本章总体标准差口径，求第一组归一化优势，并说明第二组需要怎样处理。不要据此断言所有损失项都没有梯度。

<details><summary>答案与解释</summary>

第一组均值 1，标准差 1，优势为 `[-1,-1,1,1]`。第二组没有组内优劣差别，标准差为零，需要稳定处理，这一奖励分量不提供相对区分。仍可能有参考策略约束等其他训练项。

</details>

**任务 3：** 教师只能返回文本，学生使用不同 Tokenizer。你筛选教师答案后训练学生，应该称哪类蒸馏？上线前至少还缺哪两项检查？

<details><summary>答案与解释</summary>

属于序列或响应层面的蒸馏，不是直接逐 Token 分布匹配。还需要独立任务质量与泛化检查，以及延迟、成本、安全、拒答等实际部署条件的验证；教师文本本身也应先筛选。

</details>
