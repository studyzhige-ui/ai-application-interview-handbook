# LLM Foundation｜面试前 20–30 分钟速查

> 这份不是第一遍学习材料，只用于面试前快速恢复主线。

## 1. 总链路

```text
Text
→ Tokenizer
→ Token IDs
→ Embedding + Position
→ Transformer Blocks
→ Hidden State
→ LM Head / Logits
→ Decoding
→ Next Token
→ Autoregressive Loop
```

记住：模型处理的是 Token，不是字符；生成是逐 Token，不是一次写完整句。

---

## 2. Context

```text
Total Budget
= System
+ User
+ History
+ RAG
+ Tool Result
+ Output Reserve
```

关键：

- Context Window ≠ Memory；
- Long Context ≠ 不需要 RAG；
- 能塞进去 ≠ 能稳定利用；
- 输入越长 → Prefill / Cost / KV Cache 压力越大。

### Lost in the Middle

长 Context 中不同位置的信息利用率可能不同，中间证据可能更难被稳定使用。

---

## 3. Transformer

```text
Transformer Block
= Self-Attention
+ FFN
+ Residual
+ Normalization
+ Position Mechanism
```

### QKV

```text
Attention(Q,K,V)
= softmax(QK^T / sqrt(d)) V
```

- Q：查什么；
- K：怎样被匹配；
- V：真正传递什么。

### Causal Mask

位置 i 只能看 `<= i`，不能偷看未来 Token。

### RoPE

旋转 Q/K，让相对位置信息进入 Attention。

---

## 4. Generation

### Logits

未归一化词表分数。

### Softmax

把 Logits 变成下一 Token 概率分布。

### Temperature

低 → 分布更尖、输出更稳定；高 → 更发散。

### Top-k

只留概率最高 k 个候选。

### Top-p

保留累计概率达到 p 的动态候选集合。

⚠️ 低 Temperature ≠ 更真实。

---

## 5. KV Cache / Serving

### KV Cache

缓存历史 Token 的 K/V，避免 Decode 时重复算整个前缀。

代价：显存。

```text
KV Size
∝ Layers × KV Heads × Head Dim × Sequence × Concurrency
```

### Prefill

处理完整输入并建立 KV Cache。

### Decode

逐 Token 生成并读写 KV Cache。

### TTFT

第一个 Token 等待；常看 Queue + Prefill。

### TPOT

每个输出 Token 间隔；看 Decode。

### Continuous Batching

请求动态进入 / 退出 Batch，提高 GPU 利用率。

### PagedAttention

KV Cache 按固定 Block 管理，减少连续显存预留与碎片。

---

## 6. Precision / Quantization

粗略权重内存：

```text
参数量 × bytes_per_parameter
```

但最终显存还包括：

```text
Weights
+ KV Cache
+ Runtime Buffer
+ Framework Overhead
```

量化：

- 降低内存 / 带宽；
- 可能提高吞吐；
- 可能损失质量；
- 不保证一定更快。


最大模型 ≠ 最优业务模型。

---

## 8. Embedding / Reranker

### Bi-Encoder

```text
Query → q
Doc   → d
sim(q,d)
```

文档可预计算，适合 ANN 大规模召回。

### Cross-Encoder

```text
[Query, Doc]
→ Joint Model
→ Relevance Score
```

更准但贵，适合少量候选 Rerank。

```text
Retriever Recall
是后续 Reranker 的候选上限
```

---

## 9. Prompt Engineering

稳定结构：

```text
Goal
Context
Constraints
Examples
Tool / Capability
Output Contract
Fallback
```

Production 必须：

```text
Prompt Version
+ Evaluation Set
+ Regression
+ Cost / Latency
```

Prompt 不是万能层。

---

## 10. Hallucination

先做 Attribution：

```text
Model?
Prompt?
RAG?
Tool?
Context Freshness?
Parsing?
```

治理：

```text
RAG / Tool
+ Refusal
+ Grounding / Citation
+ Rule Validation
+ Test / Human Review
```

有 RAG ≠ 零幻觉。

---

## 11. Prompt vs RAG vs Fine-tuning

```text
任务表达问题
→ Prompt

外部 / 私有 / 实时知识
→ RAG / Tool

稳定行为能力差距
→ Fine-tuning

Timeout / Permission / Idempotency
→ Backend / Agent Runtime
```

---

## 12. SFT / LoRA / DPO / RLHF / GRPO / Distillation

### SFT

学习目标示范回答。

### LoRA

```text
ΔW = BA
rank r << d
```

只训练低秩 Adapter。

### RLHF

```text
Preference
→ Reward Model
→ RL Optimization
```

PPO 是可能采用的算法之一。

### DPO

直接用：

```text
Chosen vs Rejected
```

学习偏好。

### GRPO

基于奖励的策略优化方法之一，常见于可验证 Reasoning 场景；重点看 Reward / Sampling / Stability。

### Distillation

Teacher → Student，目标是迁移特定能力、降延迟 / 成本。
