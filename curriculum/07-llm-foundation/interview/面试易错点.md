# Interview｜容易造成错误工程判断的说法

[← 模块首页](../README.md) · [表达训练](高频面试题.md) · [速查表](面试前速查表.md)

使用时不只记住右栏结论。为自己常犯的错误补一个“触发条件—后果—正确动作”的例子，再回正文解释发生过程。

## 输入与表示

| 易错说法 | 为什么不成立，应怎样判断 | 回看 |
|---|---|---|
| 字符数就是 Token 数 | 切分依赖词表、语言与模板。先编码完整实际输入，再按服务的输入、输出和总窗口规则验算。 | [第 02 章](../docs/02-TokenContext与LongContext.md) |
| 长窗口等于都能可靠利用 | 能放入与能利用不同。检查实际入参、截断与证据位置，再做固定条件对照。 | [第 02 章](../docs/02-TokenContext与LongContext.md) |
| Token ID 越接近，语义越相似 | ID 是词表索引。相似性由训练出的表示及度量决定。 | [第 03 章](../docs/03-TransformerBlock.md) |
| FFN 直接在 Token 之间交换内容 | 标准逐位置 FFN 改变每个位置的特征；跨位置混合主要来自 Attention。 | [第 03 章](../docs/03-TransformerBlock.md) |
| 把被屏蔽位置的分数乘零就行 | softmax 中 exp(0)=1。被屏蔽位置应最终权重为零；还要避免整行全部无可见位置。 | [第 04 章](../docs/04-Attention与Position.md) |
| RoPE 可以保证无限长外推 | 位置建模方式不替代训练分布、扩展方法和长任务评测。 | [第 04 章](../docs/04-Attention与Position.md) |

## 生成与资源

| 易错说法 | 为什么不成立，应怎样判断 | 回看 |
|---|---|---|
| 概率高的 Token 表示事实置信度高 | 它是当前条件下的生成分布，不是事实正确性的校准概率。 | [第 05 章](../docs/05-Generation与Decoding.md) |
| 温度越低，下一步排序越不同 | 正温度只改变差距，不改变同一组 logits 的排序；采样结果分布会改变。 | [第 05 章](../docs/05-Generation与Decoding.md) |
| 温度为零能绝对复现任何服务 | 它常表示贪心约定；模型、模板、版本、内核与并发仍可能影响结果。 | [第 05 章](../docs/05-Generation与Decoding.md) |
| 一次前向、一个 Token、一个分片是一回事 | 常规解码、推测验证和网络缓冲有不同粒度。按实际事件定义指标。 | [第 05 章](../docs/05-Generation与Decoding.md) |
| KV 保存的是历史回答文本或全部 QKV | 标准缓存复用历史 K/V，文本和业务记忆是不同对象。新 Q 与历史 K 匹配即可，不必为此保存全部历史 Q。 | [第 06 章](../docs/06-KVCache与PrefillDecode.md) |
| 刚选出的 Token 已经写进 KV | 通常需要把它再送入模型才形成该位置的 K/V。首 Token 与最终停止时尤其要区分。 | [第 06 章](../docs/06-KVCache与PrefillDecode.md) |
| 模型换 Adapter 后前缀相同就能复用缓存 | 缓存还依赖权重、位置、编码等条件；不兼容时须隔离或失效。 | [第 06 章](../docs/06-KVCache与PrefillDecode.md) |
| PagedAttention 消除了显存限制 | 仍有实际 K/V、尾块与元数据；它减少特定浪费，不创造无限容量。 | [第 07 章](../docs/07-ServingEngine与性能.md) |
| FlashAttention 把所有模型的关系计算变成线性 | 它主要优化内存读写；全注意力仍有位置两两关系，架构稀疏化是另一件事。 | [第 07 章](../docs/07-ServingEngine与性能.md) |
| 4 位权重意味着整套运行显存降到四分之一 | 基础权重存储与 KV、激活、计算精度、量化元数据不同，速度也由硬件与内核决定。 | [第 07 章](../docs/07-ServingEngine与性能.md) |
| TTFT 下降证明所有用户都变快 | 还要检查输出长度、TPOT、端到端完成时间、并发与尾延迟。 | [第 07 章](../docs/07-ServingEngine与性能.md) |
| 客户端断开证明 GPU 计算已取消 | 需要确认取消信号是否到达服务、请求是否终止及资源是否回收。 | [第 07 章](../docs/07-ServingEngine与性能.md) |

## 调用、检索与多模态

| 易错说法 | 为什么不成立，应怎样判断 | 回看 |
|---|---|---|
| HTTP 200 或合法 JSON 就能执行 | 分别检查完成状态、拒绝、结构、跨字段约束、权限和动作结果。 | [第 08 章](../docs/08-ModelAPI与Selection.md) |
| 每次调用便宜的模型总成本最低 | 重试、低成功率和更长输出都可能改变每个成功任务的成本。 | [第 08 章](../docs/08-ModelAPI与Selection.md) |
| 成对评审高分就是业务事实准确率 | 评审可能受顺序、长度与偏好影响；要用真实任务和可核验标准。 | [第 08 章](../docs/08-ModelAPI与Selection.md) |
| 任意取平均就能得到可用语义向量 | 池化必须匹配模型训练约定，均值要排除 Padding，归一化要处理零向量。 | [第 09 章](../docs/09-Embedding与Reranker.md) |
| 同维 Embedding 可以混在一个空间 | 模型、模板、池化和归一化都可能改变空间；先验证兼容性。 | [第 09 章](../docs/09-Embedding与Reranker.md) |
| Reranker 可以找回没召回的文档 | 只能重排给到的候选。缺候选需向前排查。 | [第 09 章](../docs/09-Embedding与Reranker.md) |
| Reranker 分数在 0 到 1 就是概率 | 分数意义与校准依赖训练和实现；不能随意跨模型或跨查询合并。 | [第 09 章](../docs/09-Embedding与Reranker.md) |
| Vision 模型就是 OCR | 视觉关系、区域对应和时间信息不都能由文字提取表达；也不能忽略 OCR 的可检索性。 | [第 10 章](../docs/10-MultimodalFoundation.md) |
| 提高分辨率或抽更多帧一定更好 | 可能增加成本、挤占预算，且仍会漏掉未被采样事件；需要任务驱动地选区域和时间。 | [第 10 章](../docs/10-MultimodalFoundation.md) |
| 给截图就自动拥有读取其全部内容的权限 | 先做授权、必要裁剪和脱敏；屏幕中的指令仍是非可信材料。 | [第 10 章](../docs/10-MultimodalFoundation.md) |

## 质量与训练

| 易错说法 | 为什么不成立，应怎样判断 | 回看 |
|---|---|---|
| 把规则放到更高优先级就形成安全边界 | 规则影响生成行为；读取权限与外部写动作还必须由应用强制检查。 | [第 11 章](../docs/11-PromptEngineering.md) |
| Few-shot 是现场训练参数 | 推理时示例作为条件输入，不等于执行梯度更新。 | [第 11 章](../docs/11-PromptEngineering.md) |
| 引用真实意味着结论被支持 | 还要核对证据是否支持该陈述、时间和对象是否匹配，以及是否存在冲突。 | [第 12 章](../docs/12-Hallucination与干预边界.md) |
| 不回答越多，幻觉治理就越好 | 须一起看作答正确比例、覆盖率、可回答题误拒和风险。 | [第 12 章](../docs/12-Hallucination与干预边界.md) |
| RAG 或微调能保证永不幻觉 | 证据可能旧或未召回，模型也可能误读；训练目标与部署输入都有限制。 | [第 12 章](../docs/12-Hallucination与干预边界.md) |
| LoRA 和 SFT 二选一 | LoRA 是参数更新方式，SFT 是学习目标，可以组合。 | [第 13 章](../docs/13-FineTuning与LoRA.md) |
| LoRA 参数占比就是总训练显存占比 | 还要计算冻结基础权重、激活、梯度、优化器和其他开销。 | [第 13 章](../docs/13-FineTuning与LoRA.md) |
| QLoRA 表示所有运算都使用 4 位 | 冻结量化基础权重与高精度适配参数、计算过程要区分。 | [第 13 章](../docs/13-FineTuning与LoRA.md) |
| 训练损失下降就能交付模型 | 检查独立任务集、数据泄漏、边界能力、线上格式与版本兼容。 | [第 13 章](../docs/13-FineTuning与LoRA.md) |
| DPO 就是扔掉坏答案再 SFT | 标准 DPO 使用好坏回答相对参考策略的成对比较；信号不同。 | [第 14 章](../docs/14-PostTraining与Distillation.md) |
| GRPO 奖励全相同也有组内优劣 | 这组奖励不提供相对区分；仍要正确处理零方差，其他正则项也可能有作用。 | [第 14 章](../docs/14-PostTraining与Distillation.md) |
| 教师更强，所以蒸馏数据全部正确 | 教师也可能犯错，需过滤、授权与独立测试，不能只用教师再评自己。 | [第 14 章](../docs/14-PostTraining与Distillation.md) |

技术依据与版本见 [References](../../../references/llm-foundation/README.md)。这些纠偏不构成对某个未测试部署的性能或正确性保证。
