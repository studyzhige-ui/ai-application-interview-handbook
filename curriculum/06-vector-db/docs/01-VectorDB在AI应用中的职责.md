# 01｜向量数据库究竟负责什么

[模块目录](../README.md) · [02 向量空间与相似度：先把“近”说清楚 →](02-VectorSpace与Similarity.md)

你在给团队做一个知识库。用户问：“出差回来怎样报销？”文档里写的是“差旅费用报销流程”。逐字匹配可能找不到相同句子，但两句话的意思接近。系统需要找到相关段落，再把段落交给回答问题的模型。

这里先不搭完整 RAG，也不安装数据库。我们先跟着一条资料和一次查询走一遍：**向量从哪里来，数据库接过它以后做什么，又有哪些事情它并不知道。**

## 1. 从一段文字到一条可搜索的记录

Embedding Model（嵌入模型）接收文本，输出固定数量的数值，例如 `[0.12, -0.34, …]`。这组数值叫向量；数值的个数叫维度。模型经过训练，使某些相关文本在它学到的空间中更接近。这里的“相关”由训练目标和数据决定，不等于语句一定互相支持。

文档太长时，应用通常先把它分成若干文本块，称为 chunk（分块）。分块方法属于 RAG。本模块只需要知道：**数据库里的一条向量记录，可能对应整篇文档，也可能只对应其中一段，二者不能混为一谈。**

以《差旅制度》的一段内容为例：

| 对象 | 示例 | 谁负责生成或保存 |
|---|---|---|
| 原始资料 | 《差旅制度》第 3 节 | 文件存储或业务资料系统 |
| 文本块 | “差旅费用须在返回后……报销” | 应用的文档处理过程 |
| 向量 | 一组固定维度的数值 | 嵌入模型生成；向量存储保存 |
| 记录标识 | `travel-v1-section3` | 应用定义，用来找回同一条记录 |
| 附带信息 | 文档编号、版本、所属团队 | 应用写入；数据库按条件过滤 |

这些附带信息叫 Metadata（元数据）：它们描述向量对应的对象，不是向量坐标本身。数据库不能从“两个向量很近”推断它们属于同一个团队，更不能据此推断用户有权阅读。

> ⚠️ 注意：教材里的二维坐标是为了手算而构造的数据，不是真实文本模型输出，也不表示“第一维是报销、第二维是技术”。真实向量的单个坐标通常不能这样直接命名。

## 2. 一次搜索怎样完成

先假设文档记录已经写入。用户的问题到来后，最小查询过程是：

1. **应用确认用户身份和可访问范围。** 例如只允许读团队 A 的有效制度。
2. **应用调用兼容的查询编码器。** 它把问题转换成与文档向量可比较的查询向量。
3. **数据库在合法记录中搜索近邻。** “近”需要明确的距离或相似度规则。Top-K 表示按该规则取最靠前的 K 条，不是保证找到了 K 条正确答案。
4. **数据库返回记录标识、分数，以及请求返回的元数据。** 应用据此取回对应版本的原文。
5. **上层系统检查证据、组织上下文并生成回答。** 是否需要改写问题、补其他检索方式、重新排序，都属于更完整的检索系统设计。

```text
资料 ──文档处理──> 文本块 ──嵌入模型──> 文档向量与来源信息
                                             │ 写入
                                             ▼
问题 ──查询编码器──> 查询向量 ──带访问条件──> 向量搜索
                                             │
                                             ▼
                                      记录标识与分数
                                             │ 取原文
                                             ▼
                                      上层组织证据与回答
```

查询端和文档端不一定调用同一个函数：有些检索模型要求不同的查询前缀、文档前缀，或者使用配套的双编码器。关键是遵循同一套模型推荐的配对方式，而不是仅检查两边维度相等。[模型侧补充阅读](../../07-llm-foundation/docs/09-Embedding与Reranker.md)用于解释这些表示怎样产生；你不需要先学完模型训练，才能继续本章。

### 保存之后，还必须有找到它的路径

假设应用把长段落写入向量索引，把短于 512 个 token（模型处理的文本单位）的段落只放进缓存。用户的问题到来后，系统只搜索向量索引。那么，一条只存在缓存中的短制度，即使正好回答问题，也不会进入候选结果；“已经保存”并不意味着“能够被当前查询找到”。

缓存通常按键取值。只有查询过程能构造正确的键、经其他索引找到该记录，或者系统明确遍历这部分资料时，缓存中的内容才有返回路径。按长度选择存储位置本身不能建立这条路径。判断设计是否完整，应挑一条真实资料，从保存位置一直追到检索和取原文的步骤，而不是只检查写入是否成功。

## 3. 存一个数组，和提供向量检索，有什么差别

普通文件、Python 列表、关系数据库都可以保存一组数值。若只有几十条记录，应用把每条向量与查询逐一比较，再排序，就能得到结果。**“能够存向量”不是必须引入独立向量数据库的理由。**

当记录越来越多、同时查询的人越来越多时，每次都读出所有向量并计算距离，可能超过时间和内存预算。索引会预先组织数据，让查询少做不必要的工作。ANN（Approximate Nearest Neighbor，近似最近邻搜索）允许结果与穷举计算存在差异，以降低某些查询成本；具体怎样近似，后面会从可以核对的精确结果开始建立。

持续提供服务还需要回答另一组问题：新资料什么时候能搜到？删除什么时候生效？进程重启后数据能否恢复？多用户是否相互影响？这些不是一个距离公式能解决的。

因此可以分清三个层次：

| 层次 | 核心问题 | 不自动包含的能力 |
|---|---|---|
| 向量表示 | 如何把对象转换成可比较的向量 | 身份认证、持久存储 |
| 相似性搜索库 | 给定向量，怎样高效找近邻 | 完整的多用户数据库服务 |
| 向量检索服务或数据库 | 怎样长期、可靠地存储和查询记录 | 原文一定正确、回答一定可信 |

例如 Faiss 是相似性搜索库；pgvector 给 PostgreSQL 增加向量类型与索引；专用向量数据库则直接提供数据库服务。这些是组织能力的不同方式，不是“专业程度”的排名。[Faiss 官方简介](https://github.com/facebookresearch/faiss)和 [pgvector 官方说明](https://github.com/pgvector/pgvector/tree/v0.8.6)可核对各自职责。

## 4. 相似性、权限和事实，不能互相替代

假设最相似的段落来自另一家公司的内部制度。它可能在语义上非常相关，却不允许返回。再假设本公司的旧制度写“七天内报销”，新制度写“三十天内报销”。两段向量可能很接近，但应该采用哪一版，需要显式版本信息和业务规则。

由此可以得到一个很实用的分工：

- **距离负责比较表示。** 它不会判断某条内容是否过期、是否有证据支持。
- **元数据条件负责限定可搜索对象。** 条件由可信应用层构造，不交给模型随意决定。
- **原始资料与业务状态负责提供权威事实。** 搜索结果需要能追溯回它们。

这也解释了为什么向量索引经常是 Derived Index（派生索引）：原文、文本块和模型版本决定了向量，向量又决定索引。索引损坏后，理想情况下可以重建，而不是让原始知识一起消失。重建是否真的可行，还取决于是否保留了原文、处理规则和版本，不能只在架构图上写“可重建”。

## 5. 本模块与后续 RAG 怎样衔接

本模块先建立“给定向量后，怎样正确存、有效找、持续维护”的能力。后续 RAG 再回答“用户问题怎样变成好的检索请求，结果怎样变成可靠证据”。

例如，ANN 已经找回了与精确向量搜索完全相同的结果，但问题仍没答对。这时不能继续把全部精力放在索引参数上：可能是文本块缺少关键条件，也可能是嵌入表示没有把相关资料排在前面，或者回答阶段误读了证据。

你目前需要保留这条边界，而不必提前背完整检索流水线的所有缩写。

## 本章小结

向量数据库接收的是表示和记录，而不是“理解完成的知识”。一条可靠的查询同时需要可比较的向量、明确的距离规则、合法的数据范围和可追溯的来源。索引解决搜索成本，数据库机制解决持续服务；二者都不能替代权限与事实判断。

## 🎯 面试怎么回答

**问：为什么需要向量数据库，而不是把数组存起来就行？**

保存数组只解决存储表示。业务还需要按相似度找近邻，在规模上升时控制查询成本，并处理过滤、更新、删除和恢复。小数据可以直接精确搜索，也可以使用现有数据库的向量扩展；只有工作负载与服务要求需要时，才值得增加独立向量数据库。我会先说明数据规模、查询频率、访问条件和维护要求，再决定采用哪种形态。

**问：向量数据库是不是整个 RAG？**

不是。它承担向量的存储、检索和维护。RAG 还需要处理问题、资料、证据和生成过程。判断失败原因时，要区分“索引没有找回精确近邻”和“这些近邻本来就不能回答问题”。

## ⚠️ 易错点

“维度相同就可以混搜”忽略了表示空间是否兼容；“相似就能返回”忽略了访问权限；“索引可以重建”忽略了重建所需的原文和版本。遇到这三类说法，应分别追问编码方式、访问条件和恢复来源，而不是先换数据库。
