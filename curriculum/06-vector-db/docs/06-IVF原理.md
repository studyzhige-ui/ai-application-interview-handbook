# 06｜IVF：先选区域，再找向量

[← 05 HNSW：沿着图寻找近邻](05-HNSW机制与调优.md) · [模块目录](../README.md) · [07 量化与 PQ：用短编码近似距离 →](07-Quantization与PQ.md)

HNSW 沿连接寻找近邻。还有一种办法：先把向量放进若干“篮子”，查询只打开可能相关的篮子。这样不用维护搜索路径，但必须回答：**怎样选篮子，选错了会漏掉谁？**

IVF（Inverted File，倒排文件索引）把代表中心映射到属于该中心的记录列表。“倒排”指从中心找到记录，不是把向量倒着存，也不等于全文搜索中的词项倒排索引。

## 1. 先建立中心，再组织列表

训练阶段通常从有代表性的样本中学习若干中心，常见方法是聚类。中心数量记作 `nlist`。每条数据库向量根据粗分配规则归入一个中心对应的列表，列表保存记录标识以及向量或编码。

查询时先比较查询与这些中心，选择若干列表，再在列表内部比较记录。选择中心的部件叫 Coarse Quantizer（粗量化器）：它给出大致区域，而不是直接给出最终近邻。[Faiss 入门教程](https://github.com/facebookresearch/faiss/wiki/Getting-started)展示了先训练、再添加记录、最后查询的顺序。

```text
有代表性的训练向量 → 学习中心
                           ↓
每条入库向量 → 分配到中心 → 中心对应的记录列表
                           ↑
查询向量 → 选择若干中心 → 搜索这些列表 → 取 Top-K
```

训练好中心并不表示业务记录已经加入索引。`train`、`add`、`search` 是不同阶段；更新查询参数也不是重新训练。

## 2. 一个边界反例

为便于手算，假设一维空间已经有两个中心 0 和 10。按离哪个中心更近分配记录，得到：

| 中心 | 列表中的记录坐标 |
|---|---|
| 0 | 0、4 |
| 10 | 5.1、10 |

这是人为指定中心的数值例子，不声称聚类一定训练出这两个中心。查询为 4.9。

1. 查询到中心 0 的距离是 4.9，到中心 10 的距离是 5.1，因此先选中心 0。
2. 只搜索这个列表时，记录 4 离查询最近，距离 0.9。
3. 但另一个列表中的 5.1 距离只有 0.2，它才是全库最近邻。

```text
中心0       记录4     查询4.9 | 记录5.1              中心10
 ●-----------●----------?---|---●---------------------●
                        分配边界在5
```

**查询最接近哪个中心，不能证明最近记录一定属于那个中心。** 这就是只探测少量列表的误差来源。

## 3. nlist 与 nprobe 各控制什么

`nlist` 控制总共建立多少个列表，属于构建选择；`nprobe` 控制一次查询探测多少个列表，属于查询选择。上例 nlist=2。nprobe=1 漏掉 5.1；nprobe=2 搜到它。

若列表大小均匀，扫描记录数可粗估为 `N×nprobe/nlist`。例如 N=100 万、nlist=1000、nprobe=10，约比较 1 万条记录。但是还要付出选择中心的成本；真实列表大小不均匀时，应以被选列表长度之和为准。

增加 nlist 会使平均列表变短，却增加中心训练、存储和查询路由工作。在固定 nprobe 下，划分更细还可能覆盖更少的邻近区域。因此不能只说“分区越多越快、越准”。

增加 nprobe 通常提高召回，同时读更多记录。它与 HNSW 的 efSearch 都增加搜索工作，但一个数列表，一个控制图搜索宽度，数值不能直接比较。

## 4. IVF_FLAT 与 IVF_PQ 的误差不同

IVF_FLAT 在被选列表中保留原始向量，因此列表内部距离比较没有 PQ 量化误差。它仍可能因为没选某个列表而漏召回。

当 `nprobe=nlist`，且没有额外扫描上限、记录遗漏或不一致过滤时，IVF_FLAT 扫描全部原始向量，应与相同距离、数值精度和并列规则下的 Flat 结果一致。此时可能反而比直接 Flat 更慢，因为多了路由和列表管理开销。[Faiss FAQ](https://github.com/facebookresearch/faiss/wiki/FAQ)用这种方法区分区域选择误差与压缩误差。

IVF_PQ 则还把向量压成短编码。即使搜索全部列表，压缩距离仍可能改变排序。因此“nprobe 拉满”不能证明所有 IVF 索引都恢复为原始向量精确搜索。

## 5. 为什么训练样本要代表实际数据

假设中心只用中文制度训练，随后加入大量代码向量。新数据可能大量集中到少数中心，形成很长的列表。命中这些列表的查询会多读很多记录，尾延迟（少数最慢请求的耗时）随之增加。

需要观察的是列表长度分布、查询经常选择哪些列表、对应的召回和耗时，而不只是平均每个列表多长。热点列表也可能来自重复数据或自然聚集，并不能单凭不均匀就断言训练失败。

训练样本太少时，某些实现会警告或拒绝训练。例如 Faiss 聚类对中心数和样本数有要求；不能为了让实验“通过”而静默压掉警告。[Faiss FAQ 的聚类说明](https://github.com/facebookresearch/faiss/wiki/FAQ)解释了样本不足与重复训练的边界。

数据分布变化后，先测旧中心是否仍满足目标，再决定重训和重建。更新一条记录不意味着必须重新训练全库，但也不能把最初中心当成永久不变的最佳划分。

## 6. 算法分区不等于租户分区

IVF 的列表按向量空间分配，目的是缩小搜索范围。业务分区按团队、地区或知识库组织，目的是路由、管理或隔离。两个相同租户的记录可能落进不同 IVF 列表，不同租户也可能落进同一列表。

因此 nlist 不能用来表示租户数，查询选到正确 IVF 列表也不代表拥有读取权限。业务过滤和索引分区可以结合，但由产品的查询执行机制连接，不能互相替代。

## 本章小结

IVF 先学习中心并组织列表，再用查询选中的少数列表缩小搜索范围。nlist 改变划分，nprobe 改变一次搜索覆盖的区域。IVF_FLAT 主要承担区域漏搜风险；IVF_PQ 还承担量化误差。训练样本、列表倾斜和业务过滤都会改变表现。

## 🎯 面试怎么回答

**问：IVF 如何工作？nlist、nprobe 怎样影响结果？**

IVF 用粗量化器学习代表中心，把记录放入中心对应的倒排列表。查询先找较近的中心，再扫描 nprobe 个列表。nlist 是总列表数，影响划分与路由成本；nprobe 是查询覆盖多少列表，通常越大召回越高、扫描越多。近邻可能位于分配边界另一侧，所以只查最近中心不能保证找到它。评价时还要区分 IVF_FLAT 的漏搜和 IVF_PQ 的压缩误差。

## ⚠️ 易错点

训练中心不是添加业务数据；nprobe 不等于最终返回的 K；列表不一定等长；nprobe=nlist 只有在完整扫描原始向量等条件下才恢复精确结果。IVF Cell 不能承担租户授权。
