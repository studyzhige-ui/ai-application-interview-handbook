# 03｜精确搜索与 ANN：先建立可核对的答案

[← 02 向量空间与相似度：先把“近”说清楚](02-VectorSpace与Similarity.md) · [模块目录](../README.md) · [04 索引谱系：近似究竟发生在哪里 →](04-ANN索引谱系.md)

某次搜索返回了 A、C、F。它快不快，可以计时；它有没有漏掉更近的对象，需要另一个可核对的答案。这个答案不能来自另一套未经验证的近似索引。

本章先算清楚精确 Top-K，再讨论为什么要近似，以及“召回率下降”究竟下降了什么。

## 1. 精确搜索先确定搜索对象，再计算排名

Exact Search（精确搜索）指按指定规则得到真正的近邻结果。最直接的方法是穷举：对合法集合中的每一条向量计算距离，再选最小的 K 条。

沿用上一章的数据，并补充三条记录，查询仍是 `q=[1,0]`：

| 记录 | 向量 | 团队 | 平方 L2 |
|---|---|---|---:|
| A | `[1,0]` | alpha | 0 |
| B | `[10,0]` | beta | 81 |
| C | `[0.8,0.6]` | alpha | 0.4 |
| D | `[0,1]` | alpha | 2 |
| E | `[-1,0]` | alpha | 4 |
| F | `[0.6,0.8]` | beta | 0.8 |

不带团队条件的精确 Top-3 是 A、C、F；只允许团队 alpha 时，精确 Top-3 是 A、C、D。D 不是全库前三，却是合法集合中的前三。

所以，**精确答案也必须带条件**：数据快照、查询向量、距离规则、过滤条件、K 和并列处理方法。条件不同，不能直接比较两份结果来评价索引。

## 2. 为什么穷举可能变贵

设合法向量数为 N，维度为 D。朴素穷举大约需要完成 N×D 次坐标级比较与累加；还需要读出这些坐标。

例如 N=100 万、D=768，一次查询要处理约 7.68 亿个坐标。这是工作量估计，不是“需要多少毫秒”的结论。处理器、内存带宽、批量查询、并发和数据布局，都会影响实际时间。

选 Top-K 不一定要把全部距离完整排序。可以维护一个只保留 K 个最好结果的堆：堆顶放这 K 个中最差的一项，遇到更好的新结果就替换它，并恢复堆顶仍为最差项的组织规则。这样无须把所有结果完整排序，选择开销约为 `O(N log K)`；这里的记号描述工作量随 N、K 增长的数量级，不是毫秒数。无论怎样选出 K 项，仍然要计算这 N 条距离。**优化排序，不等于解决了全部距离计算。**

精确搜索也不是只适合小数据。若过滤后只剩少量记录、请求频率很低，或者硬件擅长批量计算，它仍可能满足要求。是否需要近似，应由预算和测量决定。[Faiss 的索引选择指南](https://github.com/facebookresearch/faiss/wiki/Guidelines-to-choose-an-index)也把 Flat 精确搜索作为需要先考虑的方案。

## 3. ANN 有两种主要的误差入口

ANN 允许返回结果与精确近邻不同。常见做法有两个方向：

1. **少搜索一些对象。** 图索引沿连接探索，分区索引只访问部分区域。真正的近邻可能根本没有进入候选集合。
2. **用近似表示计算距离。** 把原始向量压缩成短编码，节省存储与数据读取，但近似距离可能改变排序。即使每条编码都被比较，也仍可能不是原始向量的精确排名。

两种做法可以叠加：先只查一部分区域，再用压缩表示给候选排序。后续 HNSW、IVF、PQ 分别解释这些机制。不要把 ANN 只理解为“少看几条”，也不要理解为“随机返回一些结果”。

它希望降低的是适合当前工作负载的查询成本，但并非所有成本都下降。例如图索引可能用更多建索引时间和内存，换取较低查询延迟。[Faiss 索引表](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)区分了精确 Flat、图、倒排文件与量化表示。

## 4. 用精确结果计算索引召回率

设同一条件下精确 Top-K 的标识集合为 G，近似结果中去重后的合法标识集合为 A。本课程使用：

```text
Index Recall@K = |A ∩ G| / |G|
```

这里比较的是最终返回的前 K 个位置，去重后得到 A，不是全部内部候选池。若要评价放大的候选池，应另行报告候选覆盖，不能把它标为最终 Recall@K。

当合法记录至少有 K 条时，`|G|=K`。如果只有两条合法记录而 K=5，分母是 2，不是 5；返回这两条就完整找回了可用的精确近邻。若 `G` 为空，召回率没有分母，实验单独报告为空查询，不伪装成 0 或 100%。

例如合法精确结果为 `{A,C,D}`，ANN 返回 `{A,C,E}`，交集有两条，Recall@3 为 `2/3`。把 E 重复返回十次不能提高召回率；返回不合法记录则是正确性或权限错误，不能因召回率尚可而忽略。

```python
# 可独立运行：这里只计算集合指标，不执行向量检索。
exact_ids = {"A", "C", "D"}
ann_ids = {"A", "C", "E"}
recall = len(exact_ids & ann_ids) / len(exact_ids)
print(round(recall, 3))  # 0.667
```

如果距离在第 K 名边界并列，先约定处理方式。实验采用距离后按记录标识排序，以得到稳定的精确基准；真实评测也可接受同距离等价结果，但要在两边使用同一规则，不把合法的并列替换当成索引错误。

## 5. 索引召回不是业务相关性

这里的 G 由距离计算产生，不由人工判断“能否回答问题”产生。假设精确搜索的前三条都与问题不相关，ANN 也返回同样三条，它的索引 Recall@3 可以是 1，业务效果仍然很差。

排查时可以依次提问：资料是否已经入库并可见？相同条件下精确搜索能否找出期待的近邻？这些近邻是否真正有用？第一类涉及数据与生命周期，第二类涉及索引，第三类还涉及资料、模型和完整 RAG。

[后续 RAG 模块](../../08-rag/README.md)负责建立人工相关性、检索排序和最终回答的评估。不能把本章的集合交集公式当成全部 RAG 质量。

## 6. 一个可比较的实验应固定什么

先固定资料快照、查询集合、模型与预处理、距离、访问条件和 K。用精确搜索生成基准，再改变一个索引参数，记录召回率与资源变化。

不能拿“高召回配置在单用户下的延迟”与“低召回配置在高并发下的延迟”直接比较。也不能只保留返回成功的快查询，把超时和错误样本从报告里消掉。

本章不要求搭负载平台。先用 [数值实验](../labs/README.md#numeric)算清楚过滤后的精确答案和召回分母；[实际索引实验](../labs/README.md#faiss)再比较真实搜索库中的 Flat、HNSW 与 IVF。实验记录会区分手工模拟结果与真实库输出。

## 本章小结

精确搜索提供“在这些条件下，本该返回谁”的基准。ANN 可能因为没有搜索到对象，也可能因为近似距离而改变结果。评价时应比较同一合法集合、同一表示与距离下的结果，同时观察延迟、内存和维护成本。索引复现了精确近邻，不代表近邻已经能支持业务答案。

## 🎯 面试怎么回答

**问：ANN 牺牲什么，换来什么？怎样证明可接受？**

它允许结果偏离原始向量的精确近邻，通过缩小搜索范围或压缩表示降低查询等成本。代价可能是漏召回，也可能增加建索引时间和内存。我会固定数据、查询、距离、过滤条件与 K，用精确 Top-K 建立基准，再比较召回、延迟分布、资源和更新成本。是否可接受由业务目标决定，不能仅看一次查询有多快。

## ⚠️ 易错点

未过滤的精确结果不能评价带权限条件的 ANN；K 大于合法记录数时不能机械以 K 为分母；重复返回同一标识不增加召回。若所有方法的精确结果都无用，继续调索引参数不是主要解法。
