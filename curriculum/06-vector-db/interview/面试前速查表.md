# Vector Database｜面试前速查表

> 目标：面试前 15～20 分钟快速把主线重新装进脑子。

---

# 1. 一句话总纲

```text
Vector DB
= 高维向量存储
+ Similarity Search
+ ANN Index
+ Metadata Filter
+ Lifecycle
+ Scale / HA
```

它不是：

```text
Embedding Model
也不是
完整 RAG Retrieval System
```


---

# 3. Similarity 三件套

| Metric | 直觉 | 注意 |
|---|---|---|
| Cosine | 方向 / 夹角 | 常和 Normalization 一起讨论 |
| Dot Product | 方向 + 模长 | 模长会影响 Score |
| L2 | 欧氏距离 | 越小通常越近 |

记住：

> **Metric 必须和模型输出、Normalization、Index 配置一致。**

---

# 4. Exact vs ANN

```text
Exact
→ 扫大量候选
→ 结果精确
→ 适合小数据 / Ground Truth

ANN
→ 少看候选
→ 允许少量 Recall Loss
→ 换低 Latency / 高 QPS / Scale
```

面试关键词：

```text
Recall vs Latency
```

---

# 5. HNSW 30 秒

```text
Hierarchical Graph
→ 高层粗导航
→ 逐层下降
→ 底层局部精搜
```

参数：

```text
M
→ 连接度 / Memory / Build

efConstruction
→ Build 时搜索宽度

efSearch
→ Query 时搜索宽度 / Recall / Latency
```

绝对不要说：

> efSearch 越大越快。

---

# 6. IVF 30 秒

```text
Vector Space
→ Coarse Clustering
→ Inverted Lists
→ Query 只探测部分 Lists
```

参数：

```text
nlist
→ 总 List 数

nprobe
→ Query 搜多少个 List
```

`nprobe ↑` 通常：

```text
Recall ↑
Latency / Compute ↑
```

---

# 7. PQ 30 秒

```text
高维 Vector
→ 切 Sub-vector
→ 每段量化成 Code
→ 用短 Code 代替 float Vector
```

收益：

```text
Memory ↓
Storage ↓
```

代价：

```text
Quantization Error
→ Recall / Ranking 可能下降
```

---

# 8. HNSW vs IVF

不要背“谁更好”。

比较：

```text
Data Scale
Recall
Latency
Memory
Build Cost
Update Pattern
Filter
Hardware
```

然后 Benchmark。

---

# 9. Filter

```text
Query
+
tenant_id / permission / type / time
```

### Pre-filter

```text
先 Filter
→ 再 ANN
```

### Post-filter

```text
先 ANN
→ 再删掉不合法结果
```

风险：

```text
Top-K 不足
```

多租户要记：

> **Tenant Isolation 是安全约束，不是“记得带 tenant_id”。**

---

# 10. Lifecycle

```text
Insert / Upsert
→ Delete / Tombstone
→ Compaction
→ Rebuild
```

Embedding Model 升级：

```text
Model v2
→ Re-embedding
→ Index v2
→ Evaluate
→ Canary / Switch
→ Retire v1
```

不要把新旧 Vector Space 随便混用。

---

# 11. Distributed Vector DB

```text
Shard
→ 拆数据 / 扩容量

Replica
→ 高可用 / 读扩展
```

典型 Query：

```text
Router
→ Shard-local ANN
→ Merge Top-K
```

Shard 多了也会增加：

```text
Fan-out / Network / Merge Cost
```

# 13. Troubleshooting 两条链

## Recall 下降

```text
Embedding
→ Normalization
→ Metric
→ Filter
→ Index Parameter
→ Index Version
→ Delete / Update
→ Ground Truth
```

## Latency 上升

```text
Filter Selectivity
→ Candidate Size
→ ANN Parameter
→ CPU / Memory
→ Disk / Network
→ Shard Fan-out
→ Segment / Compaction
→ Concurrent Load
```

# 15. Graph DB vs Vector DB

```text
Vector DB
→ 谁和 Query 像？

```


# 16. Vector DB vs RAG Boundary

Vector DB：

```text
Vector Storage
Distance
ANN
Filter
Lifecycle
Scale
```

RAG：

```text
Chunk
Query Rewrite
Dense / Sparse
Hybrid
RRF
Rerank
Top-K Strategy
Retrieval Evaluation
Context Build
```

一句话：

> **Vector DB 负责“高效找向量”，RAG 负责“怎样把检索系统做好并证明它有效”。**

# 19. 项目题万能回答顺序

当面试官问：

> 你为什么这样设计 Vector Search？

按这个顺序：

```text
1. 数据规模
2. Embedding / Dimension
3. Metric
4. Filter Pattern
5. Index
6. 参数
7. Recall / Latency Benchmark
8. Update / Delete
9. HA / Shard / Replica
10. Failure / Migration
```

比直接说“用了 HNSW，因为快”强很多。
