# RAG 机制实验｜排名、证据与版本状态

[← RAG 模块](../README.md) · [综合复习](../review/README.md)

实验使用与正文相同的虚构北辰云政策，观察同一个问题经过排名、预算和版本处理后，证据怎样变化。它不需要 API 密钥、数据库或模型下载；Python 只是用于验证机制的示例语言，不是 RAG 的技术限制。

## 运行与重置

语法与标准库兼容基线为 CPython 3.13 及以上。执行前用 `python --version` 确认环境；本轮实际运行版本与检查结果记录在 [修订记录](../../../guide/project/rag-reader-revision.md)，不能把兼容声明当作所有版本均已实测。

在仓库根目录执行，PowerShell 与常见终端均可：

```bash
python curriculum/08-rag/examples/rag_lab.py
python -m unittest discover -s curriculum/08-rag/examples -v
```

第一条命令输出一份 JSON；第二条运行标准库单元测试，包括从正文自动提取并执行的 Python 片段。没有创建远端资源，不会写入知识库，也没有需要删除的数据。重新运行会重新创建内存状态；在交互环境中试验更新流程时，用 `ledger = RevisionLedger()` 重置，不沿用上一轮对象。

正文中的短片段依赖同目录 `rag_lab.py`。单独练习时先进入 `curriculum/08-rag/examples`，再启动 Python 并按正文输入；不是把片段放到任意目录都能自动导入。

## 同一组数据

数据、排序样本与函数的唯一实现来源是 [rag_lab.py](rag_lab.py)。[test_rag_lab.py](test_rag_lab.py) 导入它，不维护第二套算法。

| ID | 文档身份 | 文本的作用 | 演示预算单位 |
|---|---|---|---:|
| A | P1，v2 | 购买后 14 天内可申请普通退款 | 70 |
| B | P1，v2 | 专属资源订单例外，需人工复核 | 40 |
| C | P2，v1 | 发票更正，与本题不相关 | 60 |
| D | P3，v1 | 账户停用，与本题不相关 | 30 |

问题是：“标准版订阅购买了 10 天，已经开通专属资源，能按普通规则退款吗？”A 与 B 共同构成必要证据。这个集合是人工标注的评测答案，不是系统自动识别出了充分性。

Dense 样本顺序固定为 A、C、B；词项样本顺序固定为 B、A、D。**它们是人为设计的候选排名，不是实际向量模型或 BM25 的运行结果。** 成本 70、40、60、30 也只是演示预算单位，不是实际 Token 数。

## 实验一：改变排序，观察改变了什么

先运行默认演示。RRF 使用位置从 1 开始的倒数排名，常数取 60，预期融合顺序是 A、B、C、D。回到 [第 7 章](../docs/07-RetrievalStack.md)，核对 A 与 B 的分数是由哪两个位置贡献的。

然后在交互环境中调用 `rrf([["X", "Y"], ["Y", "Z"]], constant=1)`。在看结果前，手算 X、Y、Z 的分数和顺序；检查未出现于某一路的对象是否错误获得了额外分数。

<details><summary>参考结果</summary>

Y 的分数为 1/3+1/2=5/6，X 为 1/2，Z 为 1/3，顺序 Y、X、Z。RRF 改变的是现有候选的融合排序，不能生成没有被召回的新证据。

</details>

## 实验二：为什么精排后不能立即截断

默认演示故意使用一个负收益重排样本 A、C、B、D。它是用于排障的固定数据，不是训练出来的模型。

在预算 110 下，先截取前两条得到 A、C，再按顺序装入，只有 A 能进入上下文；B 已在上一步丢失。保留候选再按相同预算遍历，C 放不下时跳过，B 仍能放入，得到 A、B。

任务：运行演示并确认 `early_top2_context`、`keep_candidates_context`；再将顺序改为 C、D、A、B，比较结果。能否据此认为贪心装包总能保证证据完整？

<details><summary>参考结果与边界</summary>

默认分别得到 `["A"]` 和 `["A", "B"]`。新顺序得到 C、D，共花费 90 个预算单位，A、B 都装不下。这个反例说明贪心函数只演示顺序和预算，**不是语义覆盖优化器**。生产方案必须结合证据需求、去重、相关性与质量评测。

</details>

## 实验三：用同一标签比较指标

观察默认输出：只有 A 时 Recall 为 0.5、Hit 为 1、完整覆盖为 0；A、B 都在时三者均为 1。再按 [第 10 章](../docs/10-RetrievalEvaluation.md) 验证 Precision 的固定 K 分母与 NDCG 的理想排序。

任务：只有一条结果 A，相关集合也是 A，但 K=5。Precision 是 1 还是 0.2？相关集合为空时，应怎样解释实验返回的 `None`？

<details><summary>参考结果</summary>

本实验明确选择固定 K 作分母，所以 Precision=1/5=0.2。空相关集合返回不适用，不伪造 Recall=1；应转到有独立标签的不可回答与拒答评测。实际项目必须记录指标实现口径，否则名称相同也可能不能直接比较。

</details>

## 实验四：迟到、重复、删除与回滚

默认依次处理 P1 的修订号 8、7、9（删除）、8。预期状态是 `accepted`、`stale`、`accepted`、`stale`；末态保存修订号 9 的删除标记。再对同修订号提交相同内容，应得到 `duplicate`；同修订号却携带不同内容，实验会抛出 `ValueError`，要求调用方解决源事实冲突。

另一个检查把旧知识集合交给**当前**权限对象过滤。当前权限已撤销 P1，即使选择旧知识集合，结果也只有 C、D。

任务：区分这些结果证明了什么与没有证明什么。它们能证明多个 Worker 并发提交不会互相覆盖吗？进程退出后状态是否仍在？

<details><summary>参考边界</summary>

不能。实验只检查单进程中事件按给定顺序处理时的状态规则，没有数据库事务、原子比较并更新、分布式锁、持久化或真实授权服务。要验证并发和重启，必须连接真实存储，用多连接交错提交、故障注入和重启检查重新测试，不能用这里的通过结果替代。

</details>

## 从机制实验到真实系统

下一阶段应保留同一组源文档与标签，替换为真实解析器、Tokenizer、Embedding、词项检索、重排与数据库，分别记录模型、服务端、客户端、数据及配置版本。随后测真实过滤条件下的召回、输入截断、重排负收益、写入可见性、并发更新、撤权、缓存和恢复。

这些是进一步集成的验收任务，**不是本实验已经实现或通过的能力**。本目录不代替跨模块 Bridge Lab，也没有声称运行了真实 RAG 服务。
