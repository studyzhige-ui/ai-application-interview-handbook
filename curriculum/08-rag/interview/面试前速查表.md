# RAG 面试前速查表

> 面试前 10–15 分钟快速过一遍。看不懂的地方回 `docs/`，不要只背本页。

## 1. 一句话定义

RAG = **从外部知识源检索可追溯 Evidence，并把它组织进 LLM Context，使答案具备更好的新鲜度、领域知识和可验证性。**

不是：Vector DB 的别名。

---

## 2. 30 秒完整 Pipeline

```text
Corpus
→ Parse / OCR
→ Clean / Dedup
→ Chunk + Metadata / Lineage
→ Embedding + Sparse Index
→ Query Rewrite / Plan
→ Dense + Sparse Retrieval
→ RRF / Fusion
→ Rerank
→ Top-K / Context Construction
→ LLM
→ Grounding / Citation
→ Evaluation / Trace
```

Production 再加：

```text
Freshness / Version / Permission / Scale / Cost / Rollback
```

---

## 3. Chunking

核心矛盾：

```text
小 Chunk：精准，但上下文可能断
大 Chunk：完整，但语义稀释 / Noise
```

常见策略：

- Fixed；
- Recursive；
- Structure-aware；
- Semantic；
- Parent-child。

参数：Size / Overlap 必须通过 Dataset 实验。

关键句：

> Retrieval Granularity 可以和 Generation Context Granularity 分离。

---

## 4. Query Transformation

```text
Normalize
Rewrite
Intent
Clarification
Decomposition
Multi-query
HyDE
```

记住：

- Raw Query 要保留；
- 信息不足先 Clarify；
- HyDE 假想文本不是 Evidence。

---

## 5. Dense vs Sparse

### Dense

强：语义、同义改写。

弱：错误码、编号、稀有实体、版本。

### Sparse / BM25

强：精确词项、专有名词、短 Query。

弱：同义表达、语义泛化。

### Hybrid

Dense + Sparse Candidate → Fusion → Rerank。

不要直接加原始 Score。

---

## 6. RRF

```text
RRF(d) = Σ 1 / (k + rank_i(d))
```

只需记住直觉：

> 多路都排前的结果会得到更高融合分，而且不要求异构 Score 直接可比。

---

## 7. Rerank

作用：

```text
Retriever：High Recall
Reranker：High Precision
```

Rerank 变差先查：

1. 正确 Evidence 是否进入 Candidate；
2. Domain Mismatch；
3. Truncation；
4. Query Drift；
5. Score / Top-K；
6. Diversity。

---

## 8. Top-K

不是一个 K：

```text
Retriever K
Fusion K
Rerank K
Final Context K
```

前宽后窄。

观察：Recall、End-to-end、Latency、Token Cost。

---

## 9. Context / Grounding

Context Build：

```text
Dedup
Parent / Neighbor Expansion
Source Diversity
Version / Permission
Token Budget
```

Grounding：Claim 是否被 Evidence 支持。

Citation：Claim 能否回到 Source / Chunk / Version。

有 Citation ≠ 一定 Grounded。

---

## 10. Retrieval Metrics

- Recall@K：相关 Evidence 有没有进前 K；
- Precision@K：前 K 有多少相关；
- Hit Rate：是否至少命中；
- MRR：第一个相关结果多靠前；
- NDCG：多个不同相关等级的排序质量。

Retrieval Metric ≠ 最终 Answer Quality。

---

## 11. End-to-end Eval

至少：

```text
Correctness
Faithfulness
Answer Relevance
Citation Correctness
Completeness
Refusal Accuracy
Latency
Cost
```

Dataset 来源优先：真实 Query + Bad Case + 专家标注。

LLM Judge 要 Calibration。

---

## 12. 实验方法

```text
Baseline
→ Single Change
→ Ablation
→ Offline Regression
→ Online A/B
```

所有实验记版本：

```text
corpus
parser/chunker
embedding
index
retrieval config
reranker
prompt/model
dataset
```

---

## 13. Bad Case 排查口诀

```text
Source 有吗？
↓
Parse 对吗？
↓
Chunk 完整吗？
↓
Ground Truth 召回了吗？
↓
Rerank 排前了吗？
↓
最终 Context 有吗？
↓
模型 Grounded 生成了吗？
```

不要上来就说“换 Embedding”。

---

## 14. Freshness / Version

```text
Detect Change
→ Reprocess affected docs
→ Delete old chunks
→ Build new version
→ Evaluate
→ Activate
→ Rollback available
```

Embedding 大版本升级：优先 Blue-Green Index。

---

## 15. Permission

原则：

> Authorization Before Exposure。

Chunk 带 Tenant / ACL Metadata，尽量 Retrieval Pre-filter。

Cache Key 也要带 Permission Scope / Knowledge Version。

---

## 16. Scale / Observability

Ingestion：

```text
Parse → Chunk → Embed → Index
```

需要：Retry / Idempotency / Backpressure / Checkpoint。

Online Trace：

```text
Query / Rewrite
Filter
Candidate + Score
Fusion
Rerank
Final Context
Version
Model / Prompt
Answer / Citation
Latency / Cost
```

---

## 17. GraphRAG / Agentic RAG

GraphRAG：显式实体关系、多跳关系检索。

Agentic RAG：Runtime 动态决定：

```text
Retrieve?
Rewrite?
Search again?
Stop?
Refuse?
```

复杂度必须由 Evaluation 证明。

---

## 18. 项目介绍 2 分钟模板

```text
1. 业务与 Corpus 是什么
2. 为什么需要 RAG
3. Parsing / Chunk 为什么这样做
4. Retrieval Baseline
5. Hybrid / Rerank 为什么加
6. Dataset / Metric 怎么建
7. 一个真实 Bad Case 怎么定位
8. Freshness / Permission / Scale 怎么处理
9. 最终质量、延迟、成本变化
```

最后提醒：

> 面试官通常不是想听“用了什么库”，而是想确认你能不能解释 **为什么、失败怎么办、怎么证明**。
