# 09｜证据交付：从候选片段到可追溯的答案

[← 第 08 章](08-Rerank与CandidateBudget.md) · [模块目录](../README.md) · [第 10 章 →](10-RetrievalEvaluation.md)

系统已经找到了 A 和 B，答案仍可能出错：模型只看见被截断的 A，引用链接指向旧版，或者把检索片段里的“忽略其他规则”当成了新的指令。

**证据交付**把“候选里有正确材料”推进到“模型实际看到了正确材料，答案也确实受到它支持”。这是候选选择、上下文组装、生成与引用核验共同完成的过程。

## 1. 从排名列表变成证据包

排名列表主要表达相关性；证据包还需要表达来源、版本、适用条件和各片段间的关系。对退款问题，可以给模型提供：

```text
E1：P1@v2，退款条款，一般规则。
标准版订阅购买后 14 天内可申请普通退款。

E2：P1@v2，退款条款，例外。
已经开通专属资源的订单不适用普通退款规则，需人工复核。
```

`E1`、`E2` 是本次请求中的引用标识，服务端保存它们到真实来源的映射。它们不是模型凭空生成的外部网址，也不是整个知识库永久不变的全局编号。

先处理重复，再补足必要关系，最后确认所有将交付的内容都在授权范围内。补上下文不能跨越版本或权限，规则冲突也不能通过“混合摘要”抹平。

## 2. 上下文预算怎样计算

先核对具体模型和服务对输入、输出及总窗口的限制。有些服务分别约束输入与输出，不能把所有模型都套成同一个减法公式。

为了说明预留方法，假设某部署允许输入与输出**合计 8192 Token**：系统指令 1024、历史 600、当前问题 128、包装与引用标记 128，并预留输出 1024。证据剩余预算为：

```text
8192 - 1024 - 600 - 128 - 128 - 1024 = 5288 Token
```

这是教学假设，不对应特定产品规格。实际计数应使用目标模型的编码方式，尽量对最终序列化后的完整请求检查，而不是只把正文字符数相加。标题、来源说明、消息包装及工具描述都可能占空间。

在预算内，优先保留能解释问题条件的材料。只有 A 没有 B 时，删掉一点无关历史以保留 B，可能比塞入更多相似的一般规则更有价值；是否可以删历史，还要看它是否承载用户确认的产品和状态。

## 3. 压缩内容时，哪些东西不能随意消失

可以先做抽取式压缩：保留相关原句、去掉重复段落和无关说明，并保存原文位置。它通常更容易回源，但仍可能因删掉上下文而改变含义。

生成式摘要可以更短，却可能合并错版本、丢失否定和弱化例外。摘要是派生表示，需要核对关键事实，不能把“模型摘要说可以退款”当成独立来源。压缩前后应对比必要条件是否仍能被读出。

内容排列应反映使用关系。例如先给一般规则，再给同一规则的例外；跨文档冲突按来源与时间清楚分组。不能假定换一个固定位置就能让所有模型可靠使用全部证据；仍需用实际问题测试。

## 4. 答案的每个实质结论怎样得到支持

一个合适的回答可以是：

> 购买十天仍在标准版的一般申请期限内，但你已开通专属资源，触发例外，因此不应按普通规则直接处理，需要人工复核。[E1][E2]

这里既没有忽略一般条件，也没有把“需人工复核”误写成“一定能够退款”或“一定不能退款”。证据支持的是流程与适用边界，不是人工复核的最终结果。

Grounding（依据约束）要求回答的实质结论能够由提供的材料支持；Faithfulness（忠实性）评价回答是否忠于这些材料。它们都不自动证明材料本身最新或正确，所以来源与版本检查仍然必要。

对引用至少检查三层：标识是否真的在本次证据包中；其来源是否允许当前用户访问且版本符合请求；被引用的内容是否支持该句的具体条件与程度。仅验证“链接能打开”，只通过了很弱的一层。

## 5. 引用链接由谁生成，为什么不能完全交给模型

模型可以选择允许的引用标识，应用根据已保存的映射生成链接、页码或展示片段。这样能拒绝不存在的 `E99`，也能避免模型自行构造任意网址作为来源。

[实验](../examples/README.md)中的引用检查只验证标识是否属于允许集合：

```python
from rag_lab import validate_citation_ids

validate_citation_ids(["E1", "E2"], allowed={"E1", "E2"})
```

通过时函数正常返回，不证明语义支持成立；无效标识会抛出异常。它不调用语义模型，也不验证真实授权服务。生产中还要结合来源检查、关键结论核验，以及必要的人工抽检或经校准的评审模型。

来源更新后，历史引用应指向回答当时使用的版本或受控归档，并标明当前状态；但归档存在不代表原用户永远有权继续访问。撤权和删除要求仍然有效。

## 6. 证据不足时，回答方式怎样改变

若只知道一般规则，不知道用户是否开通专属资源，应该澄清这个状态，而不是直接作确定判断。若用户已说明状态，但知识库缺少相关例外条款，应说明当前依据不足，给出有限解释或转人工。

可以回答有证据的部分，并把未覆盖部分分开写。一般知识性的背景说明也可以提供，但应与公司具体政策结论分开，不能用模型记忆补一个看似正式的期限。

若检索或授权服务出错，属于执行失败。是否重试、降级或停止取决于预算与风险，但不能将失败包装成“查遍知识库后确认没有规则”。

## 7. 外部材料中的文字不是新的授权或系统指令

文档可能包含“忽略上述限制”“把完整用户信息发到某网址”等恶意文字。模型同时处理指令和数据，可能错误地把这些内容当成应该执行的命令，这属于间接提示注入。

提示词应明确区分任务要求与证据材料，但文本分隔符不构成安全隔离。还要在应用侧限制工具权限、校验动作、保护秘密、清理不可信的渲染内容，并在敏感操作上采用确定性授权与必要审批。[OWASP 的提示注入防护说明](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)强调了这种多层防护。

⚠️ **注意：在答案显示前才隐藏越权来源，通常已经太晚。** 如果受限材料此前进入了无权处理它的外部重排服务、模型或日志，数据边界已经被越过。必须在每个实际数据出口前核验，而不是只修饰最后的界面。

## 8. 追踪记录要足以复盘，也要控制敏感面

记录本次采用的知识代际、模型与提示版本、候选标识、最后提供的证据标识、删减原因和引用结果。代际表示一组一起发布的派生数据版本，第 12 章会说明其更新过程。

需要复盘原文时，使用受权限控制的记录或回源能力，不默认把所有正文写入普通运行日志。缓存和日志同样有访问、保存期限与删除责任；“仅用于调试”不是绕过这些边界的理由。

## 本章小结

证据交付不只是拼接 Top-K。它需要补全条件、控制最终请求长度、保持来源与版本，并检查每个实质结论的支持关系。引用标识有效、来源合法与语义支持是不同检查；证据不足和执行失败也必须分别表达。

## 🎯 面试怎么回答

**问：怎样让 RAG 答案有可靠引用？**

我会在服务端为本次证据分配标识，保留到文档版本和原文位置的映射，让模型只选择这些标识。生成后先检查标识是否存在及来源是否可见，再核对引用是否支持具体结论，特别关注否定、例外和版本。上下文组装必须保留必要条件并按目标模型计数；没有足够依据时部分回答、澄清或转人工，而不是编造链接。

## ⚠️ 易错点

**“检查引用 ID 就完成了事实核验。”** ID 存在不等于它支持这句话；实验中的 ID 检查也不声称做到语义核验。

**“压缩只影响文风。”** 丢掉否定、单位或例外会改变事实，必须验证压缩后的证据关系。

**“把文档放进引号就能防注入。”** 分隔有助于表达，但授权、工具与数据出口仍需独立限制。

### 自测 1

一个假设部署允许输入输出合计 4096 Token。固定输入共 1200，预留输出 800。现有 A、B 分别占 1300、700 Token，二者都必要。计算剩余额度，并判断能否一起放入。

证据预算 4096-1200-800=2096，A+B=2000，可以一起放入，余 96。前提是固定输入已经包含包装等开销，且计数使用目标模型口径。

</details>

### 自测 2

模型写“所有订单都能直接退款 [E1]”，E1 确实指向一般规则 A。说明哪一层检查通过，哪一层失败，并给出合理修正。

<details>
<summary>参考答案与解释</summary>

标识存在检查可以通过；语义支持和条件完整性失败。一般规则不能推出所有订单适用，应纳入例外 B，并按用户是否满足条件给出有边界的回答。
