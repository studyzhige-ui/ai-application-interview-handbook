## 1. 复习时先重建四个层次

```text
01—03｜数据与对象
名字 → 对象 → 容器保存的引用 → 修改／共享／拷贝
                    ↓
04—07｜执行与组织
函数调用 → 参数与作用域 → 逐项处理 → 迭代／暂停 → 包装与资源范围
                    ↓
08—10｜对象协作与输入边界
类与实例 → 行为协议 → 异常／文件／模块 → 解析／结构／业务校验
                    ↓
11—13｜运行机制与成本
引用生命周期 → GC／GIL → 执行模型与取消收尾 → 数据结构与复杂度
```

每条箭头都应该能用一句话说明：**下一步为什么需要前一步？** 例如，不先分清名字绑定与对象修改，就很难真正理解参数共享；不先分清生成器的创建与消费，就容易把异步函数调用误解为已经执行完成。

## 2. 怎么使用图解、自测和正文

先读完对应正文，再看图解，把节点之间的因果关系说出来。做题时先暂停，口述、画引用关系或手写几行代码；形成答案以后，再点击折叠题目或“查看参考答案”核对。答案默认使用 GitHub 原生 `<details>` 折叠，不预先展开。

遇到错误，不只记“这里有坑”，还要补全：**原先误解是什么 → 实际修改／执行的是哪一层 → 正确写法是什么 → 这个结论有哪些前提**。

正文统一使用章末 🎯 面试回答、⚠️ 易错点与折叠自测。正文负责首次讲解，Review 负责主动回忆，集中题库负责面试表达，三个入口不互相替代。

## 4. 跨章节综合自测

<details>
<summary>为什么“变量赋值、函数传参、浅拷贝、可变类属性”可以用同一张对象图解释？</summary>

它们都涉及名字、容器或属性怎样持有对象引用。先找到对象，再画出各访问路径，最后判断当前操作是改绑定、改外层引用还是改子对象，就能解释变化会被谁看到。细节分别见 01、03、04、08 章。

</details>

<details>
<summary>为什么“生成器按需运行”和“异步任务等待时挂起”有关联，却不能当成同一个概念？</summary>

二者都需要理解保存执行进度、暂停与恢复，但协议与调度目的不同。普通生成器由消费方逐项推进并产出值；协程通过 await 表达等待，Task 与事件循环管理相关执行。不能因为都能暂停，就把生成器说成自动并发的任务。见 06、12 章。

</details>

<details>
<summary>一个模型输出能被 JSON 解析，也能构造出类型正确的对象，为什么仍可能不能执行？</summary>

解析解决表示格式，结构校验解决字段契约，业务校验解决当前状态与规则，权限检查解决当前主体是否获准行动。不同层的通过不能互相替代，执行还可能涉及审批、幂等与副作用。见 08—10 章，并在后续 Agent／Backend 模块继续展开。

</details>

<details>
<summary>为什么停止等待一个任务，和释放这个任务占用的一切资源，不是一回事？</summary>

调用方可以先停止消费或超过等待预算，但子任务、线程函数或下游请求可能仍在执行。需要明确取消是否传递、是否等待清理结束、谁持有资源，以及已经发生的副作用怎样处理。正常语言控制流中的清理，也不能替代进程强杀或远程服务的可靠性设计。见 07、09、11、12 章。

</details>

## 5. 进入面试训练之前

能不看答案解释机制，再压缩成 30 秒回答。先说定义与核心因果，再给一个例子，最后说明前提和边界。不能独立解释的地方，回到上表对应正文，而不是只反复记忆短答案。

图解继续采用可在 GitHub 阅读的文字关系图或保守 Mermaid 语法；知识关系是主体，不为装饰引入额外图文件。整体复习节奏可以参考 Learning Path，不绑定固定周次或天数。
