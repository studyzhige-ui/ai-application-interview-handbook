## 先从单个值开始：数值、布尔值与文本

容器组织多个值，值本身先要有清楚的语义。`int` 表示整数，`float` 表示近似的浮点数，`bool` 表示 `True/False`；`str` 表示 Unicode 文本，`None` 表示这里约定的“没有值”。这些对象不可原地改值，计算后通常把结果重新绑定给名字。

### 数值运算：除法、向下取整与余数

```python
print(7 / 2)       # 3.5：/ 是通常的除法，即使两边都是 int
print(7 // 2)      # 3：// 对商向负无穷方向取整
print(-7 // 2)     # -4，不是截去小数部分得到 -3
print(-7 % 2)      # 1：-7 = (-4) * 2 + 1
print(2 ** 3)      # 8：** 是乘方
print(2 + 3 * 4)   # 14：乘法先于加法；用括号明确改变顺序
```

对非零整数除数 b，`a == (a // b) * b + a % b`。余数为零或与除数同号，所以负数不能照搬其他语言的求余直觉。`int(-3.5)` 则向零截断为 `-3`，不是 `//` 的取整规则。除数为零会抛 `ZeroDivisionError`。整数可随值增长使用更多存储，并不意味着任意大整数计算都只花常数时间。

### float 为什么不能总用精确相等比较

二进制有限位数不能精确表示大多数十进制小数，和十进制不能有限表示 1/3 类似。误差来自表示和运算，不是 Python 随机算错。

```python
import math
from decimal import Decimal

print(0.1 + 0.2 == 0.3)                    # False
print(math.isclose(0.1 + 0.2, 0.3))         # True：按容差比较
print(Decimal("0.1") + Decimal("0.2"))     # 0.3：从十进制文本建立值
```

测量值、模型分数常使用 float，并根据业务量纲设置相对或绝对容差；接近零的比较尤其需要合适的 `abs_tol`。金额可以采用最小货币单位的整数，或 Decimal 并明确精度及舍入规则。`Decimal(0.1)` 会把已有浮点近似带进去，不能修复此前误差。`round` 是舍入，不是把二进制 float 永久变成十进制精确数。布尔值虽属于整数类型体系，也不应无意把 `True` 当成业务数量 1。

### 文本处理：每次返回结果，原文本仍在

```python
raw = "  Python, API,  数据  "
clean = raw.strip()                       # 只移除两端空白
parts = clean.split(",")                  # ['Python', ' API', '  数据']
print(clean.replace("API", "接口"))      # Python, 接口,  数据
print("a  b\n c".split())                # ['a', 'b', 'c']：连续空白合并
print("a,,b".split(","))                  # ['a', '', 'b']：显式分隔符保留中间空项
print("API" in clean)                     # True：子串判断
print(f"共有 {len(parts)} 项")             # 共有 3 项：表达式填入文本
```

`strip(chars)` 的参数是“两端可移除的字符集合”，不是一整个前缀；精确移除前缀可用 `removeprefix`。`split` 拆成列表，`join` 把文本片段接起来；这些操作与 `replace` 都不会修改原来的 str。单引号和双引号都能表示文本，`\n` 是换行字符，`\t` 是制表符，反斜杠负责转义。

`len("你")` 是 1，但 `len("你".encode("utf-8"))` 是 3：前者数 Unicode 码点，后者数字节。一个视觉字符还可能由多个码点组成，不能把码点数直接当屏幕宽度。`str` 与网络/文件中的 `bytes` 要在编码边界转换；[第 09 章](09-异常-文件-模块与导入.md)继续解释读写时如何指定编码。

以上是本章的值语义基础。接下来比较容器时，再分别看组织关系、修改方式和成本，不把所有“有多个内容”的对象视为同一种结构。

## 1. 先把讨论边界画清楚

### 1.1 这五种类型都可以叫“容器”吗

广义上，`list / tuple / str / dict / set` 都能组织一组内容，并支持 `in` 这样的成员判断；在入门对比里可以把它们放进“容器与文本类型”这一组。但**它们不是同一种容器，也不是相同的物理存储结构**。

| 类型 | 中文与数据关系 | 顺序 | 能否修改自身 | 重复规则 | 典型访问 |
|---|---|---|---|---|---|
| `list` | 列表：按位置排列的元素 | 有顺序 | 可以 | 允许重复 | `items[0]` 按索引 |
| `tuple` | 元组：固定的一组元素引用 | 有顺序 | 不能替换自身元素引用 | 允许重复 | `record[0]` 按索引 |
| `str` | 字符串：文本序列 | 有顺序 | 不可以 | 允许重复字符 | `text[0]`、`text[1:3]` |
| `dict` | 字典：键到值的映射 | 保留插入顺序 | 可以 | 等价的键只保留一项 | `data[key]` 按键 |
| `set` | 集合：不重复的成员 | 不保证业务可依赖的遍历顺序 | 可以 | 等价的成员只保留一份 | `x in seen` 判断成员 |

**Sequence（序列）** 强调按位置排列，列表、元组、字符串属于这一组。**Mapping（映射）** 强调通过 Key（键）找到 Value（值），字典属于这一组。**Set（集合）** 强调成员及集合关系。

“有序”不是“已经排序”：字典按插入顺序遍历，不会自动按键的大小排序。Python 3.7 起，保留字典插入顺序是语言保证。集合即使某次输出顺序看起来稳定，也不应据此设计业务。

### 1.2 三层理解，不是三个同义词

```text
语言／接口语义：你能做什么？例如按索引取值、按键查找、原地追加。
        ↓
底层数据结构：实现如何组织引用和查找信息？例如动态数组、哈希表。
        ↓
操作成本：为了完成一次操作，要移动、比较、分配多少东西？
```

底层数据结构确实涉及“数据怎样在内存中组织”，但不只是磁盘或内存中摆在哪里，还包括**怎样通过这些组织方式执行查找和修改**。本章底层直觉主要以 CPython 为例，不把某个实现版本的字段布局说成 Python 语言规范。

### 1.3 容器槽位、引用、对象：先记住改动发生在哪一层

```text
名字 t ──引用──> tuple 对象
                  ├─ slot 0（元素位置）──保存引用──> list 对象 [1, 2]
                  └─ slot 1（元素位置）──保存引用──> int 对象 3
```

引用不是子对象内容的副本。CPython 中可以把它理解为用于找到对象的指针；教学图用箭头表示，不需要记住某个十六进制地址。

对 list、tuple 而言，“改元素”可能是**替换槽位里的引用**，也可能是**沿着原引用修改子对象**。两者不同。字典还需要查找索引等额外结构，字符串则不能理解成“每个字符槽位都存一个 Python 字符对象指针”。不要把一张引用示意图当成所有类型的统一内存布局。

### 1.4 在看 O(1) 之前，先知道它在回答什么

`n` 表示元素数量，`k` 表示这次处理的元素数量。**Time Complexity（时间复杂度）** 关注规模增长时工作量怎样增长；**Space Complexity（空间复杂度）** 关注额外存储怎样增长。

`O(1)` 表示在指定成本模型下，工作量有不随容器长度增长的常数上界，不代表“一纳秒”；`O(n)` 常表示要处理与元素数量成比例的内容。**Average（平均）** 是对不同输入情况讨论平均成本；**Amortized（均摊）** 是把一连串操作的总成本分摊到每次操作。两者不能混为同一个概念。第 13 章再系统展开。

## 2. 按位置组织数据：list、tuple、str

### 2.1 list：会增长的引用数组

```python
nums = [1, 2, 3]             # 初始列表：[1, 2, 3]
nums.append(4)               # 末尾追加一个元素 4 → [1, 2, 3, 4]
nums.extend([5, 6])          # 逐个追加输入中的元素 → [1, 2, 3, 4, 5, 6]
nums.insert(0, 100)          # 在索引 0 前插入 100 → [100, 1, 2, 3, 4, 5, 6]
print(nums[2])              # 取索引 2 的元素，输出 2
last = nums.pop()           # 删除并返回末尾元素；last=6，列表不再包含这个末尾位置
print(last)                 # 6
```

**Dynamic Array（动态数组）** 的直觉是：CPython list 用一段连续的引用槽位保存元素引用，另外记录已使用长度和可用容量；实际元素对象可以分散在别处。

```text
列表的槽位： [ 引用A ][ 引用B ][ 引用C ][ 空余容量 ]
                 │        │        │
实际对象：       1        2        3       （不要求相邻）
```

按索引访问时，可以根据“起始位置＋索引×槽位大小”直接找到槽位，不需要先经过前面的每一个元素。

**为什么在中间插入贵？** 假设在 B 前插入 X：

```text
插入前：[ A ][ B ][ C ][ 空 ]
先右移：[ A ][ 空 ][ B ][ C ]   ← 移动的是后续引用，不是深拷贝 B、C 对象
再写入：[ A ][ X ][ B ][ C ]
```

为了保持序列顺序，后面的引用必须让出位置。越靠近开头，需要移动的引用越多，所以最坏需要 O(n) 工作量。

| 操作 | 典型成本 | 原因 |
|---|---|---|
| `items[i]` | O(1) | 根据位置直接找到引用槽位 |
| `items.append(x)` | 均摊 O(1) | 大多数写入空余容量，偶尔扩容 |
| `items.pop()` | 通常／均摊 O(1) | 移除末尾，不必搬移后续元素；容量收缩可能增加单次成本 |
| 中间插入、删除 | O(n) | 后续引用需要移动 |
| `x in items` | O(n) 次候选检查 | 通常逐个寻找匹配元素 |

`append` 偶尔遇到容量不足，需要申请更大的引用区并搬移已有引用，这一次不是 O(1)。保留额外容量让扩容不必每次发生，因此长串追加操作的平均每次成本可以是均摊 O(1)。表中通常把单次元素比较视为常数成本；复杂对象的比较本身也可能很贵。

### 2.2 append 与 extend：一个整体，还是逐项加入

```python
a = [1, 2]                   # 准备第一个列表
a.append([3, 4])             # 把整个列表 [3, 4] 作为一个元素放进去
print(a)                    # [1, 2, [3, 4]]：长度为 3，最后一个元素仍是列表

b = [1, 2]                   # 准备第二个列表
b.extend([3, 4])             # 取出输入中的 3、4，分别加入 b
print(b)                    # [1, 2, 3, 4]：长度为 4
```

`extend` 接收 **Iterable（可迭代对象）**，即可以逐项取值的对象；不只接受列表。例如 `b.extend("ab")` 会分别加入 `"a"` 和 `"b"`。迭代的底层协议在第 06 章解释。

⚠️ 错误：`items = items.append(x)`。正确：单独写 `items.append(x)`；这个方法原地修改列表并返回 `None`，不返回修改后的列表。

列表删除也要按意图区分：`items.remove(x)` 删除第一个值相等的项，找不到时抛 ValueError；`items.pop(i)` 删除并返回指定位置的项，越界时抛 IndexError；`del items[i]` 只表达删除，不提供返回值。例如 `[1,2,1]` 上 remove(1) 后是 `[2,1]`，不是删掉所有 1。三者的查找与搬移成本也不同，不能只因为都叫“删除”就视为同一种操作。

### 2.3 tuple：固定的是自己保存的那组引用

```python
t = ([1, 2], 3)             # tuple 的第一个元素引用列表，第二个元素引用整数
inner = t[0]                # 保存对内部列表的另一条引用
# t[0] = [9]                # 错误：想把 slot 0 改成引用另一个列表，抛 TypeError
t[0].append(4)              # 正确：沿 slot 0 的原引用，修改那个 list 的内部内容
print(t)                    # ([1, 2, 4], 3)
print(t[0] is inner)         # True：tuple 的第一个槽位仍指向原来的列表
```

```text
禁止：tuple.slot0 ──> 原列表     改成     tuple.slot0 ──> 另一个列表
允许：tuple.slot0 ──> 原列表 [1, 2]      原地变为    原列表 [1, 2, 4]
```

所以“tuple 不可变”的准确边界是：**不能增删或替换它自己保存的元素引用；不意味着沿这些引用可访问到的整张对象图都不可变。** 你看到的打印结果变了，是内部列表内容变了，不是 tuple 换了槽位引用。

```python
single = (1,)                # 单元素元组需要逗号；仅写 (1) 仍然是整数 1
record = ("小林", 20)        # 固定的两项记录
name, age = record           # 解包这两项，name='小林'，age=20
```

tuple 适合固定记录，但不保证“用了 tuple 就深度不可变”，也不保证“一定可哈希”。后面会看到，是否可哈希还取决于元素。

### 2.4 str：文本不可原地改，大量拼接要考虑复制

```python
text = "hello"               # 创建字符串
# text[0] = "H"              # 错误：不能原地替换字符串中的字符
changed = "H" + text[1:]     # 正确：构造新字符串；text[1:] 是 'ello'
print(text, changed)         # hello Hello：原字符串仍然没改

parts = ["hello", " ", "world"]  # 三个字符串片段
result = "".join(parts)      # 用空字符串作为分隔符连接片段
print(result)                # hello world
```

`separator.join(parts)` 是“在片段之间放入分隔符，再生成结果”。`"-".join(["a", "b"])` 得到 `"a-b"`。输入片段需要是字符串，数字应先明确转换。

循环里反复 `text += piece` 可能不断构造、复制越来越长的字符串；某些实现和场景有优化，不能宣称每次都必然进行同样复制。大量片段已准备好时，`join` 更直接地表达一次连接的意图。

## 3. 在学习 dict、set 之前，先理解哈希

### 3.1 为什么要计算 Hash（哈希值）

在列表里找一个键，通常要逐项检查。哈希表希望先通过键算出一个整数，再据此缩小候选范围，而不是每次扫描整个容器。

**Hash Function（哈希函数）** 把对象映射为整数；`hash(key)` 取得哈希值。它是快速定位的辅助信息，不是对象唯一编号，也不是加密承诺。

### 3.2 三个不同层次，不能合成一个“相等”

| 层次 | 表达式 | 含义 |
|---|---|---|
| 身份相同 | `a is b` | 两条引用通向同一个对象 |
| 值相等 | `a == b` | 按类型定义的规则，两个值是否相等 |
| 哈希相等 | `hash(a) == hash(b)` | 两个可哈希对象得到相同哈希值，仍可能不相等 |

对于**可哈希对象**，必须遵守：值相等的对象具有相同哈希值。反过来不成立：不同值可以有相同哈希，这叫 **Hash Collision（哈希碰撞）**。

```python
a, b = -1, -2                # 两个不同整数
print(a == b)                # False：值不相等
print(hash(a), hash(b))      # 这两个整数的哈希值均为 -2
print(hash(a) == hash(b))    # True：证明哈希相同不意味着值相同
```

`__eq__` 是自定义相等规则的方法名，`__hash__` 是自定义哈希行为的方法名。先理解二者职责；第 08 章再学习怎样定义这些方法。不要把“hash equality”背成额外的官方概念，它通常只是指 `hash(a) == hash(b)` 这个事实。

### 3.3 可哈希，不是“看起来不能修改”这么简单

**Hashable（可哈希）** 要求对象可提供在其生命周期内稳定的哈希值，并遵守“相等对象哈希一致”的契约。哈希容器才能在以后通过相同的定位依据找到键。

```text
插入时：hash(key) = H1 → 沿 H1 对应的路径保存
如果后来哈希变成 H2 → 查询改走另一条路径 → 可能找不到原来的键
```

| 对象 | 是否可哈希 | 原因 |
|---|---|---|
| `int`、`str` | 可以 | 提供稳定的值与哈希规则 |
| `list`、`dict`、`set` | 不可以 | 这些内置可变容器没有可用的哈希实现 |
| `tuple` | 取决于所有元素 | 计算元组哈希还需要计算其元素哈希 |
| `frozenset` | 可以（元素必须可哈希） | 不可变集合，创建时已有成员可哈希的要求 |

```python
valid_key = ("user", 123)    # 两个元素都可哈希，所以这个 tuple 可作键
lookup = {valid_key: "小林"} # 用固定记录作为键
print(lookup[valid_key])     # 小林
# hash(([1, 2], 3))          # 错误：tuple 中包含不可哈希的 list
```

⚠️ “可变”与“不可哈希”不是所有自定义对象上都成立的等价命题。有些自定义对象按身份比较和哈希，即使内部属性能变，仍可以可哈希。必须判断具体类型的契约，而不是只背“可变都不行”。

## 4. dict：把完整查找机制放在一起理解

### 4.1 先会使用：键和值各自是什么

```python
user = {"name": "小林", "age": 20}  # 键是字段名，值是对应的数据
print(user["name"])                 # 按键 'name' 取值，输出 小林
user["age"] = 21                    # 更新已存在键的值，不是修改键对象本身
user["skills"] = ["Python"]         # 新增键；值可以是列表等任意对象
print("name" in user)               # True：in 判断的是键，不是值
print(list(user.keys()))            # 把所有键转成列表，保留插入顺序
print(list(user.values()))          # 把所有值转成列表
print(list(user.items()))           # 得到由 (键, 值) 二元组组成的列表
```

**字典要求键可哈希，不要求值可哈希；字典自身仍然不可哈希。** 这是三件事：键的要求、值的要求、容器自身的能力。

```python
data = {"tags": ["a", "b"]}  # 合法：键是字符串，值是列表
# invalid = {[1, 2]: "x"}    # 错误：把 list 当键，抛 TypeError
# hash(data)                # 错误：dict 自身不可哈希，即使它的每个键都可哈希
```

### 4.2 哈希表查找，不是“hash 就是列表索引”

```text
拿到 key
→ 计算 hash(key)
→ 根据哈希与表容量选择候选位置
→ 检查候选项是否是目标键
→ 不匹配：按探测规则继续寻找
→ 匹配：取得该键关联的 value
→ 遇到真正未使用的位置：可以判断不存在
```

**Probe（探测）** 是“按规则继续检查候选位置”。完整哈希值通常不是直接拿来当下标，还要经过表大小等因素映射；即使完整哈希不同，也可能先映射到同一位置。

CPython 字典采用开放寻址一类的查找思想。其内部还有索引表、条目等布局细节，所以这里的“槽位”是查找位置的抽象，不等于 list 的元素数组。理解查找链足够支撑应用面试，不必把某一版本的 C 字段或探测公式背成永久规范。

对于不同对象，哈希相同后仍要通过相等规则区分键。实现还会识别**同一个键对象**，而非每次机械调用 `__eq__`；例如 `NaN` 具有“不等于自己”的特殊数值行为，但同一个 NaN 对象仍可以作为已存键被找回。日常用正常的字符串、整数键，先记住“哈希定位，身份／相等规则确认”。

### 4.3 碰撞不会自动覆盖；等价键才会更新同一项

```python
d = {-1: "甲", -2: "乙"}    # 两个键哈希相同，但值不相等
print(len(d))               # 2：碰撞不是覆盖，两个键可以同时存在
print(d[-1], d[-2])          # 甲 乙：仍能找到各自关联的值

same = {1: "整数"}          # 先以整数 1 建一项
same[True] = "布尔值"       # True 与 1 相等且哈希一致，更新的是同一个字典项
print(len(same))            # 1，而不是 2
```

“Key 不重复”指按字典的键匹配规则不重复，不是“对象类型和地址必须都一样”。`1`、`1.0`、`True` 在这种键语义下不能当作三个独立编号使用。

### 4.4 删除为什么要保留“曾用过”的信息

考虑一个简化的开放寻址表，A、B 从同一候选位置开始探测：

```text
位置：     0          1          2
原来：   [A]        [B]       [未使用]
删除 A： [已删除]   [B]       [未使用]
```

之后查找 B，先遇到位置 0。如果把它误标成“从未使用”，查找就会在这里停止，错误地说 B 不存在。因此需要区分 **Unused（未使用）** 与 **Deleted / Dummy（已删除标记）**：前者可以结束这条查找，后者要继续探测。这一串查找路径叫 **Probe Chain（探测链）**。

具体版本的删除标记、空洞和重建策略可能不同；不变的理解是：**删除不能破坏仍在使用的查找路径**。

### 4.5 Resize（扩容）为什么影响单次成本

表太满时，候选位置更容易被占用，探测路径变长。字典会在必要时分配或重建更合适的表结构，把条目重新组织到可查找的位置。

所以平均查找、插入、删除很快，并不意味着每次插入都只做固定几步。应区分平均查找成本、摊到很多次插入上的扩容成本，以及恶劣碰撞情况下的最坏成本。自定义哈希与相等比较很昂贵时，也不能只看表的 O(1) 就认为整次调用很便宜。

### 4.6 `d[key]` 与 `d.get(key, default)`：缺失是否正常

```python
settings = {"limit": 0, "note": None}  # 0 和 None 都是实际保存的值
print(settings["limit"])              # 0：该键确实存在
# settings["missing"]                # 错误示例：缺少键会抛 KeyError
print(settings.get("missing", 10))    # 10：键不存在时返回默认值
print(settings.get("note", "无备注")) # None：键存在，不会因为值为 None 就改用默认值
```

**KeyError（键错误）** 表示未找到键。“不存在就说明程序状态有问题”时，直接索引便于暴露错误；“不存在是预期分支”时，`get` 更自然。它不是为了让所有错误都悄悄消失。

## 5. set：只保留成员，不保存键值对应关系

### 5.1 集合操作与成员判断

```python
a = {1, 2, 3}               # 创建集合，成员必须可哈希
b = {3, 4, 5}               # 另一个集合
print(a | b)                # 并集：属于任意一方的成员，内容为 {1, 2, 3, 4, 5}
print(a & b)                # 交集：共同成员，内容为 {3}
print(a - b)                # 差集：在 a 而不在 b 中的成员，内容为 {1, 2}
print(2 in a)               # True：判断成员是否存在
```

这里集合的打印顺序不作为保证。`set` 同样利用哈希思想查找成员，因此同样需要处理哈希与相等规则；不必在学完 dict 后重新背另一套碰撞概念。

```python
seen = set()                # 空集合；{} 是空字典，不是空集合
seen.add("A")               # 添加成员 A
seen.add("A")               # 再次添加等价成员，不会增加第二份
seen.discard("B")           # 删除 B；不存在时也不报错
# seen.remove("B")          # 错误示例：不存在时抛 KeyError
seen.remove("A")            # A 存在，删除成功
```

`remove` 适合“成员理应存在”，`discard` 适合“无论原先有没有，都保证最后没有”。区别是意图，不是哪个方法更高级。

### 5.2 去重需要保留顺序时怎么办

```python
items = ["b", "a", "b", "c"]  # 原始顺序
mapping = dict.fromkeys(items) # 依次建键；重复键不新增一项，值默认都是 None
unique = list(mapping)         # 遍历字典的键并转成列表
print(unique)                  # ['b', 'a', 'c']：保留首次出现的顺序
```

合起来就是 `list(dict.fromkeys(items))`。这里元素必须可哈希；由列表等不可哈希对象组成的数据不能直接套这个写法，需要根据业务选取可哈希标识或用其他比较方案。

## 6. 切片、反向遍历与复制成本

### 6.1 语义回到“取哪些位置”，成本回到“复制哪些引用”

```python
nums = [0, 1, 2, 3, 4, 5]    # 六个元素
part = nums[1:5:2]           # 从索引 1 到 5 之前，每次走两步，取索引 1、3
print(part)                 # [1, 3]
part.append(99)             # 修改新列表的外层结构
print(nums)                 # [0, 1, 2, 3, 4, 5]：原列表外层不受影响
```

内置 list 的切片创建新列表，并复制所选元素的引用。切出 k 项，需要 O(k) 时间和 O(k) 额外引用存储；不是递归复制每个子对象。

```python
rows = [[1], [2]]            # 两个内部列表
part = rows[:]               # 复制外层引用数组
part[0].append(9)            # 沿共享引用修改第一个内部列表
print(rows)                 # [[1, 9], [2]]：子对象仍共享，第 03 章会系统解释
```

tuple、str 的普通部分切片也通常需要构造结果，但**不可变对象的完整切片等特殊情况可能复用原对象**，不能说所有切片必然创建不同身份的新对象。内置 list 的切片不是 NumPy 某些数组切片那种 **View（视图）**；不要把第三方类型的零拷贝行为直接套过来。

### 6.2 只反向遍历，不一定要复制整个序列

```python
items = [1, 2, 3]            # 原列表
backward = items[::-1]       # 创建反向的新列表，额外保存全部元素引用
print(backward)              # [3, 2, 1]
for item in reversed(items): # 返回反向迭代器，逐个取值，不先复制整个列表
    print(item)              # 依次输出 3、2、1
```

`reversed(items)` 适合“只要逐项消费”；要保留完整反向结果，仍需存储结果。原地改变列表顺序可用 `items.reverse()`，它与 `[::-1]`、`reversed()` 又是三个不同意图。

## 7. 把选择落实到应用，而不是背类型排名

| 需要组织什么 | 常用结构 | 应留意的边界 |
|---|---|---|
| Request State（请求状态）、ID 到对象映射、Cache Metadata（缓存元数据）、Structured Payload（结构化数据载荷） | dict | 键是否稳定可哈希，缺失与 None 是否不同 |
| Dedup（去重）、Visited ID（已访问编号）、Permission Scope（权限集合） | set | 是否需要保序，成员是否可哈希 |
| Retrieval Candidates（检索候选）、Chat History（对话历史）、Batch Data（批次数据） | list | 大量切片是否抬高内存峰值 |
| 固定记录、组合键 | tuple | 内部对象可能可变；作键还要满足可哈希要求 |
| 文本与输出片段 | str | 编码在第 09 章讲；大量拼接与切片仍有成本 |

数值与文本补充依据：[浮点表示与比较](https://docs.python.org/3/tutorial/floatingpoint.html)、[Decimal 的构造与精度](https://docs.python.org/3.11/library/decimal.html)。

## 8. 🎯 面试怎么回答

### dict 为什么快

> Python dict 基于哈希表思想，通过 key 的 hash 快速定位候选槽位，冲突时继续探测并用 equality 判断真实 key，因此平均查找、插入、删除接近 O(1)。但不是最坏情况绝对 O(1)，扩容和冲突都会影响单次成本。删除也不能简单破坏探测链，所以实现通常需要保留删除状态。

### list vs tuple

> list 可变，适合动态序列；tuple 自身元素绑定不可修改，更适合固定记录。tuple 是否可哈希取决于内部元素是否都可哈希。

### Slicing

> 对常见 Python 内建序列，切片通常会创建新对象，切出 k 个元素大致要 O(k) 时间和空间。`[::-1]` 很简洁，但也通常意味着复制；只想反向迭代时可以考虑 `reversed()`。

## 9. ⚠️ 易错点

- dict 平均 O(1) ≠ 最坏情况绝对 O(1)；
  正确理解：碰撞、扩容以及键的哈希和比较成本都会影响单次工作量。
- Hash 相同 ≠ 对象相等；
  正确理解：哈希是定位信号，还需要确认目标键；不同键可以碰撞并共存。
- 相等对象必须有一致 Hash；
  正确边界：这是可哈希对象的契约，不能对不可哈希的 list 直接调用 `hash`。
- 删除槽位不能随意破坏 probe chain；
  正确理解：查找遇到已删除位置应继续，不应误当作从未使用而提前停止。
- tuple 不一定可哈希；
  正确判断：逐个看元素是否可哈希，包含 list 的 tuple 就不能作字典键。
- set 不要依赖遍历顺序；
  正确选择：对可哈希元素保序去重可以使用 `list(dict.fromkeys(items))`。
- list 切片通常会复制；
  正确理解：创建新外层列表并复制引用，不等于深拷贝内部对象。
- `[::-1]` 简洁但通常不是零额外空间。
  正确选择：只反向消费时用 `reversed()`；需要副本时接受复制成本。

<details>
<summary>1. 两个不同 key 的 hash 一样时，dict 为什么还能同时保存它们？</summary>

Hash 只用于快速定位候选位置；发生碰撞时哈希表会继续探测其它槽位，并使用 key equality 区分真正的 key。

</details>

<details>
<summary>2. 为什么删除一个 dict key 不能简单理解成把槽位恢复成“从未使用”？</summary>

因为其它发生过碰撞的 key 可能依赖这条探测链；如果查找在这里提前停止，就可能错误地认为后续 key 不存在。

</details>

<details>
<summary>3. `items[:]` 通常有什么成本？</summary>

对于常见内建序列，它通常会创建一个新序列并复制引用/元素视语义而定，因此与结果长度相关，通常需要 O(k) 时间和额外空间。

</details>
