# 04. 函数、参数、作用域与闭包

[← 上一章：共享与拷贝](03-可变对象-对象身份-深浅拷贝.md) · [模块主页](../README.md) · [下一章：数据处理表达式 →](05-lambda-推导式-常用内置函数.md)

前面已经会写几行代码，也知道名字怎样引用对象。函数做的是进一步组织代码：**给一段处理过程命名，明确它接收什么、返回什么，以及里面的名字到哪里查找。**

不要一开始就同时背 `*args`、LEGB、闭包。先走一遍普通调用，再逐步增加调用方式和名字查找规则。

```text
定义函数 → 调用函数 → 参数绑定 → 执行函数体 → 返回结果
                                     ↓
                              名字从哪里查找？
                                     ↓
                         作用域 → 外层变量 → 闭包
```

## 1. 一个函数从定义到调用，发生了什么

### 1.1 定义不是立即运行函数体

```python
def add(a, b):                # 定义函数对象，并把名字 add 绑定到它；a、b 是形参
    result = a + b           # 函数被调用时才计算，result 是本次调用里的局部名字
    return result            # 把结果交回调用位置，结束本次调用

answer = add(2, 3)           # 2、3 是实参；本次 a=2、b=3，返回结果 5
print(answer)               # 5
```

**Parameter（形参）** 是定义处的接收名字，**Argument（实参）** 是调用时实际传入的对象。可以把一次调用画成：

```text
调用处先计算实参 → 新的一次函数执行环境 → 把形参绑定到传入对象
                                      → 执行函数体 → 返回一个结果对象
```

这里绑定的是对象引用，不是深拷贝实参；修改与重新绑定的区别沿用第 03 章。

### 1.2 return 和 print 不是一回事

```python
def show_sum(a, b):           # 这个函数只显示结果，没有显式返回结果
    print(a + b)             # 把结果输出到屏幕，不等于交给调用方继续计算

value = show_sum(2, 3)       # 屏幕先显示 5；函数执行完默认返回 None
print(value)                # None
```

`return` 会立即结束本次调用；不带值的 `return` 和走到函数末尾都返回 `None`。需要继续使用计算结果，就明确返回它，而不是只打印它。

```python
def coordinates():          # 定义返回一组数据的函数
    return 1, 2              # 返回一个 tuple，不是两条独立返回通道

point = coordinates()       # point 得到 (1, 2)
x, y = coordinates()        # 对返回的 tuple 解包，x=1、y=2
```

### 1.3 函数也是对象：传函数与调用函数要分开

```python
def greet(name):             # 接收一个名字，生成问候语
    return f"Hello, {name}"  # f-string：把花括号中表达式的值填进字符串

f = greet                    # 不加括号：让 f 引用同一个函数对象
print(f("Tom"))             # 加括号调用，输出 Hello, Tom
message = greet("Tom")      # message 引用的是返回的字符串，不是函数本身
```

函数可以被赋值、作为参数传递、作为返回值返回。**Higher-order Function（高阶函数）** 就是接收函数或返回函数的函数；第 05 章的数据处理工具和第 07 章的装饰器都建立在这一点上。

### 1.4 调用栈与递归：返回后回到哪里

一次调用保存自己的参数、局部变量和“调用结束后从哪里继续”。尚未结束的调用形成 **Call Stack（调用栈）**：最里面的调用先完成，再把结果交给上一层。递归只是函数在处理较小问题时再次调用自己，不是重新启动整个程序。

```python
def total_to(n):             # 输入约定为非负整数
    if n == 0:              # 基本情况：不用再拆小
        return 0
    smaller = total_to(n - 1)  # 当前层暂停，等待子调用的返回值
    return n + smaller      # 子调用结束后继续当前层

print(total_to(3))           # 6
```

```text
total_to(3)：保留 n=3，等待 total_to(2)
  total_to(2)：保留 n=2，等待 total_to(1)
    total_to(1)：保留 n=1，等待 total_to(0)
      total_to(0)：直接返回 0
    n=1 的这一层得到 smaller=0，返回 1
  n=2 的这一层得到 smaller=1，返回 3
n=3 的这一层得到 smaller=3，返回 6
```

每层的 `n` 是不同调用的局部名字；子调用不会把父层的 n 改成 0。必须有能到达的基本情况，并让输入向它靠近，否则会耗尽递归深度而失败。这个版本对 n<0 不满足输入约定；面向外部的接口应先拒绝负数，而不是期待递归替它校验。对 n 项，这里执行 O(n) 次调用并保留 O(n) 层现场；普通累加用循环更省调用栈。第 13 章的树遍历则利用同一机制返回后继续访问另一个分支。

### 1.5 类型提示：描述值的契约，默认值描述调用方式

```python
def first_name(names: list[str]) -> str | None:
    if not names:
        return None
    return names[0]

print(first_name(["小林"]))   # 小林
print(first_name([]))         # None
```

`names: list[str]` 表示期望“元素为 str 的列表”，`-> str | None` 表示结果可能是文本或 None。`|` 是联合类型，不表示把两个值合并。`typing.Optional[str]` 与 `str | None` 含义相同；Optional 的名字并不意味着参数可以不传。

| 注解 | 表达的契约 |
|---|---|
| `dict[str, int]` | 字符串键映射到整数值 |
| `tuple[str, int]` | 固定两项，依次为文本和整数 |
| `tuple[int, ...]` | 任意长度的整数元组 |
| `list[str | None]` | 列表中的每一项可以是文本或 None |
| `list[str] | None` | 整个值可以是文本列表或 None |

```python
def required(value: str | None):  # 允许 None，但仍必须传一个参数
    return value

def optional(value: str | None = None):  # 有默认值，才可以省略实参
    return value

print(required(None))             # None：显式提供了值
print(optional())                 # None：使用默认值
# required()                      # 缺少参数，抛 TypeError
```

Python 本身不会仅凭这些注解逐项校验数据。编辑器/静态检查器可据此发现不一致；运行时是否拒绝错误输入，要看实际执行的检查。第 08 章用注解描述对象行为，第 10 章用 Pydantic 将字段声明转成运行时规则。后续 FastAPI 的“必填”和“可为 null”也沿用这两个独立维度。

## 2. 参数绑定：怎样把输入交给函数

### 2.1 按位置传，还是按名字传

```python
def user(name, age):          # 两个普通参数，可按位置或关键字传入
    return f"{name}: {age}"  # 用格式化字符串返回记录

print(user("Tom", 22))       # 按位置：第一个值给 name，第二个给 age
print(user(age=22, name="Tom"))  # 按关键字：明确指出每个值给哪个参数
```

**Positional Argument（位置实参）** 靠顺序匹配；**Keyword Argument（关键字实参）** 靠名字匹配。普通调用中位置实参放在关键字实参前。不能同时通过位置和关键字给同一个参数重复赋值，也不能漏掉必需参数。

### 2.2 默认值：只在没有传这个参数时采用

```python
def greet(name, prefix="你好"):  # prefix 有默认值，name 仍然必需
    return f"{prefix}，{name}"   # 使用本次绑定的两个参数

print(greet("小林"))             # 你好，小林：没有提供 prefix
print(greet("小林", prefix="欢迎"))  # 欢迎，小林：显式值覆盖默认值
```

默认值不会因为实参是 `0`、`False`、`None` 就自动启用。调用者只要传了，该参数就绑定到传入对象；是否接受这些值，需要函数自己的规则。

### 2.3 收集额外参数：`*args` 和 `**kwargs`

```python
def total(*args):            # 把未单独匹配的位置实参收集成 tuple
    print(args)              # 显示收集结果
    return sum(args)         # sum 对其中的数值求和

print(total(1, 2, 3))        # 先显示 (1, 2, 3)，再显示返回值 6


def show(**kwargs):          # 把未单独匹配的关键字实参收集成 dict
    return kwargs            # 返回这份参数字典

print(show(name="Tom", age=22))  # {'name': 'Tom', 'age': 22}
```

`args`、`kwargs` 是常用命名约定，不是必须照写的关键字。语法能力来自前面的 `*`、`**`。这里的“可变参数”表示数量可变，不表示收集结果都是可变对象；`args` 是 tuple。

### 2.4 调用时的星号：方向相反，展开已有数据

```python
def add(a, b):                # 接收两个普通参数
    return a + b             # 返回相加结果

nums = [10, 20]              # 已经有一组按顺序组织的数据
print(add(*nums))            # 展开为 add(10, 20)，输出 30
params = {"a": 10, "b": 20}  # 已经有一组按参数名组织的数据
print(add(**params))         # 展开为 add(a=10, b=20)，输出 30
```

💡 定义处的星号负责**收集**，调用处的星号负责**展开**。`**` 展开的调用参数名必须是字符串，还要与目标函数允许的参数匹配；展开不会绕过重复参数、缺参数等检查。

### 2.5 `/` 与 `*`：明确允许的调用方式

```python
def format_record(a, /, b, *, c):  # / 前仅位置，* 后仅关键字，中间两种都行
    return a, b, c                 # 返回绑定结果，方便观察

print(format_record(1, 2, c=3))    # (1, 2, 3)：合法
print(format_record(1, b=2, c=3))  # (1, 2, 3)：也合法
# format_record(a=1, b=2, c=3)     # 错误：a 被规定为仅位置参数
# format_record(1, 2, 3)          # 错误：c 必须通过 c=... 指明
```

完整签名再回来看，就不会是一串待背符号：

```python
def demo(a, b=10, *args, c=20, **kwargs):  # 按不同规则接收输入
    return a, b, args, c, kwargs          # 返回各部分，观察匹配过程

print(demo(1, 2, 3, 4, c=5, mode="fast"))  # (1, 2, (3, 4), 5, {'mode': 'fast'})
```

| 位置 | 含义 |
|---|---|
| `a` | 普通必需参数，位置或关键字都可 |
| `b=10` | 普通参数，未传时用默认值 |
| `*args` | 收集剩余位置实参 |
| `c=20` | 位于星号收集之后，只能以关键字传入 |
| `**kwargs` | 收集剩余关键字实参 |

🎯 **面试回答**：`*args` 接收任意数量的位置参数并打包成元组，`**kwargs` 接收任意数量的关键字参数并打包成字典。更准确地说，收集的是没有被前面具体参数消费的额外实参。

## 3. 默认参数为什么在定义时求值

先区分两个时间点：**执行 `def` 语句创建函数对象**，以及**以后调用这个函数**。默认参数表达式在前一个时间点求值，结果被函数保存下来。

```python
limit = 10                   # 定义时的配置值

def take(n=limit):           # 此刻求值 limit，保存整数对象 10 作为默认值
    return n                 # 返回本次参数

limit = 20                   # 改变外部名字不会重新计算已有默认值
print(take())               # 10
print(take(limit))          # 20：显式传入的是当前的 limit
```

第 03 章的可变默认参数因此可以直接推导，而不用另背一条口诀：

```python
# 错误设计：默认列表在多次调用之间共享。
def bad_add(x, items=[]):     # 定义时只创建一次默认列表
    items.append(x)          # 不断修改那个共享对象
    return items             # 返回累计结果

# 正确设计：每次缺省调用创建自己的列表。
def add(x, items=None):       # 用 None 表示没有提供列表
    if items is None:        # 不把合法的空列表当成缺失
        items = []           # 在本次函数体执行期间创建
    items.append(x)          # 修改本次选定的列表
    return items             # 返回结果
```

默认表达式“在定义时求值”也会帮助修复后面的延迟调用问题。但保存的是对象引用，不是自动做深拷贝；默认值引用可变对象时，这一点仍然重要。

## 4. 作用域：函数里的一个名字到哪里找

### 4.1 Scope（作用域）与 Namespace（命名空间）

命名空间可以理解为“名字与对象之间的映射”；作用域讨论“在某段代码里，哪些名字可以被找到，以及从哪里找”。同名变量可以在不同作用域绑定到不同对象。

对普通嵌套函数中的名字读取，先建立 **LEGB** 顺序：

```text
L — Local：当前函数的局部名字
↓ 找不到
E — Enclosing：定义它的外层函数的名字，逐层向外
↓ 找不到
G — Global：当前模块的全局名字
↓ 找不到
B — Built-in：内置名字，例如 print、len
```

```python
x = "global"                 # 模块级名字

def outer():                 # 外层函数
    x = "enclosing"          # outer 的局部名字
    def inner():             # 在 outer 内定义的内层函数
        x = "local"          # inner 自己的局部名字
        print(x)             # 优先找到局部 x
    inner()                  # 调用内层函数

outer()                      # local
```

若删除 inner 里的赋值，读取会找到 enclosing；再删除 outer 里的赋值，才会找到 global。**查找依据是函数定义时的词法嵌套关系，不是“谁调用我，就找谁的局部变量”。** 类作用域、推导式等还有细节；不要把简化 LEGB 说成所有 Python 语境都没有例外。

### 4.2 为什么先读取、后赋值也会报错

```python
count = 0                    # 模块级名字

def bad_increment():         # 错误示例函数，下面不调用它
    print(count)             # 函数内有对 count 的赋值，它被视为局部名字，但此处尚未绑定
    count = count + 1        # 因而调用时前一行会抛 UnboundLocalError
```

**UnboundLocalError（局部变量未绑定错误）** 不是因为找不到全局 `count`，而是这个函数里的 `count` 已被认定为局部名字。需要更新全局状态时可以显式声明；更好的普通接口常是接收输入、返回新值，让调用方管理状态。

### 4.3 global：重新绑定模块级名字

```python
count = 0                    # 模块级计数

def inc():                   # 为教学演示更新全局状态
    global count             # 本函数中的 count 指模块级名字
    count += 1               # 修改模块级绑定

inc()                        # 调用一次
print(count)                 # 1
```

`global` 不表示“创建一个到处共享的万能变量”，目标是当前模块的名字。原地修改一个已找到的全局列表通常不需要 `global`；**给名字重新赋值**与**通过名字修改对象**仍是不同动作。大量全局可变状态会增加测试、并发与排障难度，不应作为默认设计。

### 4.4 nonlocal：重新绑定外层函数中已有的名字

```python
def make_counter():          # 每次调用创建一份独立的外层计数状态
    count = 0                # 要被内部函数继续访问的变量
    def inc():               # 返回的内部函数
        nonlocal count       # 找最近一个已经绑定 count 的外层函数作用域
        count += 1           # 更新那个外层绑定，而不是创建新的局部 count
        return count         # 返回更新后的计数
    return inc               # 返回函数对象，不在这里调用它

counter = make_counter()     # 得到携带计数状态的函数
print(counter())            # 1
print(counter())            # 2
```

`nonlocal` 要求外层函数中已经存在这个绑定；如果紧邻的外层没有，会继续找更外层函数，不会退到模块全局。最近的是“最近一个有该绑定的外层函数”，不是无条件选紧挨着的那一层。

## 5. 闭包：函数为什么能继续访问已经返回的外层变量

### 5.1 先沿一次函数工厂调用解释

```python
def make_multiplier(n):      # 输入倍率，创建一个使用该倍率的函数
    def multiply(x):         # 内部函数，x 是以后调用时的新输入
        return x * n         # x 来自当前调用，n 来自外层函数
    return multiply          # 返回内部函数对象，保留对外层变量 n 的访问

double = make_multiplier(2)  # double 是一个函数，关联倍率 2
print(double(10))            # 20：make_multiplier 已结束，n 仍可访问
```

```text
make_multiplier(2) 执行
→ 为 n 建立绑定
→ 创建 multiply，并让它能访问 n
→ 返回 multiply
→ 外层调用结束，但返回函数仍持有访问 n 的关联
→ double(10) 使用这份关联计算 10 × 2
```

**Closure（闭包）** 的关键不是“一个函数里面又写了一个函数”，而是函数保留了对外层词法作用域变量的访问。它可以用于保存状态、函数工厂、装饰器，以及延迟执行时携带上下文。它保留的不是整个外层代码重新运行的能力，也不意味着把所有外层变量都复制成快照。

### 5.2 晚绑定：创建函数时，不一定已经读出最终结果

先用已经熟悉的 `def` 观察，而不是直接跳到 lambda：

```python
def make_readers():           # 把循环放在函数里，明确展示闭包变量
    readers = []             # 保存稍后才调用的函数对象
    for i in range(3):       # 同一个外层变量 i 依次绑定到 0、1、2
        def read():          # 每轮创建一个新函数
            return i         # 真正调用时才读取共享的外层变量 i
        readers.append(read) # 保存函数，并没有执行 read()
    return readers           # 循环结束，i 最后为 2

readers = make_readers()      # 得到三个稍后执行的函数
print([f() for f in readers]) # 依次调用并收集结果：[2, 2, 2]
```

最后一行是列表推导式，表示“逐个取出函数 f，调用 f()，把返回值放进新列表”，下一章系统展开。**Late Binding（晚绑定）** 在这里指函数调用时才读取变量的当前值，不在创建函数时自动冻结它。

修复：在每轮定义时保存当前值作为默认参数。

```python
def make_readers():           # 每次构造独立的一组读取函数
    readers = []             # 收集函数对象
    for i in range(3):       # 当前值依次为 0、1、2
        def read(value=i):   # 执行 def 时求值 i，保存到这个函数的默认参数里
            return value     # 以后使用本次函数自己的默认参数
        readers.append(read) # 保存当前函数
    return readers           # 返回函数列表

print([f() for f in make_readers()])  # [0, 1, 2]
```

### 5.3 再看同一问题的 lambda 写法

`lambda: i` 是“创建一个无参数函数，调用时返回 i”；`lambda i=i: i` 是“创建一个默认参数为当前 i 的函数”。它们与上面两个 `def` 的关键区别完全相同。

```python
funcs = []                   # 保存函数对象
for i in range(3):           # 循环变量最终是 2
    funcs.append(lambda: i)  # 创建时不读取返回值，调用时查找 i
print([f() for f in funcs]) # [2, 2, 2]

funcs = []                    # 重新开始
for i in range(3):            # 依次构造三个默认参数不同的函数
    funcs.append(lambda i=i: i)  # 右侧 i 在定义时求值，左侧 i 是函数参数名
print([f() for f in funcs])   # [0, 1, 2]
```

模块顶层循环中的 `i` 是全局名字，严格说不是闭包变量；放进外层函数后才是闭包情形。两者都可能出现“延后调用时读到最终值”的现象，不应把所有 lambda 循环问题都机械称为同一种作用域。

本章依据：[函数定义与控制流](https://docs.python.org/3.14/tutorial/controlflow.html)、[执行模型与名字绑定](https://docs.python.org/3.14/reference/executionmodel.html)、[数据模型中的函数对象](https://docs.python.org/3.14/reference/datamodel.html)。

## 6. 🎯 高频面试题

### Q1：`*args` 和 `**kwargs` 的区别？

`*args` 收集额外位置参数为 tuple；`**kwargs` 收集额外关键字参数为 dict。

### Q2：`global` 和 `nonlocal` 的区别？

- `global` 指向模块级全局变量；
- `nonlocal` 指向外层函数作用域中的变量。

### Q3：什么是闭包？

🎯 **回答框架**：闭包通常指一个内部函数捕获并保存了其外层作用域中的变量，即使外部函数已经返回，内部函数仍能访问这些变量。闭包常用于状态保存、函数工厂和装饰器。

### Q4：为什么默认参数不能随便写 `[]` 或 `{}`？

因为默认参数在函数定义时只创建一次，可变对象会被后续调用共享。

## 7. ⚠️ 易错点

- 错误：`f` 与 `f()` 都是函数。正确：`f` 引用函数对象，`f()` 是调用表达式，其结果由函数返回值决定。
- 错误：打印结果就是返回结果。正确：`print` 输出信息，`return` 把对象交回调用方。
- 错误：星号处处表示同一操作。正确：定义处收集，调用处展开；赋值解包又有自己的语境。
- 错误：默认值在每次调用时重算。正确：在定义语句执行时求值；这是默认参数共享与默认值捕获的共同原因。
- 错误：`nonlocal` 随便找一个外部变量。正确：找已有绑定的外层函数作用域，不找模块全局。
- 错误：闭包自动保存变量值的快照。正确：通常保留变量访问关系，之后调用会读取当前值；需要快照时显式设计。
