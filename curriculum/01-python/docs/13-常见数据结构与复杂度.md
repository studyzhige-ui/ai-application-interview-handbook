## 1. 复杂度：规模变大，工作量怎样增长

### 1.1 先定义 n，再谈 O(...)

**Time Complexity（时间复杂度）** 描述输入规模增长时，操作量怎样增长；**Space Complexity（空间复杂度）** 描述所需存储怎样增长。本章通常用 `n` 表示输入项数、`k` 表示要保留的结果数量。

| 复杂度 | 中文直觉 | 典型例子与前提 |
|---|---|---|
| O(1) | 在指定成本模型下有不随 n 增长的常数上界 | 数组按有效索引找到槽位 |
| O(log n) | 每步大致排除固定比例 | 对有序且支持高效随机访问的数据二分查找 |
| O(n) | 与 n 成比例 | 遍历所有元素 |
| O(n log n) | 每项参与约 log n 层处理 | 常见高效比较排序 |
| O(n²) | 所有项之间进行两两级处理 | 朴素双层全遍历 |

`log` 可以先理解为“不断减半需要多少次”：16 → 8 → 4 → 2 → 1，大约四次。讨论增长量级时，固定底数差别通常不影响这里的分类。

O(1) 不表示实际耗时永远相同；一次磁盘访问与一次内存访问都不能仅凭写成 O(1) 就认为等快。还要明确一次哈希、比较、复制是否真的能视为常数成本。

### 1.2 最坏、平均、均摊：描述的不是同一个维度

**Worst Case（最坏情况）** 讨论不利输入；**Average Case（平均情况）** 讨论某种输入分布下的平均；**Amortized Cost（均摊成本）** 把一串操作总成本分摊到每次。

```text
list append：多数很便宜，偶尔扩容很贵 → 一长串追加可均摊分析
hash 查找：不同碰撞情况成本不同       → 平均快不代表最坏情况也同样快
```

说空间复杂度时，还要说明是否计算输入存储、输出结果和递归调用栈。本章对辅助空间会尽量单独说明，不把“返回一个长度 n 的列表”同时说成总空间 O(1)。

## 2. 线性结构：数组与链表的区别来自组织方式

### 2.1 Dynamic Array（动态数组）与 Python list

以 CPython list 为例，连续的是**对象引用槽位**，不是所有被引用对象本体。它可以根据起始位置与索引直接定位槽位，需要增长时再扩展容量。

```text
连续槽位：[引用 A][引用 B][引用 C][空余容量]
实际对象：   ↓       ↓       ↓
           对象 A   对象 B   对象 C    （不要求相邻）
```

| 操作 | 典型复杂度 | 原因 |
|---|---|---|
| `items[i]` | O(1) | 直接定位引用槽位 |
| `items.append(x)` | 均摊 O(1) | 大多数写末尾，偶尔扩容 |
| 末尾 `items.pop()` | 通常／均摊 O(1) | 无需移动后续引用；容量收缩可能增加单次成本 |
| `items.insert(0, x)` | O(n) | 给新元素让位，后续引用右移 |
| `x in items` | O(n) 次候选检查 | 通常逐项寻找 |

容量不足时，追加可能分配新引用区并搬移现有引用，所以不能说每次 append 都是最坏 O(1)。这个机制已在第 02 章展开，这里用它解释选型。

### 2.2 Linked List（链表）：通过连接找到下一个节点

**Node（节点）** 保存值或值的引用，以及指向下一个节点的连接。

```text
[value A | next] ──> [value B | next] ──> [value C | None]
```

要找第十项，通常需要沿连接走过去，不像数组那样直接算出位置。已知道插入点及所需连接时，可以改少量链接插入节点，而不移动后面所有节点。

| 对比 | 数组／动态数组 | 链表 |
|---|---|---|
| 按位置随机访问 | O(1) | O(n) |
| 内存局部性 | 槽位连续，通常较好 | 节点可能分散，通常较差 |
| 中间插删 | 通常要搬移后续引用 | 已定位且具备必要连接信息后可改链接 |
| 额外结构 | 容量与引用数组 | 每个节点的连接信息 |

**Memory Locality（内存局部性）** 表示接下来需要访问的数据是否靠近，有利于硬件缓存利用。复杂度相同，也可能有不同常数成本。

⚠️ 错误：“链表删除一定 O(1)。”正确：已拿到目标位置及所需前驱／链接信息时，改链接可以 O(1)；如果还要先找这个节点，整体可能 O(n)。Python 内置 list 不是链表。

## 3. 栈与队列：先定义取出的规则，再选实现

### 3.1 Stack（栈）：后进先出

**LIFO（Last In, First Out，后进先出）** 像叠盘子，最后放上去的先取走。

```python
stack = []                    # 用列表末尾作为栈顶
stack.append(1)               # 入栈 1
stack.append(2)               # 入栈 2，现在栈顶是 2
print(stack.pop())            # 2：弹出最后加入的元素
print(stack.pop())            # 1
```

典型用途包括 DFS（深度优先搜索）、括号匹配、表达式解析、Undo（撤销）以及理解函数调用栈。它们共同需要“最近尚未完成的工作先继续”。

空栈不能直接 pop；实际流程应先判断是否有元素，或把空栈作为明确的错误处理。

### 3.2 Queue（队列）：先进先出

**FIFO（First In, First Out，先进先出）** 像排队，先进入的人先被处理。

大量使用列表 `pop(0)` 可以表达先进先出，但每次头部删除都可能移动后面的引用，不适合高频队列操作。正确的本地两端队列选择可以是 `deque`：

```python
from collections import deque  # 标准库双端队列

q = deque()                    # 创建空队列
q.append(1)                    # 从右端加入 1
q.append(2)                    # 从右端加入 2
print(q.popleft())             # 1：从左端取出最早加入的成员
```

**Deque（Double-ended Queue，双端队列）** 为两端操作设计，常见两端插入和删除为 O(1) 级操作；它不是让任意中间位置访问都变成 O(1)。其块与连接实现也不要简单说成“每个元素一个链表节点”。

本地 deque 不是分布式消息队列，也不自动提供阻塞等待、持久化或跨进程交付。线程通信、协程通信和持久任务队列要按各自执行模型选择接口。

## 4. Hash Table（哈希表）：通过键缩小查找范围

```text
key（键）
→ hash（哈希值）
→ candidate slot（候选位置）
→ identity / equality check（身份／相等确认）
→ target（目标项）
```

哈希值帮助定位，不是唯一身份证。碰撞时继续探测并区分目标键；平均查找、插入和删除通常接近 O(1)，最坏情况不一定。

Python dict／set 的键要求、碰撞、相等契约、删除标记与扩容统一回到[第 02 章](02-核心数据类型与容器.md)。这一章只补数据结构选择角度：需要按编号迅速找到状态、去重、建立缓存索引时，哈希表通常比逐项扫描更合适。

## 5. 树：用节点与连接表达层次关系

### 5.1 Tree（树）与二叉树

树适合表达层次。**Root（根）** 是入口节点，**Child（子节点）** 在下一层，**Leaf（叶子）** 没有子节点。**Binary Tree（二叉树）** 的每个节点最多有左右两个子节点；它并不自动有大小排序规则。

```python
class TreeNode:                        # 一个简单二叉树节点
    def __init__(self, value, left=None, right=None):  # 子节点缺省为 None
        self.value = value             # 节点保存的值
        self.left = left               # 左子树入口引用
        self.right = right             # 右子树入口引用

root = TreeNode(                       # 构建下面图示的具体树
    "A",                               # 根节点
    TreeNode("B", TreeNode("D"), TreeNode("E")),  # 左子树
    TreeNode("C"),                     # 右子树
)
```

```text
        A
       / \
      B   C
     / \
    D   E
```

`None` 在这里明确表示“这个方向没有子节点”，而不是一个数值零或空字符串。

### 5.2 BST（二叉搜索树）额外规定大小关系

**BST（Binary Search Tree，二叉搜索树）** 在二叉树基础上规定：对每个节点，整个左子树的键都小于当前键，整个右子树的键都大于当前键（这里先约定键不重复）。只比较直接两个孩子还不够；左孩子下面的任何后代也要受祖先的上界约束。允许重复键时，需要另定一致的存放规则。

查找时，每比较一次就根据大小选择进入左侧还是右侧。成本取决于 **Height（树高）**：平衡较好时高度约 log n，查找接近 O(log n)；如果每次都长在同一边，退化成链条，就可能需要 O(n)。不是只要叫“树”，查找就自然有对数复杂度。

### 5.3 四种遍历，区别是“什么时候访问当前节点”

| 遍历 | 中文与访问规则 | 上图结果 |
|---|---|---|
| Preorder | 前序：根 → 左 → 右 | A、B、D、E、C |
| Inorder | 中序：左 → 根 → 右 | D、B、E、A、C |
| Postorder | 后序：左 → 右 → 根 | D、E、B、C、A |
| Level-order | 层序：从上到下逐层 | A、B、C、D、E |

“根”在递归的每一步指当前子树的根，不是反复访问整棵树最顶上的 A。

## 6. DFS 与 BFS：用栈还是用队列管理未完成工作

### 6.1 DFS：先沿一个方向深入

**DFS（Depth-first Search，深度优先搜索）** 通常使用递归调用栈或显式栈。下面沿用上一节已经构建好的 `root`。

```python
def dfs(root):                        # 返回这棵二叉树的前序遍历结果
    result = []                       # 保存输出；不作为默认参数跨调用共享
    def visit(node):                  # 递归访问当前子树
        if node is None:              # 没有节点时停止这一分支
            return                    # 返回上层调用
        result.append(node.value)     # 前序：先访问当前节点
        visit(node.left)              # 再深入左子树
        visit(node.right)             # 左侧结束后深入右子树
    visit(root)                       # 从根开始
    return result                     # 返回收集结果

print(dfs(root))                      # ['A', 'B', 'D', 'E', 'C']
```

递归时，每层未完成的调用被保留在调用栈上，走到叶子再逐层返回。将访问当前节点的语句放在两次递归之间，就是中序；放在两次递归之后，就是后序。

### 6.2 BFS：先处理当前层，再处理下一层

**BFS（Breadth-first Search，广度优先搜索）** 使用队列保存“已经发现但还没处理”的节点。

```python
from collections import deque         # 为先进先出队列提供高效两端操作


def bfs(root):                        # 返回层序遍历结果
    if root is None:                  # 空树不需要入队
        return []                     # 明确返回空结果
    queue = deque([root])             # 初始只发现根节点
    result = []                       # 保存访问顺序
    while queue:                      # 还有待处理节点就继续
        node = queue.popleft()        # 取出最早发现的节点
        result.append(node.value)     # 访问当前节点
        if node.left is not None:     # 如果存在左子节点
            queue.append(node.left)  # 把左子节点加入队尾，等待以后处理
        if node.right is not None:    # 如果存在右子节点
            queue.append(node.right) # 把右子节点加入队尾
    return result                     # 队列耗尽，所有节点处理结束

print(bfs(root))                      # ['A', 'B', 'C', 'D', 'E']
```

只弹出根节点而不把子节点入队，遍历不会自动延续。队列的变化是 `[A] → [B,C] → [C,D,E] → [D,E] → [E] → []`，所以能逐层推进。

### 6.3 时间与空间要分别看

在每个节点只访问一次、节点处理成本视为常数时，这两种树遍历都是 O(n) 时间。除输出列表之外，递归 DFS 的调用栈约 O(h)，h 为树高；BFS 队列约 O(w)，w 为最大层宽。保存全部访问结果本身另需 O(n) 空间。

非常深的树可能触及 Python 递归深度限制，显式栈可以避免依赖深递归。推广到 **Graph（图）** 时，还可能有环和多条路径到达同一节点，需要 **Visited（已访问记录）** 防止重复或无限循环；不能把只适用于无环树的代码原样套到所有图。

## 7. Heap（堆）：不排序全部，只维护“下一项是谁”

### 7.1 最小堆只保证局部关系与堆顶最小

**Priority Queue（优先队列）** 根据优先级而不是进入先后选择下一项。二叉堆是一种常见实现。**Min-heap（最小堆）** 保证父节点不大于子节点，因此根是最小值，但整个底层列表并不是已排序序列。

```python
import heapq                          # 标准库堆操作；下面常用接口维护最小堆

heap = []                             # 用列表作为堆的存储
heapq.heappush(heap, 3)                # 插入并调整，维护堆关系
heapq.heappush(heap, 1)                # 插入 1，它会成为最小候选
heapq.heappush(heap, 2)                # 插入 2
print(heap[0])                        # 1：只查看最小值，不删除
print(heapq.heappop(heap))            # 1：取出最小值并恢复堆关系
```

| 操作 | 典型成本 |
|---|---|
| 查看 `heap[0]` | O(1) |
| `heappush` 插入 | O(log n) |
| `heappop` 弹出最小值 | O(log n) |
| `heapify` 把已有列表整理成堆 | O(n) |

树形关系可以存在数组中，不一定要创建带左右指针的 TreeNode。堆的插入和删除主要沿一条父子路径调整，路径长度与树高相关，所以常见成本是 O(log n)。

⚠️ 空堆没有 `heap[0]`，也不能直接弹出。需要对堆内部做操作时用 heapq 维护性质，随意 append 后就不一定还是合法堆。

以从 0 开始的数组为例，位置 i 的孩子在 `2*i+1`、`2*i+2`，父位置在 `(i-1)//2`（i>0）。因此 `[2,5,3,9]` 表示根 2，孩子 5 和 3，5 的左孩子是 9。

插入 1：先放末尾得到 `[2,5,3,9,1]`；与父 5 交换为 `[2,1,3,9,5]`；再与父 2 交换为 `[1,2,3,9,5]`。每次只向上一层，最终根最小，但 9 与 5 并没有全局排序。弹出根则以末项补根，再与较小孩子逐层交换恢复性质。完全二叉树的高度约 log n，这就是一条调整路径的成本来源。

### 7.2 为什么 Top K 的候选用最小堆

问题：从一亿个可比较数值中找最大的 100 个。若只需要 100 项，就不必把一亿项全部保存并排序。

```text
保留 K 个当前最大的候选
→ 想接纳更大的新值时，淘汰候选里最小的那个
→ 用最小堆，让最弱候选一直在堆顶
```

这里目标是“最大的 K 项”，却用“最小堆”；因为堆顶服务的是**谁最该被替换**，不是直接输出全局最大值。

### 7.3 完整 Top K：处理 k=0、负值与不足 K 项

```python
import heapq                          # 使用最小堆保存候选


def top_k(data, k):                   # data 可逐项迭代，不要求先转为完整列表
    if type(k) is not int:            # 本例要求恰好整数，不把 bool 当数量配置
        raise TypeError("k 必须是整数")  # 拒绝错误类型
    if k < 0:                        # 负数量没有定义
        raise ValueError("k 不能为负数") # 明确拒绝
    if k == 0:                       # 不需要任何结果
        return []                    # 直接返回，不访问空堆堆顶
    heap = []                        # 最多保存 k 个候选
    for x in data:                   # 每次只取一个输入
        if len(heap) < k:            # 候选尚未填满
            heapq.heappush(heap, x)   # 先加入并维护最小堆
        elif x > heap[0]:            # 新值比当前最弱候选更大
            heapq.heapreplace(heap, x) # 替换最小候选并恢复堆关系
    return sorted(heap, reverse=True) # 只排序保留下来的候选，按降序输出

print(top_k([3, 1, 5, 2, 4], 3))     # [5, 4, 3]
print(top_k([3, 1], 5))              # [3, 1]：输入不足 k 项时返回所有已有项
print(top_k([3, 1], 0))              # []：不会访问 heap[0]
```

输入要遵守可比较的排序契约。这里保留按出现次数计的最大 K 项，重复值可以重复进入结果；“最大的 K 个不同值”是另一份任务契约，不能无意混用。

遍历阶段通常概括为 O(n log k)，保留结果后还要支付最终 O(k log k) 的排序成本；用 `log(k+1)` 表达可以覆盖 k=1 的常数调整情形。实际候选数最多为 `min(n,k)`，辅助候选存储为 O(k)。当 k 远小于 n 时，避免全量存储与排序更有价值；k 接近 n 时就未必比全量排序更合适。

## 8. 回到 AI 应用：不是为了算法名词而选结构

| 需求 | 常见结构 | 中文含义与边界 |
|---|---|---|
| Top-K Candidate、Best-N Result | 堆 | 保留最好的少量候选，不必排序全部数据 |
| Priority Scheduling | 优先队列／堆 | 按优先级选下一项，不等于先进先出 |
| BFS、Local Task Buffer、Sliding Window | 队列／deque | 层序推进、本地任务缓冲、滑动窗口 |
| Dedup、Cache Index、ID → State | set／dict | 去重、缓存索引、编号到状态的映射 |
| Workflow Dependency、Agent Plan、文件／仓库结构 | 树／图模型 | 描述层次或依赖关系，必要时考虑环 |

真正的分布式 Queue（队列）、Cache（缓存）、Scheduler（调度器）还有持久化、可靠性和跨机器协调等问题，属于 AI Backend／System Design。这里的数据结构基础负责让你看懂“为什么要这样组织数据和未完成工作”。

本章依据：[collections.deque](https://docs.python.org/3.14/library/collections.html#collections.deque)、[heapq](https://docs.python.org/3.14/library/heapq.html)、[Python 数据结构教程](https://docs.python.org/3.14/tutorial/datastructures.html)。复杂度使用本章说明的抽象前提，不代表对每次实际运行时间的保证。

## 9. 🎯 面试怎么回答

### 为什么 Top K 常用 Heap

> 当只需要最大的 K 个而 K 远小于 N 时，可以维护大小为 K 的最小堆。堆顶是当前候选中最小值，新元素只有大于堆顶才需要进入，单次调整 O(log K)，总体大约 O(N log K)，空间 O(K)，避免全量排序和保存全部候选。

### Array vs Linked List

> 动态数组随机访问 O(1)、缓存局部性好，但中间插删常需要搬移；链表随机访问 O(n)，但在已经定位节点时修改链接成本低。不能简单说“链表删除永远 O(1)”。

## 10. ⚠️ 易错点

- O(1) 不等于实际永远一样快；
  正确理解：它描述随规模增长的量级，实际常数与内存访问方式仍重要。
- `list.append` 是均摊 O(1)；
  正确理解：单次扩容可能更贵，把一串追加总成本分摊后讨论均摊值。
- `list.pop(0)` 不是高效队列；
  正确选择：本地高频两端操作可用 deque，而不是不断搬移列表后续引用。
- 链表删除 O(1) 需要“已经定位”这个前提；
  正确补充：还需要所需前驱／链接信息；查找时间要另外计算。
- Python `heapq` 默认最小堆；
  正确理解：本章常用接口让最小值在堆顶，堆内部并不整体排序。
- “stack / heap” 可能指数据结构，也可能指运行时内存语境；
  正确做法：先确认上下文，别把优先队列的堆当成内存分配区域。
- Hash Table 平均 O(1) 不是最坏情况绝对保证。
  正确理解：碰撞、扩容与元素操作成本影响实际开销。

## 11. 本章自测

<details>
<summary>1. 为什么 `deque.popleft()` 比大量 `list.pop(0)` 更适合队列？</summary>

`list.pop(0)` 通常需要搬移后续元素，是 O(n)；`deque` 为两端操作设计，左端弹出通常 O(1)。

</details>

<details>
<summary>2. 一亿个数取最大 100 个为什么不需要全量排序？</summary>

维护大小为 100 的最小堆即可；每个新元素最多做 O(log 100) 的堆调整，空间也只需 O(100)。

</details>

<details>
<summary>3. “链表删除是 O(1)”什么时候成立？</summary>

当已经拿到待删除位置以及所需前驱/链接信息时，修改链接本身可以 O(1)；如果还需要遍历查找目标节点，整体仍可能 O(n)。

</details>
