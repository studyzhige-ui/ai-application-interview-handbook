# AI Backend Engineering 高频面试题

> 目标不是背标准答案，而是训练：**概念 → 机制 → Failure → Scale → Verification**。

## 1. 从 URL 到服务返回经历什么？

答题框架：DNS → IP → TCP/QUIC → TLS → HTTP → LB/Gateway → Application → Downstream → Response/Stream。继续追问每层 Failure 和 Timeout。

## 2. TCP 和 UDP 区别？

TCP 有连接、可靠字节流、顺序、流控/拥塞控制；UDP 提供 Datagram，本身不提供同等可靠性语义。不要简化成“TCP 慢 UDP 快”。

## 3. TCP 三次握手为什么不是两次？

需要双方确认收发能力与初始序列状态，建立双方认可的连接语义。

## 4. TCP 已经可靠，为什么支付接口仍需幂等？

因为业务可能已执行成功但 Response 丢失。TCP 不能消除 Unknown Outcome，Retry 仍可能重复副作用。

## 5. HTTPS 相比 HTTP 多了什么？

TLS 提供加密、完整性和身份认证。证书/非对称机制帮助建立可信共享秘密，后续数据主要用高效对称加密。

## 6. HTTP/1.1、HTTP/2、HTTP/3 怎么比较？

HTTP/2 在 TCP 上多路复用；HTTP/3 基于 QUIC，QUIC 在 UDP 上实现可靠 Stream、拥塞控制与安全机制。真实选型还要看基础设施支持。

## 7. SSE 与 WebSocket 怎么选？

Server→Client 单向事件为主，SSE 简单；真正双向低延迟控制、语音、实时交互更适合 WebSocket。Transport 不等于 Durable Run。

## 8. Streaming 断线如何 Resume？

Reconnect 只重建连接；Resume 还需要 `run_id + event_id/cursor`、durable state 和事件重放/快照。

## 9. HTTP、RPC、MQ 怎么选？

需要同步结果、对外 API → HTTP；内部强 Schema/低延迟调用 → RPC；不需同步等待、需要 Buffer/Replay/Consumer Scale → MQ。

## 10. Process / Thread / Coroutine 区别？

关注隔离、共享内存、调度成本、CPU Parallelism、I/O 等待。Python 语言细节归 Python 模块，这里重点回答 Service Capacity。

## 11. Thread Pool 参数怎么设计？

看任务是 CPU/I/O、Task Runtime、Queue Capacity、Downstream Capacity，并用 Load Test 观察吞吐、P99、Queue、Context Switch。不要背固定公式。

## 12. Thread Pool Queue 为什么不能无限长？

持续过载时等待、内存、Timeout 不断增长；任务开始时可能已超过业务 Deadline。

## 13. Connection Pool 满了怎么办？

先判断原因还是症状：连接泄漏？Query 变慢？事务太长？下游饱和？再决定是否调 Pool。

## 14. 为什么多个 Worker 会放大连接数？

Pool 通常每进程一份：`pods × workers × pool_size` 才是潜在总连接量。

## 15. Backpressure 是什么？

上游比下游快时，让上游减速、排队、拒绝或降级，防止 Queue/Memory/Latency 无限增长。

## 16. Rate Limit 和 Concurrency Limit 区别？

Rate Limit 控单位时间量；Concurrency Limit 控同时在飞数量。外部 Provider 常同时有两类限制。

## 17. Token Bucket 和 Sliding Window 区别？

Token Bucket 允许可控 Burst；Sliding Window 更准确约束最近时间窗口，但状态/计算更复杂。

## 18. Load Shedding 为什么不是失败设计？

过载时快速拒绝部分请求可能保护剩余容量，优于全部接收后所有请求排队超时甚至进程崩溃。

## 19. Timeout 和 Deadline 区别？

Timeout 是单操作相对时长；Deadline 是全链路绝对截止时间，向下游传播剩余预算。

## 20. Timeout 为什么不等于 Cancellation？

调用方停止等待不代表 DB/Model/Tool 工作停止，可能继续产生副作用，需要 Cancellation Propagation 和 Idempotency。

## 21. 哪些错误不该 Retry？

参数/Schema 错误、权限拒绝、明确业务拒绝等永久错误。先分类再 Retry。

## 22. Exponential Backoff 为什么还要 Jitter？

无 Jitter 时大量客户端仍会在相同退避点同步重试；Jitter 打散重试波峰。

## 23. Retry Storm 怎么形成？

下游变慢 → timeout → retry → load 更高 → 更慢 → 更多 timeout。要用 retry budget、backoff、load shedding、circuit breaker。

## 24. Circuit Breaker 三个状态？

Closed 正常；失败达到条件后 Open 快速失败；冷却后 Half-open 少量探测，成功则关闭，失败继续打开。

## 25. Retry、Circuit Breaker、Fallback 区别？

Retry 再试同路径；Breaker 暂停调用故障下游；Fallback 换替代路径/模型。

## 26. Idempotency-Key 怎么设计？

一个逻辑操作稳定 Key；服务端原子 Claim，保存请求指纹、状态和结果；重复 Key 同参数复用结果，不再执行副作用。

## 27. Distributed Lock 能替代 Idempotency 吗？

不能。Lock 控同一时刻执行权；Idempotency 控同逻辑操作重复到来时副作用只发生一次。

## 28. 为什么 Exactly-once 很难跨系统保证？

MQ、DB、外部 API 是不同事务边界，任何两个步骤之间都可能 Crash。常用 At-least-once + Idempotent Consumer + Reconciliation。

## 29. 为什么需要 MQ？

解耦 Producer/Consumer 的时间与容量，提供 Buffer、异步消费、扩展与 Replay；代价是重复、顺序、积压和最终一致性。

## 30. At-most-once / At-least-once 怎么理解？

前者可能丢但少重复；后者宁可重复也不静默丢，Consumer 需要幂等。

## 31. Consumer 处理成功但 Ack 前 Crash 怎么办？

消息可能重新投递，因此 Side Effect/状态写入必须幂等或可去重。

## 32. Kafka Partition 为什么重要？

它是并行消费和局部顺序的核心边界。同 Key 可路由同 Partition 保序，但 Topic 不保证跨 Partition 全局顺序。

## 33. Consumer 数大于 Partition 数为什么可能无收益？

传统 Consumer Group 中一个 Partition 同时通常分配给一个成员，多余 Consumer 没 Partition 可处理。

## 34. Kafka Lag 高怎么排查？

看 Producer Rate、Partition Skew、Consumer 数、单条处理时间、下游延迟、Retry、Poison Message、Rebalance。

## 35. Outbox 解决什么？

把业务状态和待发送 Event 放在同一 DB Transaction，避免 DB 成功但 MQ publish 丢。Relay 仍可能重复发。

## 36. Lease / Heartbeat 如何恢复 Worker Crash？

Worker Claim 获得有限 Lease，Heartbeat 续租；Crash 后 Lease 过期，其他 Worker Reclaim。仍需 Idempotency/Fencing 防重复。

## 37. 202 Accepted 的 Long-running API 怎么设计？

`POST /jobs → task_id`，之后 `GET status`、SSE events、Cancel；Task State durable 存储，不依赖原 HTTP Connection。

## 38. DB + Redis 双写怎么保证最终一致？

先定义 DB 为 SoT，常见 DB commit 后 invalidate cache，并配 Retry、TTL、Outbox/CDC、Version、Reconciliation。必须画 Failure Window。

## 39. 延迟双删为什么不是万能？

Delay 难估、Process 可能 Crash、第二次删除也可能失败，不能替代可靠事件和对账机制。

## 40. Compensation 和 Rollback 区别？

Compensation 是新的业务动作，例如退款、释放库存、纠正通知，不等于数据库事务回滚。

## 41. MySQL / Redis 怎样分层？

MySQL 通常做 durable business truth；Redis 做 Cache、Session、Quota、短状态、协调。先定义 State Ownership，不按“谁快”选。

## 42. Authentication / Authorization 区别？

Authentication 确认身份；Authorization 判断对资源/动作的权限。多租户权限必须传播到 DB/Cache/Vector/Task/Tool。

## 43. JWT 为什么不能代表完整认证系统？

还需要登录、刷新、撤销、权限、设备、Key Rotation、Session 等机制。

## 44. Service Discovery 和 Load Balancing 区别？

Discovery 得到可用实例集合；Load Balancing 决定本次请求选择哪个实例。

## 45. UUID / Snowflake / 自增 ID 怎么选？

按全局唯一、趋势递增、本地生成、索引局部性、隐私与排序需求选择，没有万能方案。

## 46. 线上 CPU 100% 怎么排查？

先范围/变更 → process/thread → user/system/iowait/load → Trace/route → Queue/Retry/GC/Profile → 验证 Root Cause。

## 47. Docker 与 VM 的核心差别？

Container 通常共享 Host Kernel，依赖 Namespace/cgroup 等隔离；VM 有独立 Guest OS/Kernel，隔离边界和成本不同。

## 48. Readiness / Liveness / Startup Probe 区别？

Startup 判断启动完成；Readiness 判断是否接流量；Liveness 判断是否需要重启。

## 49. 为什么 Liveness 写错会雪崩？

临时过载触发重启会把流量压到剩余 Pod，进一步过载并连锁重启。

## 50. Observability 的三类核心信号？

Trace / Metric / Log；通过 Context Propagation 关联。AI Service 还要带 model/prompt/retrieval version。

## 51. P99 突然变慢如何定位？

先看 QPS/Error/版本，再用 Trace 拆 Queue、Pool、DB、Retrieval、LLM、Tool，并结合资源饱和指标定位。

## 52. Dynamic Config 如何安全热更新？

获取新版本 → Schema/Semantic Validate → Stage → Atomic Swap → 保留 last-known-good → 可回滚，并记录 config_version。

## 53. Monolith 什么时候拆 Microservice？

看业务边界、团队 Ownership、独立 Scale/Deploy、Failure Isolation 收益是否超过网络/一致性/运维成本。

## 54. SSRF 是什么？

服务端根据不可信输入访问攻击者指定目标，可能触达 localhost、内网、metadata。需要 URL/IP 校验与 Network Egress 隔离。

## 55. Prompt Injection 为什么不能只靠 Prompt 防？

Prompt 不是 Security Boundary；真实权限必须由 Server Policy、Scoped Credential、Sandbox、Approval 和 Audit 强制执行。

## 56. ThreadLocal 在线程池中有什么风险？

线程会复用；不清理时旧 Request Context 可能污染下一个任务或长期持有对象引用。

## 57. Java HashMap 和 Python dict 可以直接类比吗？

只能做 hash/collision/resize 的概念类比，具体桶、树化、布局机制不同，不能混写实现。

## 58. Go Goroutine 和 Python Coroutine 区别？

Python asyncio 通常在 Event Loop 中通过 await 协作式挂起；Go Goroutine 由 Runtime Scheduler 映射到多个 OS Thread，可利用多核，机制不同。

## 59. Channel 和 MQ 有什么区别？

Channel 是进程内 Runtime 并发原语；MQ 是跨进程/节点的持久消息系统，提供 Delivery、Replay、Consumer Group 等语义。

## 60. AI Backend 面试遇到开放题最通用的回答顺序？

```text
Requirement / State
→ Normal Path
→ Capacity / Concurrency
→ Failure / Timeout
→ Retry / Idempotency
→ Consistency / Recovery
→ Security / Tenant
→ Observability / Verification
```
