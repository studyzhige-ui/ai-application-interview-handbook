# Backend 机制实验

[模块主页](../README.md) · [复习与综合自测](../review/README.md)

这些实验把“看起来失败”和“状态真的改变”分开观察。不启动 Web 服务、真实 MQ、Redis、MySQL、Kubernetes 或外部支付系统，不需要密钥。

## 环境与运行

使用 Python 3.13 标准库，包括 sqlite3、unittest 和线程池。SQLite 的单写者串行化不同于 InnoDB 行锁，实验不能证明 MySQL 并发性能；实际执行版本及验证范围见[精修验收记录](../../../guide/audits/backend-clarity-refinement-2026-09-28.md)。

从仓库根目录依次运行：

```bash
cd curriculum/03-backend-engineering
python examples/backend_lab.py
python examples/clarity_lab.py
python -m unittest discover -s examples -p "test_*.py" -v
python examples/sync_snippets.py
python examples/check_navigation.py
```

第一个命令进入模块，随后分别运行原子提交与任务代际演示、版本缓存与哈希环演示。unittest 执行两份测试文件；后两项分别检查正文片段和模块导航，默认不修改内容。

维护者修改统一实现后，可运行 `python examples/sync_snippets.py --apply` 同步带标记的正文片段，再检查与测试。Future 的短示例由测试直接从正文读取执行，不另复制一份实现。

## 1. 观察本地提交、重试和旧工作者

`backend_lab.py` 每次建立独立临时目录与空数据库。输入是 team-a 的 doc-42 和稳定操作键，先保存、再同键重试，随后比较旧、新任务代际：

```text
第一次: {'doc_id': 'doc-42', 'version': 1}
同键重试: {'doc_id': 'doc-42', 'version': 1}
文档数/操作数/事件数: 1 1 1
代际: 1 2
旧工作者写回: False
新工作者写回: True
```

前两行是返回结果，第三行是数据库实际行数。两次打印不等于产生两次业务效果；文档、操作结果与 Outbox 一起提交，重试读回结果。后两行表示条件修改是否改变一行，False 不证明所有外部动作都被撤销。

结束时关闭连接并删除自己的临时目录。测试也使用独立目录，线程测试在受控工作终结后关闭池。`init_db(path)` 只建缺失表，不清空已有文件；手动使用时不要指向业务数据库。

## 2. 观察所选版本与缓存内容怎样关联

`clarity_lab.py` 用顺序调用建立以下逻辑时间线，不模拟网络时延：发布版本 7，旧读者选到 7 后暂停；发布 8，并将缓存清空；旧读者迟到回填 7；新读者重新查询权威版本。

```text
迟到回填后的新读取: (8, '新正文')
键 40 的去向: B -> D
键 95 的去向: A -> A
```

第一行表明新读者选择 8，v7 缓存没有成为公共最新指针。若权威版本不可确认，测试要求明确失败；缓存不可用时则可读取权威来源中的准确版本。已经选到 7 的在途读者仍可能完成旧读，这是特意保留的保证边界。

后两行来自人为设置的哈希环位置：A=20、B=60、C=90，随后加入 D=50。测试遍历 0～99，验证只有 `(20,50]` 的选择变化，不假装执行了真实数据迁移。

## 3. 每类验证能证明什么

| 观察对象 | 运行范围 | 不包含的保证 |
|---|---|---|
| 有界线程池与 Future | 真实 Python 线程、超时、待运行取消与异常收集 | 不强杀运行线程，不证明远端操作停止 |
| 本地防重与六个并发调用 | 真实 SQLite 文件、独立连接、事务 | 不是 InnoDB 行级并发或吞吐验收 |
| 子进程提交后读取 | 子进程正常提交退出，另一个进程读回 | 不是强杀、断电、磁盘故障实验 |
| 任务领取与代际 | 真实条件 SQL，显式逻辑租约时间 | 不实现跨机器时钟与外部资源 fencing |
| 令牌与等待预算 | 显式时刻和成本计算 | 不是分布式限流器或跨机计时协议 |
| 外部动作后本地失败 | 内存 FakeProvider 反例 | 不调用真实供应商，不提供外部幂等 |
| 缓存反例与版本化读取 | 内存状态、不可变修订和顺序事件 | 不连接 Redis，不证明复制、故障切换或授权 |
| PKCE S256 | RFC 7636 附录 B 的公开测试向量与格式检查 | 不实现授权码绑定、回调、令牌端点或完整 OAuth 安全 |
| 哈希环与 Linux 数值 | 位置枚举及正文 FD 表的算术 | 不搭负载均衡器，不执行线上 Linux 故障注入 |

PKCE 的向量是规范中的公开例子，不是可用于真实登录的秘密。Linux 章节的 PID、地址与 FD 数值是教学构造，不能当作本机观测。

## 4. 改变条件再判断

先预测，再运行对应测试：调用方超时但线程还在执行，接纳名额是否释放？同键改参数是否产生新版本？缓存丢失后权威版本还在，旧内容是否能决定新读者的选择？把版本 7 冒充版本 8，会在哪一步被拒绝？

[原机制实现](backend_lab.py)与[原机制测试](test_backend_lab.py)保留本地事务和容量边界；[版本与映射模型](clarity_lab.py)由[精修测试](test_clarity_lab.py)执行。它们没有生产系统必需的真实发布器、权限服务、时钟协议和跨系统核对。

文档保存函数仍未实现多人编辑的预期版本冲突检查：新键生成新版本不等于防止旧编辑覆盖。版本模型中的团队键隔离，也不能冒充真实主体授权。
