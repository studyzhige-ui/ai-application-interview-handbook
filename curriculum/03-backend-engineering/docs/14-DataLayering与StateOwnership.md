# 哪些状态必须保存，恢复时相信哪一份

[← 一次请求完成了什么，后端负责到哪里](01-AIBackend职责与RequestPath.md) · [模块主页](../README.md) · [从字节到安全请求：TCP、TLS 与 HTTP →](02-TCPTLS与HTTPVersions.md)

任务 job-42 的执行进程重启后，内存里的“做到第几步”消失了。数据库还有文档，缓存里有旧结果，事件系统里可能有消息。恢复时相信哪份？不事先约定，程序就只能猜。

**状态归属** 回答：一项事实由谁确认，其他副本丢失或冲突时从哪里恢复。先确定这些责任，再选择存储组件。

## 1. 从“能不能重建”区分状态

文档原文、成员权限和付费获得的结果可能无法从缓存重新生成，需要相应的持久存储、备份与恢复。 **Source of truth（权威事实来源）** 是冲突和恢复时指定的裁决依据，不是永不失败的数据库。

可由原文重新生成的摘要、由文档与版本重建的检索索引，属于 **派生状态** 。可重建不表示可任意过时：权限撤销以后，旧索引仍可能暴露敏感内容，访问边界不能等待重建才生效。

| 信息 | 权威记录或责任主体 | 丢失后的处理 |
|---|---|---|
| 文档、版本、团队归属 | 业务存储中的文档记录 | 从经过验证的备份或副本恢复 |
| 操作是否已提交 | 结果记录或业务账本 | 查原记录，不靠再次执行猜测 |
| 文档摘要缓存 | 原文及摘要处理版本 | 重算；期间按策略回源或拒绝 |
| 任务及检查点 | 持久任务记录 | 重新领取，核对已完成位置 |
| 正在传输的连接 | 当前实例和网络状态 | 建立新连接，不能恢复旧套接字本身 |

**检查点（checkpoint）** 记录已经安全完成到哪里。“前 5000 行已入库”必须与数据提交边界相符；只保存内存计数 5000，没有确认这些数据提交，不是可靠检查点。

## 2. 根据责任选择存储，而不是根据产品名猜可靠性

关系数据库用记录、约束和事务维护业务事实；缓存服务支持低延迟与共享短期状态，但持久化、复制、过期和淘汰配置影响丢失风险。用了 Redis 不一定易失，开启持久化也不表示任意故障都不丢。

对象存储保存大文件，业务记录保存文件身份、版本、大小与访问范围。消息系统交付工作或事件，不替业务确认完成；检索索引帮助查找，不替代权限和原始文档。

例如同样把数据放在 Redis：登录会话丢失可能要求重新登录，唯一订单丢失却无法如此处理。决定要求的是丢失后果，不是产品名字或“读起来快”。

## 3. 什么是无状态实例

API 实例 A、B 都能读同一份持久任务记录，下次请求到 B 仍能查到 job-42，这叫业务层的 **无状态化** 。进程里仍可以有连接池、局部变量和缓存。

关键在于实例是否是长期业务事实的唯一持有者。任务只在 A 的字典里，即使总把用户路由到 A，也只是暂时绕开共享问题；A 重启后，路由无法恢复空掉的内存。

## 4. 版本把“哪份较新”变成可判断的条件

文档从版本 3 更新到 4，事件带上 `doc_id=doc-42, version=4`，下游便有条件判断是否已经处理。只通知“文档变了”，通常还得回源查版本，乱序时也难以判断应接受哪次变化。

版本的递增、重置、删除后重建和并发分配必须有可靠规则。不同文档的版本 4、5 不代表共同先后，不同机器的时间戳也不天然构成全局因果顺序。

> ⚠️ 防倒退依据只存在于可淘汰缓存时，缓存丢失会连“已经见过 4”一起删除。版本 3 可能重新被接受。依据的保存期必须覆盖它要防护的时间窗口。

## 5. 从丢失后果推导恢复要求

**RPO（恢复点目标）** 描述允许的数据回退量，通常按时间衡量； **RTO（恢复时间目标）** 描述允许多长时间恢复服务。它们是业务目标，不是声明后自动兑现的能力。

例如最多回退 5 分钟，要求 30 分钟内恢复，仍要演练：备份完整吗、密钥可取得吗、恢复后任务会重复吗、索引如何追上、权限是否正确？有备份文件不证明这些工作能在 30 分钟内完成。

本地实验用真实 SQLite 文件和进程退出后的读取观察持久记录，不验证集群、断电、备份或 RPO/RTO。目标与实测分别记录，不能相互代替。

## 本章小结

先分清业务事实、操作结果、执行进度与派生数据，再选择存储。实例不应是长期事实的唯一持有者；版本依据、恢复记录和可重建内容的寿命不同，决定了故障后还能确认什么。

## 🎯 面试怎么答

**MySQL、Redis、消息队列和检查点怎样分工？**

> 先按丢失后果划分。业务事实和重复操作结果需要可靠记录；缓存与索引通常由事实重建；消息负责交付，检查点记录已确认进度。具体产品是否满足要求，还要验证事务、复制、持久化、淘汰及恢复能力，不只按快慢选。

## ⚠️ 易错点

> ⚠️ 无状态实例仍有连接池和在途工作，区别是它不独占唯一长期事实。

> ⚠️ 检查点不能替代业务账本，备份存在也不证明恢复目标已达成。
