# 02｜同一份数据，怎样保存才方便使用

[← 上一章](01-Redis是什么.md) · [Redis 首页](../README.md) · [下一章 →](03-过期与内存淘汰.md)

同样是“存数据”，商品名称需要整体读出，用户资料可能只改一个字段，消息要保留顺序，签到名单不能重复，排行榜还需要排序。选类型，首先是在选：**接下来能怎样方便地操作这份数据。**

本章每种类型只用一个小场景。先理解数据的形状，再看常用操作；不需要一次记住命令的全部参数。

## 1. 先分清键与键里的内容

`lab:user:42` 是一个完整键名。冒号是帮助人阅读的命名约定，不是 Redis 自动创建了三层文件夹。

一个键在一个时刻对应一个类型的值。`TYPE key` 查看类型，`EXISTS key` 查看是否存在，`DEL key` 删除整个键。不存在的键被 GET 读取时通常得到空回复，在 redis-cli 中显示为 `(nil)`；它与实际保存的空字符串 `""` 不同。

接下来使用的五种常见类型，分别表达一个值、字段集合、顺序、成员关系和分数顺序。[类型概览](https://redis.io/docs/latest/develop/data-types/)

## 2. String：整体值，也能做计数

String 保存一串字节。普通文字、数字的文字表示、整段 JSON 都可以放进去。JSON 是一种表示字段和嵌套内容的文本格式；把它作为 String 保存，不表示 Redis 自动按其中字段操作。

以访问次数为例：

<!-- redis-lab: core_counter -->
```redis
SET lab:visits 10
INCR lab:visits
GET lab:visits
```
<!-- redis-expect: ["OK", 11, "11"] -->

依次得到 `OK`、整数 `11`、字符串 `"11"`。INCR 直接在服务端把整数内容加一；GET 只是取出保存的内容。**存储类型仍是 String，不因用过加法就变成另一种类型。**

围绕整体值，常用操作可以分成三族：`SET/GET` 替换与读取，`MSET/MGET` 一次处理多个键，`INCRBY/DECRBY` 在服务端调整整数。MGET 按请求键的顺序返回一项对应一个位置，缺失项保留空回复，不会把后面的值向前挤；MSET 的多键写在单节点命令范围内一起执行，但不直接附带每键 TTL，Cluster 下多键命令还受同槽约束。`SET ... NX` 只在键不存在时写，`XX` 只在存在时写，未满足条件要与报错区分。

例如在 visits=11 时 INCRBY visits 4 得到 15，而先 GET 11 再 SET 15 会在两个客户端交错时覆盖别人的增加。批量读 N 个值至少要处理 N 项及其字节；所谓单键查找平均 O(1)，没有承诺传输任意长度内容都是零成本。

只有内容能按命令要求解释时，数值操作才成立。对 `hello` 执行 INCR 会出错，而不是自动把它变成数字。

## 3. Hash：一个对象的字段分别管理

用户的名字和积分属于同一份资料，但积分可能独立变化。Hash 在一个键下保存若干“字段—值”，例如 `name → Alice`、`points → 10`。

<!-- redis-lab: core_hash -->
```redis
HSET lab:user name Alice points 10
HSET lab:user points 12
HGET lab:user points
```
<!-- redis-expect: [2, 0, "12"] -->

第一条新增两个字段，回复 `2`；第二条更新已有字段，回复 `0`；最后读到 `"12"`。**HSET 返回的是新增字段数，0 不等于没有修改。**

`HMGET lab:user name points missing` 按字段顺序得到 Alice、12、空回复；`HGETALL` 返回全部字段和值，`HLEN` 返回字段数，`HEXISTS` 检查一个字段，`HINCRBY` 对字段整数原子加减，`HDEL` 删除指定字段。HGETALL 要处理整个对象，字段很多时可用 HSCAN 分次遍历；但 HSCAN 不是快照分页，可能重复返回，COUNT 也不是固定条数。单字段查找和取完整对象的成本不能混为一谈。

String JSON 适合整份读取和替换；Hash 适合经常单独读取或修改字段。Hash 的字段值本身不是任意嵌套对象，复杂层次需要明确编码或选择相应 JSON 能力。

> ⚠️ 操作整个对象和操作其中一个字段不是一回事。DEL 删除整个 Hash，HDEL 只删除指定字段；最后一个字段删除后，键也不再存在。

## 4. List：顺序有意义，而且允许重复

设先收到 m1，再收到 m2。List 保存它们的先后，可以在左右两端加入或取走元素：

<!-- redis-lab: core_list -->
```redis
RPUSH lab:messages m1 m2
LRANGE lab:messages 0 -1
LPOP lab:messages
```
<!-- redis-expect: [2, ["m1", "m2"], "m1"] -->

RPUSH 从右端加入，回复新长度 `2`；LRANGE 读出 `[m1, m2]`，不修改列表；LPOP 取走左端 m1，列表只剩 m2。这种一端加入、另一端取出的配合，形成先到先处理的顺序。

`RPUSH / LPUSH` 决定从哪一端加入，`LPOP / RPOP` 决定从哪一端取走；`LRANGE` 用于查看一段内容，`LTRIM` 则真的移除范围外元素。`LRANGE key 0 -1` 取从第一项到最后一项；`LTRIM key 0 19` 只保留前二十项。重复加入 m1 会保存两份，List 不自动按业务消息编号去重。[List 规则](https://redis.io/docs/latest/develop/data-types/lists/)

空 List 上 LPOP 立即返回空；`BLPOP key timeout` 则等待元素或到达等待期限，返回键名和弹出值。阻塞的是这次客户端调用，不是让 Redis 停止服务其他连接。弹出会删除元素，消费者拿到后崩溃并不会自动补回；`LMOVE/BLMOVE` 可把元素从待办列表原子转移到处理中列表，但确认、超时接管仍需协议，第 14 章会用消费组解释更完整的交付账。两端单元素操作通常 O(1)，长范围读取、按中间位置查找则要考虑遍历与输出数量。

## 5. Set：只关心成员，不保存顺序和次数

签到名单需要判断 Alice 来过没有；反复签到不应把人数重复增加。这适合 Set，即不重复的成员集合。

<!-- redis-lab: core_set -->
```redis
SADD lab:seen alice bob alice
SCARD lab:seen
SISMEMBER lab:seen alice
```
<!-- redis-expect: [2, 2, 1] -->

第一次实际新增两名成员，回复 `2`；人数也是 `2`；最后的 `1` 表示 Alice 在集合中。三个数字分别表示新增数、总数和判断结果，不能混用。

SREM 删除成员，SMEMBERS 取全部成员，SSCAN 分次遍历；SCARD 取成员数，不必取回名单再数。设 A={alice,bob}、B={bob,chen}，SINTER A B 得到 {bob}，SUNION 得到 {alice,bob,chen}，SDIFF A B 得到 {alice}；交换差集顺序则得到 {chen}。集合结果没有显示顺序保证。

成员判断通常平均 O(1)，但全量返回和集合交并差要检查输入与结果规模，不能把“哈希查找快”推广为任意集合运算 O(1)。SPOP 会随机移走成员，SRANDMEMBER 只随机读取；读与删也必须按命令区分。

## 6. ZSet：成员不重复，但多一个排序依据

排行榜既需要识别参赛者，又要按成绩排序。Sorted Set，通常简称 ZSet，为每个唯一成员关联一个分数（score）。

<!-- redis-lab: core_zset -->
```redis
ZADD lab:rank 10 alice 20 bob
ZADD lab:rank 25 alice
ZRANGE lab:rank 0 1 REV WITHSCORES
```
<!-- redis-expect: [2, 0, ["alice", "25", "bob", "20"]] -->

Alice 的分数从 10 更新为 25，没有新增第二个 Alice。最后按高分到低分取前两名，同时返回分数：Alice 25，Bob 20。`REV` 反向排列，`WITHSCORES` 表示带上分数。

`ZSCORE` 取成员分数，`ZINCRBY` 调整分数，`ZRANK/ZREVRANK` 取从 0 开始的升/降序名次，`ZCARD` 数全部成员，`ZCOUNT` 数分数区间内成员。上述数据中 ZSCORE alice 是 25，ZRANK alice 是 1，ZREVRANK alice 是 0。

ZRANGE 默认按排名选范围，端点包含；加 BYSCORE 则按分数区间选，`(20` 表示不含 20，`-inf/+inf` 表示无穷边界。例如 `ZRANGE lab:rank 20 25 BYSCORE` 得到 bob、alice，而 `ZRANGE lab:rank 0 0` 只得到升序第一名 bob。ZREM 按成员删除，ZREMRANGEBYRANK 按位置删除，ZREMRANGEBYSCORE 按分数删除；把时间当 score 清理滑动窗口时用的是第三种，不能把时间戳当排名。

有序查找常见成本为 O(log N)，范围返回还加 O(M) 的结果成本；某些带较大 offset 的范围形式还会多遍历。相同分数按成员的字节字典序排列，不自动按加入时间；分数用双精度浮点数，整数在 ±2^53 范围内可精确表示，超大业务编号不应随手作为精确分数。[Sorted Set](https://redis.io/docs/latest/develop/data-types/sorted-sets/)

把五种类型放回同一张选择表，会比继续记命令更有用：

| 最常做的动作 | 更自然的类型 | 先记住的核心语义 |
|---|---|---|
| 整体保存、整体读取或计数 | String | 一个键对应一个整体值 |
| 独立读写对象字段 | Hash | 一个键下管理多个字段 |
| 保留先后与重复 | List | 有顺序的元素序列 |
| 判断成员是否存在并去重 | Set | 唯一成员集合 |
| 按分数排序或取范围 | ZSet | 唯一成员 + 排序分数 |

> ⚠️ 类型由使用需求决定。最近消息要顺序，用 List；签到要唯一成员，用 Set；成绩要按分数排，用 ZSet。不能因为名字里都有“集合”，就当成同一种容器。

Geo 位置查询属于按地理距离组织和筛选的特定场景，不是普通排行榜。遇到经纬度需求时再查[Geo 用法](https://redis.io/docs/latest/develop/data-types/geospatial/)，不需要为理解这里的五种基本模型先学习地图算法。

**理解练习：** 为商品介绍、用户积分资料、最近消息、签到名单和排行榜分别选类型。每项说出一次最常做的读取或修改；能说出动作，才说明选择有依据。需要连续运行与更多回复对照时，使用[数据类型实验](../examples/labs.md#lab-data-types)。

## 本章小结

键负责定位，值类型决定适合的操作。五种常见模型是整体值、字段、顺序、唯一成员和分数排序；返回值还要按具体命令理解，不能用一个“成功或失败”概括。

## 🎯 面试怎么回答

**五种常用类型怎样选择？**

> 先看最常发生的动作：整值与计数用 String，字段更新用 Hash，顺序记录用 List，成员判断用 Set，分数和范围查询用 ZSet。再限制一次读取多少、集合最多增长到多大。

## 易错点

> ⚠️ HSET 的 0 可以表示更新已有字段；List 的重复元素也不一定是写入失败。

> ⚠️ 全量读取会传回全部结果，大对象不能仅因存于内存就被无成本地读取。

## 本章自测

<details>
<summary>1. 最近三条消息为什么不能直接用 Set？</summary>

Set 不提供加入顺序，也会合并重复成员，无法无条件还原消息顺序。List 保留顺序，另行处理消息去重。

</details>

<details>
<summary>2. ZADD 给已有成员写新分数，成员数怎样变化？</summary>

成员数不变，更新的是该成员的分数。记录每次独立事件时，需要不同的成员标识。

</details>

<details>
<summary>3. HDEL 一个字段与 DEL 整个键，影响范围有何不同？</summary>

前者只移除字段，后者移除整份值；Hash 最后一个字段删除后，键也不再存在。

</details>
