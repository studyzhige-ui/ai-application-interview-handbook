# 01｜Redis 是什么，为什么系统里还需要它

[Redis 首页](../README.md) · [下一章 →](02-键与常用数据类型.md)

你打开一个商品页面，页面要显示名称和介绍。接下来一千个人打开同一个页面，系统又读取了一千次几乎相同的内容。正式数据当然要保存，但每次展示都重新取得一遍，可能没有必要。

一种做法是：把常用结果再存一份，后续请求先读这份副本。**为减少重复获取而保留的副本，叫缓存。** Redis 经常用来保存它，不过缓存只是 Redis 的一种用途。

## 1. Redis 是一个独立保存和处理数据的服务

应用向 Redis 发送请求，Redis 读取或修改自己管理的数据，再返回结果。应用和 Redis 可以在同一台机器，也可以通过网络相连；多个应用实例能访问同一份 Redis 数据。

```text
应用 A ──┐
         ├──→ Redis 服务 ──→ 保存的数据
应用 B ──┘
```

这里的“应用实例”，就是正在运行的一份应用程序。A、B 各自在自己内存里保存的对象不会自动同步；它们都向同一个 Redis 读写，才有了共同访问的位置。

Redis 的常见数据访问主要在内存中完成，并提供针对数据结构的操作，因此适合频繁访问、需要较低延迟的状态。低延迟不是每条请求永远很快，也不是只要放进 Redis 就获得可靠恢复。[Redis 数据模型](https://redis.io/docs/latest/develop/data-types/)

## 2. 键负责找到数据，命令负责操作数据

把一个名字与一份内容关联起来，是 Redis 最基本的使用方式。名字叫**键（key）**，内容叫**值（value）**。例如键 `lab:product:42:name` 对应文字 `notebook`。

下面两行是 Redis 命令，不属于某种应用开发语言。可以先看懂它们的含义，再选择是否打开客户端练习：

<!-- redis-lab: core_first_read -->
```redis
SET lab:product:42:name notebook
GET lab:product:42:name
```
<!-- redis-expect: ["OK", "notebook"] -->

SET 保存值，服务器回复 `OK`；GET 按键取值，回复 `notebook`。同一个键再 SET 为别的文字，会替换这份值，而不是额外添加一行。

**客户端**负责发送这些命令、显示或交给应用处理回复；**服务器**负责管理数据。`redis-cli` 是一个命令行客户端，不是服务器本身。关闭查看数据的客户端，不会因此关闭仍在运行的 Redis 服务。

默认你已有代码环境。选择运行时，可用[可选实验入口](../examples/README.md)核对隔离实例与数据起点；阅读直接沿输入、返回值和状态变化进行。

## 3. 缓存与正式记录的区别，不在数据长什么样

假设商品名称在业务数据库和 Redis 中各有一份。我们约定数据库保存正式版本，Redis 保存用于展示的副本。两者暂时不同，就以数据库为准。这种最终依据通常称为**权威来源（Source of Truth）**。

因此，缓存缺失不等于商品被删除。应用可以重新从数据库取得商品，再建立缓存。反过来，若一个付款结果只存在一个临时 Redis 键里，这个键一旦丢失又没有别处可查，它就不是“随时可丢的缓存”，而是唯一业务记录。

Redis 也能用于经过设计的持久数据存储。能否承担正式记录，要根据持久化、故障恢复和业务要求判断；不能只凭“用了 Redis”就说数据一定会丢，也不能凭“开启了持久化”就断言任何故障都不丢。

## 4. 什么时候值得使用 Redis

先看任务，再决定是否增加这个服务：

| 任务 | Redis 能提供的帮助 | 要提前想清楚的事 |
|---|---|---|
| 很多人反复读取少变的商品介绍 | 保存可复用的读取副本 | 内容改变后，旧副本能用多久 |
| 多个服务共同记录请求次数 | 在共享位置直接增加计数 | 统计范围和期限是什么 |
| 多个应用实例识别登录用户 | 读取同一份会话记录 | 何时失效，丢失后如何重新认证 |
| 展示用户最近几条消息 | 保存有顺序的有限窗口 | 完整历史应从哪里查询 |

如果访问量很小，原有数据库已经满足需求，增加缓存还会增加更新和故障处理工作。**Redis 的价值是解决具体访问问题，不是让架构图多一个组件。**

本课重点是上述数据与状态机制。Redis 产品还有搜索、JSON、向量等能力，选用时应按实际任务比较；这里不会把全部产品功能都变成入门前提。

## 本章小结

Redis 是可被多个应用访问的数据服务；键定位数据，命令完成操作。缓存是数据在系统中的一种角色，是否允许丢失和怎样恢复，取决于它有没有可信的重建来源。

## 🎯 面试怎么回答

**Redis 和缓存是什么关系？**

> Redis 是产品，缓存是保存可复用副本的使用方式。Redis 还可保存计数、会话和事件等状态。设计时应说明哪份数据是权威、能否重建，以及增加 Redis 具体节省了什么。

## 易错点

> ⚠️ 不要把“客户端关闭”“Redis 服务停止”“数据永久丢失”当成同一件事。

> ⚠️ 缓存之外没有数据来源时，不能一边把它叫缓存，一边默认丢失没有影响。

## 本章自测

<details>
<summary>1. Redis 里没有商品名称，能否据此判断商品不存在？</summary>

不能。若 Redis 是缓存，可能尚未缓存、已经失效或被清理。应按读取流程查询权威来源。

</details>

<details>
<summary>2. 两份应用各有一个本地对象，为什么不等于共享 Redis？</summary>

它们是各自独立的内存；修改其中一份不会自动修改另一份。共同读写 Redis 则访问同一个服务管理的状态。

</details>

<details>
<summary>3. 为什么小项目未必需要立刻加入 Redis？</summary>

如果现有访问成本已可接受，缓存节省的工作可能不足以抵消更新、部署和故障处理成本。先确认具体问题。

</details>
