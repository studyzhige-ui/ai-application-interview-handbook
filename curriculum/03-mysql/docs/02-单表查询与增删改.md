# 02｜用 SQL 查询、增加、修改和删除记录

[← 数据库、MySQL 与关系表](01-数据库与关系表.md) · [MySQL 目录](../README.md) · [字段、约束与表之间的关系 →](03-数据类型约束与表关系.md)

上一章的两条任务都还是待办。现在需要看清它们、把第一条改成完成，再添加一条新任务。把这些动作做明白，就已经掌握了 SQL 最常用的四类操作：查询、增加、修改和删除。

本章先用 `first_tasks(id, title, status)` 这三个列。标题是文字，编号是整数，状态使用 `pending` 和 `done`。示例按文中顺序推演；每一步都给出变化后的结果。已有环境中可选运行时，先按[实验入口](../examples/README.md)核对隔离连接。

## 1. 建表和写入是两件事

**建表规定数据的结构，插入才会增加记录。** 下面先建空表：

<a id="sql-basics_create"></a>

<!-- mysql-example: basics_create -->
```sql
CREATE TABLE first_tasks (
    id BIGINT PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    status VARCHAR(16) NOT NULL DEFAULT 'pending'
) ENGINE=InnoDB;
```

括号里每一行声明一个列：`BIGINT` 是整数类型，`VARCHAR(100)` 是最多 100 个字符的文字；`PRIMARY KEY` 把 `id` 设为主键，值必须有且不能重复；`NOT NULL` 表示不能缺值。最后的 `ENGINE=InnoDB` 指定使用本课程讨论的存储引擎。

`DEFAULT 'pending'` 的作用很具体：插入时省略状态，就填入待办。默认值不限制全部合法状态；这两种规则不能混在一起。现在写入两条任务：

<a id="sql-basics_insert"></a>

<!-- mysql-example: basics_insert -->
```sql
INSERT INTO first_tasks (id, title)
VALUES (1, '整理笔记'), (2, '练习 SQL');
```

列清单是 `id, title`，每组值也按这个顺序填写；状态被省略，所以两行都得到 `pending`。单引号包住文字，逗号分开值，语句末尾的分号表示本句结束。SQL 关键字用大写是为了便于阅读，不是必须大写。

> ⚠️ `CREATE TABLE` 不是重置操作。若表已经存在，不要重复建表或随手删库；按实验页核对并重置这一张练习表即可。

## 2. 查询先分清“哪些行”和“哪些列”

<a id="sql-basics_filter"></a>

<!-- mysql-example: basics_filter -->
```sql
SELECT id, title
FROM first_tasks
WHERE status = 'pending'
ORDER BY id;
```

结果是两行：

| id | title |
|---:|---|
| 1 | 整理笔记 |
| 2 | 练习 SQL |

读这句 SQL 时，先看 `FROM` 确定表，再看 `WHERE` 判断哪些行满足条件，最后看 `SELECT` 要返回哪些列。`ORDER BY id` 让结果按编号升序显示。**这是帮助理解结果的顺序，不是数据库底层必须逐步照做的物理算法。**

`WHERE status = 'pending'` 中的等号做比较。条件为真才留下该行。组合条件时，`AND` 要求同时满足，`OR` 表示至少一个满足；混用时可用括号明确分组。例如 `id = 1 AND (status = 'pending' OR status = 'done')`，先把括号理解成允许的两种状态，再加上编号必须为 1 的限制。

常用条件可以按需求回看，不必把每种符号当成一节：

| 想找什么 | 条件片段 | 含义 |
|---|---|---|
| 编号至少为 2 | `id >= 2` | 比较大小 |
| 编号是 1 或 2 | `id IN (1, 2)` | 在指定值中 |
| 标题以“练习”开头 | `title LIKE '练习%'` | `%` 匹配零个或多个字符 |
| 编号不是 1 | `id <> 1` | 不相等 |

这些是接在 `WHERE` 后面的条件片段，不是独立 SQL。`LIKE` 中 `_` 可匹配一个字符；文字是否区分大小写还取决于列的比较规则，具体设置在数据类型章节再说明。

## 3. 排序与限量：取“前面”之前，先定义先后

如果只要编号最大的一条任务，可以这样查询：

<a id="sql-basics_top"></a>

<!-- mysql-example: basics_top -->
```sql
SELECT id, title
FROM first_tasks
ORDER BY id DESC
LIMIT 1;
```

`DESC` 表示降序，因此返回 `(2, '练习 SQL')`。默认的 `ASC` 表示升序。`LIMIT 1` 决定最后返回一条，不是说服务器永远只检查一行。

如果任务后来增加了 `priority`（优先级）列，排序时可能出现并列值。此时可以用编号作第二排序条件，例如 `ORDER BY priority DESC, id ASC`，表示先按优先级降序，同优先级再按编号升序。**排序条件决定并列记录的顺序，不能依赖它们碰巧以某种次序出现。**

## 4. 修改和删除：先指定对象，再检查结果

把编号 1 改成完成：

<a id="sql-first_update"></a>

<!-- mysql-example: first_update -->
```sql
UPDATE first_tasks SET status = 'done' WHERE id = 1;
SELECT id, status FROM first_tasks ORDER BY id;
```

查询得到 `(1, 'done')`、`(2, 'pending')`。`SET status = 'done'` 指定新值，`WHERE id = 1` 指定对象。两个位置都出现等号，但前者赋予新值，后者比较条件。

再增加一条临时任务，查到后删除：

<a id="sql-basics_delete"></a>

<!-- mysql-example: basics_delete -->
```sql
INSERT INTO first_tasks (id, title) VALUES (3, '临时练习');
SELECT id, title FROM first_tasks WHERE id = 3;
DELETE FROM first_tasks WHERE id = 3;
SELECT id, title FROM first_tasks WHERE id = 3;
```

第一次查询返回临时任务，第二次是空结果。删除一行不等于删除表，表的列结构和其他记录仍在。

> ⚠️ 没有 `WHERE` 的 UPDATE 或 DELETE 会作用于全表。练习时先用相同条件 SELECT 看目标，再修改并检查结果；这不能替代工作环境里的权限、备份和变更审查。

以上使用自动提交连接；显式事务的多步提交留到事务章节。在应用中接收用户输入时，还应把参数值与 SQL 结构分开交给驱动，不能直接拼接用户文字。参数绑定的原理和动态列名限制在[多表查询章节](04-关联查询与分组统计.md)中结合完整查询解释，不要求先学某个语言的驱动接口。

## 本章小结

先建表定义结构，再用 INSERT 写入。SELECT 分别指定表、条件、返回列和顺序；UPDATE 与 DELETE 必须明确影响范围，并用查询核对修改后的状态。

## 🎯 面试怎么回答

### SQL 基础操作怎样区分？

SELECT 读取结果，INSERT 增加记录，UPDATE 修改匹配记录，DELETE 删除匹配记录。WHERE 选择行，SELECT 清单选择返回列；排序和数量限制不能代替筛选条件。

## ⚠️ 易错点

> ⚠️ DEFAULT 提供省略时的值，不自动限制全部可填写的内容。

> ⚠️ LIMIT 只限制返回数量，不等于访问成本固定。
