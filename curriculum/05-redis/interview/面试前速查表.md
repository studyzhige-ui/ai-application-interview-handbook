# Redis 面试前速查表

> 目标：20～30 分钟快速唤醒，不替代正文。

## 1. Redis 的一句话定位

```text
低延迟、内存优先、Key → Typed Value 的 Data Structure Server，
常用于 Cache / Session / Counter / Rate Limit / Hot Runtime State。
```

MySQL = 长期结构化业务 Truth；Redis = Hot / Ephemeral / Cached State；Vector DB = Semantic Retrieval。

---

## 2. 数据结构

```text
String → Cache / Counter / Token / Lock Value
Hash   → Object Fields
List   → Ordered Sequence / Simple Queue
Set    → Unique Membership
ZSet   → Member + Score / Rank / Time Window
```

扩展：

```text
Bitmap → boolean state
HyperLogLog → approximate cardinality
Geo → location
Stream → append-only events + consumer group
```

---

## 3. Redis 为什么快

```text
Memory-first
+ efficient server-side data structures
+ mostly single-threaded command execution
+ Event Loop / I/O Multiplexing
+ short command path
+ low lock/context-switch overhead
```

别说：

```text
“因为单线程所以快”
```

---

## 4. I/O Multiplexing

```text
many sockets
→ OS reports ready sockets
→ Event Loop handles ready events
```

Linux 常见 epoll。

解决“哪些连接 Ready”，不等于并行执行命令。

---

## 5. TTL vs Eviction

```text
TTL / Expiration
→ business lifecycle
→ lazy + active expiration

Eviction
→ maxmemory pressure
→ allkeys / volatile / noeviction
```

LRU = recent；LFU = frequency。

---

## 6. Cache 三兄弟

```text
Penetration
→ data does not exist
→ validation / negative cache / bloom filter

Breakdown / Stampede
→ one hot key expires
→ singleflight / mutex / logical expiration

Avalanche
→ many keys / Redis fail together
→ TTL jitter / HA / rate limit / degrade
```

---

## 7. BigKey vs HotKey

```text
BigKey = Value too large
HotKey = QPS too concentrated
```

BigKey：拆分、限制大小、`UNLINK`、避免全量命令。

HotKey：Local Cache、read spread、key sharding、singleflight。

Cluster 不自动解决单 HotKey。

---

## 8. RDB vs AOF

```text
RDB = snapshot
AOF = write log
```

RDB：紧凑、恢复快、Snapshot 间有丢失窗口。

AOF：fsync 决定安全窗口，需要 Rewrite。

Persistence ≠ Replication ≠ Backup。

---

## 9. Replication / Sentinel / Cluster

```text
Replication
→ Primary → Replica
→ mostly async
→ possible stale / recent write loss

Sentinel
→ monitoring + automatic failover
→ non-sharded HA

Cluster
→ 16384 hash slots
→ sharding + replica + failover
```

`WAIT` 降低丢失风险，但 ≠ 强一致。

---

## 10. Cluster

```text
slot = CRC16(key) mod 16384
```

Hash Tag：

```text
user:{123}:profile
user:{123}:settings
```

同 `{123}` → 同 Slot。

多 Key Transaction/Lua 常要求同 Slot。

---

## 11. Transaction / Pipeline / Lua

```text
MULTI / EXEC
→ queued commands continuous execution
→ no generic MySQL-style rollback

WATCH
→ optimistic lock
→ changed → EXEC abort

Pipeline
→ reduce RTT
→ not transaction

Lua / Functions
→ server-side atomic read-modify-write
→ long script blocks others
```

---

## 12. Distributed Lock

Acquire：

```text
SET lock:key unique-token NX PX ttl
```

Release：

```text
if value == my-token
then delete
```

必须原子。

追问：

```text
TTL expires while owner paused
→ new owner acquires
→ old owner resumes
```

解决层次：

```text
owner token → safe release
renewal/watchdog → reduce lease expiry
fencing token → downstream rejects stale owner
idempotency/state machine → business side effects
```

---

## 13. Pub/Sub vs Stream

```text
Pub/Sub
→ online broadcast
→ offline subscribers miss messages

Stream
→ persisted entries
→ consumer group / pending / ack
```

Redis Stream ≠ automatically Kafka replacement。

---

## 14. Session / Agent State

Session：

```text
shared multi-instance state + TTL
```

Conversation：

```text
Redis = recent/hot
Durable DB = full history
```

Agent：

```text
Redis = current step / owner / lease / heartbeat
Durable checkpoint semantics = Agent Harness / System Design
```

Agent State ≠ Agent Memory。

---

## 15. Rate Limit

Fixed Window：

```text
INCR + TTL
```

Sliding Window：

```text
ZSet timestamp score
→ remove old
→ count
→ add current
→ Lua atomic
```

Redis failure：提前定 Fail-open / Fail-closed。

---

## 16. Semantic Cache

```text
Query → Embedding
→ similar historical query
→ threshold
→ reuse answer
```

风险：

```text
False semantic hit
Tenant leak
Permission mismatch
Knowledge/version stale
```

Threshold 必须用 Dataset 验证。
