# Redis｜面试前的一页回忆路径

[← Redis](../README.md) · [面试题](高频面试题.md) · [综合回顾](../review/README.md)

先说清对象与过程，再补上版本和失败条件；这张卡只帮助回忆，不再列一遍所有命令。

## 从一份数据开始

**谁是权威 → 怎样读取修改 → 保留多久 → 丢了怎么办。**

String 是整体值，Hash 是字段，List 是有序可重复记录，Set 是唯一成员，ZSet 是成员与分数。命令回复可能是新增数、最终值或判断结果，不能统一看成成功码。

## 从一次缓存访问开始

命中后还要满足权限和版本；未命中由应用回源。更新来源后安排失效，仍需处理删除失败和旧读晚回填。

穿透看不存在数据，击穿看重复重建，雪崩看大范围回源。负缓存、布隆过滤、单飞、旧值、TTL 抖动和降级各有触发条件，不是同一套万能措施。

本地缓存增加副本，语义缓存增加错误复用风险。两层命中率先统一分母；结果可复用不等于外部动作已经执行。

## 从一条命令开始

端到端时间包含等待、连接、网络、排队、执行与结果处理。I/O 多路复用发现就绪连接，不替命令执行；Pipeline 减少逐条等待，不创造事务。

大键看单次成本，热键看流量集中。编码是实现不是类型本身，used_memory、RSS 和正文容量也不是同一口径。

## 从两个并发操作开始

原生命令优先表达能一次完成的修改；MULTI/EXEC 连续执行队列，WATCH 检查观察后变化，Lua 在服务端进行有限判断。它们都不提供任意外部业务的通用回滚或恰好一次执行。

锁的三个问题分开：**当前是谁 → 租期何时结束 → 旧工作者还能否写下游。** owner token、续租、可信版本与幂等分别解决不同部分。

## 从一次故障开始

RDB 保存某时刻，AOF 提供恢复记录；复制提供副本，Sentinel 负责非分片切换，Cluster 分配固定槽。独立备份与恢复演练不能省略，WAIT 也不等于任意故障零丢失。

消息的**收到、完成、确认、删除**四个事实要分开。最近窗口不等于完整历史，会话期限不等于无限续期，热状态不等于可恢复检查点。

## 最后落到自己的设计

给出权威来源、访问模型、生命周期、并发保护、恢复依据、容量估算与验证方法。只用需要的机制，不为凑齐架构堆组件；只有真实执行过的实验才称为已验证。
