## 一次设计的检查顺序

```text
定义用户动作和完成 → 给出窗口、规模与不变量
→ 计算工作量 → 找权威状态与操作身份
→ 走正常路径 → 在提交边界安排失败
→ 检查权限、预算与恢复 → 说明替代方案和验证
```

## 先问清是哪一种事实

| 容易混在一起的对象 | 需要区分 |
|---|---|
| 成功 | 接受请求、生成结果、供应商受理、送达、已读 |
| 状态 | 权威事实、可重建视图、允许丢弃的临时工作 |
| 身份 | 业务对象、一次操作、一次网络或执行尝试 |
| 时间 | 统计窗口、请求 deadline、租约、缓存 TTL、来源新鲜度 |
| 费用 | 估算、预留、未知、已确认消耗与重复回执 |
| 恢复 | 重放交付、重算纯计算、重复外部动作 |

## 量纲与条件

| 估算 | 条件与式子 |
|---|---|
| 平均在途量 | 稳定系统、同一观察边界：到达率 × 平均停留时间 |
| 简化处理能力 | 同成本任务、槽位持续可用：槽位数 / 每项占用时间 |
| 突发积压 | 恒定速率模型：max(到达率 − 处理率, 0) × 持续时间 |
| 消化积压 | 积压 / (处理率 − 正常到达率)，分母必须大于 0 |
| Token 吞吐 | 调用数 × 每次对应 Token 数；输入、输出分别计算 |
| 调用费用 | 输入量 × 输入单价 + 输出量 × 输出单价，先统一计价单位 |
| 原始保留量 | 新增记录/s × 每记录 B × 保留秒数，再分开算索引与副本 |
| 请求误差预算 | 窗口内合格请求数 × (1 − 目标好事件比例) |
| 向量原始载荷 | 向量数 × 维数 × 每维字节；不是整个索引容量 |
| 单位 | 1 B = 8 b；GB = 10⁹ B，GiB = 2³⁰ B |

平均、理想容量与一次模拟不能推出真实 P99；分位数不能直接相加；最大处理能力等于到达率没有消化积压余量。

## 失败信号与首先检查的边界

| 信号 | 首先问什么 |
|---|---|
| 同一操作反复到达 | 身份与参数是否绑定，业务唯一约束与保留窗口是否足够？ |
| 不同操作争同一资源 | 检查和修改是否在一个原子裁定边界？ |
| 旧工作者仍在执行 | 实际资源是否知道当前执行代际，并拒绝旧提交？ |
| 外部成功可能丢回执 | 有无可靠查询、供应商幂等或对账路径？未找到是否可能竞态？ |
| 缓存失效或旧值回填 | 回源能否限流，陈旧可接受吗，返回前授权是否有效？ |
| 一个分片没返回 | 整体结果允许不完整吗，如何标识并控制总 deadline？ |
| 队列增长 | 最紧的是工作者、模型配额、网络还是预算？ |
| 断线重新连接 | 读取快照和补事件的交接在哪里，而不是重做业务？ |
| 切回旧索引 | 增量是否完整、配置是否兼容、当前撤权与删除是否仍生效？ |

## 组合 AI 系统

**网关：** 先能力和数据政策，再预留资源与费用，逐次记录尝试，正确处理部分输出和最终用量缺失。

**企业 RAG：** 后台更新与在线回答隔离；来源、块、编码、索引相互兼容；代际切换不回滚当前授权。

**长期 Agent：** 持久 Run、检查点、操作记录、批准和预算；恢复前核对未知副作用，重连只恢复交付。

**垂直系统：** 领域定义与权威事实先于模型解释；检索提供依据，确定性计算核对规则，受控工具产生动作，人工处理不可安全自动决定的部分。

## 收尾时必须说清的验证边界

说出输入和假设、目标版本、实际执行环境、观察结果，以及没有验证的层级。给出可推翻方案的故障条件与回退选择，不把“图画完”“有测试”“历史 PASS”当作真实系统已完成。
