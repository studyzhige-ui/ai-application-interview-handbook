# LLM Foundation｜高频面试题

> 来源基线：冻结 `S001–S279` HUMAN-A。`Source Count` 只统计独立真人招聘流程；额外的“体系必会”题用于补齐知识链，不虚构真人频率。

## 第一组｜最高优先级真人问题

### 1. Prompt Engineering 应怎样系统设计？`LLM-023` · 30 sources ⭐⭐⭐

**30 秒：**

Prompt 应明确 Goal、Context、Constraints、Examples、Tool / Capability 与 Output Contract，并进行版本化。优化不能靠几个 Demo 感觉，而要用真实 Evaluation Set 对 Baseline 做 Regression，同时看任务成功率、格式通过率、成本和延迟。Prompt 解决不了最新知识、权限、Tool Reliability 和长期状态，这些要交给 RAG / Backend / Agent Runtime。

### 2. Transformer 整体 Architecture 是什么？`LLM-005` · 10 ⭐⭐⭐

**30 秒：**

Token 先映射成向量并加入位置信息，再经过多层 Transformer Block。每层核心包含 Self-Attention 和 FFN，并通过 Residual / Normalization 稳定深层信息流。Decoder-only LLM 使用 Causal Mask，只允许当前位置关注过去 Token，最终 LM Head 输出词表 logits 做 next-token prediction。

### 3. Model 应怎样选？`LLM-017` · 10 ⭐⭐⭐

**30 秒：**

不只看参数量和公开榜单，而要用真实业务 Eval 比较 Task Success、Tool / Structured Output、TTFT / TPOT、Context、Cost、Safety 和 Provider Reliability。简单任务可以路由到小模型，困难任务用更强模型，目标是业务质量、延迟和成本的 Pareto 最优。

### 4. Hallucination 为什么出现，怎样治理？`LLM-022` · 10 ⭐⭐⭐

**30 秒：**

LLM 优化的是条件生成概率，不是实时事实查询，因此流畅不等于真实。我会先区分模型本体、RAG、Tool、Context 和解析错误；再用 RAG / Tool 提供权威证据，对证据不足做拒答，并在高风险任务增加 Citation、Rule、Test 或 Human Review。Temperature=0 和 RAG 都不能保证零幻觉。

### 5. Fine-tuning 基本流程是什么？`LLM-020` · 9 ⭐⭐⭐

**30 秒：**

先建立 Base / Prompt / RAG Baseline，再准备高质量 Train / Validation / Holdout 数据，做 SFT 或 PEFT，训练后不仅看目标任务提升，还要做通用能力、格式、Tool、Hallucination 等 Regression，最后才进入版本化部署和 A/B。动态知识通常优先 RAG，而不是 Fine-tuning。

### 6. SFT / LoRA / PPO / DPO / GRPO / Distillation 分别解决什么？`LLM-021` · 8 ⭐⭐⭐

**30 秒：**

SFT 学示范答案；LoRA 是参数高效 Fine-tuning；RLHF 常用偏好数据训练 Reward 再做 RL，PPO 是可能的策略算法；DPO 直接用 chosen / rejected Pair 学偏好；GRPO 属于基于奖励的策略优化方法；Distillation 用强 Teacher 迁移能力到更小 Student。应用岗重点是问题边界、数据和成本，不必装作训练算法岗。

## 第二组｜模型机制主线

### 7. Context Window 为什么不能无限塞？`LLM-002` · 7 ⭐⭐⭐

Context Window 是单次推理 Token 容量，不是目标长度。输入越长会增加 Prefill、KV Cache、成本和噪声，还存在长上下文利用率问题，所以应用必须做 Token Budget、Retrieval 和 Compression。

### 8. Q / K / V 怎样计算，为什么能建模关系？`LLM-006` · 7 ⭐⭐⭐

Q/K 负责匹配，V 负责传递内容。核心是 `softmax(QK^T / sqrt(d))V`，让每个 Token 根据当前 Query 动态聚合其它位置的 Value。

### 9. Embedding 为什么能表示语义？`LLM-018` · 6 ⭐⭐⭐

Embedding 模型通过对比学习等目标，让相关样本向量更近、不相关样本更远。检索常用 Bi-Encoder，文档可以离线预计算向量，在线 Query 再做 ANN。

### 10. Multi-Head Attention 为什么需要多个 Head？`LLM-007` · 5 ⭐⭐

多个 Head 使用不同投影，让模型能在多个表示子空间同时建模 Token 关系；不是说每个 Head 都有固定可解释功能。Serving 中 MQA/GQA 还会通过减少 K/V Head 降低 KV Cache。

### 11. Token 是什么？`LLM-001` · 4 ⭐⭐

Token 是 Tokenizer 词表中的离散单元，可能是字符、词或 subword。Context、成本、Chunk 和 Prefill 都按 Token 而不是字符计算。

### 12. Multimodal Transformer 怎么理解？`LLM-010` · 4 ⭐⭐

不同模态先通过 Vision / Audio Encoder 得到表示，再经 Projector、Adapter、Cross-Attention 或统一 Token 方式与语言模型对齐。Visual Token 也会占 Context 和成本。

### 13. Lost in the Middle 是什么？`LLM-003` · 2 ⭐⭐

长 Context 中不同位置的信息利用率可能不一致，重要证据在中间可能更难被稳定使用。它说明“能塞进 Context”不等于“能被稳定利用”。

### 14. FFN 在 Transformer 里做什么？`LLM-008` · 1 · 体系必会

Attention 负责跨 Token 聚合，FFN 对每个位置做非线性特征变换；Residual / Norm 一起帮助深层网络稳定训练和信息传递。

### 15. RoPE 核心思想是什么？`LLM-009` · 1 · 体系必会

按位置旋转 Q/K 表示，使 Attention Dot Product 自然带上相对位置信息。Long Context 扩展与训练位置分布、RoPE Scaling 强相关。

## 第三组｜Generation / Serving

### 16. KV Cache 为什么能加速？`LLM-011` · 3 ⭐⭐⭐

缓存历史 Token 在每层 Attention 的 K/V，Decode 新 Token 时不必重复计算完整前缀。代价是显存，规模随序列长度、KV Heads 和并发增长。

### 17. Prefill 和 Decode 分别是什么？`LLM-012` · 1 · 体系必会

Prefill 一次处理已有输入、建立 KV Cache，偏并行计算；Decode 每步生成一个 Token，依赖历史 KV，串行性更强。

### 18. PagedAttention / vLLM 主要优化什么？`LLM-013` · 4 ⭐⭐

PagedAttention 用固定 Block 管理动态 KV Cache，减少连续显存预留和碎片；vLLM 等 Serving Engine 再结合 Continuous Batching、Scheduler 和 Streaming 提高吞吐。

### 19. LLM API Latency 怎样拆？`LLM-014` · 3 ⭐⭐⭐

至少拆 Queue、Prefill / TTFT、Decode / TPOT、Network。输入长先看 Prefill，输出长看 Decode，不能只看总请求耗时。

### 20. Temperature / Top-k / Top-p 有什么区别？`LLM-015` · 3 ⭐⭐

Temperature 改变概率分布尖锐程度；Top-k 固定保留 k 个候选；Top-p 按累计概率动态保留候选集合。它们控制 Decoding 行为，不直接提高事实正确率。

### 21. 为什么生成是逐 Token 的？`LLM-004` · 2 ⭐⭐

Decoder-only LLM 自回归生成，下一个 Token 依赖已有 Token，所以 Decode 有串行依赖；这也是 KV Cache、Streaming 和长输出延迟的来源。

### 22. Continuous Batching 为什么重要？体系必会

不同请求输出长度不同，静态 Batch 会让短请求空等长请求；Continuous Batching 允许完成请求退出、新请求加入，提高 GPU 利用率。

### 23. Quantization 为什么不一定更快？体系必会

低 bit 通常降低显存和带宽，但速度取决于硬件 Kernel、反量化开销和 workload；必须同时测质量、TTFT、TPOT、吞吐和显存。

## 第四组｜Model API / Retrieval Model

### 24. Chat / Model API 应怎样抽象？`LLM-016` · 5 ⭐⭐

上层统一 Message、Model、Sampling、Structured Output、Stream、Usage；下层 Provider Adapter 处理字段、错误码和 Capability。不要把业务绑死某家 API，也不要抽象掉所有差异化能力。

### 25. Bi-Encoder 和 Cross-Encoder 有什么区别？`LLM-019` · 3 ⭐⭐⭐

Bi-Encoder 独立编码 Query / Doc，可预计算并做 ANN，适合大规模召回；Cross-Encoder 联合编码 Query-Doc，相关性更准但每 Pair 都要算，因此适合少量候选 Rerank。

### 26. 为什么 Retriever 没召回正确文档，Reranker 救不了？体系必会

Reranker 只能重排候选集，正确文档如果不在 Candidate Top-K 中，它没有机会看到；Retriever Recall 是后续 Rerank 的上限之一。

## 第五组｜Fine-tuning / Alignment

### 27. Prompt、RAG、Fine-tuning 怎么选？体系必会 ⭐⭐⭐

任务表达不清先 Prompt；缺外部 / 实时知识用 RAG / Tool；稳定重复的模型行为能力差距再考虑 Fine-tuning；超时、幂等、权限等属于 Runtime。

### 28. LoRA 为什么参数高效？体系必会 ⭐⭐⭐

冻结 Base Weight，用低秩矩阵 `BA` 表示权重增量，只训练少量 Adapter 参数，降低训练显存、Optimizer State 和 Artifact 大小。

### 29. DPO 和 SFT 的核心区别？体系必会

SFT 学“目标回答是什么”；DPO 学“两个回答中更偏好哪一个”，直接使用 Preference Pair 调整模型行为偏好。

### 30. Distillation 的价值是什么？体系必会

让小模型学习强 Teacher 在目标任务上的输出 / 偏好 / 表示，用来降低延迟与成本，但不会自动复制 Teacher 的全部通用能力。

# 面试复习顺序

不要按 `Source Count` 从高到低硬背。

推荐：

```text
Token / Context
→ Transformer / Attention
→ Generation / Sampling
→ KV Cache / Serving
→ Model API / Selection
→ Embedding / Reranker
→ Prompt / Hallucination
→ Fine-tuning / Alignment
```

然后再回到 Source Count 高的题做强化。
