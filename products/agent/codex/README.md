# Codex｜从源码理解持续执行的编程 Agent

[↑ Agent 产品源码](../README.md) · [Agent 通用课程](../../../curriculum/09-agent/README.md) · [源码依据](../../../references/agent/codex-source-index-current.md)

Codex 接到“修复分页错误”后，需要找到实现和测试，把观察结果交给模型，执行被允许的修改，再检查修改是否满足要求。任务变长以后，还要处理上下文容量、跨会话经验、工具失败和中断恢复。本模块沿这些过程阅读公开源码，理解模型判断怎样变成可追踪的工程行动。

学习重点不是记住 Rust 类型名，而是能沿一条任务回答：模型实际看见什么，谁执行动作，状态保存在哪里，以及失败后该检查什么。

本模块面向已经理解模型调用、工具调用、上下文和持久状态基本区别，但第一次阅读 Codex 实现的学习者。必要前提可在 [Agent 通用课程](../../../curriculum/09-agent/README.md)建立；无需先熟悉 Rust 全部语法。

功能存在、源码默认开启、当前会话实际可用，是三个问题。具体开关与失败条件放在对应机制旁解释，例如[记忆启用与版本](02-memory-lifecycle.md#entry-version)，不从“找到代码”推断所有用户都会运行。

## 阅读主线

先看信息怎样支持下一次判断，再看动作怎样执行；理解工具与权限后，继续看后台记忆整理，最后处理持续运行与验收。

| 阅读顺序 | 专题 | 读完应能解释什么 |
|---:|---|---|
| 1 | [上下文](01-context-lifecycle.md) | 第一次与第二次请求具体差在哪里，指令、快照、历史与压缩怎样配合？ |
| 2 | [工具](03-tool-lifecycle.md) | 一次调用怎样完成参数、许可、执行和回填；工具变多后怎样发现与组织？ |
| 3 | [记忆](02-memory-lifecycle.md) | 一段历史怎样变成候选经验、整理材料，再被新任务读取和核验？ |
| 4 | [工程与评测](04-engineering-evaluation.md) | 资源怎样持续使用，记录怎样保存，中断怎样恢复，协作结果怎样验收？ |

专题路径保留为稳定引用标识；第一次学习按上表及页首的上下篇导航，而不是按文件名排序。四篇共同使用 [AI Coding 分页练习](../../../practice/coding/exercises/09-ai-coding-lab/README.md)。题面、实现和测试由该目录统一维护，产品模块不复制另一份算法。

## 核心设计：先认识一条最小工作链

```text
用户提出任务
    ↓
宿主整理指令、历史、环境与工具说明
    ↓
请求模型生成文字或工具调用
    ↓                         ↑
宿主检查并执行调用，将结果记入历史
    ↓
满足本轮结束条件
    ↓
用实际代码差异与测试验收任务
```

宿主是运行 Codex 核心流程、管理工具与状态的程序；模型负责生成判断与调用意图，不能仅靠一段文字执行外部动作。真实循环入口是 [session/turn.rs 的 `run_turn`](https://github.com/openai/codex/blob/67a709665ac7b50311b93e32612c9a8281684787/codex-rs/core/src/session/turn.rs)。图中省略压缩、钩子和故障分支，先用于识别职责；第一篇将它展开为两次具体请求。

## 怎样阅读和验证

第一次沿正文跟踪输入、动作与结果，再用就近源码链接核对；源码索引会提示应先找的类型、函数或分支。`struct` 表示带名字的数据结构，`impl` 中通常能找到相关操作；`async` 和 `.await` 表示执行中可能等待。更具体语法在它影响理解时就地解释。

第二次合上正文，重建任务链，再做章末条件变化自测；最后用“🎯 面试怎么回答”整理表达。各篇保留小结、易错点和折叠答案，工程篇提供[整条链的回顾图](04-engineering-evaluation.md#review-map)与[可运行练习入口](04-engineering-evaluation.md#lab)。

正文的请求清单、材料样例和故障时间线均标明教学身份。源码阅读、手工推演、本地测试与真实 Codex 运行分别记录；已有测试文件不等于本次运行通过，Python 参考实现通过也不等于 Agent 端到端验证完成。
