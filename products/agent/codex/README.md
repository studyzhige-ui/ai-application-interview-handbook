# Codex｜从源码理解持续执行的编程 Agent

[↑ Agent 产品源码](../README.md) · [Agent 通用课程](../../../curriculum/09-agent/README.md) · [源码依据](../../../references/agent/codex-source-index-current.md)

Codex 接到“修复分页错误”后，需要找到实现和测试，把观察结果交给模型，执行被允许的修改，再检查修改是否满足要求。任务变长以后，它还要处理上下文容量、跨会话经验、工具失败和中断恢复。本模块沿这些过程阅读公开源码，理解一个编程 Agent 怎样把模型判断变成可追踪的工程行动。

学习重点不是记住 Rust 类型名，而是能沿一条具体任务回答：信息从哪里来，模型实际看见什么，谁执行动作，状态保存在哪里，以及哪一种失败能够安全重试。

## 核心设计：先认识一条最小工作链

```text
用户提出任务
    ↓
客户端把输入交给核心执行流程
    ↓
整理本次模型请求需要的指令、历史、环境与工具信息
    ↓
模型给出文字，或提出工具调用
    ↓                         ↑
核心执行允许的工具，把结果记入历史
    ↓
满足结束条件后完成本轮；测试和代码差异另行证明任务结果
```

这张图省略了压缩、审批、扩展和故障分支，用来先识别职责。真实循环入口是 [`session/turn.rs::run_turn`](https://github.com/openai/codex/blob/67a709665ac7b50311b93e32612c9a8281684787/codex-rs/core/src/session/turn.rs)。一条模型回复并不总意味着整个任务结束：工具后续、待处理输入和停止钩子都可能影响是否继续。第一章会把这些分支放回具体时间线。

## 怎样读代码并检验理解

第一次先沿正文理解输入、状态变化和结果，再打开附近的固定源码链接核对关键条件。第二次合上正文，画出一次任务从输入到结果的过程，并完成章末自测。最后使用“🎯 面试怎么回答”整理表达，而不是用答案代替首次学习。

代码中的 `struct` 表示一组有名字的数据，`impl` 中通常能找到对这些数据的操作；`async` 函数和 `.await` 表示执行可能需要等待。先跟踪“谁调用谁、等待什么、成功和失败返回什么”，不必一开始就逐项翻译所有字段。更具体的语法在第一次影响解释时说明。

源码阅读、模拟推演、运行测试和真实服务验证必须分别记录。能找到某个测试，只说明上游有这项检查；只有实际运行并保留结果，才构成本次执行证据。
