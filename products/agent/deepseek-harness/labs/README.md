# DeepSeek Harness｜从源码判断到实际验证

[← 模块入口](../README.md) · [上下文](../01-context-lifecycle.md) · [记忆](../02-memory-lifecycle.md) · [工具](../03-tool-lifecycle.md) · [工程与验证](../04-engineering-evaluation.md)

实验围绕同一个分页任务：输入 `[10, 20, 30]`，页码从 1 开始，每页两项，第一页应为 `[10, 20]`，第二页应为 `[30]`；只修改实现，不修改测试。这里不再维护一份假 Harness，也不另写分页参考程序冒充产品实验。分页任务的实现与测试沿用 [Coding 的 AI 协作章节](../../../../practice/coding/docs/09-ai-coding.md) 中的同一份工作副本；每轮开始前恢复自己的实验副本，不能重置正在并行工作的共享仓库。

本目录包含可独立执行的**只读源码与环境检查脚本**，以及需要真实上游运行环境才能执行的实验任务。脚本成功只表示所检查前提成立，不代表 Harness 测试或模型任务通过。

## 1. 固定源码与环境

教学对象是 `deepseek-ai/deepseek-harness@477b4f420553e8a52c2fbccc464d7561b239c443`，包版本为 `0.1.7-rc.2`。根 `package.json` 要求 Node `^22.19.0 || >=24.0.0`，包管理器为 `pnpm@11.7.0`。不要用较旧环境失败，或换成较新快照成功以后，仍报告本教学版本通过。

在已有的独立上游检出目录之外执行：

```bash
# 只读取源码、Git 状态和本机版本；不会安装依赖、修改工作区或调用模型。
python /path/to/this/labs/verify_snapshot.py /path/to/deepseek-harness
```

输出给出 HEAD、包版本、实际 Node/pnpm 版本、关键源文件 Git blob 校验、阻塞项及从当前 Git 清单发现的相关测试文件。返回码 `0` 表示这些门槛未发现阻塞；返回码 `2` 表示需要先解决差异。即便返回 `0`，仍须按上游 `AGENTS.md`、`package.json` 和所选测试目录说明安装、构建、执行测试。脚本没有下载或切换源码，也没有测试所有依赖兼容性。

Git 对象中的内容使用 LF；若检出工具自动转换 CRLF，字节校验会明确拒绝，而不是把不同字节当成相同源码。应在自己的实验检出中确认换行设置，不要为消除报错修改校验值。

## 2. 建立可复现的记录

每次实验先保存以下信息，放在自己的实验输出目录，而非提交秘密到仓库：源码 SHA、工作区差异、Node/pnpm 版本、使用的 profile（配置组合）、有效插件与权限设置、模型路由、输入、预期结果、实际结果。密钥、私有工作目录和真实用户内容应脱敏。基础组合不是所有 SDK 组合的默认值，缺失插件时应报告组合差异。

单元测试先从脚本返回的真实路径中选择，再检查测试定义使用何种运行器。不能仅凭 `.test.ts` 后缀猜测所有文件都能用同一命令运行。单独报告已运行数、失败数和跳过原因；缺少凭据而跳过的集成测试不是通过。

## 3. 实验 A：补充要求何时进入请求

**前提与初始状态：** 使用隔离的工作目录和新会话；选择允许观察请求与会话事件的实际运行入口。模型正在进行第一次读取时，再发送“第二页应返回 `[30]`”。记录该入口把消息作为 Queue 还是 Steer 处理，不能从按钮名称猜测。

**任务：** 对照 Inbox 的入队、领取、用户消息提交和下一次请求，解释补充要求在哪个边界生效。另一轮只注入背景而不唤醒，检查有没有因此独立启动任务。

**可检查结果：** 已发请求不会被追溯修改；背景入队不等于远端收到；同一步请求重试不能重复追加相同用户输入。需要同时保留本地事件和真实请求证据，不能只看界面文字。

## 4. 实验 B：引用快照与跨会话记忆

**初始状态：** 会话 A 记录一个只用于测试的唯一字符串；B 显式引用 A。随后在 A 更正字符串，再观察 B。另建完全没有引用 A 的会话 C，不复制旧历史。

**任务：** 分别验证 B 的不可变引用、旧会话检索入口、以及显式启用外部记忆服务时的 A 写入—C 读取。每种路径单独运行，不得用引用成功代替外部记忆成功。

**可检查结果：** B 保留捕获时的版本；普通工具结果不会因此全部导入引用；C 只有从实际外部存储读到唯一字符串，才支持这次跨会话读取成立。还需检查同一存储空间、服务连接和权限，不能由模型自称记得判断成功。

**重置与清理：** 使用测试账户和独立存储空间。根据所用记忆服务的真实删除接口清理测试项，再新建会话验证删除；不要猜通用删除命令，也不要删除整个共享数据目录。未配置外部服务则该子任务为未执行。

## 5. 实验 C：执行顺序和结果传播

**初始状态：** 从固定上游测试中选择执行前批准、guard、结果后处理与并发调度相关案例。秘密样本必须是专用测试字符串，不使用真实凭据。

**任务：** 检查批准后被 guard 拒绝时业务函数是否被调用；只替换 `content` 后规范 `value` 是否仍存在；A、B 两个允许并行的调用反序完成时，最终提交顺序是什么。

**可检查结果：** 检查调用计数、规范值、模型可见内容及事件顺序，不仅是输出快照。超时定义还依赖超时策略插件；声明 `timeoutMs` 并不等于工具注册表自己执行了超时控制。

这些测试即使通过，也不证明任意外部写入能取消、任意共享文件操作都可并行，或真实秘密已完成所有通道的防泄漏验证。

## 6. 实验 D：中断后的真实状态核对

**前提：** 只在隔离副本进行故障注入。不要手工破坏真实用户的会话文件。优先使用上游持久化和恢复测试已有故障注入点。

**任务：** 区分“调用尚未启动”“已启动但没有可靠结果”“工具结果已保存”三个时点。对于文件写入已完成但结果未保存的情况，恢复后先只读检查文件，再决定是否重试；记录检查点修复与外部状态核验各自提供的证据。

**可检查结果：** 合成错误恢复消息不伪装成真实执行回执；不可读的新格式不能静默回退到旧格式；日志尾部修复不掩盖完整记录的内部损坏；第二次执行不会仅因缺少结果而无条件重写。

真实进程崩溃、文件系统锁、Windows/POSIX 行为和真实外部系统取消须分别测量。内存模拟或一种操作系统上的单元测试不能代替它们。

## 7. 用任务结果验收，而不是只看模型结束

回到分页任务，保存修改前后文件差异、实际测试命令与退出状态、第一/二页的结果，以及“测试文件未改”的证据。若模型通过删除断言提高通过率，必须判为违反约束；不能把正常结束的 Turn 当成完成标准。

实验结论至少区分：源码静态检查、上游单元测试、模拟依赖的实验、真实模型请求、真实工具副作用、跨会话外部存储、跨系统恢复和生产验证。可以只完成其中几层，但未执行的层必须留下明确空白。
