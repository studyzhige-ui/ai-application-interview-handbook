# DeepSeek Harness｜沿一个任务理解上下文、记忆、工具与恢复

[↑ Agent Products](../README.md) · [通用 Agent 课程](../../../curriculum/09-agent/README.md) · [技术资料索引](../../../references/agent/README.md)

用户提出：“修复分页函数。`[10, 20, 30]` 每页两项时，第一页应返回 `[10, 20]`。只修改实现，不修改测试。”模型能建议把偏移公式改成 `(page - 1) * page_size`，但一个可用的编码助手还要知道：读哪个文件、遵守哪些项目规则、有没有写权限、工具到底改成功没有，以及程序中断后能不能安全继续。

本模块以 DeepSeek Harness 的真实实现解释这些问题。**模型负责产生下一步建议，Harness 负责组织输入、控制执行、记录结果，并让失败后的判断有依据。** 上面的分页任务是贯穿讲解的教学场景，不是已经运行成功的产品测试记录。

## 核心设计：先建立一个最小系统模型

理解主线先分清三个对象，不必先记住全部包名：

| 对象 | 在分页任务中负责什么 | 不等于什么 |
|---|---|---|
| Agent（正在工作的智能体实例） | 接收消息，组织一次次模型请求，调用工具 | 模型本身，也不是所有历史数据 |
| Session（会话） | 记录任务输入、请求相关事实、回复、工具结果和执行边界 | 每次都完整发送给模型的聊天文本 |
| Tool（工具） | 读取文件、修改文件、运行测试等具体操作 | 模型输出的一段建议，或未经执行的函数名 |

一个会话可以跨多次进程运行保留；一个活跃 Agent 则有正在等待的请求、取消信号和待处理消息。这些活跃对象不能靠保存几段聊天记录原样复活。什么可以从记录重建、什么必须重新创建，是第四章的核心问题。[实现入口：Agent Loop](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/packages/core/agent-loop/src/agent.ts)、[会话与启动架构](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/docs/architecture.md)。

```text
用户的任务
    │
    ▼
Agent 接收输入、组装一次请求
    │                         Session 记录相关事实
    ├── 模型提出工具调用 ──────────────────┤
    │                                      │
    ▼                                      ▼
工具检查权限并执行                    派生模型可见的历史
    │                                      │
    └── 结果回到下一次请求 ◀────────────────┘
                         │
                         ▼
                   继续工作或结束本轮
```

图中“记录”不表示远端服务已经收到请求，也不表示外部副作用已经完成。沿主线阅读时，要持续区分**程序知道什么、记录证明什么、外部世界发生了什么**。

## 四章怎样连起来

| 阅读顺序 | 入口 | 本章解决的完整问题 | 读完应能做出的判断 |
|---:|---|---|---|
| 1 | [上下文生命周期](01-context-lifecycle.md) | 用户输入、项目规则和历史怎样成为本次模型请求；过长时怎样缩减 | 区分待处理输入、已记录事实、当前模型视图和实际请求；解释压缩改变了什么 |
| 2 | [记忆生命周期](02-memory-lifecycle.md) | 后续任务需要旧信息时，应恢复会话、引用会话、读取项目规则，还是调用外部记忆 | 找到信息的写入者、存储者、召回入口及更新边界，不把“存过”当作“会自动想起” |
| 3 | [工具生命周期](03-tool-lifecycle.md) | 一项能力怎样变成可发现、受约束、可取消且有结果的工具 | 追踪参数、审批、执行、结果投影；判断错误是否意味着操作没发生 |
| 4 | [工程闭环与验证](04-engineering-evaluation.md) | 断网、进程崩溃、插件卸载和子智能体协作后怎样继续 | 用日志和外部状态划定重试边界；区分源码判断、模拟测试和真实服务证据 |

[源码阅读与验证练习](labs/README.md)提供统一的任务条件和检查方法。章末自测的任务可直接阅读，提示与参考答案默认折叠。先独立推演，再展开答案；阅读源码时不要求照抄完整实现。

进入本模块前，至少应知道模型请求由消息组成、工具调用需要程序实际执行、一次异步调用可能失败。函数调用与测试还不熟悉，可以先看 [Coding 的工程修复练习](../../../practice/coding/docs/09-ai-coding.md)。更一般的 Agent 分层与设计取舍由[通用课程](../../../curriculum/09-agent/README.md)负责，本模块会就地解释跟随源码所需的最小前提。

## 为什么它的源码分布在许多插件里

DeepSeek Harness 使用 **Cordis 插件框架**。插件把一种服务或处理过程注册进共同的应用上下文；其他插件通过明确的接口使用它。比如工具注册器提供 `ctx.tools`，模型适配器提供请求能力，Agent Loop 使用这些能力推进任务。**循环本身也是插件，而不是所有其他功能必须修改的特权中心。** 注册还与插件生命周期关联，卸载时要撤销自己的注册。[架构说明](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/docs/architecture.md)。

要区分三个容易混用的词：

- **Plugin（插件）**：实现或接入一个具体职责的代码，例如模型适配器、工具注册器。
- **Bundle（组合包）**：分发一组插件配置及其代码，例如共同基础组合 `dsh-base`。
- **Profile（运行配置档）**：决定本次启动采用哪些组合包和覆盖配置，例如 `web`、`headless`、`sdk`。

因此，“仓库存在这个包”“当前组合装载了这个包”“当前 Agent 能使用该能力”是三种不同判断。`sdk-minimal` 是不应用 `dsh-base` 的独立组合，不能把 Web 的默认行为直接套给它。配置补丁按顺序覆盖指定行，而且替换的是整行 `config`，不是逐字段深度合并；YAML 中为了阅读而排列的行序也不是插件启动顺序。[组合规则](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/docs/architecture.md)、[基础组合源文件](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/packages/bundle/base/cordis.patch.yml)。

这解释了源码阅读方式：先找到所用 Profile 的组合，再沿调用追到实现；不能仅凭目录里有一个 `memory`、`sandbox` 或 `subagent` 名称就宣布能力已生效。

## 第二遍怎样重建主线

合上正文，试着画出“用户发来任务—读取实现—修改实现—测试—给出结论”的时间线。在每个动作旁写出：谁在执行、读写什么、留下什么事实、失败后还知道什么。再改变一个条件：测试返回前进程崩溃，或者新会话需要引用上次的决定。能够沿同一模型推导这些变化，才说明四章已经连起来。

[工程章的综合自测](04-engineering-evaluation.md#self-test)用故障点和权限变化检查这种迁移能力。源码核验范围、面经对应、稿件验证和未执行项记录在[审查与验证记录](../../../guide/audits/deepseek-harness-reader-first-2026-09-27.md)。
