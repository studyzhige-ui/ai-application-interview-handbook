# 工具、文件与作业｜让实际动作接回循环

[← 上一章](01-boot-and-agent-loop.md) · [本产品目录](README.md) · [下一章 →](03-skills-mcp-and-ptc.md)

模型提出的动作要通过当前作用域的工具链。跟完通用派发之后，再看第一方文件的版本观察、Bash 前后台作业和完成通知怎样改变真实状态。

<a id="definition"></a>
## 先看一次读取：说明、实现与结果怎样相连

工具有两个基本部分：给模型看的说明，以及宿主中真正执行的函数。说明告诉模型可以请求什么；执行函数负责操作文件或服务。

| 时点 | 分页任务中发生什么 | 此时已经知道什么 |
|---|---|---|
| 请求包含读取工具说明 | 模型得知可读取文件以及参数要求 | 能提出读取，不代表已经读过 |
| 模型返回读取调用 | 给出工具名、调用 ID 和参数 | 知道本次请求要读哪个目标 |
| 程序检查并执行 | 检查是否允许，校验参数，读取文件 | 才可能获得真实文件内容或错误 |
| 结果写回历史 | 下一步模型获得内容或失败说明 | 可据此修改，或调整读取目标 |

DSH 的 `defineTool()` 将作者写的参数声明、业务函数和输出定义整理成可注册工具。**输出定义**说明返回值应满足什么结构，以及怎样渲染给模型。它连接说明、执行和结果，但不会把“声明会读文件”变成成功证据。[定义源码][schema]

参数结构正确也不代表目标存在或调用者有权读取。接下来先确定本次 Agent 能看见哪个工具，再沿执行链判断是否真的可用。

<a id="visibility"></a>
## 当前 Agent 为什么只看见一部分工具

Scope（作用域）是插件与 Agent 使用服务的上下文层级。全局可以注册通用工具，Agent 的局部层可以限制继承来的能力，或注册自己的工具。

假设全局有读取与写入，审阅 Agent 只继承读取：

| 配置变化 | 审阅 Agent 的情况 |
|---|---|
| 全局存在写工具，本层限制继承写入 | 不能只因全局存在就直接调用写入 |
| 宿主又在本层注册一个写工具 | 必须重新审查本层新增能力，不能继续笼统称为只读 |
| 工具插件卸载 | 旧请求见过的名称不保证此刻仍可执行 |

因此，工具可见性取决于**当前生效的视图**，不是某个目录里存在的全部包。子 Agent 有独立作用域，也不自动证明继承了父级全部限制。[工具视图实现][tools]

> ⚠️ **限制继承项，不等于不可突破的只读边界。** 本层注册与底层文件权限也要检查。请求构造时的工具说明和执行时的实际实现不能被混为一谈；失败时不能暗中改用更高权限实现。

<details>
<summary>核对 `view(scope)` 的合并顺序</summary>

实现先收集全局及祖先层贡献，应用沿途限制，得到允许继承的工具；再加入当前层自己的注册，同名时本层覆盖。本层注册不受这组继承过滤处理，所以 `restrict()` 不能被描述为所有后续注册都无法突破的万能白名单。[源码][tools]

</details>

<a id="pipeline"></a>
## 沿调用顺序判断：到底停在哪一层

下面仍以一次文件读取或编辑为例。`pre` 是执行前策略，`post` 是执行后策略，guard（守卫）是在执行前还能否决动作的检查。

```text
模型提出工具名、调用 ID、参数文本
        ↓
解析参数，保留调用身份与不可变参数快照
        ↓
执行前策略：允许、拒绝、取消，或要求批准
        ↓  要求批准时，先等待本次批准
再次检查取消与 guard
        ↓
调用 execute 包装器：校验参数，再调用业务函数
        ↓
校验返回值，生成模型内容，执行结果后处理
        ↓
冻结最终结果，按调用关系写回历史
```

正常允许且参数合法时，业务函数执行；中途拒绝则返回失败，不会“先执行再问”。模型看到失败后，可以在后续步骤修正参数或选择其他动作。[工具运行链][tools]、[多调用调度器][calls]

### 参数能传递，不等于适合这个工具

执行器保存参数快照，避免等待期间有人改变已经记录的输入；工具自己的结构校验则判断这些输入是否符合声明。两者不是同一次检查。

例如，字符串可以是合法 JSON 值，但读取工具可能需要一个含路径的对象。即使对象结构正确，文件也可能已经不存在。**传递格式、参数结构、业务条件与权限要分别成立。**

`defineTool()` 的参数检查位于业务函数之前，但晚于执行前策略和批准流程。策略代码不能未经检查就假定某个参数字段一定存在。[校验包装][schema]

<details>
<summary>空参数、错误 JSON 与并发分类怎样处理</summary>

`parseArguments()` 解析有效 JSON；空文本变成空对象，解析失败则保留原字符串，使调用仍能携带身份与错误输入。随后执行器要求参数可无损表示为 JSON，并冻结快照。

`defineTool()` 检查失败会抛出带 `INVALID_ARGS` 的 `ToolArgsError`，通过后才调用业务函数。其并发分类包装也先检查参数；无效参数按不安全并发处理。[解析入口][calls]、[包装实现][schema]

</details>

> ⚠️ **结构校验不能替代未表达的业务条件。** Schema 可以声明整数及范围，但接口究竟从 0 还是 1 开始、文件当前版本是否仍与编辑依据一致，要由相应业务与权限逻辑核对。基础组合的第一方文件工具已有下节所述观察策略；任意第三方工具仍不能自动获得同样保证。

### 批准以后仍可能不执行

一次编辑先进入 `ask`，用户同意；等待期间任务被改为禁止写入，随后 guard 否决。正确解释是：**本次审批通过，但另一个执行条件不成立，业务函数没有运行**，不是文件写完后又回滚。[`prepareExecution()` 与审批调用][tools]

取消也可阻止继续执行。guard 只能否决，不能扩大批准范围或悄悄改写参数。需要审批却缺少审批服务，或调用没有所属 Agent 时，审批分支失败关闭；这不等于所有没有 Agent 的普通调用都必然被拒绝。

<a id="file-observation"></a>
## 文件修改依据：观察过哪个版本，才能改哪个版本

基础组合装配 `fs-observation-policy`。它按 Session 与文件目标保存三种状态：尚未观察、确认不存在、确认存在且版本为 V。读取不是只把文本交给模型，还建立此 Session 的编辑依据；观察缓存属于活跃内存，插件卸载会清空。

- **write**：未观察或确认不存在时，只提出“目标仍不存在才创建”；已观察到 V 时，只提出“仍是 V 才替换”
- **edit**：未观察直接返回需要先读；确认不存在返回找不到文件；已观察存在才带版本条件进入提供者
- **真正写入**：文件提供者执行原子的新鲜度/不覆盖检查，成功观察再更新此 Session 的依据

因此“读 A → 其他人改成 B → 依据 A 编辑”不能悄悄覆盖 B。工具应返回冲突，Agent 重新读取 B、重新判断修改，再提交。新建和修改使用不同条件，是为了既能创建未知的新文件，又不把“没读过”当成覆盖现有文件的许可。[观察与意图规则](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/fs/fs-observation-policy/src/index.ts)

该规则是基础组合中的具体插件能力；去掉插件，裸提供者的修改行为不同。它不替任意第三方工具或 Shell 写入自动补版本检查，也不是全机器文件锁。

<a id="approval"></a>
## 策略、批准与沙箱各守住什么

| 机制 | 回答的问题 | 分页任务中的含义 |
|---|---|---|
| 执行策略 | 当前动作允许、拒绝，还是需要询问 | 编辑是否应进入审批 |
| 单次批准 | 这个具体请求能否继续 | 同意这次编辑，不是所有后续写入 |
| 沙箱 | 执行期间实际可访问哪些资源 | 是否能写测试文件或访问网络 |
| 模型提示 | 怎样向模型说明任务规则 | 告诉模型不得改测试，但不能替代系统权限 |

一次写入要同时满足适用条件。沙箱允许写工作区，不代表用户要求你改所有文件；提示里禁止改测试，也不自动形成文件系统层的不可写保证。

审批服务的策略为 `ask` 与 `never`。`ask` 交给配置的回答者，回答者可由界面中的人或受控机器决策端承担；服务本身不会自动创建人工界面。回答者不可用或报错时，动作失败关闭。

**`never` 表示不交互，并拒绝需要批准的请求，不是自动批准。** 它也不禁用原本已经被策略允许的普通工具。基础组合将 `danger-full-access` 与 `approval: never` 配对，不表示靠审批再追加授权；实际访问仍取决于该权限预设及工具配置。[审批语义][approval]、[组合配置][base]

<details>
<summary>单次批准的日志与迟到回答</summary>

允许结果为 `allowed-once`，不是永久授权仓库或后续同名命令的通行证。审批请求处于打开的 Turn 中，`approval/asked`、`approval/decided` 写入日志；模型一般获得工具最终结果与当前策略，不会获得人工界面的全部内容。取消后到达的迟答不能复活已取消操作。[生命周期][approval]

</details>

### 审批策略的变更怎样进入下一步

会话级策略变更先写 `approval/policy` 事件，再给活跃 Agent 注入变更说明；完整当前策略作为运行背景放在保留历史之后，不为一次切换重写稳定的系统提示前缀。下一步骤据此得到新状态。

每次 ask 必须在打开的 Turn 内写入 `approval/asked`，再写匹配的 `approval/decided`，这样决定被包含在可重放边界中。没有打开轮次时先拒绝，不留下孤立询问。缺回答者、回答异常或非法结果统一失败关闭；只有 `allowed-once` 授予本次许可。取消先结算时，迟到回答不能重新启动工具。[实际审批链](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/interaction/user-approval/src/index.ts)

<a id="outputs"></a>
## 返回给程序的值、模型看到的文字、真实文件状态

工具业务函数先返回供程序使用的结构化结果，DSH 称为 **canonical value（规范值）**；渲染器再把它变成给模型看的 **content（内容块）**。两者又都应来自实际操作，而不能凭空证明外部状态。

下面只展示关系，不是可直接注册的 SDK 对象：

```text
程序返回值：   { changed: true, file: "pagination.py", testCount: 4 }
模型可见文字： “已修改 pagination.py；执行了 4 项测试。”
实际证据：     文件差异、测试命令、退出状态与输出
```

如果 `testCount` 只是工具作者随手填的 4，通过结构检查也不会变成真实测试证据。规范值是执行局部数据，不作为独立字段原样写入会话工具结果，不能假定重放历史就能恢复原程序对象。[输出设计][tools-readme]

### 只修改展示，会发生什么

工具返回含测试秘密的规范值，后处理把模型文字改为“已隐藏”。模型看不到原文，但程序化调用方可能仍得到原规范值，并通过另一条路径输出。

**控制模型展示与控制程序取得的数据，是两个安全目标。** 不该读取的数据应在入口阻止；程序也不该取得的结果，需要处理规范值或拒绝结果，并核对其他输出通道。仅检查模型截图不能证明所有通道都安全。[后处理链][tools]

### 结果被拦截，不等于操作被撤销

若编辑函数已经写入磁盘，后处理再阻止模型看到结果，文件不会自动恢复。防止未授权写入要在执行前约束；补偿已经发生的修改，需要业务提供可验证的恢复操作，且补偿也可能失败。

> ⚠️ **结果失败与副作用失败不等价。** 外部操作可能已完成，只是返回或保存失败。恢复后的安全核验在[会话与恢复章](05-session-and-recovery.md#semantic-recovery)继续分析。

<details>
<summary>后处理顺序与替换规则</summary>

成功规范值先经过结构检查和渲染。`projectContent` 准备执行相关内容，然后进入执行后策略；策略可保留、替换规范值、替换展示内容或拦截结果。替换规范值会重新校验与渲染，只替换 `content` 则保留原值。`finalizeContent` 最后处理内容，再冻结结果并通知观察者。[源码][tools]

</details>

### 长输出应该留下可继续工作的证据

测试输出很长时，可把完整结果外置，内联保留退出状态、关键失败信息和取回入口。外置资料可能过期或保存失败，必须明确反馈不可用，不能伪造永久有效路径。

结果外置控制这次进入会话的体积；第五章的历史压缩控制后续请求继续携带多少旧内容，两者不是同一动作。基础溢出策略的内联预算为 12,500 Token；另有按字符保留头尾的压缩辅助组件，二者的单位不能互换。[配置][base]

<a id="jobs"></a>
## Bash、前台超时与后台完成怎样接回 Agent

在配有作业注册表及控制工具的基础组合中，Bash 调用先解析本次工作目录和沙箱策略，通过许可后登记作业，再启动进程。显式后台执行返回 `jobId`；前台执行先等待，这段等待结束有三种不同含义：

| 等待结束时 | 处理 | 模型此时能确认什么 |
|---|---|---|
| 命令已退出 | 取得退出码与输出，移除未曾交给模型的内部作业记录 | 命令的实际终态 |
| 进程已启动但还在运行，允许提升 | 保留后台作业，读取当前输出，返回 `promoted` 与编号 | 可以继续读取，尚未退出 |
| 准备仍未完成、进程未启动 | 停止准备，返回准备超时结果 | 没有可保留的运行进程 |

默认允许后台与超时提升，但提升需要整套后台能力。未装配相应能力时的前台超时走终止路径；调用者主动取消也会停止并等待收束，不能把“超时”和“取消”都写成自动转后台。Windows 基础组合选 PowerShell，不能把这里核验的 Bash 路径当作所有平台实现。[Bash 等待分支](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/shell/tool-bash/src/index.ts)

`job_output` 读取流式作业自上次读取后的增量；提升时已经消费的输出不会再从头返回。带等待的读取超时只返回当前状态，作业仍可继续。停止作业与移除完成记录是不同操作：从列表消失不能替代拿到终态。

作业结算时，通知插件找到拥有它的 Agent。忙碌时把完成消息注入 next-step；默认 wakeup 模式下，空闲时通过 followup 唤醒。若配置 quiet 或用尽连续唤醒额度，则仅注入，等待其他输入唤醒。已被等待者取得终态的作业不再重复通知。模型通过 job_kill 提出取消的作业，也会抑制后续完成通知；取消请求回执不等于已经终止或取得最终输出，仍需按需读取确认。拥有者已释放时也没有收件队列。[完成通知与输出消费](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/jobs/tool-jobs/src/index.ts)

**贯穿例子。** 测试返回编号 J，模型不能宣布通过；稍后完成通知进入 Inbox，Agent 在下一步骤读取退出码和失败摘要，再决定改代码还是交付。这解释了为什么一次工具返回并不一定结束它启动的资源生命周期。

<a id="cancellation"></a>
## 超时与取消：先定位时点，再判断结果

超时表示等待预算耗尽，取消表示调用方要求停止。它们都不能单独证明业务尚未开始或外部操作已经撤销。

| 时点 | 应作出的判断 |
|---|---|
| 调度前取消 | 该调用未分派；其他调用是否开始仍要另查 |
| 已分派，正在等待外部系统 | 传递取消并等待已启动工作收尾，不能假定外部已撤销 |
| 文件已经修改，结果回填前取消 | 文件可能已改，验证可能未完成；应分别记录 |

DSH 使用取消信号协调已启动工作的结算，不把“不再等待 Promise”当成工作已经消失。普通工具错误可回填供模型调整，不一定结束整轮；但内部重试不能绕过已经生效的取消。[取消与收尾][tools-readme]、[执行实现][tools]

> ⚠️ **声明超时还需要实际执行策略。** `timeoutMs` 本身不是注册表内置计时器，截止时间由 `dsh-tool-call-timeout-policy` 包装策略实施。核对定义的同时，要检查所用组合是否挂载了它。

<a id="concurrency"></a>
## 并发执行与有序回填，是两个维度

同一步读取实现和测试文件，可以允许重叠执行；先写文件、再读修改后的内容，则有前后依赖。DSH 根据工具的并发安全分类使用有界并行池；未明确安全或分类失败的调用走保守独占路径。[分类与调度][tools]、[调用调度器][calls]

```text
模型提出： A 读取实现       B 读取测试
实际完成： B               A
结果回填： A               B
```

B 先完成，也不能越过 A 改变模型历史中的调用顺序。独占调用形成屏障；后续调用实际启动前重新分类，所以等待期间的注册或策略变化可能影响它们。

按序回填便于重建历史，**不保证外部执行顺序固定，更不自动解决共享文件竞争**。两个写工具若错误声明并发安全，仍可能互相覆盖。

<details>
<summary>哪些部分按序，取消后怎样收尾</summary>

执行前策略、规定的结果后处理与提交维持顺序，允许重叠的是执行体；调度器不是把整批调用直接交给 `Promise.all()`。取消后停止补充新工作，已启动调用先收尾，未启动调用获得相应失败结果。内部调度故障先收束已派发调用，拥有步骤的 Agent 再补保守错误回执；不伪造成功结果。[完整实现][calls]
