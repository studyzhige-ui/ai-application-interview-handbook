# System Design｜面试易错点

> 这些错误比“少背一个组件”更致命，因为它们会暴露你没有形成系统思维。

1. 一拿到题就画数据库、Redis、Kafka，没先问 Requirement。
2. 把“高并发”当数字，不问平均、峰值、Burst 和分布。
3. 把“强一致”当完整需求，不写业务 invariant。
4. 不区分 Freshness 与 Consistency。
5. 只算 QPS，不算 Payload、Storage、Network、Token / Model Cost。
6. 只看平均值，不看 HotKey、Hot Tenant、P99。
7. 把 Cache 当默认 Source of Truth。
8. Cache Aside 被说成“天然强一致”。
9. Redis 挂了就让全部流量直接回源 DB。
10. 看到热点只会“加机器”，不分析热点 Key/Partition。
11. `hash(id) % N` 被当成万能 Sharding。
12. Shard 越多被说成 Query 越快。
13. Partition、Shard、Replica、Namespace 混为一谈。
14. 扩容只说“加节点”，不讲 Rebalance 和在线影响。
15. 数据迁移只做 Snapshot，不处理 Delta Catch-up。
16. Migration 用 Deep OFFSET 扫千万行。
17. Batch Size 越大被说成越高效。
18. Queue 被当成无限容量。
19. 有 Queue 就认为系统不会过载。
20. 不监控 Queue Age，只看 Queue Length。
21. MQ 被说成 Exactly-once 自动保证业务只执行一次。
22. Retry 前没有 Idempotency。
23. Timeout 后直接认定服务端没有执行。
24. 所有错误都 Retry。
25. 多层同时 Retry，形成 Retry Amplification。
26. Backoff 没有 Jitter。
27. Circuit Breaker 被当成“所有故障万能解”。
28. Failover 被当成“绝对不丢数据”。
29. Replica 被当成 Backup。
30. 不定义 Failure Domain，所有副本在同一故障域。
31. 过载时坚持服务所有功能，不做 Degradation / Load Shedding。
32. 系统恢复后一次性 Drain 全部积压任务。
33. 分布式锁一出现就默认正确，不讲 lease/owner/fencing。
34. Compensation 被说成真正 Rollback。
35. Eventual Consistency 被理解成“随便多久都行”。
36. 没有 Reconciliation / 对账机制。
37. 多租户只加 `tenant_id` 就宣称完成隔离。
38. Cache Key 不带 Tenant / Permission Scope。
39. Queue 没有 Fairness，大租户可以饿死小租户。
40. Permission 只在 UI 做。
41. RAG 全局召回后才过滤权限。
42. Secret 被写入 Prompt / Trace / Log。
43. Agent Tool Permission 只靠 System Prompt。
44. Sandbox 与 Permission 混为一谈。
45. LLM Gateway 只做 Provider 字段转换。
46. Model Failover 不验证 Tool / Schema / Quality 兼容。
47. AI Platform 只按 QPS 做 Quota，不看 Token/Step/Cost。
48. RAG 只监控 Answer，不保留 Retrieval Trace。
49. Index / Embedding 升级直接在线覆盖，没有 Generation / Rollback。
50. RAG Permission 更新后不清 Cache / Derived Index。
51. AgentRun 绑定 HTTP Connection，断线就丢执行状态。
52. Checkpoint 只保存 Messages，不保存 Goal / Side Effect / Budget。
53. Tool 成功但 Checkpoint 失败的重复副作用窗口没有处理。
54. Worker Lease 到期后默认旧 Worker 已经停止。
55. Agent Cancel 被理解成所有副作用自动回滚。
56. 多 Agent 只因为“更高级”就拆，不看 Context/Tool/Parallel/Verify 边界。
57. Financial Agent 让 LLM 直接心算关键数字。
58. Customer Service 用 RAG 回答实时订单状态。
59. GraphRAG / Agentic RAG 被当成普通 RAG 的默认升级版。
60. 最后不讲 Metric、Load Test、Evaluation 和 Rollback。

## 一个判断标准

面试中每提出一个组件，都问自己四件事：

```text
它解决什么具体问题？
为什么不是更简单的方案？
它新增什么 Failure / Cost？
怎么证明收益大于代价？
```

如果答不上来，就很可能是在堆组件。
