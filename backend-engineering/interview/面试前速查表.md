# AI Backend Engineering｜面试前速查表

> 最后 10–15 分钟只看这张。不要背句子，记住因果链。

## 1. Request Path

```text
URL
→ DNS
→ TCP/QUIC
→ TLS
→ HTTP
→ Gateway/LB
→ Service
→ Pool / DB / Cache / MQ / LLM / Tool
→ Response / Stream
```

问自己：哪里会 Timeout？哪里会排队？哪里有 Side Effect？

---

## 2. Network

```text
TCP：连接 + 顺序 + 重传 + 流控/拥塞控制
UDP：Datagram，应用自己决定可靠语义
HTTP/1.1：成熟、Keep-Alive
HTTP/2：TCP 上多路复用
HTTP/3：QUIC/UDP，上层实现可靠 Stream
TLS：身份 + 完整性 + 加密
```

记住：**TCP Reliable ≠ Business Idempotent**。

---

## 3. Communication

```text
HTTP：对外/通用 Request-Response
RPC：内部强 Schema / 低延迟
MQ：Async / Buffer / Replay / Consumer Scale
SSE：Server → Client Stream
WebSocket：Bidirectional
```

Reconnect ≠ Resume；Resume 需要 `run_id + event_id/cursor + durable state`。

---

## 4. Capacity

```text
Concurrency != Parallelism
Coroutine 轻量 != 下游无限容量
Thread Pool = workers + queue + reject
Connection Pool = concrete connections
Semaphore = logical concurrency permits
```

总连接记得乘：

```text
pods × processes × pool_size
```

---

## 5. Backpressure

```text
Producer > Consumer
→ Queue grows
→ Wait grows
→ Memory grows
→ Timeout
→ Retry
→ Meltdown
```

保护：

```text
bounded queue
concurrency limit
rate limit
load shedding
degradation
```

Token Bucket：允许 Burst。

---

## 6. Timeout / Deadline

```text
connect timeout
pool acquire timeout
read timeout
request timeout
end-to-end deadline
```

Deadline 向下传播剩余预算。

Timeout ≠ Cancellation。

---

## 7. Error Taxonomy

```text
Transient → maybe retry
Permanent → no retry
Validation → fix request
Permission → deny / re-auth
Business Reject → normal business result
Overload → backoff / shed
Unknown Outcome → idempotency/status/reconcile
```

---

## 8. Retry / Resilience

```text
retryable?
→ backoff
→ jitter
→ retry budget
→ one retry layer
→ circuit breaker
→ fallback / degradation
```

Retry + Side Effect 必须考虑 Idempotency。

---

## 9. Idempotency

```text
stable operation key
→ atomic claim
→ request fingerprint
→ PROCESSING
→ side effect
→ persist result
→ duplicate returns same/current result
```

Lock ≠ Idempotency。

Exactly-once 不要跨系统绝对化。

---

## 10. MQ

```text
Producer Failure
Broker Failure
Consumer Failure
```

At-most-once：可能丢。
At-least-once：可能重复 → idempotent consumer。

```text
DLQ != finished
Ack != whole business transaction
```

---

## 11. Kafka

```text
Topic
→ Partitions
→ Consumer Group
→ Offset
```

- Ordering：通常 Partition 内；
- Consumer > Partition：传统 Group 下多出来可能闲置；
- Lag：先看 producer、partition skew、consumer、downstream、rebalance；
- Hot Partition：加 Consumer 不解决。

---

## 12. Reliable Long Task

```text
POST /jobs
→ durable task row
→ Outbox / MQ
→ Worker Claim
→ Lease + Heartbeat
→ Checkpoint / Progress
→ Result
→ Poll / SSE
```

Crash：Lease expire → Reclaim。

Reclaim 安全需要 Idempotency / Fencing。

---

## 13. Consistency

```text
DB = Source of Truth
Cache = Derived State
```

DB + Cache：

```text
DB commit
→ invalidate cache
→ retry / TTL / CDC / version / reconcile
```

最终一致性必须有 Convergence Mechanism。

Saga：forward actions + compensation。

---

## 14. State Ownership

```text
MySQL：durable business truth
Redis：cache/session/quota/ephemeral coordination
MQ：delivery
Object Storage：large object
Vector DB：retrieval index
Agent Checkpoint：runtime state
```

Cache 丢失不可恢复 → 它已经不是普通 Cache。

---

## 15. Auth / Tenant

```text
Authentication = Who
Authorization = Can do what
Approval = This risky action needs human confirm?
```

```text
principal
→ tenant_id
→ DB / Cache / Vector / MQ / Tool
```

Prompt 不是 Permission Boundary。

---

## 16. Discovery / LB / ID

```text
Discovery → available instances
Load Balancer → choose one
```

Stateless：实例不拥有唯一长期业务事实。

ID：

```text
Auto increment / UUID / Snowflake
```

按 unique / ordered / local / index / privacy 需求选。

---

## 17. Observability

```text
Metrics → trend / alert
Logs → event detail
Traces → request path
```

看：

```text
Rate / Error / Duration
P50 / P95 / P99
Queue Depth / Wait
Pool Utilization
Retry Rate
Downstream Latency
```

AI 再加：

```text
TTFT / tokens / cost / model version / prompt version / retrieval version / tool span
```

---

## 18. Linux

```text
scope / recent change
→ process
→ CPU / load / iowait
→ memory / OOM
→ disk / inode / deleted-open file
→ port / FD / connection
→ dependency / trace
```

Host free memory ≠ Container 不会 OOM。

---

## 19. K8s / Deployment

```text
Startup = started?
Readiness = receive traffic?
Liveness = restart needed?
```

Graceful Shutdown：

```text
not ready
→ stop new traffic
→ drain
→ checkpoint / cancel
→ close pool
→ exit
```

Scale API Pod 之前先看 DB/Provider Capacity。

---

## 20. Config / Release

```text
config validate
→ version
→ atomic swap
→ last-known-good
```

Feature Flag：owner + expiry + rollback。

Canary：Error/Latency + AI Quality/Cost。

Microservice：按 business capability / ownership / scale / failure boundary 拆，不按表拆。

---

## 21. Security

```text
Untrusted Input
→ Parse
→ Schema
→ Business Validation
→ AuthN
→ AuthZ / Tenant
→ Least-Privilege Capability
→ Audit
```

SSRF：URL/IP + redirect + egress isolation。

Secret：Provision → Use → Rotate → Revoke → Audit。

LLM Output 也不可信。

---

## 22. Cross-language Mapping

```text
FastAPI Depends ↔ Spring DI（概念映射，不等价）
contextvars ↔ ThreadLocal ↔ Go context
Python Lock ↔ Java Lock ↔ Go Mutex
asyncio coroutine ↔ goroutine（不同 Runtime）
MQ ≠ Channel
Python dict ≠ Java HashMap implementation
```

---

# 最后 60 秒

遇到任何 Production 开放题，按这个顺序：

```text
1. Requirement / SLA
2. State Ownership
3. Normal Path
4. Capacity / Pool / Queue
5. Timeout / Error
6. Retry / Idempotency
7. Consistency / Recovery
8. Security / Tenant
9. Observability / Verification
10. Scale / Degradation
```

一句总原则：

> **不要只说“加组件”；先解释它解决什么 Failure，又引入什么新的 Failure。**
