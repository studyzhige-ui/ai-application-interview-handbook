# 面经来源质量准入规则

更新日期：2026-09-09

本项目的目标不是追求“收集数量最大”，而是建立一个能真实校准 AI 应用 / Agent 求职知识体系的数据集。**宁可漏掉一些来源，也不要让低质量、二次加工或疑似虚构内容污染频率统计。**

## 1. 正式 `Sxxx` 来源的硬性准入条件

正式面经原则上至少满足以下条件中的大部分，并通过真实性判断：

1. **可追溯页面**：有稳定 URL 或可公开访问页面。
2. **面试元数据明确**：至少能确认公司/岗位，最好还能确认日期、轮次、时长。
3. **第一人称痕迹充分**：能看出候选人在描述自己的面试经历、回答情况、结果或现场感受，而不是题库作者代写。
4. **技术问题足够具体**：通常至少 5 个有信息量的问题；若只有少量问题，则必须是非常深入、独特的一手追问。
5. **问题与目标岗位高度相关**：AI Application / Agent / RAG / AI Backend / Harness / Coding Agent 等。
6. **正文不是“标准答案驱动”**：真实问题应是主体，长篇标准答案、模板化“高手答法”不能反过来冒充原始面经。

## 2. 质量分级

### A 级：高置信第一人称

特征：

- 公司、岗位、日期/轮次明确；
- 候选人本人复盘；
- 有较完整问题列表；
- 能看到自然的“答得不好 / 被追问 / 手撕 / 面试结果”等现场信息；
- 技术问题不是模板化批量生成。

用途：

- 参与真实面经频率统计；
- 可用于新增 canonical question；
- 课程优先级的重要证据。

### B 级：第一人称但信息密度低

特征：

- 可以确认是真实面试；
- 只有 2～4 个问题或只讲面试结构；
- 技术细节不足。

用途：

- 可保留为来源结构/岗位信号；
- 原则上不单独推动新增 canonical question，除非出现独特问题。

### C 级：整理 / 合集 / 原帖索引

特征：

- 作者把多个真实面经二次汇总；
- 能帮助发现原帖，但不能确认每条问题独立来源；
- 可能重复计算已有样本。

用途：

- Source Discovery；
- 不与原帖重复计数；
- 找到原帖后尽量升级到 A/B 级原始来源。

### D 级：问题信号 / 二次创作

特征：

- “某大厂三面场景题”“Agent 高频 50 题”“高手答案”等；
- 无法证明对应真实面试场次；
- 可能本身很有工程价值。

用途：

- 仅用于 Gap Analysis / 系统设计训练；
- 不进入真实面经频率；
- 不应为了扩大题量大量建立 canonical question。

### E 级：平台线索 / 待核实

例如小红书搜索结果只看到原标题但打不开正文。

用途：

- 写入 `research/leads/`；
- 等待稳定正文、原作者同步帖或其他证据；
- 不参与任何频率统计。

## 3. 默认排除项

以下来源即使搜索排名很高，也默认不进入正式 `Sxxx`：

- 水短视频：只有“面了几轮、很难、挂了”，没有具体技术追问；
- 纯 SEO 博客：大量关键词堆砌、固定“标准答案”、没有候选人现场信息；
- 标题明显属于 `三年面试五年模拟 / 含完整答案 / XX面试宝典 / 40题全解析` 且无法追溯原始面经；
- 从其他平台搬运但不注明原帖的内容；
- 多家公司问题拼接成一篇故事，无法判断每个问题来自哪一场；
- 只有评论区传言或截图标题，无法确认正文；
- AI 批量生成痕迹明显、问题排列异常规整且没有真实经历上下文的内容；
- 付费墙只露出很短片段，无法验证剩余问题和来源真实性的内容。

## 4. 去重与交叉验证

同一候选人可能把一场面试同步发布到牛客、小红书、CSDN 等多个平台：

- 标题/公司/日期/问题高度一致 → 视为同一来源，不增加频率；
- 二次博客引用原帖 → 只保留原帖为主来源；
- 合集再次收录已经归档的第一人称帖子 → 不重复计数；
- 如果两个候选人独立遇到语义相同的问题 → canonical question 增加独立来源命中数。

## 5. canonical question 新增门槛

从 Batch 06 起，不再以“看到了一个新说法”就创建新 ID。

新增 canonical question 至少满足之一：

1. A 级真实来源出现此前知识体系没有覆盖的能力；
2. 已有主题被追问到明显不同的工程层次，值得单独学习；
3. 多个独立 A/B 级来源反复出现，说明需要提升为独立知识点；
4. 虽然只有一个来源，但问题对 Runtime / Reliability / Security 等体系完整性至关重要。

否则优先记录为“已有问题得到强化”。

## 6. 研究优先级

搜索时的优先顺序：

1. 最近 30～60 天的第一人称真实面经；
2. 目标公司 / 目标岗位的完整技术面复盘；
3. Agent Harness / Runtime / RAG / Database 等少见高深度追问；
4. 高质量跨模块 AI Backend 面经；
5. 原帖缺失时才使用合集作为发现入口。

**质量永远高于 Batch 数量和 `Sxxx` 数量。**
