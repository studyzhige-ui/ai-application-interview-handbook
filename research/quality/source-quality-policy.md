# 面经来源质量准入规则

更新日期：2026-09-09

本项目的目标不是追求“收集数量最大”，而是建立一个能够真实校准 **AI 应用开发 / Agent 开发** 求职知识体系的数据集。**宁可少收，也不能让自动化面试、二次加工、低信息密度或疑似虚构内容污染正式样本。**

## 1. 从 Batch 11 起：正式样本只接受 HUMAN-A

新的正式 `Sxxx` 来源必须同时满足以下三道硬门槛：

1. **Human Interviewer Gate**：明确属于真人面试官参与的技术面 / Leader 面 / 项目深挖。AI 自动面试、AI 模拟面试、自动化题库筛选不进入正式样本。
2. **A-grade First-person Gate**：候选人本人第一人称复盘，真实性和信息密度达到 A 级。
3. **Role Scope Gate**：岗位属于 `role-scope-policy.md` 定义的 AI Application / Agent / RAG / AI Backend / AI Full-stack / Agent Runtime 等目标方向。

也就是说：

```text
真人面试官
   +
候选人本人高质量复盘
   +
目标 AI Application / Agent 岗位
   ↓
正式 HUMAN-A 样本
```

任意一项不满足，都不进入新的正式 Batch 和真人面试频率统计。

## 2. HUMAN-A 的硬性判断标准

正式来源原则上应同时具备：

- **可追溯页面**：稳定 URL 或可稳定核验的公开页面；
- **公司 / 岗位明确**：最好还能确认日期、轮次、时长或业务团队；
- **真人互动痕迹**：例如“面试官追问 / 引导 / 打断 / 反问 / 现场讨论 / 手撕 / 画图”等自然互动；
- **第一人称结果痕迹**：例如“答得不好 / 被追问住 / 约二面 / 挂了 / OC / 入职后确认面试官”等；
- **技术问题具体且有上下文**：通常至少 5～8 个有信息量的问题，或少量但非常深入、独特的连续追问；
- **问题顺序具有真实面试流**：项目 → 追问 → 基础 → 场景 / Coding，而不是异常整齐的题库分类；
- **正文不是答案驱动**：候选人的面试经历和问题是主体，而不是“标准答案 / 高手答法 / 解析”包装出来的内容。

## 3. 旧的 A～E 分级如何处理

历史批次里曾保留 A/B/C/D/E 不同层次来源用于扩大召回。从 Batch 11 起：

- **A + human**：正式核心样本，可进入频率统计、canonical question 证据和课程优先级分析；
- **B**：不再创建新的正式 `Sxxx`，最多作为发现线索；
- **C 整理 / 合集**：只用于寻找原帖；
- **D 二次创作 / 高频题 / 标准答案**：只可作为非正式搜索线索，不参与真实面经研究；
- **E 标题 / 平台线索**：只进入 Leads；
- **automated interviewer**：无论问题质量多高，一律排除出真人正式样本。

历史文件保留稳定 ID 便于追溯，但后续正式频率统计必须以 **HUMAN-A Core** 为准，不能把旧的 B/C/D/E 或 automated 来源混入。

## 4. 默认排除项

以下内容即使搜索排名很高，也不进入正式样本：

- AI 自动面试 / AI 模拟面试 / 自动化题库；
- 水短视频：只有“面了几轮、很难、挂了”，没有具体技术追问；
- SEO / 题库博客：关键词堆砌、固定标准答案、没有真实现场信息；
- `三年面试五年模拟 / 含完整答案 / XX 面试宝典 / 40 题全解析 / 高手答案` 等二次加工；
- 从其他平台搬运但无法找到候选人原帖；
- 多家公司题目拼成一篇，无法判断每个问题来自哪一场；
- 只有评论区传言、截图标题或平台搜索标题，无法验证正文；
- AI 批量生成痕迹明显、问题排列异常规整、没有候选人现场经历；
- 付费墙只露出很短片段，无法验证来源真实性与问题上下文；
- 虽然是第一人称，但只有 1～3 个泛泛问题、没有足够技术信息的低密度复盘。

## 5. 去重与交叉验证

同一候选人可能把同一场面试同步到牛客、小红书、CSDN 等多个平台：

- 公司 / 日期 / 问题高度一致 → 视为同一场，不增加频率；
- 评论页、推荐页、镜像页指向同一正文 → 只保留一个 canonical URL；
- 二次文章引用第一人称原帖 → 正式证据只保留原帖；
- 两个独立候选人遇到语义相同的问题 → canonical question 增加两个独立 HUMAN-A 命中。

## 6. canonical question 新增门槛

从 Batch 11 起，新增 canonical question 的证据默认必须来自 HUMAN-A 来源。至少满足之一：

1. HUMAN-A 来源出现此前体系未覆盖的稳定能力；
2. 已有主题被真人面试追到明显不同的工程层次，值得独立学习；
3. 多个独立 HUMAN-A 来源反复出现，说明应提升为独立知识点；
4. 单个 HUMAN-A 来源中的问题对 Runtime / Reliability / Security / Production 体系完整性至关重要。

否则优先记录为“已有问题得到新的真人来源强化”，不为了题量创建新 ID。

## 7. 搜索优先级

1. 最近 30～60 天的 HUMAN-A 第一人称技术面；
2. 目标公司 / 目标岗位的完整一面、二面、三面或 Leader 面复盘；
3. 同一场同时覆盖 Agent / RAG 与 Python / FastAPI / MySQL / Redis / Backend 的高质量样本；
4. Agent Harness / Runtime / Coding Agent 等少见深挖；
5. 其他平台只有在正文、第一人称和真人属性都可稳定验证时才进入正式样本。

**平台覆盖率、Batch 数量和 `Sxxx` 数量都不能高于来源质量。正式研究只认 HUMAN-A。**
