# 2026 AI 应用 / Agent 真人面经持续监控 Inbox

用途：只保存尚未归入正式 Batch、但已经达到 **HUMAN-A** 标准的候选来源。

## 固定准入标准

无论来源平台是什么，新的 Inbox 候选都必须同时满足：

1. **真人面试官**：人与人进行的技术面 / Leader 面 / 项目深挖；
2. **候选人本人第一人称**：不是整理、搬运或二次转述；
3. **高信息密度**：有真实现场痕迹，并包含足够具体的技术追问；
4. **Role Scope Gate**：岗位属于 AI 应用开发、Agent 开发、大模型应用、RAG、AI 后端、AI 全栈、Applied AI、FDE、Agent Runtime / Harness / Coding Agent 等目标方向；
5. **可稳定核验**：正文与原始 URL 实际可访问；
6. **非重复**：与当前正式来源不是同一场转载或跨平台同步。

以下内容不进入 Inbox：

- AI 自动面试 / 模拟面试；
- 低信息密度第一人称；
- 合集 / 整理 / 搬运；
- 标准答案 / 高频题 / 面试宝典 / 模拟题；
- SEO 博客 / 资源导流内容；
- 内容账号批量模板化“真人叙事”，但无法可靠确认候选人本人经历；
- 水短视频；
- 只有标题、截图或搜索摘要的线索；
- 无法追溯候选人原帖的内容；
- 与目标岗位不符的传统数据分析、BI、纯推荐、纯训练 Infra 或普通后端场次。

## 平台范围

不设平台优先级，可以搜索牛客、小红书、知乎、脉脉公开内容、CSDN / 掘金 / 个人博客、Bilibili、抖音以及其他公开可访问平台。

**平台只影响核验难度，不影响准入门槛。**

对于登录态 / App 跳转 / 动态加载导致无法直接访问的内容，可以利用搜索引擎摘要、企业页 / 话题页、作者主页和跨平台同步来定位原帖；但最终无法稳定验证正文时仍然不进入 HUMAN-A。

## 固定搜索方法

后续监控继续以组合搜索为主，而不是只看泛关键词首页：

```text

×
岗位别名（AI应用开发 / Agent开发 / 智能体开发 / 大模型应用开发 /
LLM应用 / RAG开发 / AI后端 / AI全栈 / Applied AI / FDE / Coding Agent）
×
月份（重点回扫 2026-03～09，同时追最新发布）
×
技术关键词（RAG / MCP / Skill / Harness / Runtime / FastAPI /
asyncio / MySQL / Redis / Vector DB / Context / Memory / Tool / Coding）
```

并继续使用：企业页 / 话题页 → 精确标题 / 轮次 → 作者主页 → 原帖正文 → 跨平台重复核验。

去重固定使用三层：

```text
URL 精确去重
+
题序 / 项目语义去重
+
作者 / 招聘流程时间线去重
```

## 保存字段

每个候选至少记录：

- 发现日期；
- 面试日期 / 轮次；
- 公司 / 岗位；
- 原始 URL；
- 真人面试证据；
- 第一人称证据；
- 5～12 条高信息量问题的简洁转述；
- 与现有来源的去重结论。

临时低质量 Lead 不写入本文件。只有已经通过 HUMAN-A 初审的来源才允许进入 Inbox。
